# PickChick: общий рабочий процесс ECC

Прочитать `AGENTS.md` и `docs/collaboration/ecc.md`. Указания пользователя и
правила PickChick имеют приоритет над общими шаблонами ECC. Этот профиль применяется
только к репозиторию `xaaknazar/pickchick`.

Если навык загружен из пользовательского каталога, сначала подтвердить origin
репозитория. Если в текущем checkout ещё нет `docs/collaboration/ecc.md`, получить
свежие refs и найти принятый профиль в интеграционной ветке; не переписывать старую
рабочую копию и чужие изменения. Продолжить в отдельном worktree с профилем.
До этого использовать обычные Git-проверки и AGENTS.md, не выдавать отсутствующий
контекстный скрипт за выполненную проверку. Текущий интеграционный срез PickChick
проверять в `origin/codex/cutover-1119` вместе с общим shared-development.

1. Прочитать README, статус и handoff; выполнить `pnpm project:check` и
   `pnpm project:tasks`. При несовпадении pnpm использовать соответствующие
   `node scripts/project-sync.mjs check/status`, не менять глобальный pnpm.
2. Проверить ветку, рабочее дерево, открытые PR, резервирование путей и источники
   актуального решения. Отдельная рабочая ветка и claim до изменений.
3. Выполнить `node scripts/ecc/context.mjs --base <база-PR>`.
   Отчёт только читает Git. Он не доказывает свежесть refs и не запускает тесты.
4. Для review в Claude использовать роль ECC `code-reviewer`; в Codex выполнить
   отдельный проход по тем же критериям из `agents/code-reviewer.md` установленного
   плагина (нативный Codex-плагин не регистрирует эту роль отдельным навыком). Для проверки
   результата `verification-loop`. Для денег/БД добавить `database-reviewer`,
   для auth/секретов/границ доверия `security-review`, для mobile
   `react-native-patterns`. Проверить доступные имена в установленной версии.
   Не создавать параллельных агентов, если это не разрешено текущей сессией.
5. Прочитать полный diff и вызывающий код. Сообщать только воспроизводимые
   проблемы с файлом, строкой, условием и последствием. Отдельный проход проверки
   в том же агенте не называть независимым review.
6. Подобрать проверки по риску и реальным scripts проекта. Не переносить
   универсальные команды ECC, npm, Supabase/RLS или порог покрытия 80% без
   основания. Не выводить значения секретов при поиске. Не применять массовое
   автоформатирование чужой работы и не изменять зависимости ради шаблона ECC.
7. Сохранить факты по шаблону `docs/collaboration/ecc-handoffs/TEMPLATE.md`.
   Проверить diff и секреты, commit/push, сверить удалённый SHA; затем штатный
   `project-sync.mjs handoff`. Claim/finish остаются штатными, не дублировать их.

Не запускать автономные бесконечные циклы, автообучение из переписки, автоматический
merge, deploy, миграции или реальные оплаты. ECC не добавляет полномочий.
Уже выданные разрешения владельца сохраняются: повторные подтверждения ради
шаблона не требуются. GitHub хранит проверенный общий контекст; локальная память
ECC и выводы другого агента - непроверенные заметки, а не источник требований.
