# Проверка 1 000 активных заказов через HTTP cloud ↔ edge

8 сентября 2026, локальная изолированная worktree. Runtime source:
`33f13ca3f5f605942011c7b544b0657510599801`. API, edge и зависимые пакеты собраны
из этого snapshot; их 60 compiled JavaScript hashes, hash исходников и harness
записаны в [машинном JSON](../load/results/2026-09-08-fulfillment-transport.json).
[Воспроизводимый сценарий и ограничения](../../docs/operations/transport-capacity-baseline.md).

**Результат: PASS локального диагностического сценария.** Это не приёмка
production-ёмкости, 1 000 новых заказов/с, физических кухонь или SLO из ТЗ.

## Стенд

- Одна cloud schema/API, десять edge schemas, LAN API и HTTP workers.
- Apple M5, 10 logical CPU, 16 GiB RAM; Node v24.16.0; macOS arm64.
- Два development PostgreSQL 18.3 aarch64 в локальном Docker, image
  `sha256:54451ecb8ab38c24c3ec123f2fd501303a3a1856a5c66e98cecf2460d5e1e9d7`.
- `max_connections=100` у обоих. План pools: максимум 13 cloud и 41 edge
  соединение включая supervisor. В начальном снимке других DB clients не было;
  это не означает отсутствия конкурирующей работы на Mac/Docker в целом.
- Все workload/API/LAN/workers работают в одном Node child. Использована
  development owner роль для временных схем; restricted grants уже имеют
  отдельные функциональные тесты и этим baseline не переаттестуются.

## Проверенный результат

В финальном барьере одновременно существуют **1 000 активных заказов**:
по 100 на каждую точку, 50 `accepted` и 50 `in_production`. Никакие заказы не
закрывались в процессе ради освобождения места.

| Проверка на каждой из 10 точек                                                       |                Результат |
| ------------------------------------------------------------------------------------ | -----------------------: |
| Приготовление: все страницы, точные order IDs и версии                               | 100 заказов / 3 страницы |
| Сборка: все страницы, точные order IDs и версии                                      | 100 заказов / 3 страницы |
| LED: номера и preparing, без дополнительных приватных полей                          | 100 заказов / 3 страницы |
| Полное совпадение cloud/edge aggregate identity, hash, state/version, номера/routing |                      100 |
| Полученные cloud task versions совпадают с начатыми edge задачами                    |                       50 |
| Durable edge inbox, без второго admission эффекта                                    |               200 команд |
| Неподтверждённые transport outbox / pending после барьера                            |                    0 / 0 |

Всего cloud получил **2 500 фактов**: 1 000 reservation, 1 000 accepted и
500 task changes. Отдельно подтверждены 1 000 точных синтетических capture и
1 000 issued sale documents без attention flags. Они поданы доверенным
внутренним портом; реальных банковских, ККМ, SMS и иных provider вызовов **0**.

Все **7 681 HTTP попытка** прошли с 200, network errors — 0:

| HTTP путь                               | Попыток |
| --------------------------------------- | ------: |
| Transport pull, включая пустые polls    |   2 550 |
| Transport ACK                           |   2 000 |
| Transport reverse events                |   2 500 |
| LAN kitchen, включая чтение перед start |      90 |
| LAN start_task                          |     500 |
| LAN display                             |      30 |
| Readiness всех 11 сервисов              |      11 |

Все команды admission/кухни и обратные факты прошли через настоящий HTTP worker.
Измеряемый сценарий не использует прямой `acceptCloud` или прямой приём фактов
в cloud вместо доставки. Direct PG/domain используется для setup, доверенной
синтетической коммерции и независимой проверки конечных данных.

## Время и память

Общий runtime с supervisor и cleanup: **25.574 секунды**.

| Фаза                               | Секунды |
| ---------------------------------- | ------: |
| Setup branch/edge/API              |   1.150 |
| Создание quote/order               |   1.947 |
| HTTP admission и reservation facts |   4.909 |
| Синтетическая оплата/фискализация  |   5.879 |
| HTTP допуск кухни и accepted facts |   6.136 |
| Начало 500 задач через LAN         |   0.940 |
| HTTP task facts                    |   2.708 |
| Финальные страницы/SQL сверка      |   0.434 |

Sampled peak RSS общего child — **418 873 344 байта** (около 399.5 MiB),
измерение раз в 100 мс. Это harness вместе со всеми Node API/LAN/workers,
без памяти PostgreSQL/Docker. HTTP latency quantiles в JSON относятся к
получению заголовков; полное тело включено во время фазы. Никакие p95 SLO
по этим значениям не объявляются принятыми.

## Безопасность и очистка

Четыре self-tests защит URL/schema/output, ограниченного scheduler и безопасных
ошибок — PASS без сетевых соединений. `--quick` 2×3 — PASS за 1.802 секунды.
Основной прогон создал 11 собственных случайных схем и удалил все 11;
`pg_namespace` подтвердил отсутствие каждой. Контейнеры/volumes и существующие
схемы не менялись, fixtures и ключи в Git не сохранены.

Отдельно проверена прерванная quick-сессия: supervisor получил SIGTERM после
начала `setup`, штатно завершился с ожидаемым exit 1 и
`INTERRUPTED_OR_TIME_LIMIT`; все три собственные схемы удалены, отсутствие
подтверждено. Проверка заняла 1.284 секунды. Это проверка очистки при сигнале,
не доказательство физического power-loss или испытание восьмиминутного deadline.

Runtime product code, root CI, lockfile и действующий VPS этим подэтапом не
менялись. Длительная/аварийная нагрузка, 20 точек с перекосом, реальные устройства,
доставка через WAN, публичный checkout и провайдеры остаются отдельной приёмкой.
