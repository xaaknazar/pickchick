# Сквозная проверка связанного тестового контура

## Локальные регрессии восстановления киоска

`kiosk_recovery.py` запускает отдельный HTTP-сервер на случайном loopback-порту
и открывает собранный operations SPA. Все API-запросы браузера перенаправлены
на этот сервер; прочие внешние запросы блокируются. Сервер является **test double**:
он выдаёт синтетические сеансы и заказы, а тест не записывает их напрямую в
sessionStorage и не обращается к VPS. Проверки не доказывают настоящую
PostgreSQL-интеграцию или подключение банка.

```sh
pnpm --filter @pickchick/operations... build
.local/design-venv/bin/python tests/operations/kiosk_recovery.py
```

Используется Playwright из `tests/design/requirements.txt` и установленный Chromium.
Восемь сценариев проверяют: очистку после возврата на старт и нового гостя;
новый ключ quote при смене режима; видимое удаление исчезнувшего SKU; ошибку первой
загрузки и пустой каталог; устаревший каталог в карточке блюда; ошибку и повтор
восстановления заказа; истёкший сеанс с незавершённой командой и помощь управляющего;
сохранение ссылки на активный заказ при отказе продления. Для незавершённой команды
проверяются reload, защита от idle reset и тот же ключ/тело повторного POST.

6 сентября 2026: 8/8 локальных сценариев прошли на Chromium при 1024×1366.
Сборка operations, TypeScript, ESLint и формат изменённых TypeScript-файлов прошли.

## Настоящий синтетический VPS flow

`browser_e2e.py` использует реальные HTTPS `/v1/test`, рабочий operations SPA и
мобильный Expo web. Он создаёт только помеченные синтетические заказы и в успешном
прогоне завершает выдачей/отменой только созданные им заказы.

До запуска должны быть развернуты backend и SPA, запущен mobile web на 8081 и
выданы временные staff keys trusted CLI. Файлы роли содержат `synthetic`, `role`,
`token`, `expires_at`; поддерживаются имена `<role>.json` и `<role>-<UUID>.json`.
Секреты не выводятся в результаты, скриншоты формы входа не снимаются. Результат
и снимки сохраняются только в игнорируемой `.local/operations-e2e/`.

```sh
TEST_FLOW_STAFF_DIR=/absolute/private/test-flow-staff \
  OPS_URL=https://pickchick.185.129.51.103.nip.io \
  MOBILE_URL=http://127.0.0.1:8081 \
.local/design-venv/bin/python tests/operations/browser_e2e.py
```

`RUN_MODE=operations` выполняет только рабочие web-сценарии, `RUN_MODE=mobile` —
только новый мобильный заказ с той же кухней/табло; по умолчанию выполняются оба.
Режим записывается в результат, поэтому частичный прогон не выдаётся за полный.

Проверяются киоск 1024×1366, мобильный web 320/390/430×844 и служебные экраны:
серверное создание, потеря **после commit** ответа тестовой оплаты, перезагрузка
и повтор с теми же ключом/телом, следующий гость без потери прежнего заказа и
утечки его номера, права служебных ролей, неизвестная оплата, разрешение управляющим,
обязательные компоненты кухни, сборка, появление номера на табло и удаление после
выдачи. Мобильный заказ проверяется в отдельном браузерном контексте; оба канала
сходятся в авторизованной кухне/управлении. У мобильного номера проверяется полная
ширина текста, чтобы поймать обрезание многоточием; номера табло проверяются в одной
строке при ширине 1024/1280/1440. Селекторы мобильных состояний ограничены текущим
экраном, поскольку React Navigation сохраняет предыдущие экраны в DOM.

Тест не подменяет ответы backend успешными фикстурами. Единственная инъекция
перехватывает уже завершённый настоящий POST и скрывает его HTTP-ответ, чтобы
проверить восстановление. Тест не запускается обычным публичным CI без приватного
стенда и временных ролей. При отказе смотрите безопасное поле `stage`; сырые
Playwright исключения не печатаются, поскольку они могут включать ввод формы.
