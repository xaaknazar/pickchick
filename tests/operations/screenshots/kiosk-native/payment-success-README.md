# Дополнительная проверка S8 и S9 — 7 сентября 2026

Один сценарий экспортированного Expo kiosk web UI прошёл на **1024×1366**:
**1/1 PASS, 7.614 с**, исходники приложения
`3d29b1eb7b113420923aa1bc56e7fdcdeba4b4d6`, Chromium `145.0.7632.6`.
Три PNG просмотрены после сохранения. Это браузерные снимки, не снимки
нативного приложения или физического iPad.

- [S8: проверка заказа и выбор оплаты](web-review-1024.png): восстановлены
  паттерн шапки, логотип, режим получения, заголовок, оранжевая сумма справа,
  синий итог внутри карточки и пояснения способов оплаты. Карточки и CTA
  помещаются на экран. Дополнительная строка помощи/отмены/языка, оценка
  приготовления и TEST-пояснения сохранены как явные дополнения.
- [Ожидание тестовой оплаты](web-payment-1024.png): отдельное состояние,
  которого нет в исходном макете. Симуляция не изображает работающий QR,
  терминал или фискальный чек.
- [S9: номер после подтверждения](web-order-darkened-1024.png): поверх фонового
  паттерна применён исходный градиент `rgba(0,40,110,.74)` →
  `rgba(0,26,80,.92)`. Полноэкранный размер и цвета подтверждены по CSS;
  оранжевый `T-900001` и статус «Готовим ваш заказ» целиком видны. Размер
  номера адаптирован к более длинному номеру TEST-заказа. В исходном макете
  номер трёхзначный; обещание получения реального чека здесь не перенесено.

Источник сравнения — канонический `design/reference-source/kiosk.html.txt`,
S8 строки 1297–1354, S9 строки 1356–1379. Эти три PNG не являются исходными
материалами заказчика. Предыдущие шесть пар и их provenance не изменены.

Сценарий создаёт корзину через UI, переключает оба radio способа оплаты,
проверяет доступность CTA и отсутствие горизонтального переполнения. До
перехода к оплате заказа нет; далее создан ровно один локальный заказ на
4190 ₸ и выполнено ровно одно тестовое подтверждение. Ответ фикстуры переводит
заказ из `awaiting_test_payment` в `preparing` с `simulated_approved`.
Все HTTP API запросы обработаны или заблокированы существующей локальной
фикстурой; запросов на VPS, в банк, ККМ, SMS или Apple не было.

В двух предварительных коротких запусках исправлены ожидания нового теста
под действующий контракт: точное имя `awaiting_test_payment` и строковая
сериализация денег `'419000'`. Это не дефекты приложения. После этих
исправлений выполнен указанный успешный запуск; полная предыдущая серия
не повторялась.

Воспроизведение после сборки общего каталога и стабильного web export:

```sh
KIOSK_UI_URL=http://127.0.0.1:4184 \
PICKCHICK_TEST_SOURCE_ROOT="$PWD" \
KIOSK_UI_OUTPUT=.local/kiosk-payment-success \
.local/design-venv/bin/python tests/kiosk/browser_payment_success.py
```

Скрипт запускает только один дополнительный тест. SHA исходников, bundle,
тестов и PNG, геометрия номера и вычисленные градиенты записаны в
[отдельном provenance](payment-success-provenance.json).
