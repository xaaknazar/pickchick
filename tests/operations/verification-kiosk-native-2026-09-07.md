## Нативная проверка

Release build-for-testing для iPad (A16), iOS Simulator 26.5, завершился успешно
в Build02. Встроенный JS bundle и семейство устройств iPad-only проверяются
отдельным release helper. Симулятор не доказывает запрет выхода на реальном iPad.

Run03 проверил модификаторы, цену 4 780 ₸, раздельные варианты и relaunch, затем
выявил ошибку ожидания теста: корзина 2×4 780 + 4 190 = 13 750 ₸ должна сразу
открываться без upsell по порогу исходного макета 10 000 ₸. Исправлен только
этот участок теста; первоначальный upsell при 8 970 ₸ и проверки обоих количеств
сохранены. Второй тест Run03 не прошёл из-за оставшейся корзины первого.
Run03 не засчитывается как успешная серия. Run04 на выделенном iPad (A16)
с чистым гостевым состоянием: **2 PASS, 1 connected-test SKIP, 0 failures**,
109,353 с. Подтверждены модификаторы, КБЖУ, оба количества, восстановление
корзины, отмена/новый гость, композиция и закреплённые действия.

Build05 собран из финального UI source `d82641047df00246ff87d58132db1c538c931348`.
Фактический Info.plist: `UIDeviceFamily = [2]`, полный экран,
`kz.pickchick.kiosk`, версия 0.1.0 (1). На нём выполнены:

- Run06 connected на iPad (A16): **1 PASS, 0 failures**, 52,458 с.
- Run07 на iPad Air 13 (M4), 1024×1366 pt: **1 PASS, 0 failures**, 38,124 с.
  [Нативные снимки и provenance](screenshots/kiosk-native/native-provenance.json).

Обе проверки использовали Release и iOS Simulator 26.5, Xcode 26.6 (17F113).
Артефакты `.xcresult` сохранены в `~/Library/Caches/PickChick/`.

Устранены две причины сбоя среды сборки: известный Clang feature-probe deadlock
во вложенном ExpoModulesJSI build и FinderInfo iCloud в generated framework.
[Проверяемый scoped launcher](../../docs/operations/ios-clang-probe-workaround.md)
сохраняет настоящие compiler output и exit code. Пакет Expo JSI размещён в
локальном Caches с проверкой неизменности 62 исходных файлов и symlink из
node_modules; его исходники не патчены. Оригинальный Expo script успешно собрал
simulator/device slices и основной build подтвердил cache-hit. Приватные логи
и provenance находятся в `.local/auth-design` и `~/Library/Caches/PickChick`.

## Заказ от нативного iPad до выдачи

Run06 создал один синтетический заказ **T-000034** в TEST API на VPS.
Нативный UI подтвердил имитацию оплаты, после terminate/relaunch восстановил
тот же номер, затем открыл витрину следующему гостю. Номер взят из XCTest
attachment, а не выбран из общей очереди.

После этого отдельная проверка через действующие ролевые API подтвердила
именно этот `channel=kiosk` заказ на приготовлении, сборке и в «Готовится»
табло. Выполнены его задания prep, затем assembly; тот же номер появился
в «Готово». После handoff состояние стало `fulfilled`, номер исчез с табло.
Оплата — `simulated_approved`, фискализация — `not_applicable`.
Другие заказы не менялись; повторного создания заказа проверяющий скрипт не делал.
Private proof: `.local/kiosk-native/T-000034-verification.json`,
завершён 7 сентября в 14:52:22 Алматы. Это проверка API кухонь/табло;
работа на физических ресторанных устройствах этим не доказана.

Первый read-only запуск проверяющего скрипта обнаружил его неверное ожидание
версии: без query API совместимо выдаёт v0.2. До любой мутации добавлен
`catalog_version=mockup-v0.3`, такой же, как у киоска. Повтор завершился успешно.

На VPS опубликован проверенный API `5d3eead08c392bdbb60eae64a0bee4e883bb0af3`:
[копия, восстановление, точные изменения и проверка сохранности данных](../../docs/operations/deployments/2026-09-07-kiosk-catalog.md).
До публикации прошли все четыре jobs [CI этого SHA](https://github.com/xaaknazar/pickchick/actions/runs/34106813343).
Финальный исходник `90e15dab8b9142fc7d11d31748236afc225a2569` дополнительно
прошёл все четыре jobs [CI выпуска](https://github.com/xaaknazar/pickchick/actions/runs/34110038944).
После правок S8/S9 Build08 + Run09 повторили связный native-сценарий:
**1/1 PASS, 30,290 с**, iPad (A16), заказ **T-000035**. Подтверждены тестовая
оплата, тот же номер после relaunch и новый гость. Затем тот же заказ прошёл
через prep/assembly, «Готово» на табло и handoff до `fulfilled` через ролевые API.
Итого за нативную приёмку созданы два синтетических заказа, оба выданы;
реальных оплат/чеков/SMS — ноль. [Финальный native-снимок](screenshots/kiosk-native/native-order-final-a16.png)
и [provenance](screenshots/kiosk-native/native-order-final-provenance.json).

Локально прошли сборка, типы, lint, формат, 31 unit-тест, контракты,
проверка 130 экранов/21 требования, 24 теста kiosk core и 30 Python-проверок
мобильных/release-инструментов. Финальная локальная цепочка была прервана
форматом provenance JSON; после исправления формат и оставшиеся этапы
повторно прошли. Полный `pnpm check` финального source также прошёл в CI.

## Доставка и устройство

Текущий статус: **0.1.0 (1) загружена, обработана и назначена закрытой группе
TestFlight**. Ниже сохранены фактические этапы и исправленные ограничения.
Первая попытка archive `kiosk-private-20260907-1` завершилась
кодом 65: Xcode не нашёл профиль для нового `kz.pickchick.kiosk`; automatic
signing также сообщил об отсутствии устройств для development profile.
Для TestFlight требуется отдельный App Store distribution profile и запись
киоска в App Store Connect, а не регистрация постороннего устройства.
После восстановления браузерной сессии root отдельно зарегистрировал
App ID `kz.pickchick.kiosk`, App Store profile `63RKQSS245` и ASC приложение
`6809407135` **PickChick Kiosk** с ограниченным доступом. Profile привязан к
существующему distribution certificate и истекает 30 июля 2027. Другие
приложения/сертификаты не менялись.

Инструмент браузера не вернул локальный download. Получение завершено через
штатный Xcode manual build с `-allowProvisioningUpdates` без регистрации
устройств. Загружен и проверен App Store profile UUID
`d3788a75-8842-442d-a2fe-f0aff9570ca5`; подписанный device build успешен.

Cleanup helper заметил параллельное удаление чужой временной EAS keychain
и отказался перезаписывать общий список. После проверки root удалил только
свою временно добавленную keychain; изменение другой сборки сохранено,
default keychain не менялась. Native project restored побайтово. Private
протокол: `~/Library/Caches/PickChick/kiosk-profile-download-01/`.
Финальный archive и export **0.1.0 (1)** завершились успешно из чистого
`90e15dab8b9142fc7d11d31748236afc225a2569`. Проверены фактические
Bundle ID, `[2]` device family и подпись; IPA — 30,0 MiB. Export options

и keychain search list восстановлены штатно в обоих финальных этапах.
Release label: `kiosk-private-20260907-2`. Apple подтвердила **Upload succeeded**
7 сентября в **15:21:30 Алматы**. Метаданные release содержат
