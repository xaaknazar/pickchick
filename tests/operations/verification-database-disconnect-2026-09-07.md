# PostgreSQL disconnect внутри транзакции — 2026-09-07

Исправлен crash процесса при потере leased PostgreSQL-соединения. В pg 8.23
pool временно снимает свой idle `error` listener при выдаче клиента. Закрытие
сокета может отдельно вызвать `error`, даже если ошибка активного запроса уже
поймана и helper выполняет `ROLLBACK`.

`transaction()` теперь ставит собственный listener на время lease, сохраняет
ошибку соединения и не возвращает повреждённый клиент в pool. Неуспешный rollback
тоже уничтожает клиент. Listener снимается после `release`, когда pool уже
установил idle listener. Обычный успешный rollback сохраняет здоровое соединение.
Обработчики принадлежат конкретным клиентам; raw driver errors не логируются.

## Подтверждение

До исправления на исходном SHA `695e1c305f976a9222c9ec408d2f5e4866326ce5`
два сценария disconnect завершались неуспехом; trigger-сценарий подтвердил
`Unhandled 'error' event` в изолированном дочернем процессе.

После исправления реальные PostgreSQL проверки **4/4 PASS**:

1. Trigger вызывает `pg_terminate_backend(pg_backend_pid())` после промежуточной
   записи в транзакции. Получена контролируемая ошибка `57P01`, незавершённая
   запись отсутствует; следующий checkout создаёт новое соединение и commit.
2. Убит собственный backend между запросами. Процесс остаётся жив, соседняя
   одновременная транзакция сохраняется, следующая транзакция работает.
3. Шестнадцать SQL/business ошибок с rollback сохраняют исходное здоровое
   соединение. Listener не накапливается, незакоммиченных строк нет.
4. Потеря idle-клиента по-прежнему обрабатывается pool; лог содержит только
   `{"event":"database_pool_error"}`, следующее соединение исправно.

Тесты создают отдельную случайную схему, завершают только собственные backend PID
и удаляют схему в `finally`. Каждый опасный сценарий работает в child process
без `uncaughtException` handler: регрессия не может считаться успешной после crash.
Проверки выполняются только на local/test URL; VPS и реальные данные не затрагиваются.

```sh
pnpm --filter @pickchick/platform... build
node --env-file=.env --test tests/integration/database-disconnect.test.mjs
```

Файл автоматически включён существующим `tests/integration/*.test.mjs` в CI.
Build/typecheck пакета, ESLint и Prettier пройдены локально. Результат GitHub CI
фиксируется после интеграции коммита в общую ветку.
Совместный прогон новых проверок и прежнего `database.test.mjs`: **14/14 PASS**,
включая конкурирующие миграции и откат DDL/бизнес-записей.

Исправление не повторяет транзакцию автоматически. Разрыв во время `COMMIT`
может оставлять результат неизвестным; вызывающий доменный код должен сверить
идемпотентную операцию. Отсутствие частичных записей здесь подтверждено для
принудительного disconnect **до COMMIT**, а не для потерянного ответа после него.
