# Локальный пароль сотрудника

Пароль проверяет PostgreSQL/edge на кассе без WAN. Существующие UUID сотрудника,
точки и терминала, роль и kitchen station grants сохраняются. У кассира нет общего
пароля по умолчанию. Миграция `011_staff_passwords.sql` создаёт пустые таблицы;
она не включает приём заказов, не открывает смену и не создаёт сотрудников.

## Первое задание пароля на Windows

Оператор сначала обновляет edge, применяет миграцию 011 и заново применяет
`applyEdgeRuntimeGrants`. В поставку оператора входят `scripts/staff-password-setup.mjs`,
`hidden-password.mjs`, `staff-file-permissions.mjs` и собранные workspace packages.

Открыть обычный PowerShell/Windows Terminal **от имени локального оператора**.
В PowerShell ISE, при перенаправленном stdin и в терминале без TTY скрытый ввод
отклоняется. Команда выполняется из защищённого каталога текущего operator runtime
`C:\ProgramData\PickChick\EdgeTools\<release>`. Подставить установленный release,
UUID сотрудника из защищённой записи монтажа и выбранный владельцем логин:

```powershell
& 'C:\Program Files\PickChick\Edge\<release>\node\node.exe' --env-file=private\edge-owner.env scripts\staff-password-setup.mjs --bootstrap .local\staff-<staff-uuid>.json --login cashier.one
```

Владелец набирает новый пароль дважды прямо на моноблоке. Символы не отображаются.
Пароль: от 12 до 128 символов, пробелы сохраняются. Не отправлять пароль в чат,
не добавлять его в команду, переменные окружения, скрипт или файл. Логин: 3–64
латинских буквы/цифры/точки/подчёркивания/дефисы, первый символ - буква или цифра;
сервер приводит его к нижнему регистру и удаляет внешние пробелы.

CLI проверяет NTFS ACL приватного bootstrap-файла и каталога, loopback PostgreSQL
`127.0.0.1:55433/pickchick_edge`, владельца таблицы и активную сессию сотрудника
из этого файла. Если bootstrap истёк/отозван, оператор сначала перевыпускает его
существующим `scripts/staff-setup.mjs <existing-setup.json> --renew`. Исходные
staff/terminal UUID и роль должны совпадать с существующей записью. При уже
заданном пароле нужен явный `--replace`; reset требует нового действующего
operator bootstrap. CLI не меняет роль и не создаёт терминалы.

После успешной записи все прежние сессии этого сотрудника отзываются. CLI печатает
только результат, UUID, роль и логин. Новый пароль и его хеши не выводятся и не
сохраняются в operator-файле. В базе остаются уникальная 32-байтовая соль, scrypt
verifier и audit без секрета. Параметры `scrypt-v1`: N=32768, r=8, p=3, ключ32байта,
maxmem64MiB; сравнение через timingSafeEqual. Используется
[стандартный Node crypto.scrypt](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback).

## Вход и выход

`POST /edge/v1/staff/login` принимает `{login,password,terminal_id}` и возвращает
существующий `StaffCredential` на 8 часов. Branch берётся только из edge config.
Терминал должен существовать, быть активным и принадлежать точке; сотрудник тоже
должен быть активным в этой точке. Роль берётся из базы, включая kitchen. POS
по-прежнему отказывает роли kitchen. Native config хранит постоянный `terminalId`.
UI не записывает пароль в state, browser storage, journal или credential-файл.

Любой неверный логин/пароль/отключённый сотрудник/неверный терминал возвращает
общий401 UNAUTHORIZED. На активном терминале допускается10попыток за60секунд,
включая неизвестные логины и успешные входы. Следующая попытка возвращает429
AUTH_RATE_LIMITED и `Retry-After: 60`. Счётчик PostgreSQL сохраняется до проверки
пароля, переживает перезапуск, не создаёт строки для случайных login/terminalUUID.
После5неверных паролей сотрудник блокируется на15минут с тем же ответом401;
успех после истечения блокировки либо operator reset сбрасывает счётчик.
Одновременно выполняются максимум2KDF; дополнительный запрос получает429.

`POST /edge/v1/staff/logout` с Bearer и X-Staff-Session-Id отзывает текущую сессию
и возвращает204. UI локально выходит даже без сети; в этом случае не заявляет,
что сервер подтвердил отзыв. Незавершённый журнал сохраняется.

Проверено автоматически на отдельном PostgreSQL18.6: настоящий HTTP login/logout,
роль kitchen, истёкшее окно bootstrap, закрытый приём, durable lockout/restart,
лимит произвольных логинов, runtime LOGIN/grants, reset/revoke, конкурентный
login/logout и переход010→011 с сохранением существующих строк. Unit-проверки
проверяют scrypt, отсутствие эха/перенаправления и восстановление режима TTY.
Физический скрытый ввод и новый вход на Windows требуют отдельного подтверждения
монтажа; эти автоматические проверки не считаются таким подтверждением.
