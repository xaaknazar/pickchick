# Customer push: подготовка без включения

Сервис выключен по умолчанию. Этот этап не деплоит worker и не отправляет
уведомления реальным гостям. APNs/FCM не заменяют чтение заказа и не выполняют
финансовых операций.

## Сервер

1. Зарезервировать ресурсы согласно AGENTS.md, проверить полный CI и штатный
   backup/restore. Применить cloud069 после принятой схемы068 и сверки номера со свежим shared.
2. Использовать действующий серверный customer-auth и checkout read configuration.
   `CUSTOMER_AUTH_ENABLED=true`; `CUSTOMER_PUSH_ENABLED=1` только после настройки.
3. `CUSTOMER_PUSH_ENCRYPTION_KEY_FILE`: файл с отдельным случайным 32-байтовым ключом
   в base64, права 0600. Ключ не заменяет ключи identity. Смена ключа требует
   перешифровки токенов; нельзя просто заменить файл у работающего сервиса.
4. Для Apple: `APNS_KEY_FILE`, `APNS_KEY_ID`, `APNS_TEAM_ID`. Ключ p8 ES256 хранится
   вне репозитория. Bundle IDs разрешены только `kz.pickchick.app` и `.dev`;
   окружение sandbox/production определяется entitlement установленной программы.
5. Для Android: `FCM_SERVICE_ACCOUNT_FILE` с отдельным service account проекта.
   Приватный ключ никогда не включается в мобильный бинарник. Для сборки используется
   отдельный `PICKCHICK_GOOGLE_SERVICES_FILE` с клиентской конфигурацией Firebase.
6. API требует SELECT identity_customers/identity_sessions; SELECT/INSERT/UPDATE/DELETE
   на собственные customer_notification_* / customer_push_* и USAGE последовательности
   consent-журнала. Worker дополнительно использует имеющиеся права чтения checkout.
   Не выдавать права изменения финансовых таблиц ради push.
7. Отдельный процесс `node services/api/dist/customer-notifications-worker.js`.
   `--once` - один проход. Нельзя запускать его на рабочей базе ради проверки без
   принятой конфигурации и согласованного выпуска. Логи содержат только счётчики и коды.

## Устройство

- В Apple Developer включить Push Notifications для нужного App ID; обновить
  provisioning profile. Нужен новый нативный бинарник: добавлен expo-notifications.
- В настройках приложения выбрать язык, включить уведомления о заказах. Разрешение
  запрашивается только по этому действию. Предложения требуют отдельного согласия.
- Проверить RU/KK/EN на физическом iPhone: foreground, background, завершённое приложение,
  отказ в разрешении, повторный вход, смена языка и смена аккаунта.
- Тестовый push разрешён только на согласованное тестовое устройство. Проверить получение
  из APNs sandbox и production/TestFlight отдельно; приём провайдером не доказывает доставку.
- Нажатие проверяет inbox текущего аккаунта и открывает «Заказы». Номер, сумма, телефон,
  состав заказа и произвольный URL в push не передаются.

## Границы и эксплуатация

Опрос серверной проекции каждые 10 секунд, заказы за последние 24 часа и только
созданные после включения уведомлений. Старые заказы после opt-in не рассылаются.
Промежуточные состояния могут быть пропущены; предыдущий неотправленный баннер заменяется
новым. Inbox дедуплицируется по аккаунту/заказу/состоянию. Доставка имеет lease, максимум
10 попыток с задержкой от 60 секунд, TTL 30 минут. Сбой после приёма APNs/FCM, но до
записи результата может вызвать повтор баннера: exactly-once доставку не обещаем.

Отзыв согласия и сеанса исключает новые отправки; уже принятый провайдером баннер
невозможно гарантированно отозвать. Токены отозванных сеансов очищаются worker;
неактивные токены и inbox очищаются через 90 дней. Журнал согласий хранится отдельно
и требует согласованного срока хранения перед коммерческим запуском.

Рекламные кампании, их частотные лимиты, отправка из бэк-офиса и произвольные шаблоны
в этом этапе не реализованы. Сохранение отдельного opt-in не запускает рассылку.

## Проверки без внешней отправки

`pnpm test:notifications` - контракты, шаблоны, классификация ответов провайдеров.
`pnpm test:integration` включает тот же набор с локальными disposable PostgreSQL schemas.
Транспорт в тесте заменён функцией; настоящие Apple/Google credentials не используются.

Первичные источники: [Expo Notifications](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/),
[APNs requests](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns),
[FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api),
[FCM errors](https://firebase.google.com/docs/cloud-messaging/error-codes).
