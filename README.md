# PickChick — технический план экосистемы

Технический план v1.0 · API v0.3.0 · 6 сентября 2026.

**Реализовано:** TypeScript/NestJS API и локальный edge, две PostgreSQL БД,
Redis, миграции, регистрация edge и HTTP-доставка меню; локальные сессии/роли
персонала, расчёт обычных SKU, стоп-лист и идемпотентный неоплаченный POS-заказ.
Это инженерный стенд без реальных оплат, чеков и передачи на кухню.
На предоставленном VPS развёрнут [частный staging](docs/operations/staging-vps.md);
[протокол запуска и восстановления копии](docs/operations/deployments/2026-09-06-staging.md).
Запуск и команды: [локальная разработка](docs/operations/local-development.md).
Контракты: [OpenAPI](packages/contracts/openapi.json) и [события](packages/contracts/event.schema.json).
Принятые решения: [ADR 0001](docs/architecture/adr/0001-foundation.md).
Регистрация и синхронизация: [инструкция](docs/operations/menu-sync.md),
[ADR 0002](docs/architecture/adr/0002-device-menu-sync.md).
Размещение: [предложение VPS и порядок внедрения](docs/operations/vps-plan.md).
Первый заказ: [локальный POS](docs/operations/local-orders.md),
[ADR 0003](docs/architecture/adr/0003-local-orders.md).

**Дизайн v0.1:** [130 экранов всех интерфейсов](docs/design/README.md),
сценарии, состояния и общие дизайн-токены. Интерактивный просмотр: `pnpm design:serve`.
Макеты используют демонстрационные данные; клиентские приложения ещё предстоит реализовать.

Канонический GitHub: [xaaknazar/pickchick](https://github.com/xaaknazar/pickchick).
Текущий этап: [состояние проекта](docs/project-status.md).
Правила последующей разработки: [AGENTS.md](AGENTS.md); для Anthropic-инструментов — [CLAUDE.md](CLAUDE.md).
Завершённые изменения проекта сохраняются коммитами и отправляются в этот репозиторий.

Актуальными являются файлы `docs/` в текущей ветке. `PickChick-technical-plan-v1.zip`
сохранён как исходный снимок плана до начала разработки; распакованный дубликат
не включается в Git. Новые изменения в этот исторический архив не дописываются.

**Рекомендуемая конструкция: центральный backend в Казахстане + автономный узел каждой точки + единая модель заказов, денег, кухни и лояльности.** Мобильное приложение, киоск, касса, кухня, табло и бэк-офис используют это ядро.

Основание: текущее описание заказчика, пять предоставленных HTML и доступное прежнее обсуждение «Техническое задание проекта» от 30 августа 2026. В нём были ориентиры на четыре месяца, RU/KZ и предоставление контента/переводов заказчиком. Ранее обсуждавшиеся 46 млн ₸ — исторический коммерческий ориентир, а не пересчитанная смета этого плана. Коммерческие условия и договор этим документом не изменяются.

Заказчик дополнительно подтвердил: **четыре календарных месяца включают тестирование и внедрение**; AI-инструменты — Fable 5.1 от Anthropic и Astra 6. Названия моделей используются в формулировке заказчика; их тарифы, версии API и доступность отдельно не проверялись.

Мощности серверов, SLO, распределение работ внутри срока и параметры программы лояльности ниже — **проектные предложения**, если прямо не указано иное. Точный контракт Kaspi для мобильной оплаты, API Яндекс Еды в Казахстане и автономная фискализация должны пройти этап подтверждения. Документы не означают, что эти доступы уже получены или система реализована.

Из HTML извлечены шаблоны и логика без запуска; исходные файлы не изменены. Текстовые извлечения с SHA-256 находятся в `docs/research/`. Просмотр локальных HTML в браузере был запрещён политикой браузерного инструмента; выводы по макетам основаны на их исходном содержимом, без заявления о визуальном тестировании.
