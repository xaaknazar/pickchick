# PickChick — технический план экосистемы

Технический план v1.0 · API v0.3.0 · состояние на 7 сентября 2026.

**Реализовано:** TypeScript/NestJS foundation API и локальный edge, cloud/edge
PostgreSQL, миграции, регистрация edge и локальная HTTP-доставка меню;
сессии/роли персонала, расчёт обычных SKU, стоп-лист и идемпотентный
неоплаченный POS-заказ. Redis поднят, но прикладные cache/queue ещё не реализованы.

Отдельный облачный **TEST-контур** связывает Expo mobile, web-киоск iPad,
две кухни, табло и управляющего через один синтетический заказ PostgreSQL.
PickChick **0.1.0 (4)** доступен в TestFlight: 24 блюда исходного мокапа,
КБЖУ/модификаторы, обновлённая корзина и локальный тестовый вход. Сборка **0.1.0 (5)**
с входом по макету, никнеймом без `@` и системным пикером даты рождения загружена
в Apple; завершение обработки и доступность в группе ещё не подтверждены.
[Состояние доставки](docs/operations/mobile-testflight.md).
Добавлено отдельное iPad-приложение **PickChick Kiosk 0.1.0 (1)** по исходному
макету: каталог v0.3, модификаторы, корзина, восстановление гостевого TEST-заказа.
[Закрытый TestFlight 0.1.0 (1)](docs/operations/kiosk-testflight.md) ·
[Single App Mode на устройствах](docs/operations/ipad-kiosk-lockdown.md).
Apple подтвердила обработку и статус «Тестируется» в `PickChick Kiosk Internal`;
в группе только владелец, публичной ссылки нет. Применение AppLock на
ресторанных iPad ещё не выполнено; полноэкранный UI сам по себе не блокирует выход.
Настоящие OTP, оплаты, чеки,
склад и лояльность ещё не работают. Локальный POS/edge пока не связан с этой
кухней; автономный ресторанный цикл при потере WAN не принят.

Основание: текущее описание заказчика, пять предоставленных HTML и доступное прежнее обсуждение «Техническое задание проекта» от 30 августа 2026. В нём были ориентиры на четыре месяца, RU/KZ и предоставление контента/переводов заказчиком. Ранее обсуждавшиеся 46 млн ₸ — исторический коммерческий ориентир, а не пересчитанная смета этого плана. Коммерческие условия и договор этим документом не изменяются.

Заказчик дополнительно подтвердил: **четыре календарных месяца включают тестирование и внедрение**; AI-инструменты — Fable 5.1 от Anthropic и Astra 6. Названия моделей используются в формулировке заказчика; их тарифы, версии API и доступность отдельно не проверялись.

Мощности серверов, SLO, распределение работ внутри срока и параметры программы лояльности ниже — **проектные предложения**, если прямо не указано иное. Точный контракт Kaspi для мобильной оплаты, API Яндекс Еды в Казахстане и автономная фискализация должны пройти этап подтверждения. Документы не означают, что эти доступы уже получены или система реализована.

При подготовке первой версии ТЗ из HTML извлекались шаблоны и логика без запуска;
исходные файлы не изменялись. Текстовые извлечения с SHA-256 находятся в
`docs/research/`. Позднее оригинал отрисован и сопоставлен с нативным приложением:
[пары скриншотов и фактические проверки](tests/operations/verification-mockup-fidelity-2026-09-07.md).
