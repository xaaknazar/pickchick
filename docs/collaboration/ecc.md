# ECC для PickChick

Решение владельца 28.11.2026: установить бесплатный ECC для Claude и Codex,
проверки изменений и передачи контекста. Это инструменты разработки, без подписки
Pro, GitHub App, новых API-ключей и выпуска приложений/серверов.

## Источник и границы

- [ECC upstream](https://github.com/affaan-m/ECC), MIT, версия 2.2.3.
- Проверенный исходник: `4adeee6732a12d1540f49a4d50a38ce8c97f9a53`.
- Codex CLI 0.169.1: нативный `ecc@ecc`, официальный marketplace.
- Claude Code 2.1.193: `ecc@ecc`, scope `project`, настройки в `.claude/settings.json`.
- Общий профиль: `.agents/skills/pickchick-control/SKILL.md`; Claude имеет тонкую
  обёртку `.claude/skills/pickchick-control/SKILL.md`. Одни бизнес-правила для обоих.
- База внедрения: `f52744aad713b66787f210788219088df9bdbc8e` из cutover,
  включающая свежий shared-development. Старый корневой checkout не сбрасывался.

ECC дополняет AGENTS.md, ADR и существующий project-sync. Он не выдаёт разрешений,
не является доказательством приёмки и не управляет сервером ресторана. Доступные
в upstream Supabase-примеры, общий TDD/80% coverage и параллельные агенты не
становятся обязательными правилами PickChick. Для небольших правок выбирать
соответствующие проверки, а не запускать все приложения без причины.

## Работа над задачей

1. Выполнить `pnpm project:check` и `pnpm project:tasks`; прочитать актуальные
   README, статус, handoff и PR. Если установленный pnpm не соответствует
   package.json, использовать `node scripts/project-sync.mjs check` и `status`
   для этих двух операций, не изменяя глобальный менеджер пакетов.
2. Новая рабочая ветка, согласованная база и claim затронутых путей. Чужие
   изменения и резервирования сохраняются. Другой checkout не обновляется сам.
3. Получить контекст изменений:

   ```sh
   node scripts/ecc/context.mjs --base origin/codex/cutover-1119
   ```

   Для PR в другую ветку явно передать её ref. Скрипт читает имена файлов из
   committed/staged/unstaged/untracked, учитывает merge-base и обе стороны
   переименований. Содержимое файлов, env и переписку он не читает; команды
   тестирования не запускает. Отчёт использует локальные refs, не заменяет fetch
   и не определяет все зависимости по именам файлов.

4. Применить нужные ECC-инструкции: code-reviewer, verification-loop,
   security-review, database-reviewer, react-native-patterns. В Claude роли
   доступны через плагин; Codex использует skills и отдельный проход review
   по инструкции из установленного `agents/code-reviewer.md`.
5. Проверить полный diff и вызывающий код. Доказать замечания сценарием, строкой
   и последствием; не создавать замечания ради количества. Не называть
   самопроверку независимым review. Выбрать реальные тесты из package.json и CI.
6. Для денег проверить повтор/гонки, неизвестный банковский исход, возврат,
   целые минимальные единицы, доверенный источник оплаты. Для БД/edge проверить
   права, миграции, durable outbox/inbox, владение данными, потерю WAN и повторную
   доставку. Тесты с БД запускаются только на изолированных fixtures.
7. Отдельно записать: код, локальные проверки, CI точного SHA, установку,
   физическую приёмку. Зелёный тест не означает выпуск или приёмку владельцем.

## Передача Claude - Codex

Общая память - проверенные файлы GitHub. Использовать
`docs/collaboration/ecc-handoffs/TEMPLATE.md`; одна запись на задачу.

- Записать задачу, разрешения, claim, ветку, базу, проверенный SHA, изменения,
  команды/результаты, CI, ограничения, откат и следующий шаг.
- Проверить отсутствие секретов и персональных данных, commit/push и удалённый SHA.
- Выполнить существующий `project-sync.mjs handoff`. Не подменять его памятью ECC.
- Получатель получает опубликованный коммит, сверяет факты и принимает claim
  по существующим правилам. История чата и локальная память не синхронизируются.

Локальные unified-memory/learned instincts остаются необязательными заметками;
для этого внедрения отдельный memory runtime/MCP и автоматическое обучение не
включены. Непроверенные заметки не повышаются до бизнес-правил автоматически.

## Автоматика и настройки

Claude использует минимальный профиль. Отключены upstream SessionStart с
подмешиванием локальных заметок, запись сессии, извлечение навыков, трекер стоимости
и маркер завершения. Вместо них наш короткий SessionStart напоминает о правилах
и текущей ветке. Он не читает транскрипт, не пишет файлы и не обращается в сеть.
Автоформатирование и постоянное наблюдение за инструментами не входят в minimal.

У Codex другая система hooks: профили Claude на неё не переносятся. Установка
плагина не означает доверие его hook-командам. Пользовательское подтверждение
в `/hooks` не подделывается. Для работы PickChick достаточно общего skill и AGENTS;
upstream SessionStart Codex не требуется для передачи контекста через GitHub.
По этой установке не заявляется автоматический запуск hook в живом Codex-сеансе.

На Mac уже были установки Claude ECC для других рабочих копий. Они сохраняются;
мастер ECC dry-run предложил удалить чужую local-установку, поэтому его apply
не выполнялся. Использован штатный `claude plugin install --scope project`.

## Новый Mac или рабочая копия

Получить принятую ветку с этим профилем и проверить upstream перед обновлением.
Первоначальная проверенная версия - 2.2.3 и SHA выше; marketplace может обновиться,
поэтому сравнивать установленную версию/исходник, а не считать команды пином.

```sh
codex plugin marketplace add affaan-m/ECC
codex plugin add ecc@ecc --json
codex plugin list --json

claude plugin marketplace add affaan-m/ECC
claude plugin install ecc@ecc --scope project
claude plugin list --json
```

Проверить `enabled`, scope и projectPath. В Codex регистрация действует на профиль
пользователя; бизнес-настройки PickChick применяются только к этому репозиторию.
Перезапустить Codex-сеанс; в Claude выполнить `/reload-plugins` или начать новый
сеанс. Не отключать проверки доверия. До применения новой версии проверить её
изменения, manifest, зависимости и поведение hooks.

## Проверки и откат

```sh
node --test tests/unit/ecc-context.test.mjs
node scripts/ecc/context.mjs --base origin/codex/cutover-1119
node scripts/ecc/session-start.mjs
```

Контекстный скрипт входит в существующий unit-набор Foundation CI. Установку
плагина проверять отдельно штатными list/cache проверками. Тесты контекстного
скрипта не являются проверкой всей библиотеки ECC или живых чатов обоих агентов.

Для отключения Claude в конкретной копии выключить `ecc@ecc` и удалить только
наш SessionStart из её настроек. Codex: `codex plugin remove ecc@ecc` (это весь
профиль пользователя). Общий профиль/скрипты откатываются отдельным revert PR.
Не удалять чужие настройки, историю, `~/.claude`, `~/.codex` или другие плагины.
