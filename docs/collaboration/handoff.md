владельца. Реализация/проверки: `docs/design/auth-sheet-v3.md`. Маршрут `/auth`

## 29 сентября: серверный checkout Kaspi и мобильный экран пилота

Добавлен отдельный авторизованный путь `/v1/customer-checkout`: сервер рассчитывает
цену из опубликованного каталога, сохраняет quote/order, а банк подтверждает деньги
через прежний durable Kaspi worker. Телефон берётся из identity, не из тела запроса.
Незавершённое оформление сохраняется до HTTP-запроса; повтор восстанавливает тот же
заказ и ту же попытку. Статусы приходят через long poll локальной проекции, без
повторных запросов клиента в банк. Поля банка и внутренних аккаунтов клиенту не выдаются.

Миграция 027 вводит неизменяемую политику `deferred_pilot`. В этом режиме реальная
оплата + подтверждение edge допускают кухню без выдуманного чека; обычные заказы
по-прежнему требуют issued receipt. Пилот ограничен серверным списком аккаунтов,
одним заказом на клиента и суммой по умолчанию **100 ₸**. Цены меню не занижались.
Для первого согласованного счёта нужен отдельный подготовленный сервером probe,
а не попытка списать полную стоимость корзины под видом проверки.

Проверено локально: 48 PostgreSQL commerce/Kaspi сценариев, 15 transport сценариев;
сборка API, mobile typecheck; браузер 320/393/768, восстановление после потери ответа,
одна команда счёта, обновление до paid, читаемые фиксированные действия. Все банковские
ответы в этих проверках подставные. Дизайн: UI/UX Pro Max + Impeccable, detect без замечаний.
