## Область ответственности

Этот Mac ведёт финансовый модуль: ввод доходов/расходов, ДДС, ОПиУ,
сводки и графики, статьи, финансовые периоды, экспорт, права, финансовый
API, хранение, проверки и документацию. Текущая работа - `finance-dashboard`,
[PR #197](https://github.com/xaaknazar/pickchick/pull/197).

Новые изменения финансов по умолчанию выполняются здесь. Другие Mac
согласуют изменения этой области перед началом работы. Это постоянное
распределение ответственности; конкретные пути по-прежнему занимают через
`claim` на время задачи и освобождают через `finish` после интеграции.
Окончание задачи не отменяет закрепление финансов за этим Mac.

Общая оболочка backoffice, общие contracts, зависимости и сервер являются
совместными ресурсами. Работа над ними требует проверки актуальных резервов.
Эквайринг, касса, киоск, кухня, мобильное приложение и игры не входят в
поручение этому Mac; потребность финансов в их данных согласуется через
контракты и отдельные задачи, без параллельного изменения чужих областей.

## Существующие задачи и выпуск

Назначение ответственного не отменяет незавершённую работу другого Mac.
В момент решения `finance-release-guard` остаётся активной задачей другого
Mac; её код не перехватывается автоматически. По завершении текущей работы
дальнейшие финансовые изменения и подготовка выпуска ведутся здесь.

Установка с этого Mac требует отдельного разрешённого SSH-доступа: сейчас
он не настроен. Нужны собственный ключ и добавление его публичной части через
доверенный доступ, с проверкой fingerprint сервера. Секреты в Git не сохранять.
До настройки доступа установка возможна через согласованную передачу
проверенного выпуска Mac с доступом; ответственность за финансовую разработку
остаётся здесь.

API/public/БД обслуживают несколько модулей: серверные резервы берутся только
на время согласованного выпуска. Постоянно закреплять весь VPS за финансами
или снимать активные резервы `kiosk-kaspi-qr` это решение не разрешает.
Выпуск по-прежнему требует зелёной CI точного исходного коммита, штатных guards,
резервной копии и проверки отката. Назначение ответственного само по себе
не означает установку нового финансового интерфейса.
