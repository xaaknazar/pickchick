## 2. Откат образа API на сборку облачной полосы (R3)

Сборка облачной полосы строго проверяет карточки ингредиента, техкарты и сотрудника, поэтому
карточка с полем P1 у неё не сохраняется и не производится. Перед откатом образа владелец схемы
выполняет `P1_PAYLOAD_STASH_SQL` (runbook «Откат образа API», блок SQL дословно; таблица
`bo_p1_payload_stash` создаётся там же, у роли API прав нет), после возврата сборки bo-ui -
`P1_PAYLOAD_RESTORE_SQL`. Прошу добавить строку в мастер-runbook отката (раздел «Откат образа API»
`backoffice-p1-cutover.md`). Откат флагов на месте этого шага не требует.

## 4. Тождество с облачной полосой (R4)

`backoffice-cloud-lane-golden.json` записан из сборки 43806cf4 (`git archive` того коммита, `tsc`,
зависимости этой полосы - вне `packages/backoffice-core` полоса меняла только флаги
`packages/platform/src/config.ts`); две записи подряд совпали байт в байт. Тест сравнивает выходы
этой полосы с `backofficeP1Options({})` с эталоном, порядок ключей включительно; с включённым
`POS_DAY` он находит 15 расхождений, то есть может упасть. Наборы - «все флаги выключены» и «роли и
отчёт продаж»; склад v2 в эталон не входит: на 075 с правами он по дизайну добавляет ключи склада P1
(§8 в.5). Перезапись эталона - только из сборки облачной полосы (команда в заголовке `.mjs`).
