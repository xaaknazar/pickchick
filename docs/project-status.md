# PickChick — состояние проекта

## PICK MAN - крупное поле и управление свайпами

По уточнению владельца убраны нижние стрелки и большая панель подсказок.
Лабиринт использует доступную ширину и высоту без ограничения клетки в 25 пунктов;
сохранены пропорции, свайпы во всей игровой области и действия доступности.
Проверены пять размеров, четыре направления свайпов, пауза/восстановление,
поворот экрана и индикатор соуса. Типы, lint, web-экспорт и Dev-сборки iOS/Android
прошли. Изменение доступно через текущий PickChick Dev; новый TestFlight не выпускался.
[Подробности и скриншоты](operations/pick-man-large-board.md).

проверяемого операторского восстановления; автоматического продвижения state нет.

Подготовлен отдельный [локальный backup/restore rehearsal](../infra/windows/native-backup.md):
защищённый custom pg_dump только `pickchick_edge`, общий PostgreSQL snapshot для
архива и контрольных counts, проверка TOC/SHA-256 и восстановление в новый случайно
названный экземпляр БД того же кластера. Cleanup требует совпадения имени, OID,
владельца и run marker; существующие БД не перезаписываются. Прошли два теста
отказов небезопасного cleanup и PowerShell parser/pins/привязка аргументов.
Физический backup и restore не выполнялись этим этапом разработки: успешный
операторский прогон и private manifest нужны до заявления о проверенной копии.

Следующий этап: обновить кассовый интерфейс, смены и модификаторы по поручению
владельца; после приёмки кассы установить защищённый канал кухни и staff grants,
затем принять запуск/перезапуск/очередь на двух физических моноблоках.
Оплата/ККМ, денежная смена и допуск неоплаченного POS на кухню этим выпуском

## Текущий этап — серверные аккаунты, каталог и исполнение заказа

- Публикация следующей версии меню: immutable release, outbox и непрерывный
  producer sequence одной транзакцией; повтор по release UUID идемпотентен.
- Настоящие HTTP pull/ACK с авторизацией устройства по своей точке. Центр
  меняет активное меню только после подтверждения применения на edge.
- На edge: проверка hash/версии/последовательности, snapshot/activation/inbox/
  cursor/ACK outbox в одном commit. Worker с timeout, ограничением размера,
  повтором/backoff и восстановлением неподтверждённого ACK после restart.
- OpenAPI v0.2.0 и команды `device:setup`, `device:revoke`, `menu:publish`,
  `sync:once`, `sync:watch`; пример меню v2 и инструкция воспроизведения.
- [ADR 0002](architecture/adr/0002-device-menu-sync.md),
  [инструкция обмена](operations/menu-sync.md),
  [предложение VPS](operations/vps-plan.md) с проверенным публичным тарифом.

Локально прошли `pnpm check` (включая 7 unit tests) и 26 интеграционных тестов.
Новые сценарии используют отдельные временные схемы в двух PostgreSQL:
реальный HTTP worker, конкурентная публикация/доставка, rollback в середине
операции, потерянный ACK-ответ, offline/retry, hash/schema/gap, изоляция точки,
ротация/expiry/revoke, старый ACK после нового меню и malformed/oversized HTTP.
Вручную выполнены CLI setup, повторная публикация примера v2, `sync:once`
(`applied`, затем `idle`) и сравнение release/version обоих HTTP API.
Права файла ключа 600 и каталога 700 проверены без вывода секрета.
[PR №2](https://github.com/xaaknazar/pickchick/pull/2) принят в main после
подтверждения продолжения заказчиком. CI на `a0487b8` прошёл;
merge commit: `ed5ce66fd49d9b03b8eccd43d82f60975d33de1d`.

**Границы:** это первая часть этапа 1Б. Работает только localhost с тестовыми
данными. Публичный одноразовый enrollment, роли/вход сотрудников и OTP клиентов,
TLS/VPN, snapshot recovery после потери БД, fencing при смене edge, DLQ/алерты,
каталог с комбо/quote/заказы, мобильные интерфейсы и оплаты ещё не реализованы.
Короткие тесты restart не заменяют полный 8-часовой аппаратный WAN-тест.

На момент этапа 1Б.1 VPS ещё не был предоставлен. Был подготовлен staging-кандидат PS Cloud Basic-4
(4 shared vCPU, 8 GB, 160 GB SSD, 28 750 ₸/месяц на 06.09.2026), с отдельной

## Этап 1Б.2 — права персонала, базовый quote и локальный заказ

Реализовано в ветке `codex/stage-1b-local-orders`:

- Trusted local setup персонала и терминалов: cashier/shift_manager/kitchen,
  8-часовые сессии и grant, хранение хеша секрета, обновление сессии и отзыв.
  Каждая операция проверяет точку, active staff/terminal, срок и роль.
- Cashier создаёт/читает/отменяет свои неоплаченные заказы на своём терминале;
  manager управляет режимом приёма, ручным стопом и заказами точки. Кухонная
  роль не имеет доступа к этому POS API.
- Quote по активному меню: обычные SKU, количество, «в зале»/«с собой», BigInt,
  KZT, immutable snapshot и TTL 5 минут по часам БД. Клиентские цены запрещены.
- Idempotent POST заказа по quote UUID; повтор возвращает прежний результат,
  changed payload конфликтует. Unique quote → order; перепроверяются TTL,
  меню, режим точки и стопы. Создание/отмена, audit, outbox и command result
  фиксируются одной транзакцией; отдельный producer для коммерческих событий.
- Заказ имеет только `awaiting_payment` или `cancelled`, без состоявшейся
  оплаты/фискализации/готовки. Отмена требует expected version и причину;
  immutable quote сохраняет исходные цены после смены меню.
- API v0.3.0, миграция edge 004, CLI `staff:setup`, `staff:revoke`,
  `local:request`, синтетические примеры, [инструкция](operations/local-orders.md)
  и [ADR 0003](architecture/adr/0003-local-orders.md).

Проверки: 10 unit и 39 integration сценариев, включая реальный HTTP,
повтор/конкуренцию, права и чужую точку/терминал, expiry, stop/menu change,
rollback outbox, обновление сессии одновременно с checkout и restart edge
при отсутствии центрального HTTP API. Build/types/lint/format/contracts проходят;
результат CI связан с актуальным SHA PR этого этапа.

Ручной CLI smoke: setup manager/cashier → open → quote на 7180 ₸ по примеру v2
→ create → replay с тем же результатом → cancel → GET cancelled → close.
Исходный закрытый режим точки восстановлен. Файлы сессий имеют mode 600,
секреты в вывод и Git не включаются. Заказ smoke синтетический, оплаты нет.

**Границы:** backend только localhost; права выдаются trusted CLI на edge,
не центральной системой управления пользователями. Нет публичного входа/PIN/OTP,
комбо/модификаторов, скидок/Чиков, расписания, складского резерва, смен ККМ,
реальных денег/чеков, кухни/табло и доставки заказов в центр. Коммерческий outbox
сохранён, consumer не реализован. Полный Gate B и аппаратный WAN-тест не пройдены.
После этапа заказчик предоставил существующий VPS; инфраструктурная работа описана ниже.
