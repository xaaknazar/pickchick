## Этап 1А — локальный исполняемый фундамент

Реализовано в ветке `codex/stage-1-foundation`:

- pnpm monorepo: API, edge, contracts, database, platform, test-fixtures.
- Node/TypeScript/NestJS и зависимости зафиксированы, lockfile включён в Git.
- Два PostgreSQL-контейнера с отдельными томами; локальный Redis cache.
- Миграции cloud/edge с lock, transaction, checksum и запретом смешивания схем.
- Организация, юрлицо, точки, устройства, каталог, цены, immutable версии меню;
  составные FK ограничивают принадлежность сущностей. Таблицы inbox/outbox
  подготовлены; работающий transport/worker пока не реализован.
- Центральные read-only endpoints точек/активного меню и локальное меню edge.
- Runtime Zod-контракты, генерируемые OpenAPI/event schema и проверка дрейфа.
- Health/readiness с раздельными состояниями БД/схемы/Redis, request ID,
  безопасные ответы ошибок и ограничение запуска на local/test/loopback.
- Синтетический seed; повторный запуск не создаёт дубликаты, приём заказов выключен.
- GitHub Actions workflow для build/types/lint/format/contracts, unit/integration
  tests на PostgreSQL и dependency audit; PR template и CODEOWNERS.
- [Инструкция запуска](operations/local-development.md) и [ADR](architecture/adr/0001-foundation.md).

Локально подтверждено:

- `pnpm check`: build, typecheck, lint, форматирование, 5 unit tests, contract drift.
- `pnpm test:integration`: 15 сценариев на реальной PostgreSQL и Nest HTTP.
- Повторный migrate/seed; fresh migrations, конкурентный runner, checksum drift,
  rollback DDL, ограничения организации/денег/снимков и дедупликация inbox.
- Меню edge читается после остановки cloud API и перезапуска edge; сбой Redis
  даёт degraded, сбой PostgreSQL — readiness 503, неверная branch binding — отказ.
- `pnpm audit --audit-level=high`: известных уязвимостей не найдено на момент проверки.

[PR №1](https://github.com/xaaknazar/pickchick/pull/1) принят в main после
подтверждения продолжения заказчиком. CI на `cfee962` прошёл;
merge commit: `f05c5caf33ad4467ddd5c44fbb5e5d908cd86ded`.

**Границы:** это завершённая первая инженерная часть этапа 1, не полный Gate A/B.
Нет OTP/RBAC/device enrollment, полноценного каталога с модификаторами/комбо,
checkout/заказа/кухни, фискализации, эквайринга или синхронизации между точками.
Прямой seed двух БД не является протоколом синхронизации; короткий restart-тест
не заменяет 8-часовую автономную приёмку. Клиентские приложения и production
развёртывание не созданы, branch protection в GitHub пока не настроен.

## Этап 1Б.1 — локальные устройства и доставка меню

Реализовано в ветке `codex/stage-1b-menu-sync`:

- Trusted local setup заранее созданного edge, ротация/отзыв ключа, срок
  30 дней, SHA-256 вместо открытого секрета в центральной БД, журнал операций.
  Один active edge на точку; приватный файл идентичности исключён из Git.
- Публикация следующей версии меню: immutable release, outbox и непрерывный
  producer sequence одной транзакцией; повтор по release UUID идемпотентен.
- Настоящие HTTP pull/ACK с авторизацией устройства по своей точке. Центр
  меняет активное меню только после подтверждения применения на edge.
- На edge: проверка hash/версии/последовательности, snapshot/activation/inbox/
  cursor/ACK outbox в одном commit. Worker с timeout, ограничением размера,
  повтором/backoff и восстановлением неподтверждённого ACK после restart.
- OpenAPI v0.2.0 и команды `device:setup`, `device:revoke`, `menu:publish`,
  `sync:once`, `sync:watch`; пример меню v2 и инструкция воспроизведения.
- [ADR 0002](architecture/adr/0002-device-menu-sync.md),
  [инструкция обмена](operations/menu-sync.md),
  [предложение VPS](operations/vps-plan.md) с проверенным публичным тарифом.

Локально прошли `pnpm check` (включая 7 unit tests) и 26 интеграционных тестов.
Новые сценарии используют отдельные временные схемы в двух PostgreSQL:
реальный HTTP worker, конкурентная публикация/доставка, rollback в середине
операции, потерянный ACK-ответ, offline/retry, hash/schema/gap, изоляция точки,
ротация/expiry/revoke, старый ACK после нового меню и malformed/oversized HTTP.
Вручную выполнены CLI setup, повторная публикация примера v2, `sync:once`
(`applied`, затем `idle`) и сравнение release/version обоих HTTP API.
Права файла ключа 600 и каталога 700 проверены без вывода секрета.
Результат удалённого CI проверять по актуальному SHA PR этого этапа.

**Границы:** это первая часть этапа 1Б. Работает только localhost с тестовыми
данными. Публичный одноразовый enrollment, роли/вход сотрудников и OTP клиентов,
TLS/VPN, snapshot recovery после потери БД, fencing при смене edge, DLQ/алерты,
каталог с комбо/quote/заказы, мобильные интерфейсы и оплаты ещё не реализованы.
Короткие тесты restart не заменяют полный 8-часовой аппаратный WAN-тест.

VPS у заказчика пока нет. Подготовлен staging-кандидат PS Cloud Basic-4
(4 shared vCPU, 8 GB, 160 GB SSD, 28 750 ₸/месяц на 06.09.2026), с отдельной
оценкой backup и подтверждением площадки РК. Заказ и deployment не выполнены.
Production-конфигурация из ТЗ сохраняется; staging не объявляется отказоустойчивым.
