# Вход и регистрация v3 - 30 сентября 2026

Основание: прямое поручение владельца перенести вход и регистрацию из
`PickChick - mockup.zip` и четырёх приложенных изображений. Визуальный источник
этой области - [неизменённый HTML v3](../../design/reference-source/auth-v3.html.txt),
SHA-256 `1597d02812a05005480812f3c502e7b52c11db10e88c3af2212f3fb75b58170a`.
Прочие экраны сохраняют прежние источники и оформление.

## Реализация

- После прежней заставки сразу меню. Гость собирает корзину и открывает товары.
- Профиль, события, заказы и оформление вызывают `/auth` поверх текущего экрана;
  прямые защищённые ссылки также закрыты. Только активный экран может вызвать
  автоматический вход, чтобы выход из аккаунта не открывал несколько листов.
- Один `OrderSheet` с локальными шагами: персонаж, телефон, код, знакомство.
  Закрытие возвращает к исходному экрану; успешный вход продолжает выбранный путь.
  Корзина и её модификаторы сохраняются.
- Иллюстрации взяты из переданного архива: Pick Man, фингерс, бургер и соусы.
  Плавное движение декора останавливается в фоне и при Reduce Motion.
- Телефон: фиксированный +7, форматирование, системная клавиатура/автозаполнение,
  скрытие клавиатуры после полного корректного номера. Действие над клавиатурой.
- OTP: шесть ячеек, системная клавиатура, вставка/автозаполнение, автоматическая
  проверка, серверный таймер, смена номера, ошибки и явный повтор после сбоя.
  Один и тот же код самопроизвольно повторно не отправляется.
- Никнейм и дата рождения в общей группе; системный выбор даты; пол необязателен.
  «Заполню позже» не сохраняет черновик полей, но отмечает завершение знакомства.
  Существующий заполненный профиль сразу возвращает человека к выбранному действию.
- Поддержка и юридические документы открываются внутри листа с возвратом к вводу.
  Гостевая поддержка показывает существующий информационный экран, отправка
  обращения без аккаунта этим изменением не добавлена.

## Реальные возможности и отличия от картинки

WhatsApp пока не подключён. Новый экран использует Telegram только когда его
разрешает конфигурация сервера; выбора SMS нет. На OTP показан подтверждённый
канал ответа. Неизвестный результат доставки обозначен как ожидание подтверждения,
а не как успешная отправка. При выключенной авторизации есть понятное состояние
недоступности и повтор подключения. Серверные лимиты, долговечные запросы,
защита сессий и согласия сохранены.

Две галочки заменены явной формулировкой действия «Продолжить»: принятие условий,
обработка данных и передача номера/кода Telegram. Версия согласия привязана к номеру
и шагу; без действия согласие не подставляется. При восстановлении старой попытки
без подтверждённого в этом листе согласия требуется отдельное принятие. Маркетинг
не включается. Эта UI-реализация не является юридическим утверждением новой формы
согласия: соответствующая пометка дизайнера сохраняется как вопрос перед запуском.

Версия приложения берётся из конфигурации, а не из вымышленного «1.0 (100)».
На узких экранах контент прокручивается; органы управления доступны без обрезания.
Общий крестик сохранён по предыдущему решению владельца.

## Проверки

- Mobile typecheck, ESLint/Prettier; 216 Node + 30 Python mobile-проверок,
  7 roadmap-проверок, регрессия композиции меню/товара/корзины.
- PickChick Dev: iOS manifest и bundle HTTP 200, 11 299 098 байт.
- Серверный HTTP fixture на 320×568, 390×844, 430×932: явная команда согласия,
  автопроверка, сохранение даты/профиля, восстановление той же сессии и выход.
  Потерянный ответ verify повторяется с прежним request_id и принятой версией
  политики даже после истечения challenge и обновления условий.
- Demo fixture на тех же размерах: неверный код, опциональные поля, валидность
  даты/запрет будущего, отмена/очистка даты, пропуск без сохранения черновика,
  сохранение независимой идентичности заказов и отсутствие записей из preview.
- Защищённые игры и оформление, возврат к прежней корзине, выход и закрытые
  операции гостя; восстановление повреждённого аккаунта. Profile 320/393.
- Две ограниченные визуальные проверки: после первой устранены смещение окна
  при автоматическом web-фокусе и обрезание номера на 320. Impeccable detector: []
  (это механическая проверка, не доказательство нативной приёмки).
- В этих сценариях нет реальной отправки OTP, банковских вызовов или заказов.
