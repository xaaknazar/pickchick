# Проверка дизайна v0.1 — 6 сентября 2026

Проверяется интерактивный HTML-прототип, а не готовые приложения Expo, iPad,
Windows POS или интеграции с банком/ККМ. Синтетические данные не отправляются на VPS.

## Выполнено

- Chromium 145 через Playwright 1.58.0: 130 страниц, 749 сочетаний экрана и
  состояния. Проверены загрузка ресурсов, отсутствие исключений, неопределённых
  экранов и горизонтального переполнения внешней рамки. Ошибок не обнаружено.
- Проверены переход меню → блюдо → корзина, изменение количества, блокировка
  подтверждения недостаточной наличности, сохранение неизвестного результата
  платежа после проверки, зависимость финальной сборки от компонентов,
  текстовый поиск по заказам и просмотр каталога при ширине 390 px.
- Визуально просмотрены семь основных макетов: mobile, kiosk, POS, kitchen A,
  kitchen B, display и backoffice. [PNG-предпросмотры](../../design/previews/).
- Статическая проверка идентификаторов, переходов и покрытия всех 20 именованных
  требований MOB/KIO/POS/KDS. Разделы BO, DSP и лояльность сопоставлены в каталоге.
- Все 9 перечисленных основных текстовых цветовых пар проходят 4.5:1.
  Результаты расчёта — в [каталоге](screen-catalog.md). Проверены соответствие
  цветов CSS/JSON, размеры рамок и SHA256 семи исходных изображений.

Обнаруженные при проверке проблемы исправлены: собственные страницы кассы для
добавок/комбо/QR; неопределённый платёж исключён из кухни/табло; сумма не разрывается
перед символом валюты; способы оплаты кассы отделены от прокручиваемого состава.

## Воспроизведение

```sh
pnpm design:catalog  # после изменений screens.json
pnpm design:check
pnpm design:serve
```

В другом терминале, из корня репозитория:

```sh
python3 -m venv .local/design-venv
.local/design-venv/bin/pip install -r tests/design/requirements.txt
.local/design-venv/bin/python -m playwright install chromium
.local/design-venv/bin/python tests/design/browser_smoke.py
```

Результат JSON сохраняется в `.local/design-qa/results.json`, семь PNG обновляются
в `design/previews/`. В CI browser smoke запускается отдельным job; источник
screens.json и документация проверяются общей командой `pnpm check`.

## Что остаётся проверить при реализации

Это не pixel-diff регрессия, не полный WCAG-аудит и не проверка всех бизнес-правил.
Состояния ошибок/отсутствия связи переключаются вручную в панели просмотра;
прототип не симулирует надёжность настоящего edge или реальный обрыв WAN.

Ещё нужны: брендбук и фактический каталог; полные RU/KZ тексты; review
каждого редактора с управляющим и кассиром; реальные размеры/разрешения оборудования;
VoiceOver/TalkBack, масштаб текста 200%, системная клавиатура и safe areas;
дистанционная читаемость LED; поведение на iOS/Android/Windows; долгие заказы и
большие очереди с реальными данными; интеграционные и аппаратные испытания.

QR, банковская оплата, сохранение форм, возвраты, push, экспорт и начисления
демонстрационные. Поле телефона не авторизует гостя. Полная проверка полей,
серверные права и восстановление операций реализуются в продуктовых приложениях
по [handoff](handoff.md) и ТЗ, затем тестируются отдельно.
