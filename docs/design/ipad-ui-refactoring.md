# iPad UI refactoring: file-by-file record

2026-10-07. Scope: `apps/kiosk`, the iPad UI requested in this chat. The customer mobile app, cashier, kitchen and finance UI are separate scopes. No global redesign is implied.

The strict rule is enforced: appearance stays in its component, layout goes through Wrapper, screens contain composition and state. Each exported visual component has a colocated `*.stories.tsx` file in the flat components folder. A story renders the production component, with explicit synthetic data and callbacks, not a visual copy.

Files below are relative to `apps/kiosk/src/components` unless prefixed otherwise. “Removed” means removed from the public API, not hidden behind a temporary compatibility layer.

## Library and safeguards

The follow-up motion pass adds `RecommendationCard.tsx` and its two stories. Previously UpsellGrid pieced together ProductCard and an added label. RecommendationCard now owns its entrance, stable confirmation line and product composition; its API is product, position, added, busy, locale and onAdd. Position is the item's sequence in the recommendation list, not an arbitrary animation delay.

ProductCard now has a semantic `variant: catalog | recommendation`; ProductArtwork has a matching recommendation variant. Compact image proportions and text limits stay inside those components. Their new variant stories exercise the same production code. ProductIntro owns its entrance opacity/transform. `useEntranceMotion.ts` supplies a shared progress value and bounded timing, while visual styles remain in each component. MenuGrid's unmount cleanup prevents a departing scroll view's final zero-offset event from overwriting the saved browsing position.

- `.storybook/main.ts`: official React Native Web Vite framework, local-only server, telemetry disabled; static output stays under `.local`.
- `.storybook/preview.tsx`: same KioskFonts and SafeAreaProvider; tablet viewports, controls, docs and accessibility panel.
- `src/stories/fixtures.ts`: real synthetic catalog; no production credentials; QR stories use a non-payment payload.
- Every component has a Default story. Additional stories cover loading/disabled actions, empty/invalid cart, selected choices, unavailable items, long quantities, Kazakh labels, modal/sheet and uncertain payment. Theme-only/asset components also have entries.
- `tests/kiosk/ui-architecture.test.mjs` parses TSX, prohibits cosmetic public props and their use on local components, verifies screen composition and story coverage, and rejects Wrapper escape hatches.
- `tests/kiosk/browser_mobbin.py` renders every built story and checks language, resize, modal bounds and Reduced Motion. Domain scenarios remain in the existing browser and unit suites.
- `useMotionPreference.ts` and `.web.ts` follow system preferences and background state. Web uses independent media-query subscriptions so one unmount cannot remove another component's listener in React Native Web. Button cancels an active press animation immediately when the preference changes; CartBar keeps informational confirmation independent of motion.
- `tests/kiosk/browser_payment_success.py` keeps order/payment assertions and now verifies an opaque white number ticket with blue text, instead of requiring the superseded decorative pattern and gradient.

## Behavior kept separate

Amounts still come from the existing integer-minor-unit cart and server quote. No client animation fabricates bank success. The existing unknown/pending payment guard, replay/recovery, no-duplicate-order behavior, enrollment storage, reset and video background lifecycle remain in their established modules. The Storybook development dependency and its esbuild build permission are explicit, pinned and confined to tooling; no animation runtime package was added.

Full native-device appearance and installation remain pending. The iOS bundle export and web tablet screenshots are not presented as native installation evidence. Global status/roadmap/handoff files remain with their current coordination owner; the scoped implementation record is here and in ipad-mobbin.md.
