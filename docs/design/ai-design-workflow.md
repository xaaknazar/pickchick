# UI/UX Pro Max + Impeccable для PickChick

Решение владельца от 23 сентября 2026: подключить оба набора, изучить их
и оценить улучшения приложения. «Impossible» в сообщении интерпретировано
как Impeccable из предшествующего списка. Установлены именно Codex skills;
это инструменты разработки, а не зависимости приложения.

## Что подключено

| Набор         | Назначение                                                      | Закреплённый источник                                                                                                                              |
| ------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI/UX Pro Max | Поиск правил UX, типографики, взаимодействия, цветов и платформ | [dcc40ff](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/tree/dcc40ff5133ef78276117db0cc34e7b83cc8aeba/.claude/skills/ui-ux-pro-max), MIT |
| Impeccable    | Разбор и улучшение структуры, состояний, оформления и движения  | [e0881d2](https://github.com/pbakaus/impeccable/tree/e0881d2de397d5e9761d7b35ff5017d8f5ebf69b/.agents/skills/impeccable), Apache-2.0               |

Полные ревизии и контрольные суммы: [design-skills.lock.json](design-skills.lock.json).
На Mac навыки установлены в `~/.codex/skills/ui-ux-pro-max` и
`~/.codex/skills/impeccable`. Codex подхватит их в следующем ходе;
в ходе установки инструкции прочитаны и инструменты уже запущены вручную.
В других рабочих средах нужна отдельная установка по этим ревизиям.
В Git сохраняются привязка, происхождение и результаты, а не копия чужих баз.

Impeccable SKILL имеет версию 4.3.1, его отдельный engine - 0.1.5.
Загрузчик получил engine из официального GitHub release и проверил его
SHA-256 по опубликованному sidecar перед исполнением. После ZIP-установки
потребовалось восстановить право выполнения launcher. Автоматические hooks
не включались; дополнительные плагины, UI-библиотеки и npm-зависимости
не добавлялись. Поиск Pro Max выполняется локально по CSV, без отправки
проектных данных внешней модели.

## Воспроизводимая установка

Использовать системный `skill-installer` Codex. Если каталог уже существует,
сначала сверить его версию; не удалять и не перезаписывать пользовательские
изменения. Установщик сам отказывается перезаписывать существующий каталог.

```sh
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-installer/scripts/install-skill-from-github.py" \
  --repo nextlevelbuilder/ui-ux-pro-max-skill \
  --ref dcc40ff5133ef78276117db0cc34e7b83cc8aeba \
  --path .claude/skills/ui-ux-pro-max
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-installer/scripts/install-skill-from-github.py" \
  --repo pbakaus/impeccable \
  --ref e0881d2de397d5e9761d7b35ff5017d8f5ebf69b \
  --path .agents/skills/impeccable
chmod u+x "${CODEX_HOME:-$HOME/.codex}/skills/impeccable/scripts/impeccable"
```

Сверить SHA-256 обоих SKILL.md с lock-файлом. Для Impeccable при первом
запуске нужен доступ к GitHub releases; его бинарник кешируется вне проекта.
Обновлять версии отдельным проверяемым изменением, а не переключаться
автоматически на `main`.

## Как применять UI/UX Pro Max

Прочитать SKILL.md. Для одной проблемы искать конкретный результат:

```sh
python3 "${CODEX_HOME:-$HOME/.codex}/skills/ui-ux-pro-max/scripts/search.py" \
  "touch target size" --domain ux
python3 "${CODEX_HOME:-$HOME/.codex}/skills/ui-ux-pro-max/scripts/search.py" \
  "accessibility labels" --stack react-native
```

Его база включает стили, продуктовые рекомендации, палитры, пары шрифтов,
UX-правила, иконки, графики, GSAP и руководства по 22 стекам. Наличие категории
не делает её обязательной: графики полезны бэк-офису, GSAP - web, а мобильному
приложению нужны React Native, native controls и текущая анимационная система.

`--design-system` использовать для исследования направления нового экрана.
Проверять соответствие результата продукту и платформе перед сохранением.
Не сохранять автоматически сгенерированный MASTER.md как новый источник
истины поверх `docs/design/design-system.md` и `packages/design-tokens`.

Первый запрос `food ordering mobile` предложил restaurant-палитру красного
цвета, Playfair Display SC/Karla и структуру landing funnel. Они отклонены:
у PickChick уже есть бренд, а каталог приложения не является лендингом.
Уточнение `restaurant ordering --domain product` дало релевантную категорию
Restaurant/Food Service: энергичная композиция и качественные фото еды подходят.
Это полезный ориентир, но не новый утверждённый макет.

Запросы про Dynamic Type вернули роли, изображения, клавиатуру и общую шкалу
шрифтов. Это не подтверждённое руководство по Dynamic Type; для него использованы
native references Impeccable и существующие требования проекта. Результаты
поиска проверять по смыслу, не принимать весь top-3 автоматически.

## Как применять Impeccable

Прочитать SKILL.md, затем загрузить контекст из корня рабочего дерева:

```sh
"${CODEX_HOME:-$HOME/.codex}/skills/impeccable/scripts/impeccable" context \
  --target apps/mobile/src/screens/ProfileScreen.tsx
```

В текущем проекте контекст сообщает об существующей реализации и отсутствии
отдельных PRODUCT.md / DESIGN.md. Для адресного аудита это не блокер:
источниками остаются README, ТЗ, дизайн-система, код и исходный макет владельца.
Новые конкурирующие документы автоматически не создавались. При отдельном
редизайне следовать init/new-work и фиксировать только подтверждённые решения.

| Семейство команд                           | Применение в PickChick                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------ |
| `init`, `document`, `extract`              | Контекст продукта, документация существующего дизайна, выделение общих компонентов   |
| `shape`                                    | Сценарий нового экрана до реализации                                                 |
| `critique`                                 | Отдельное исследование композиции и UX; имеет собственный процесс независимых оценок |
| `audit`                                    | Техническая проверка; для mobile читать **audit.native.md**, для web - audit.md      |
| `adapt`, `typeset`, `layout`               | Малые телефоны, крупный текст, отступы и визуальная иерархия                         |
| `harden`, `clarify`, `onboard`             | Ошибки, пустые/загрузочные состояния, RU/KZ, первый вход, понятные подписи           |
| `animate`, `optimize`                      | Осмысленное движение, скорость, отсутствие задержек действий                         |
| `distill`, `quieter`, `bolder`, `colorize` | Управление плотностью и акцентами внутри утверждённого бренда                        |
| `delight`, `overdrive`                     | Выборочные эффекты для игр/промо; проверять цену по производительности               |
| `polish`                                   | Финальная согласованность после исправления функций и доступности                    |
| `live`, `generate`                         | Варианты в web-превью; не доказательство нативного поведения                         |

`craft` - устаревший alias. `hooks`, `doctor`, `pin` - служебные команды;
автоматически включать их или обновлять инструменты для обычной UI-правки не нужно.
Сами названия команд обозначают инструкции для агента: не все являются
исполняемыми CLI-подкомандами. Перед применением читать соответствующий reference.

## Совместный порядок работы

1. Определить конкретный пользовательский сценарий и его текущее состояние.
2. Сверить оригинальный макет, последние решения владельца, токены и реальные
   скриншоты. Прочитать подходящий reference Impeccable.
3. Найти адресные рекомендации Pro Max, явно указав стек. Отфильтровать
   несовместимые и неподтверждённые результаты.
4. Составить короткий список проблем с доказательствами и приоритетом.
5. В задаче на реализацию исправить согласованный объём. До UI-изменений
   прочитать craft-floor; для одной кнопки не запускать весь редизайн.
6. Проверить сценарий и вид: 320/393/768, клавиатура, длинные RU/KZ строки,
   крупный системный текст, reduced motion, ошибки и пустые данные.
7. Отдельно проверить native на iOS/Android. Web-снимки помогают с композицией,
   но не подтверждают VoiceOver/TalkBack, системный Back и FPS на устройстве.
8. Зафиксировать проверки, ограничения и следующие шаги в PR и roadmap.

## Правила PickChick выше общих рекомендаций

- Сохранять #0047BB / #FF671F, тёмную mobile-тему #04143A, Jost/Manrope,
  логотип, реальные фото и предоставленные обложки игр. Рабочие оттенки
  mobile action/accent уже отличаются от базовых брендовых цветов намеренно.
- Фирменные шрифты не заменять на системные только потому, что так советует
  общий native reference. Проверять масштабирование и читаемость наших шрифтов.
- Цель касания mobile - 48; Android 48dp, iOS как минимум 44pt. Маленькая
  иконка внутри большой кнопки не считается маленькой областью нажатия.
- Не добавлять паузу фонового видео и стрелки под PICK MAN/BLOCKS вопреки
  владельцу. Сохранять reduced motion, фоновые паузы и действия доступности.
- Не придумывать баланс Чиков, отметки «7 + 1», сообщения, оплату или награды.
- Не включать светлую тему, Dynamic Color или новую навигационную архитектуру
  только ради общего чек-листа: это отдельные продуктовые решения.
- Никакой общий балл или количество установленных скиллов не является
  доказательством качества приложения. Нужны сценарии и проверка на устройствах.
