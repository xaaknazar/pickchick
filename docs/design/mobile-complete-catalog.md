# Мобильный каталог и тестовый профиль — 7 сентября 2026

По запросу заказчика приложение заполняется по исходному
`design/reference-source/mobile-v2.html.txt`, а не по сокращённой foundation-фикстуре.
Срок и production Gate основного roadmap не меняются.

## Реализованное поведение

- 24 блюда: исходные названия, описания, цены, порции и КБЖУ. Единственный датасет
  `packages/test-order-flow/src/complete-catalog.ts` используется сервером и галереей.
  Мобильный каталог получает эти данные через API.
- Выбор напитков, соусов, размеров и дополнительных позиций; ограничения количества,
  недоступные варианты и видимые доплаты. Разные наборы одного блюда имеют отдельные
  строки корзины. Сервер проверяет выбор и рассчитывает окончательную сумму.
- Корзина: «Всегда кстати», состав выбранного набора, приблизительное время приготовления,
  выбор Kaspi/карты, закреплённые действия. Метод оплаты включён в серверный снимок.
- Тестовый телефонный вход с кодом `123456`: локальный профиль, ограничения попыток,
  восстановление после перезапуска и выход. [Границы demo-входа](mobile-demo-account.md).
- Имитация успешной/отклонённой/неизвестной оплаты остаётся связанной с TEST-кухней.
  Банк не вызывается и деньги не списываются; это поясняется непосредственно при оплате.
- Прокрутка меню и закрепление категорий выполняются через Reanimated; React получает
  изменение выбранной категории/свёрнутой шапки, а не каждое движение экрана.
  Конечный якорь ограничен реальной длиной списка; блокировка выбора снимается
  при жесте и завершении прокрутки. Это исправление механизма, не измерение FPS.
- Иконки имеют одинаковые рамки и исходные контуры табов. Текст кнопок переносится,
  узкие экраны и крупный шрифт учитываются. Вершина SVG горы выходит на 6 px
  над карточкой, высота которой определяется реальным текстом.
- Убран баннер «Меню обновилось» и большая надпись «Тестовый контур» в оформлении.
  При единовременном переходе каталога v0.2 → v0.3 прежние товары/количество сохраняются,
  варианты заполняются включёнными опциями, цены берутся из свежего меню. Старые
  уже созданные заказы сохраняют свои снимки. При последующих несовместимых релизах
  действует прежняя проверка версии корзины.

## Совместимость и ограничения

Расширенный TEST-контракт `mockup-v0.3` выбирается query `catalog_version`.
Без него API выдаёт прежний строгий формат: установленная сборка 3 и старые
киоск/кухонные клиенты продолжают работать. Выбранные опции видны на старой кухне
в названиях строк/задач. В новых снимках хранятся выбранные опции, а не весь
справочник модификаторов. Миграция 005 расширяет допустимое описание задачи;
readiness проверяет её наличие до допуска API.

КБЖУ взяты из мокапа, а не из утверждённых технологических карт. Числа относятся
к базовой порции; допы в них не учтены. Пустой список аллергенов означает отсутствие
подтверждённых сведений. Исходные противоречия и нормализации описаны в
[README каталога](../../packages/test-order-flow/README.md). Бесплатные включённые
варианты выбраны по умолчанию, платные допы начинаются с нуля.

Для воды и Piko в переданных bundled-материалах нет пригодного исходного фото:
используется логотип-заглушка. Достоверные фото и техкарты ещё нужны от ресторана.
Редактор каталога в бэк-офисе этим этапом не реализован; данные пока изменяются
в серверном источнике через проверенный выпуск. Production OTP, банковский
эквайринг, ККМ, бонусный ledger и нагрузочная приёмка остаются отдельными этапами.
