# Мобильный вход и дата рождения

Решение заказчика от 7 сентября 2026: перенести вход из исходного мокапа,
запрашивать дату рождения, выбирать её пикером и убрать `@` перед никнеймом.
Визуальный источник — `design/reference-source/mobile-v2.html.txt`, M02–M04.

## Поведение

Номер → код → «Знакомимся» → меню. Сохранены Jost, тёмно-синий фон,
размеры карточек, отдельные кнопки внизу и «Заполню позже». На экране телефона
сохранена цифровая клавиатура макета; при системной клавиатуре она скрывается.
Ввод допускает вставку полного номера и не теряет символы при быстром наборе.

Любая из трёх карточек даты открывает один пикер полной даты. iOS использует
нативные колёса в нижней панели, Android — системный диалог, браузерный preview —
поле `date` с системным выбором. Выбор подтверждается отдельно; отмена не меняет
дату формы. Никнейм без `@`, дата и пол необязательны. Доступны очистка и
редактирование в «Мои данные». Будущие/несуществующие даты не сохраняются;
минимальный год — 1900, високосные годы учитываются. Дата сохраняется без времени.

Нативный компонент установлен через Expo в совместимой версии 9.1.0:
[Expo DateTimePicker](https://docs.expo.dev/versions/latest/sdk/date-time-picker/),
[API и ограничения системных пикеров](https://github.com/react-native-datetimepicker/datetimepicker).
Новому модулю требуется пересборка приложения; одного обновления JavaScript недостаточно.

## Данные и границы этапа

Тестовый профиль хранится целиком в SecureStore на устройстве и localStorage
в preview. Формат v2 включает nickname, birthDate, gender, completedAt.
Старый v1 преобразуется при восстановлении без выхода из аккаунта. Ошибка записи
не считается успешным сохранением. Вход с другим номером создаёт отдельный пустой
тестовый профиль; выход удаляет локальную запись. Обычное обновление приложения
сохраняет профиль; откат на старую сборку 4, которая не знает v2, не поддерживается.
