# Kaspi Smart POS: локальный API для кассы (конспект документации Kaspi)

Источник: «Smart POS. Документация по интеграции», Kaspi Гид
(`guide.kaspi.kz/.../Smart-POS-Dokymentatsia-po-integratsii.pdf`), прочитано 15.11.2026. Версия и
дата документа в нём не указаны. Это конспект для реализации ([ADR-0017](../architecture/adr/0017-kaspi-smart-pos-adapter.md)),
а не копия; при расхождении прав документ Kaspi. На нашем терминале не проверено.

## Сеть и защита

- `https://<IP или DNS терминала>:8080/v2/<метод>`, ответы JSON, все методы - `GET` с параметрами
  в строке запроса. HTTP без TLS отклоняется.
- Касса и терминал в одной частной сети, у терминала постоянный IP (вручную или резерв DHCP по
  MAC); кабель предпочтительнее Wi-Fi.
- Сертификат терминала выдан на `*.kaspipos.kz`. Для проверки имени нужен DNS-адрес (свой DNS или
  hosts); формат имени в документе не указан. По IP защита та же, если не проверять имя. Мы
  ходим по IP и закрепляем SHA-256 сертификата.
- Терминалу нужен интернет; список адресов для firewall - раздел 3.10 документа.
- Защита интеграции: «Настройки» → «Панель администратора» (пароль администратора) → «Защита
  интеграции» → «Настроить доступ», затем касса вызывает `/v2/register`, на терминале -
  «Разрешить». Там же «Только интеграция» (запрет ручных оплат и возвратов на терминале - нам не
  включать, пока возврат через API не сделан), «Номер терминала», «Оплата только по QR».
- IP и MAC: «Настройки» → «Kaspi Гид» → «О терминале»; «Проверка» → «Проверить соединение».

## Токен

- Заголовок `accesstoken` во всех методах, кроме `register` (у `status` в таблице - `accessToken`
  и `terminalId`; HTTP-заголовки регистронезависимы, `terminalId` мы не шлём, пока терминал не
  потребует).
- Токен живёт 24 часа: `expirationDate` (пример `2024-09-25 17:27:03`, местное время терминала).
  Обновление - `revoke`; старый токен перестаёт работать, когда использован новый.
- Нет токена - HTTP 401; истёк - 401 или 403 (в документе расходится).

## Методы

| Метод            | Параметры                                                                                     | Данные ответа (`data`)                                                     | Ошибки                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `/v2/register`   | `name`                                                                                        | `accessToken`, `refreshToken`, `expirationDate`                            | 999 нет `name`; 105 прошлый register не завершён                                                  |
| `/v2/revoke`     | `name` (как в register), `refreshToken`                                                       | новые `accessToken`, `refreshToken`, `expirationDate`                      | 999 пустой `refreshToken`; 105 неверный refresh token                                             |
| `/v2/payment`    | `amount` (целые тенге, > 0), `owncheque` (bool, необяз.)                                      | `processId`, `status`=`wait`                                               | 999 сумма; 106 оплаты заблокированы; 107 прошлая операция не завершена; 108 «что-то пошло не так» |
| `/v2/refund`     | `amount`, `method` (`qr`/`card`/`alaqan`), `transactionId` (orderNumber или rrn), `owncheque` | `processId`, `status`=`wait`                                               | 999 неизвестный method; 107; 108                                                                  |
| `/v2/status`     | `processId`                                                                                   | `status`, `subStatus`, `message`, `transactionId`, `addInfo`, `chequeInfo` | 101 процесс не найден                                                                             |
| `/v2/actualize`  | `processId`                                                                                   | как `status`                                                               | 100 нет интернета; 101; 102; 103 нельзя актуализировать; 104 транзакция не найдена; 105           |
| `/v2/deviceinfo` | -                                                                                             | `posNum`, `serialNum`, `terminalId`                                        | -                                                                                                 |

Отмены через API нет: отменяют на терминале (`fail`, `subStatus`=`ProcessCancelled`). Отчётов
через API нет. `/v2/remains` упомянут, но не описан.

## Статусы

- `status`: `wait` (идёт), `success` (оплачено, есть `transactionId`), `fail` (не прошло,
  `message`), `unknown` (итог неизвестен - только `actualize`, не чаще раза в 10 с).
- `subStatus`: `Initialize`, `WaitUser`, `WaitForQrConfirmation`, `ProcessingCard`,
  `WaitForPinCode`, `ProcessRefund`, `QrTransactionSuccess`, `QrTransactionFailure`,
  `CardTransactionSuccess`, `CardTransactionFailure`, `ProcessCancelled`.
- `chequeInfo`: `storeName`, `city`, `address`, `status`, `amount` (строка со знаком тенге),
  `date`, `bin`, `terminalId`, `method` (`qr`/`card`/`alaqan`), `type` (`payment`/`refund`); для
  QR - `orderNumber`, для карты - `cardMask`, `rrn`, `authorizationCode` и др.
- Опрашивать `status` примерно раз в секунду. Ожидание гостя по умолчанию 180 с, подтверждение
  60 с; QR живёт около 3 минут. Операции хранятся на терминале 24 часа.

## Ограничения

- Одна операция одновременно (107).
- Только целые тенге.
- Удалённая оплата не поддерживается; смена терминала закрывается сама.
- Формат ошибки: HTTP-код и `statusCode` в теле (`999` - общие ошибки запроса и авторизации).
