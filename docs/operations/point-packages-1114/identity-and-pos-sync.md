## Безопасный канал доставки

Планируется временный отдельный SFTP-доступ к VPS, а не публичная ссылка.
Его создание и проверка входят в будущее согласованное окно, сейчас не выполнялись.

1. Claude на Windows создаёт отдельную пару ключей только для обмена файлами.
   Закрытый ключ доступен только оператору/Administrators/SYSTEM и остаётся на кассе.
   Codex получает через владельца только `.pub`. Это не ключ POS sync и не ключ Mac.
2. Codex создаёт временную учётную запись `pickchick-xfer` с chroot, только
   `internal-sftp`, входом только по этому публичному ключу и без shell, команд,
   port forwarding, agent forwarding, X11 и TTY. Корень chroot принадлежит root,
   не доступен пользователю на запись. Операционная подпапка `to-point` разрешает
   только чтение, `from-point` - запись только этому пользователю. Доступ ограничен
   согласованным окном и отзывается после подтверждения установки.
3. Перед выдачей identity проверить конфигурацию `sshd -t` и эффективные ограничения
   временного пользователя. Сначала проверить передачу несекретного пробного файла
   в обе стороны. Если канал не готов, ключ устройства **не продлевать**.
4. Для первого SFTP-соединения Claude сверяет fingerprint уже доверенной записи
   `C:\ProgramData\PickChick\FulfillmentSync\known_hosts` с указанным выше.
   Старый файл не менять. Использовать `StrictHostKeyChecking=yes`,
   `HostKeyAlgorithms=ssh-ed25519`, `IdentitiesOnly=yes`, `BatchMode=yes`, отдельный
   ключ обмена и явный `UserKnownHostsFile`. При несовпадении остановиться.
5. Codex передаёт подготовленные файлы на VPS через существующий защищённый
   операторский SSH. Для identity исходная копия имеет права 600; отдельная копия
   доставки внутри chroot принадлежит root и доступна только группе временного
   SFTP-пользователя на чтение (640, без других участников группы).
6. Claude скачивает файлы в отдельную папку операции под
   `C:\ProgramData\PickChick\EdgeTools\private-transfer-<UUID>` на NTFS.
   Явный ACL без наследования: текущий оператор, Administrators, SYSTEM.
   Сверяет размеры и SHA-256, не печатает содержимое identity.
7. После проверки установленного файла, ACL и нового heartbeat удалить только
   временные копии этой операции, закрыть временный доступ. При незавершённой
   передаче сохранить уже выданный кандидат защищённым до восстановления.

Через этот канал на кассу поступают `connection.json`, `known_hosts`, их опись
и новая `device-identity.json`. Обратно передаются только публичный ключ туннеля,
`cloud-binding.json` и обезличенное подтверждение проверки. Пароли БД, owner env,
закрытые SSH-ключи и device token не передаются в чат, GitHub, почту или мессенджер.
SFTP-учётная запись и постоянная учётная запись POS имеют разные ключи и ограничения.
