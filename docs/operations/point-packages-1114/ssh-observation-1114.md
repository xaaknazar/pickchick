## Сопоставление

Claude пишет на Windows PID туннеля, локальный порт и UTC событий. Нужны отдельно
метки Connection refused и Connection reset. Учитывать синхронизацию часов.
Снимки VPS дают интервал исчезновения до пяти секунд, а не точную секунду RST.
Локальный исходящий порт Windows может отличаться от порта, видимого VPS, из-за NAT.
Нужно сопоставлять время, адрес и последовательность соединений; не смешивать
сеансы `pickchick-ops` с туннелем. Команда ss без sudo не показывает пользователя SSH.

Старое ESTABLISHED после разрыва Windows либо смена внешнего адреса дают полезное
свидетельство о сети/NAT, но сами по себе не устанавливают источник сброса.
Односторонняя потеря пакетов и задержка обнаружения разрыва также возможны.
Если совпадения не позволяют различить причины, требуется журнал sshd/kernel
либо отдельный согласованный захват TCP-заголовков с обеих сторон.

## Риски PR370 до слияния

Проверен точный коммит `8c79d0baf3907e8676ec006acd87fe0bda67bad2`,
[PR370](https://github.com/xaaknazar/pickchick/pull/370). Реализация
Assert-RuntimeNeighbor одинакова в операторах 024, 025 и после 028.

1. **Повторная проверка после ожидания отсутствует.** Assert-RuntimePreserved
   сначала сверяет файлы, затем последовательно соседей. Если PostgreSQL уже
   проверен, во время ожидания туннеля до 120 секунд он может перезапуститься
   или может измениться сохранённая конфигурация. После возвращения туннеля
   функция может вернуть успех без повторной сверки этих условий. На ступени
   024 после этой функции вызывается миграция. Это расширяет прежний короткий
   промежуток между проверками до двух минут и нарушает требование строгой
   проверки соседей перед переходом.
   Ссылки: `update-runtime-stage2-1024.ps1:78-80,223-224`,
   `update-runtime-queue-recovery-025.ps1:140-142`,
   `update-runtime-head-028.ps1:125-127`.
2. **PathName пропускается при прежнем PID.** Ранний return при Running и прежнем
   ProcessId выполняется до сравнения PathName. Изменённая регистрация службы
   Windows с ещё работающим старым процессом проходит эту ветку. Требование
   неизменного PathName должно проверяться и на этом пути.
   Ссылки: `update-runtime-stage2-1024.ps1:69`,
   `update-runtime-queue-recovery-025.ps1:131`,
   `update-runtime-head-028.ps1:116`.

Предложение: отдельно дождаться туннеля, затем непосредственно перед продолжением
снова сверить все сохранённые файлы и строгих соседей без дополнительного ожидания;
PathName проверять перед каждым успешным возвратом для туннеля. Добавить случаи
изменения PID PostgreSQL и сохранённого файла во время ожидания, а также смены
PathName при прежнем PID. Смена PID PostgreSQL по отдельности уже проверяется,
но одновременный случай с ожиданием туннеля текущие тесты не покрывают.
