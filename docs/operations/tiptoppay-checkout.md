# TipTop Pay: карта и кошельки

Решение владельца от 5 октября 2026: пока подключается TEST-оплата.
Kaspi остаётся действующим реальным способом оплаты. TEST TipTop Pay не должен
создавать коммерческий capture, фискальный документ или заказ на кухне.

## Реализованный LIVE-каркас (выключен)

Приложение получает разрешённые методы с сервера. Выбор сохраняется за заказом;
после старта попытки его нельзя сменить. Сумма, KZT, идентификаторы клиента и
попытки задаются сервером. Страница HTTPS открывает официальный TipTop Widget.
Номер карты/CVV и секрет API не проходят через приложение.

Одноразовая ссылка содержит случайный токен во fragment; в БД хранится только
SHA-256. POST обменивает токен на параметры; URL не сохраняется в mobile storage,
не включается в ошибки. Повторное открытие после потребления не создаёт вторую
попытку. Клиентский результат виджета не подтверждает деньги.

Check/Pay/Fail проверяются по Content-HMAC исходного form-urlencoded тела,
терминалу, клиенту, сумме, валюте и типу операции. TEST отклоняется LIVE-ledger.
Check допускает один TransactionId на попытку; поздний Pay сохраняется через
идемпотентный inbox. Fail оставляет неопределённость для возможного позднего Pay.
Выключение новых оплат не скрывает существующий способ/состояние.

Бэк-офис показывает попытки отдельно от подтверждённых оплат, провайдера,
банковский идентификатор и время. Неподдерживаемые возвраты TipTop Pay не создают
бесполезную очередь: кнопка скрыта и сервер возвращает NOT_READY.

## TEST-путь

Отдельная authenticated сессия использует серверный quote без создания
коммерческого заказа. Отдельная таблица sandbox хранит результат TEST-уведомлений;
в UI и бэк-офисе он явно обозначается тестовым. Мобильная корзина сохраняется.
Тестовый счёт не участвует в обороте, бонусах, акции 7+1, фискализации или кухне.

## Проверенное состояние кабинета

5 октября: probe `/test` принял credentials без списания. Кабинет PickChick
показывает TEST, карта включена, Google Pay включён, Apple Pay выключен.
Это не доказательство доступности каждого кошелька на устройстве.
Ключ хранится только в приватном server env, не в Git и не EXPO_PUBLIC.
После проверки владелец намерен заменить секрет; обновить все server env
и повторить безопасный probe, не выводя секрет.

Apple Pay web требует HTTPS, файла `.well-known/apple-developer-merchantid-domain-association`
и включения метода в кабинете для того же домена. На `pickchick.kz`/`api.pickchick.kz`
TLS-проверка в этом этапе не прошла; текущий API origin приложения - nip.io HTTPS.
Проверку домена нельзя считать выполненной. Native Apple Pay потребует отдельной
merchant/entitlement/certificate настройки; текущий этап использует hosted browser.

TipTop отдельно требует настройки у менеджера для `restrictedPaymentMethods`
и `paymentMethodSequence`. Без подтверждения TEST запускает общую форму карты,
а отдельные маршрутизируемые кошельки не обещаются. LIVE требует
`TIPTOPPAY_METHOD_ROUTING_VERIFIED=true`; вручную ставить флаг без проверки нельзя.

## Серверное включение

Шаблон переменных: `infra/payments/tiptoppay.env.example`. LIVE switches остаются
false. Миграции 039/040, права, HTTPS routes, подписанные уведомления и ограничение
режима должны устанавливаться одним охраняемым релизом после полной CI.
Не заменять действующие Caddy/compose целиком из новой ветки.

LIVE-настройки требуют verified terminal, matching merchant legal entity,
explicit deferred fiscal approval и running reconciliation. TEST не требует
фискального разрешения, поскольку не отражает реальную продажу.

`infra/payments/tiptoppay-grants.mjs` разделяет создание checkout-сессии и приём
банковских подтверждений. Отключение новых оплат - флаг выдачи, не отзыв чтения
незавершённых сессий. Нельзя отзывать receiver права до обработки поздних Pay.

Для LIVE-reconcile подготовлены compose, oneshot service и минутный timer в
`infra/payments`. Образ - точный проверенный API SHA, сеть должна совпадать с
фактической частной сетью staging. Worker env содержит отдельный
`TIPTOPPAY_RECONCILE_DATABASE_URL` и credentials, bind read-only; порты отсутствуют.
Worker делает только `payments/find`, до 20 попыток на сессию с интервалом не менее
двух минут. Перед включением проверить реальный запуск timer и журнал выполнения.
Флаг сам по себе не означает, что worker запущен. После исчерпания бюджета случай
остаётся неопределённым и требует операционного разбора, повторное списание запрещено.

## Источники и приёмка

- [TipTop Pay docs](https://developers.tiptoppay.kz/): Widget, Check/Pay/Fail, payments/find, Apple Pay, Google Pay.
- [Apple Pay on the Web](https://developer.apple.com/documentation/applepayontheweb).
- Адресные TEST/LIVE PostgreSQL и HTTP сценарии: `tests/payments/tiptoppay-checkout.test.mjs`.
- Бэк-офис и права: `tests/backoffice/tiptoppay-reporting.test.mjs`, `tests/unit/tiptoppay-grants.test.mjs`.
- Mobile: browser fixture `tests/mobile/browser_kaspi_checkout.py`, payment-methods tests.

Локальные тесты и имитация провайдера не являются приёмкой реального сервиса.
Для TEST требуется закончить hosted-сессию на официальной тестовой карте,
проверить подписанное уведомление и отдельную запись бэк-офиса без денежных
изменений/кухни. Apple Pay и Google Pay проверяются отдельно на поддерживаемых
устройствах после их настройки. LIVE пока не включается.
