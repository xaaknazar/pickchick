# Что должен сделать владелец после исправлений 19.10.2026

Собрано из заметок всех полос и интеграции. Код ничего из этого не делает сам. Пункты
сгруппированы; внутри группы - по порядку выпуска. Подробности - в заметках полос
([сводка](README.md)).

## Решения

1. **Продажи в приложении без чека (7.0).** Вместе с бухгалтером решить: продолжать мобильные
   продажи Kaspi без фискального чека или выключить их до подключения Webkassa/ККМ
   (`CUSTOMER_KASPI_SALES_ENABLED=false`, без нового выпуска). Опубликовать условия платных заказов
   с новой версией согласия (сейчас опубликованные условия говорят, что оплаты нет).
2. **Ручные возвраты Kaspi (0.3, 7.1).** Решить, включать ли регистрацию ручных возвратов
   (`BACKOFFICE_MANUAL_REFUNDS_ENABLED=true` + права при provision), и назначить, кто делает возврат
   в Kaspi Pay. Порядок для персонала - в pay.md.
3. **Ручное «оплачено» для киоска (4.3).** Сейчас кабинет только освобождает зависший киоск и
   записывает, что управляющий увидел в Kaspi Pay; оплату в учёт пишет только банк. Решить, нужно
   ли ручное подтверждение оплаты с записью в учёт.
4. **Решения PM по умолчанию** (README, «Решения PM») - подтвердить или изменить: правило стопа
   комбо, 10 минут на неотправленную попытку Kaspi, ручные возвраты, выключатель продаж, домен.
5. **Решения полос** - подтвердить или изменить: оплаченный заказ, которому касса отказала, сразу
   становится делом менеджера; разбор неполученного кассой оплаченного заказа через 15 минут;
   закрытие забытого «готов» в облачной кухне через 3 часа; бесплатное «Начать заново» 15 секунд
   после показа QR; выход из демо через 3 минуты; один код сотрудника на все киоски точки.
6. **Стоп комбо на самой кассе (1.3).** Решить: расширение меню кассы двумя шагами (сначала касса,
   потом облако) или стоп «везде» из кабинета. До этого кассир сам не продаёт остановленный
   товар в комбо.
7. **Доля кодов входа для новых номеров.** Оставить 80% на день запуска или временно поднять до
   90-100 при большой рекламной волне (`CUSTOMER_AUTH_NEW_PHONE_BUDGET_PERCENT`).
8. **Финансы (4.4).** Финансовый Mac должен принять изменение «закрытие месяца кумулятивно»
   (коммит `204d318b`) до выпуска API с ним.
9. **PITR** (точка восстановления базы): включать ли, это одна перезагрузка cloud-db в тихое окно.
10. **Переход на 6-значные PIN кассы**: назначить время (перевыпуск PIN всех сотрудников, затем
    `pinLength: 6` на всех кассах точки сразу).

## Аккаунты, ключи и данные

    (`SELECT expires_at FROM device_credentials`) и продлить вручную, если осталось меньше 10 дней
    ([edge-identity-rotation.md](../edge-identity-rotation.md)); затем включить автопродление
    (сначала облако, потом касса).
12. **Код сотрудника киоска (3.3, 3.4, 3.0).** Придумать код 6-8 цифр (не 1111/1234), на доверенной
    машине сгенерировать верификатор `node scripts/kiosk-staff-pin.mjs`, добавить
    `KIOSK_STAFF_PIN_VERIFIER` в env API, сообщить код только управляющим.
13. **App Review (2.3).** Выбрать номер, который не принадлежит реальному клиенту, и 4-значный код;
    прописать `CUSTOMER_REVIEW_ACCOUNT_*` в `customer-auth.env`; вписать номер и код в App Review
    Information (текст - в sec.md); после одобрения выключить флаг.
14. **Telegram-бот для оповещений** и закрытый чат; в `watchdog.env` задать
    `WATCHDOG_OTP_DAILY_BUDGET` равным `CUSTOMER_AUTH_DAILY_SMS_BUDGET` API. Баланс Telegram Gateway
    смотреть в его кабинете (watchdog видит только отказы доставки); назначить дежурного по
    повторному входу кассира Kaspi.
15. **Хранилище резервных копий (5.2/7.4).** Независимое S3-совместимое хранилище в РК (другой
    провайдер или регион): bucket с versioning/object lock и lifecycle, два ключа (запись для VPS,
    чтение для учений). Затем первое учение восстановления на реальной копии с записью времени.
16. **Резервная копия кассы (6.4).** Решить, куда и как часто копировать базу кассы (второй диск
    или NAS; рекомендация: ежечасно, 48 часовых и 14 дневных копий) и дать окно для проверки задачи
    на Windows. Отрепетировать восстановление по [edge-restore.md](../edge-restore.md) на стенде.
17. **Меню: связанные товары и состав комбо.** Проставить «Связанный товар» вариантам комбо, чей id
    не совпадает с товаром (`cola-bottle`, `cola-can`, `cola-zero` -> `cola`; `piko-apple`,
    `piko-orange` -> `piko`; `iced-tea-sweet/unsweet` -> `iced-tea`; `fuse-*`); заполнить состав
    комбо (`combo_components`), если стоп компонента (например, картофеля) должен закрывать комбо.
18. **Контакт поддержки** (телефон, WhatsApp, почта или страница) для `EXPO_PUBLIC_SUPPORT_URL` и
    поля Support URL в App Store Connect.
19. **Второй канал входа** (WhatsApp или SMS): без него покупатели без Telegram войти не могут
    (приложение теперь честно это говорит).
