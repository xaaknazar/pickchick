# Обработчик счетов: runtime 21 октября 2026

Подготовлен отдельный оператор `infra/staging/release-kaspi-runtime-1021.py`.
Исходный работающий обработчик `pickchick-kaspi-worker`:
`b18beb08b86341e13ab2b919edd01f523cea0c23`, образ
`sha256:bb7ba74705a2a39a9165e51ab21ce8b6939bb2ab20d0928013cf5ac4dd303b19`.
Прежние инструменты закреплены на других старых версиях и не подходят.

Оператор требует чистого опубликованного исходника и полной CI точного SHA,
родства с установленным API и того же набора файлов миграций. Он проверяет
исходные compose/env, сохраняет команду, ограничения контейнера, read-only mounts,
сессию банка и все соседние контейнеры. Изменяется только образ обработчика.
Compose-переменные разрешаются в прежние пути без выдачи значений секретов.

До переключения не должно быть выдаваемых/открытых/неопределённых счетов и
ожидающих отправки операций. При их наличии выпуск останавливается.
Новый счёт, QR или платёж для проверки не создаётся. Используется общая
серверная deployment-блокировка; при неизвестном результате она сохраняется.
При подтверждённой ошибке возвращается прежний образ с исходным compose/env.

Порядок: новый API, QR worker из PR269, полная CI этого кандидата, read-only
запуск оператора, затем тот же вызов с `--apply`; после20с проверить процесс,
отсутствие рестартов, все параметры и соседей. Учётные данные не меняются.
Миграции не запускаются, новые возможности по флагам не включаются.

Проверки: пять Python regression tests для закреплённого compose, запрета
изменения безопасности/секретных подключений, исходника и незавершённых счетов.
Факт установки, SHA/CI и хеш образа будут добавлены после выполнения.
