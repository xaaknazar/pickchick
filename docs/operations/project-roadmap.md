# Пульт проекта PickChick

По решению владельца от 16 сентября 2026 добавлен отдельный интерактивный
центр проекта: весь объём работ, направления, зависимости, относительный план,
действия заказчика, ссылки на интерфейсы и совместные результаты проверок.

## Два вида данных

1. `docs/roadmap/project.json` - проверяемый срез требований и фактов из репозитория.
   У задачи есть направление, этап, ответственный тип участника, зависимости,
   следующий шаг, критерии приёмки и ссылки на доказательства. Четыре факта
   «реализовано / проверено / установлено / принято» отражают конкретную задачу,
   а не готовность всего продукта к эксплуатации. Их обновляет разработчик
   вместе с `docs/project-status.md` в проверяемом коммите.
2. Общие отметки команды - рабочий статус, результат ручной проверки, имя
   проверяющего и замечание. Они сохраняются сервером сразу и появляются у
   других участников при обновлении, максимум через 30 секунд в открытой вкладке.
   Зелёная ручная проверка не меняет подтверждённые факты в репозитории.

Данные не извлекаются автоматически из произвольного текста GitHub. Каждая
публикация собирает актуальный JSON, проверяет существование файлов и отсутствие
циклических зависимостей и закрепляет SHA исходного коммита и хеш данных.
В интерфейсе видны дата и версия этого среза. Новые коммиты сами по себе не
означают успешную установку, приёмку или публикацию новой версии пульта.
Публикация описана в `infra/roadmap/README.md`.

Срок остаётся T0 + четыре календарных месяца. T0 не согласована. План показывает
относительные недели, а не выдуманные даты или процент готовности ресторана.
Фаза после запуска относится к развитию и не сокращает обязательный объём.

## Совместная работа

Вход - отдельный ключ команды. Сервер выдаёт HttpOnly/Secure/SameSite cookie,
действующую семь дней. Ключ не находится в URL, репозитории или публичных
файлах. Имя в форме проверки указывает сам участник; это не персональная
криптографическая подпись или назначение роли управляющего рестораном.

Для каждой правки передаётся версия записи. Если другой участник уже сохранил
изменение, сервер отвечает конфликтом, а интерфейс сохраняет введённое замечание.
Нельзя незаметно перезаписать результат коллеги. История предыдущих отметок
сохраняется отдельно. Чтобы отметить проверку успешной или неуспешной, требуется
описать результат. Сброс доступа выполняется заменой защищённого файла ключа
и перезапуском только сервиса пульта; старые сессии отзываются.

## Границы тестирования

Раздел проверок открывает реальные доступные ссылки с подписью среды:
демонстрационный дизайн, синтетический TEST-заказ, установленный бэк-офис.
Служебные экраны требуют своих существующих доступов. Ключ пульта не даёт
прав на кухню, заказы, каталог, банк или iiko. Кнопка ссылки не выполняет
оплату, изменение заказа или автоматический прогон тестов.

Макет получен; 22 сентября касса обновлена до POS0.4.3/edge014. Вход по личным
PIN и плавность подтверждены владельцем. Отдельная кухня и двухэкранный цикл
ещё не приняты. Факты нового среза появятся онлайн после отдельной публикации.
Обследование iiko ожидает ссылки и отдельного доступа.

## Устройство и локальная проверка

`apps/roadmap` - отдельное приложение Node 24 без внешних runtime-зависимостей.
Нефинансовые отметки хранятся в SQLite с WAL, синхронным сохранением, транзакцией
и проверкой версии; постоянный каталог отделён от сменяемого кода выпуска.
Сервис не подключён к ресторанным PostgreSQL, Redis или платёжным адаптерам.
Это дополнение к архитектуре проекта, а не замена его транзакционного ядра.

```sh
pnpm --filter @pickchick/roadmap build
pnpm --filter @pickchick/roadmap test
ROADMAP_ORIGIN=http://127.0.0.1:4192 \
ROADMAP_DATA_DIR=/private/path/roadmap-data \
ROADMAP_KEY_FILE=/private/path/roadmap-key \
node apps/roadmap/server.mjs
```

Создайте случайный ключ длиной не меньше 40 символов в закрытом файле,
не копируйте ключи из примеров тестов. Открыть `http://127.0.0.1:4192/roadmap/`.
Развёртывание использует отдельный контейнер и внутреннюю сеть только с gateway;
существующая версия API и данные ресторана не меняются.

CI `Project roadmap` проверяет ссылки на исходники, зависимости, сборку,
доступы, защиту от межсайтовых запросов, конфликт двух участников, сохранение
истории после перезапуска и отзыв сессий при смене ключа.
