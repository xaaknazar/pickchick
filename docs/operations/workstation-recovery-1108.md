## Рабочие копии и идентичность

Существующего checkout PickChick в доступной облачной рабочей папке не было.
Выполнен обычный HTTPS clone без копирования старого `.git` или `.local`.

- `/workspace/pickchick`: общая ветка, получены все refs.
- `/workspace/pickchick-stage2-windows`: отдельный worktree на исходном checkpoint
  `codex/stage2-windows-1030`, без изменений файлов.

  ветка `codex/workstation-recovery-1108`.

Штатная утилита создала новую идентичность **облачного checkout**. Это не идентификатор
нового Windows-компьютера. На Windows нужен собственный clone и свой автоматически
созданный workstation ID. Финансовое закрепление старого Mac не переносилось.
GitHub HTTPS-доступ действует; секреты и приватные ключи не выводились и не копировались.

В облаке подготовлены Node24.16.0 из `.node-version` (архив сверен с официальным
SHASUMS256) и pnpm11.19.0 из `packageManager`. Каталоги инструментов и кеша
находятся вне Git. Настройка этого окружения не является установкой Windows-кассы.

Проверки в облаке:

## Связь и ключ: первый шаг на Windows

У облачной среды VPN не настроен, TCP-доступ к LAN не предоставлен, SSH-ключей
кассы здесь нет. Сеанс не имеет доступа к дискам и терминалу Windows владельца.
SSH-сеанс с кассой не установлен: нет нового fingerprint, проверки служб или срока
из `device_credentials.expires_at`. Это ограничение доступа, не доказательство
отключённой кассы. Локальный адрес мог измениться.

Последний документированный срок: **20.11.2026 12:34:54 Asia/Almaty**, то есть
**13:34:54 Asia/Bishkek**. Если выпуск не состоялся до10.11, предусмотрено ручное
продление **не позднее13.11**. Продление и автопродление сегодня не выполнялись.

Для продолжения нужен локальный Codex на новом Windows, подключённом к ресторанной
LAN или разрешённому VPN. Сначала:

1. Найти имеющийся checkout, проверить `git status`, сохранить все изменения.
   Если checkout отсутствует, сделать новый clone в выбранную папку Windows.
   Не переносить старые `.git`, `.local` и идентификатор Mac.
2. Установить закреплённые Node24.16.0/pnpm11.19.0, получить refs, выполнить
   `pnpm project:check` и `pnpm project:tasks`; отдельно согласовать три области
   интеграции выше. Принять кассовую задачу штатным claim после удовлетворения guard.
3. Проверить актуальный адрес кассы и порт22, затем сверить fingerprint с
   `SHA256:LyXj9xzIn/z9OubsMrmqEtVhwSpjayGahVyeCaMLf0M`. Пользователь SSH - `Админ`.
   При несовпадении остановиться. Не применять `StrictHostKeyChecking=no` и
   не доверять одному только результату ssh-keyscan.
4. Через разрешённый доступ прочитать только метаданные: службы, готовность edge
   и туннеля, дату действующего credential в облаке и обезличенный `edge_identity`
   статус. Не печатать identity JSON, токены, пароли или строки заказов.
5. Если продление не подтверждено, подготовить адресный ручной шаг по
   [identity rotation](edge-identity-rotation.md#ручное-продление-владелецоператор)
   и принятому решению30.10. Учесть, что ручная ротация отзывает старый ключ и требует
   согласованного переключения файлов/служб; диагностика сама её не запускает.
