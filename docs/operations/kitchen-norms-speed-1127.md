# Нормы станций на кухне и «Скорость кухни» (27.11.2026)

Владелец 27.11 выбрал «Полностью, с кассой»: пороги таймера кухни задаются в бэк-офисе,
а в бэк-офисе есть отчёт скорости по станциям.

## Как это работает

- Норма станции - существующее поле «Норма, секунд» записи «Станция» в бэк-офисе.
  Таймер на кухне жёлтый после нормы и красный после двух норм. Без нормы: 5 и 10 минут
  (Kitchen 0.4.12).
- Путь нормы: публикация станции → план станций (cloud070) → касса применяет план
  (edge024, `EDGE_STATION_PLAN_SYNC_MODE=apply`) → `GET /edge/v1/fulfillment/stations`
  отдаёт `targetSeconds` для станции, к которой привязана запись (`edge_station_id`).
- Отчёт: `GET /v1/backoffice/operations/branches/:id/ops/kitchen-speed?date=YYYY-MM-DD`,
  раздел «Отчёты». Только чтение, без миграций и флагов. Источники: события кухни заказов
  приложения и киоска (`cloud_fulfillment_inbox`) и, если включена синхронизация кассы,
  заказов кассы (`pos_kitchen_sync_inbox`). Время - время событий на кассе.

## Выкладка

1. Облако: API и веб бэк-офиса с этой ветки. Миграций нет.
2. Сервер кассы: обновление runtime кассы (код `fulfillment-controller.ts`). Без миграции.
3. Право чтения плана для runtime кассы (добавляет ровно два права, обратимо):

   ```
   node --env-file=<edge owner env> infra/windows/station-plan-read-grant.mjs inspect <toolsRoot> <branchId>
   node --env-file=<edge owner env> infra/windows/station-plan-read-grant.mjs apply <toolsRoot> <branchId>
   ```

   Без права касса просто не отдаёт нормы, кухня держит 5 и 10 минут.

4. Доставка плана должна быть включена: облако `BACKOFFICE_STATION_PLAN_DELIVERY_ENABLED=true`,
   касса `EDGE_STATION_PLAN_SYNC_MODE=apply`. Станции в бэк-офисе привязаны к станциям кассы
   и опубликованы.

## Проверка

- Бэк-офис → «Отчёты» → «Скорость кухни» → сегодня → таблица станций.
- На кухне заголовок «Дольше N мин» показывает две нормы открытой станции.
