# Комментарий клиента при оформлении

## Причина и поведение

В оформлении был неактивный блок с подписью «Передача на кухню подключается».
По замечанию владельца он заменяется настоящим многострочным полем. Сохраняется
текущий дизайн оформления; применяются адресные рекомендации UI/UX Pro Max и
Impeccable по полям, фокусу, клавиатуре и состояниям.

Лимит - 60 символов, как у существующего комментария кухни. Поле необязательное;
пустая строка не добавляется в снимок. Черновик сохраняется при возврате в корзину.
Текст привязывается к серверной котировке до создания заказа; повтор запроса после
обрыва использует ту же котировку. Изменение комментария не создаёт платёж.

API объявляет поддержку через `orderCommentEnabled`. Старый сервер не получает
неподдерживаемое поле и не обещает передачу комментария. Текст хранится в
PostgreSQL вместе со снимком заказа и передаётся штатным outbox на локальный
узел. Кухня и сборка уже выводят `kitchenComment` отдельно от модификаторов.
В банковское сообщение и на публичное табло комментарий не добавляется.

## Совместимость

Старые установленные клиенты используют строгие схемы ответов. Новые поля
возвращаются только при `Accept: application/json; profile=pickchick.checkout-comments-v1`;
остальные клиенты получают прежний формат config/order/list/watch. Ревизия
заказа остаётся согласованной с long poll.

Существующие котировки без комментария сохраняют прежние дайджесты. Комментарий
исключается из проверки каталожного расчёта, но входит в неизменяемый снимок
заказа. Денежные поля и подтверждение оплаты не меняются. Контракт локального
узла уже поддерживает это поле, поэтому обновление кассы не требуется.

Текущая общая ветка также содержит подготовленную миграцию031 автоматического
канала входа. При выпуске API после schema030 она должна применяться штатным
профилем. Это не включает WhatsApp: его доступы и документы остаются отдельной
зависимостью.

## Проверки и установка

Локально: сборка и TypeScript всего проекта, ESLint, 123 unit-теста,
проверка контрактов и дизайн-каталога прошли. Browser fixture на 320/393/768/852
проверяет ввод, возврат в корзину, перезагрузку с сохранённым черновиком,
передачу текста в quote, восстановление потерянного ответа и показ комментария
в статусе оплаченного заказа. Просмотрены реальные скриншоты 320/393 px.
Мобильные тесты хранения настроек - 6/6; Impeccable detect без замечаний.

Commerce PostgreSQL - 60/60. Проверка доставки комментария через cloud outbox
до кухонной очереди и выпуск ещё выполняются. Физическая
клавиатура iPhone и показ комментария на действующей кухне пока не приняты
владельцем. Новые реальные счета, оплаты и OTP для проверки не создаются.
