## Новый шаг базы024 ->025

`infra/windows/queue-recovery-upgrade-db.mjs` экспортирует транзакционный helper.
Он сверяет все25 файлов с закреплённым ledger, точный установленный024, точку и роль;
сохраняет прежние строки, последовательности и права. Добавляет только чтение сверки
и INSERT решений кассовой роли; исключает PUBLIC/лишние права. Повторный запуск,
подменённые файлы, чужая точка/роль и неожиданные default-grants дают отказ/ROLLBACK.

Helper **не является самостоятельным установщиком**: у него нет CLI, он не выполняет
restore-fence, не останавливает службы и не меняет runtime. До использования на кассе
его нужно включить в проверенный Windows-оператор после cloud072, свежей копии,
maintenance-lock и остановки писателей. Вызов helper вручную вместо этих условий
не является согласованной процедурой выпуска.

Локальные проверки:

```text
pnpm project:check
pnpm project:tasks
pnpm build
node --env-file=<local-test.env> --test tests/operations/queue-recovery-upgrade.test.mjs
pnpm exec eslint infra/windows/queue-recovery-upgrade-db.mjs tests/operations/queue-recovery-upgrade.test.mjs
TMPDIR=/private/tmp python3 -m unittest discover -s tests/operations -p test_windows_stage2_release.py
```

Новый тест:8/8, без пропусков; подключён к Foundation CI. Проверки оператора Windows:
2 passed,1 Windows-only skip на Mac. `pnpm check` прошёл: сборка, типы, lint,
форматирование,382 теста passed,1 штатный skip,0 failed, contracts и design.
Первая попытка остановилась на форматировании нового verification.json; файл исправлен,
полный повтор прошёл.
