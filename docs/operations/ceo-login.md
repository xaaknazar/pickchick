# Личный кабинет CEO - 7 октября 2026

Подготовлен вход по логину `ceo` и паролю на `https://pickchick.kz/backoffice/`.
До записи результата выпуска ниже это кандидат, а не установленный сервис.
Других сотрудников по поручению владельца пока не создаём.

## Как устроено

Отдельный сервис `pickchick-staff-login` обслуживает бэк-офис и ограниченный
прокси существующего API. Приватная конфигурация содержит scrypt-хеш пароля
(N=131072, r=8, p=1, случайная соль) и существующий серверный доступ директора.
Пароль генерируется криптографически; ни пароль, ни bearer не попадают в Git,
логи или URL. В браузере вместо bearer остаётся только несекретный маркер
`session`; cookie сессии Secure/HttpOnly/SameSite=Strict, без Domain.

Один CEO сопоставлен существующему actor_id: права по точкам и авторство
финансовых операций проверяет прежний API. Браузер не может подменить actor
или bearer. Не создаются новые финансовые записи, роли или миграции.

Сессия действует до 8 часов, до часа без запросов данных. Выход немедленно
отзывает сессию. Сессии и ограничитель попыток живут в памяти одного экземпляра;
перезапуск завершает все сессии и сбрасывает ограничитель, но не данные ресторана.
Не запускать несколько реплик без общего хранилища сессий/лимитов.
30 попыток за 15 минут на экземпляр, только один scrypt одновременно.
Проверяются Host, Origin и Sec-Fetch-Site; все изменения требуют того же Origin.

Старый адрес nip.io с личным файлом директора сохраняется. Это действующий
операторский доступ, а не обход проверки полномочий. Файл нельзя раздавать
сотрудникам; каждому следующему пользователю потребуется отдельный actor и роль.

## Приватная выдача и отзыв

`infra/backoffice-login/provision.mjs` принимает три пути: существующий личный
JSON директора, новый приватный серверный файл и новый файл выдачи CEO.
Создаёт оба выходных файла исключительно с `wx`, режим 0600, пароль не печатает.
Не передавать пароль параметром командной строки. Файл выдачи хранится локально,
сервер получает только хеш и токен. После сохранения пароля в менеджере паролей
владелец может удалить файл выдачи.

Для смены/отзыва пароля оператор создаёт новую приватную конфигурацию и
пересоздаёт только `pickchick-staff-login` с новым read-only mount. Это завершает
все сессии. Не изменять старый каталоговый token и не сбрасывать PIN кассиров.
Самостоятельное восстановление пароля, второй аккаунт, MFA и экран управления
сотрудниками в этот этап не входят.

результате или внешней гонке lock сохраняется для обследования.
