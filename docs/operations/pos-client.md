# Касса Windows: локальный UI этапа неоплаченных заказов

`apps/pos` — самостоятельный web-клиент существующего edge API. Он работает
с реальной локальной сессией персонала и PostgreSQL, а не с данными галереи.
Этот этап покрывает часть POS-01, POS-04 и POS-05. Полный POS по ТЗ ещё не принят.

## Что работает

- Импорт приватного файла сессии, выданного `staff:setup`, и серверная проверка
  роли, точки, терминала, отзыва и срока. Касса не выдаёт себе доступ и не
  предлагает вымышленный PIN-вход. Роль kitchen не допускается.
- Меню активного release, поиск, категории, количество и «в зале / с собой».
  Каталог не подменяется облачным TEST-каталогом mobile/kiosk.
- Стоп-лист: кассир видит доступность, начальник смены меняет её с причиной.
  Новые позиции недоступны для добавления до ответа edge о стопе.
- Серверный quote в целых минимальных единицах KZT; UI отличает предварительную
  сумму от расчёта edge. Истечение quote, новый release, стоп и закрытие приёма
  обрабатываются явно. Клиент не отправляет цену, роль или branch ID в checkout.
- Идемпотентный неоплаченный заказ, поиск по UUID, ссылки на последние 100
  известных этому сотруднику/терминалу заказов и чтение актуального состояния.
- Отмена с причиной: кассир — своего заказа на своём терминале, начальник
  смены — доступного заказа точки. Версию и права окончательно проверяет edge.
- Начальник смены открывает/закрывает приём **неоплаченных** заказов. Это
  настройка edge; она не открывает смену ККМ или операционный день.
- Сохранение корзины, неизвестного запроса и идентификаторов до HTTP;
  восстановление после reload и повтор с прежними body/Idempotency-Key.
  После успешного POST выполняется GET: идемпотентный ответ может содержать
  историческое состояние, которое уже изменил другой сотрудник.

## Запуск на стенде

Нужны Node.js **24.16+ в ветке 24** и pnpm 11.19.0 из требований репозитория,
подготовленные локальные БД/edge и меню по [local-orders.md](local-orders.md).
В рабочей копии выполнить:

```sh
pnpm build
pnpm db:migrate
pnpm staff:setup examples/local-cashier.json
pnpm start:edge
```

В другом терминале из корня:

```sh
node --env-file=.env apps/pos/server.mjs
```

Открыть **http://127.0.0.1:4176** в Microsoft Edge или Chrome. Для рабочего
полноэкранного просмотра Windows используется F11. Это не аппаратная
блокировка Windows, не kiosk-lockdown и не настройка автозапуска.
Выбрать `.local/staff-STAFF_UUID.json` через кнопку «Выбрать файл сессии».
Ключ не копировать в адресную строку, аргументы запуска или настройки сборки.

`POS_PORT` меняет локальный порт UI. `POS_EDGE_PORT`, затем `EDGE_PORT`, затем
3101 определяют порт edge. Сервер слушает **только 127.0.0.1** и обращается
**только к 127.0.0.1**. В адресе браузера использовать 127.0.0.1, не localhost:
проверяется точный Host/Origin. Не публиковать этот процесс в WAN и не
размещать его на публичном `/pos` рядом с гостевым киоском.

Текущий проверенный режим — UI и edge на одном локальном стенде. Если edge
будет отдельным Linux mini-PC в ресторане, защищённый LAN gateway, сертификаты,
Windows service/installer, автообновление и запуск после питания должны пройти
следующий аппаратный этап. Этот клиент не обходит loopback-ограничение edge.

Необязательный приватный `POS_CONFIG_FILE` задаёт только подписи точки и
категорий, например `.local/pos-display.json`:

```json
{
  "branchLabel": "Название локальной точки",
  "categories": {
    "10000000-0000-4000-8000-000000000005": "Порции"
  }
}
```

Путь задаётся оператором в окружении процесса; файл не содержит credentials.
Подпись не меняет branch binding — точку определяют проверенная сессия и edge.
Текущий MenuSnapshot содержит category UUID, но не названия категорий/фото.
Без подписей показывается «Категория N»; вместо вымышленных фотографий —
буквенные карточки. Модификаторы, комбо и изображения должны появиться вместе
с соответствующим контрактом локального меню/расчёта, а не только в UI.

## Журнал и общий терминал

Токен хранится только в `sessionStorage` текущей вкладки, очищается при выходе
и при ответе UNAUTHORIZED. Он не попадает в URL, localStorage, публичные assets,
логи proxy или Git. При восстановлении вкладок браузер может восстановить и
`sessionStorage`; на общем терминале нужно явно нажимать «Выйти». `sessionStorage` не является шифрованным OS vault: доступ
к профилю Windows, расширениям и браузеру должен быть ограничен персоналу.

Несекретный журнал в `localStorage` разделён по branch/staff/terminal. В нём
есть корзина, UUID, неизменный pending request и до 100 ссылок на заказы; нет
телефонов, токенов или платёжных данных. Выход скрывает данные сотрудника,
но сохраняет его журнал для разрешения неизвестного результата. Другой
сотрудник не возобновляет чужой запрос. Сервер повторно проверяет права.

Web Locks разрешает одну вкладку на branch/terminal, в том числе при другом
сотруднике. Без поддержки Web Locks вход блокируется. Это защищает от
перезаписи журнала двумя вкладками одного браузерного профиля; не является
межкомпьютерной блокировкой. Использовать один управляемый профиль браузера
на физическом терминале. Произвольное клонирование профиля/credential-файла
не является штатным способом работы.

Если доступ истёк, оператор выпускает новую сессию через `staff:setup --renew`.
После входа **того же сотрудника на том же терминале** pending восстанавливается
с прежним ключом. Не удалять localStorage, не менять payload вручную и не
создавать новый заказ вместо неизвестного. Ошибка записи блокирует HTTP;
повреждённый журнал блокирует восстановление и не перезаписывается молча.

Перед выводом терминала из эксплуатации разобрать pending, найти заказы на
edge и выйти из сессии. Удаление данных браузера без такого разбора может
потерять локальную ссылку, хотя сам заказ останется в PostgreSQL.

## Границы автономности

Assets обслуживает локальный Node-процесс, внешних шрифтов/CDN/API нет.
Потеря WAN сама по себе не нужна этому пути. При потере edge/LAN клиент не
подтверждает заказ из кеша и не имитирует оплату. Service Worker, установка
PWA, аппаратный тест отключения WAN и физический Windows-моноблок этим этапом
не приняты.

Индикатор показывает время последнего реального ответа edge. Он не называется
«интернет работает». WAN не измеряется; банк, ККМ, принтер, кухня и облачная
доставка outbox отмечены как не подключённые. Платёж, чек и приготовление
заказа остаются `not_started / not_requested / blocked`.

Единая лента всех каналов, короткие номера выдачи, смены/наличные/сдача,
фискализация, печать, возврат денег, бонусы, локальные модификаторы, kitchen
execution и центральная синхронизация ещё требуют следующих этапов roadmap.
Здесь нет fake cash/Kaspi-кнопок, тестового подтверждения приготовления или
автоматической выдачи заказа.

## Проверки

```sh
node apps/pos/build.mjs
node --env-file=.env --test --test-concurrency=1 tests/pos/core.test.mjs
node --env-file=.env --test tests/pos/browser.test.mjs
```

Для browser-теста установить Python Playwright/Chromium в отдельной среде;
переменная `POS_TEST_PYTHON` задаёт путь к её Python. Тесты используют реальные
Nest edge / PostgreSQL и trusted provisioning во временных схемах, затем
удаляют схемы. Основные данные стенда не изменяют. Не запускать против VPS.

Проверены 6 core/integration-сценариев и browser-flow 1280×800 / 1920×1080:
неверный ключ/роль, серверный integer quote, неизвестный create после commit,
reload, идентичный replay и актуальный GET, истечение/смена/продление сессии,
ошибка/повреждение storage, конфликт стопа, отмена с полной причиной,
однократные order/outbox эффекты, отдельная вкладка, фиксированные действия,
поиск, менеджерский стоп и режим приёма. HTTP auth не заменён мокапом.
Единственная намеренная браузерная подмена — потеря ответа уже состоявшегося
create. Изображения проверки сохраняются в `.local/pos-browser/`; credentials
фикстуры находятся в отдельном временном файле mode 0600 и удаляются.

Отдельного исходного POS HTML в bundle заказчика не найдено. Композиция
использует предусмотренные ТЗ кассовую сетку/корзину, палитру и логотип;
`design/previews/pos-sale.png` — прежний производный макет, не доказательство
согласования нового экрана один в один. До внедрения необходима приёмка на
физическом Windows-терминале и реальном составе меню.
