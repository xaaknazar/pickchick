# Подготовка PickChick к App Store - 22.10.2026

Это подготовка карточки и проверочного входа. Отправка Apple на рассмотрение и
публичный выпуск не разрешены этим этапом. На кассу и киоск ничего не устанавливать.

## Решения владельца

- Цены остаются текущими, перед запуском владелец поменяет их в кабинете.
- На прямое уточнение о сборке21: «Пока оставить текущую оплату». Kaspi не отключать.
- Возвраты обрабатывает ресторан через кабинет/банк; этот этап не включает
  `BACKOFFICE_MANUAL_REFUNDS_ENABLED` и не подтверждает автоматический возврат денег.
- Оформить карточку, подготовить выделенный доступ Apple и создать страницу поддержки.
- Номер/код и закрытые контакты App Review владелец ввёл в защищённый локальный файл.
  В Git, отчётах, скриншотах и логах их нет.

## Карточка

[metadata.json](metadata.json) содержит точный подготовленный текст RU/en-GB,
а также тот же английский текст для возможной en-US. Лимиты Apple проверены.
В Apple внесены русский и английский (Великобритания), описание, промотекст,
ключевые слова, подзаголовки, категория «Еда и напитки», copyright.
Выбран ручной выпуск. Отдельного казахского языка карточки Apple не предлагает;
казахский интерфейс приложения и упоминание всех трёх языков сохранены.
В возрастной анкете отмечено редкое условное игровое столкновение в Pick Man,
остальные перечисленные виды нежелательного контента отсутствуют. Результат9+.

[review-notes.en.txt](review-notes.en.txt) объясняет вход, удаление аккаунта и
ограничения проверки. Контакты и реквизиты входа заполняются только в закрытом
App Review. Наличие сохранённых полей не означает, что серверный вход уже включён.
Фактическое включение и проверка фиксируются отдельным результатом ниже.

## Безопасный проверочный вход

В установленном API `d6085655` уже реализован один review-аккаунт. До настройки
read-only проверка подтвердила: review выключен и номер не задан, обычная
серверная авторизация и текущая оплата включены. Новый runtime не требуется.

`infra/staging/app-review-access.py` меняет только три настройки проверочного
входа, сохраняя image, остальные переменные, секретные файлы, соседей и указатели.
Оператор проверяет номер штатным парсером приложения и read-only поиском по HMAC;
чужой существующий клиент не может стать проверочным. Применение требует точную
полную CI, опубликованный исходник, manifest, закреплённые image/config и общую
блокировку. Снимок прежнего конфига сохраняется0600. Неизвестный результат оставляет
принадлежащую операции блокировку для разбора.

Ввод оператора - приватный JSON по stdin с `phone` и `code_digest`.
Digest вычисляется локально как SHA256 от `pickchick-review-code-v1:` и кода.
Код, номер и digest не передавать аргументами команд и не печатать. Исходный
локальный файл0600 содержит отдельно контакты Apple; они не нужны серверу.

Порядок: свежие refs/резерв `@vps/api`, чистый опубликованный кандидат, полная CI,
проверенный архив с `app-review-source.json`, затем read-only `enable` и только
после успешного результата `enable --apply`. Обязательные параметры:
`--source-sha`, `--expected-api-sha`, `--expected-image`,
`--expected-compose-hash`, `--ci-proof`. SHA установленного API остаётся прежним.
SSH только с закреплённым host key и `StrictHostKeyChecking=yes`.

Для отключения после проверки использовать `disable` с актуальным hash конфига.
Номер сохраняется: он защищает уже созданные сессии от заказа/платежа.
Не восстанавливать слепо старый конфиг без номера после создания review-профиля.
При оставленной блокировке сначала сверить процесс, конфиг и её owner; чужие
блокировки не снимать. Откат кода/БД для этого изменения не требуется.

### Ограничение полноты App Review

Доступ позволяет меню, конфигуратор, корзину/расчёт, профиль, удаление и мини-игры.
Создание заказа, платёж и TEST-заказ запрещены сервером для этого номера;
банковский адаптер также не получает его телефон. SMS/Telegram для него не
отправляются. Ограничение прямо раскрыто Apple; оно не выдаётся за полноценную
проверку оплаченного заказа. Перед отправкой требуется определить и подтвердить
доступный Apple полный сценарий, не создающий реальную оплату и кухонный заказ.

## Страница поддержки

Исходники `infra/public-staging/support/`: RU/KK/EN, обычные HTML-страницы без
аналитики, форм и JavaScript; понятный контакт, оплата/возвраты, вход и удаление.
Внешний вид использует действующие цвета и шрифты PickChick. Генератор Pro Max
предложил рекламный hero, не соответствующий задаче чтения; взяты правила
доступности, а визуальная основа - действующий бренд. Impeccable применён
адресно к странице помощи, без нового редизайна продукта.

Реальный телефон не хранится в Git: при публикации берётся единственный контакт
ресторана из уже опубликованной политики конфиденциальности. Приватные контакты
Apple не используются. `support-page-release.py` сохраняет все старые файлы и
маршруты; новый маршрут разрешает толькоGET/HEAD известных страниц поддержки.
Полная CI, manifest, CAS pins и общая блокировка обязательны. При неудаче
возвращается прежний gateway; неизвестный результат сохраняет блокировку.
