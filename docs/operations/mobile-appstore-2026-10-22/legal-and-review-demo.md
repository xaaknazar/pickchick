# Условия storefront и демонстрация заказа

Владелец 22.10.2026 подтвердил [точную редакцию](legal-final-proposal.md) и отдельное
принятие прежними пользователями перед платным заказом. Версия `storefront-2026-10-22`.
Это разрешение на подготовленную редакцию, а не подтверждение отправки App Review.

## Изменения

- GET/PATCH собственного профиля возвращают текущую версию условий и состояние
  согласия. PATCH принимает только обе актуальные версии и явное `accepted: true`.
- Сервер сохраняет новые terms/privacy отдельно, не переписывает старые записи,
  не меняет маркетинг. Блокировка клиента сериализует повторные нажатия.
- Без актуального согласия новые заказы и банковские команды отклоняются.
  Чтение истории, статуса, выход и удаление аккаунта остаются доступны.
- Перед оплатой приложение показывает документы, отдельное «Принимаю условия»
  и «Не сейчас». Ошибка сохранения не разрешает финансовую команду. В старых
  установленных сборках нет нового окна: до платного заказа нужно обновиться
  либо снова войти с принятием текущих документов.
- Настройки содержат публичную демонстрацию. Она копирует корзину отдельно,
  показывает учебный результат, существующий экран статуса и игры. Демонстрация
  явно обозначена, не создаёт заказ, счёт, чек, бонусы или команду кухне.
  Это учебный сценарий, не подтверждение банковской интеграции или реальной оплаты.
- Новые строки RU/KK/EN. Сборка 23 зарезервирована после просмотра Apple;
  последняя загруженная сборка была 22. Версия приложения и Bundle ID сохранены.

## Проверки подготовки

397 mobile JS + 59 Python PASS. Typecheck mobile и сборка API PASS.
56 integration identity/abuse PASS, включая сохранение истории согласий,
параллельный повтор, неверную версию, отзыв сессии и защиту аккаунта Apple.
Изолированный браузер: принятие/закрытие/ошибка сохранения/повтор на 320x568 и
393x852; демонстрация RU/KK/EN на обоих размерах, восстановление и неизменность
настоящей корзины. Ни один запрос не достиг реального банка или сервера.

## Публикация и откат

Пока это подготовка: полная CI текущего кандидата, публикация страниц и API,
архив/обработка сборки 23 и отправка Apple ещё не подтверждены.

1. Полная Foundation CI точного опубликованного SHA.
2. `infra/public-staging/legal-update.py`: только два существующих HTML-документа
   из подтверждённого текста. Старые страницы проверяются по SHA-256; реквизиты
   берутся из них и не копируются в Git. Общий lock, неизменяемый public release,
   проверка остальных ресурсов, соседей и HTTP. Откат - прежний gateway compose
   и прежний public pointer; старые страницы сохраняются целиком.
3. `infra/staging/appstore-legal-release.py`: текущий API d6085655, schema068,
   существующие image/compose/public pins. Перед переключением обязательны
   зашифрованная копия, изолированное восстановление и запуск кандидата.
   Меняются API image и версия согласий; миграций, цен и обновления workers нет.
   Соседние банковские процессы сохраняются. Откат возвращает прежний API image
   и compose, без восстановления БД и без удаления новых согласий.
4. Native Release 23 из чистого SHA, прежняя подпись и storefront. Проверить
   встроенный JS, Bundle ID, номер, обработку Apple и внутреннюю группу.
5. Обновить инструкцию проверяющему и выбранный бинарник карточки. Не представлять
   демонстрацию как банковскую оплату. Публичный выпуск остаётся ручным.

В базовом shared после установленного API также есть уже принятый код проверки
суммы kiosk QR и изменения зависимостей Expo. Новый оператор допускает только
точную базу b906718c и перечисленные изменения согласий. Отдельные bank/QR workers
не обновляет; включение новых функций, каталог, цены и касса в этот этап не входят.
