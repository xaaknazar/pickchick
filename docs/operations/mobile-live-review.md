# Просмотр мобильного дизайна без повторной загрузки в TestFlight

Для совместной работы над дизайном используется отдельный **PickChick Dev**.
Нативный клиент один раз устанавливается на iPhone с этого Mac; затем Metro
передаёт изменения JavaScript/TypeScript и интерфейса через Fast Refresh.
[Официальный рабочий процесс Expo](https://docs.expo.dev/develop/development-builds/introduction/).

## Для владельца продукта

1. Первый запуск: подключить разблокированный iPhone кабелем, подтвердить
   доверие Mac, включить Developer Mode и подтвердить его после перезагрузки.
   [Инструкция Apple](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device).
2. После установки открыть **PickChick Dev**. Для обычной LAN-сессии Mac и iPhone
   должны быть в одной доступной друг другу сети; Mac включён, Metro запущен.
   Если проект не открылся автоматически, использовать QR текущего Metro.
3. Открыть обычный пользовательский сценарий или «Профиль → Все экраны дизайна».
   Галерея использует отдельную демонстрационную корзину; настоящую связь
   синтетического заказа с TEST-кухней проверять в обычном сценарии приложения.
4. Сообщить экран, действие и нужное изменение; приложить скриншот при необходимости.
   После сохранения кода проверить обновившийся экран. Некоторые изменения
   требуют Reload или повторного перехода, а не переустановки приложения.

Последовательность согласования: витрина/нижняя навигация → карточки блюд и комбо
→ корзина/оформление → вход/дата рождения/профиль → история/статусы и остальные
экраны ТЗ. Для каждого экрана проверять оригинальный мокап, читаемость текста,
размеры нажатия, отступы, клавиатуру, safe area, прокрутку и закреплённые действия.
Снимок галереи не заменяет проверку обычного сценария и его состояний.

## Конфигурация и запуск Metro

| Параметр                        | Обычная сборка              | Сборка для живого просмотра         |
| ------------------------------- | --------------------------- | ----------------------------------- |
| Вариант                         | По умолчанию `release`      | `PICKCHICK_APP_VARIANT=development` |
| Имя                             | PickChick                   | PickChick Dev                       |
| iOS Bundle ID / Android package | `kz.pickchick.app`          | `kz.pickchick.app.dev`              |
| URL scheme                      | `pickchick`                 | `pickchick-dev`                     |
| API                             | Существующий HTTPS TEST VPS | Тот же TEST VPS                     |

Выбор варианта задан в `apps/mobile/app.config.ts`, исходная конфигурация
`app.json` сохранена. Отличающиеся идентификаторы позволяют приложениям
сосуществовать; локальные вход и корзина у Dev отдельные. API/provider flags
не переключаются этим вариантом. Настройка не включает настоящие SMS или оплату.

Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm --filter @pickchick/mobile dev
```

Команда запускает dev client в LAN с явной схемой `pickchick-dev`. Пользоваться
адресом/QR именно этого запуска. `127.0.0.1` и `localhost` на iPhone указывают
на сам телефон, а не на Mac. Не открывать Metro в интернет через VPS или
переадресацию портов. Публичный tunnel этой конфигурацией не включается.

SDK 57 автоматически применяет plugin `expo-dev-client` при наличии пакета.
Поэтому `addGeneratedScheme:false` явно задан для обоих вариантов: обычная
сборка не получает дополнительную схему `exp+pickchick`. Launcher работает
в Debug; EAS Update, update channels и OTA-доставка здесь не подключены.

## Первичная нативная сборка

Нужны Xcode, CocoaPods, существующая Apple Team и development-подпись для
отдельного Bundle ID с зарегистрированным iPhone. App Store distribution
profile приложения TestFlight не подходит для прямой Debug-установки.

Нативный проект генерируется с `PICKCHICK_APP_VARIANT=development`. Для этого
используется отдельная рабочая копия в `~/Library/Caches/PickChick/worktrees/`,
а DerivedData/логи — в `~/Library/Caches/PickChick/development/`: ранее сборка
в Documents/iCloud воспроизводила ошибку codesign/FinderInfo. Живой Metro
запускается из основной рабочей копии, где меняется дизайн.

Не запускать `prebuild --clean` поверх вручную изменённого native project;
сначала проверить его происхождение. Установщик должен проверить Bundle ID
`kz.pickchick.app.dev`, Team, development entitlements и подпись готового `.app`.
На телефон устанавливается только этот артефакт. Данные/приложение TestFlight
не удаляются; архивирование и отправка в App Store Connect не требуются.

Добавление native-библиотеки, изменение нативной конфигурации или SDK требуют
новой сборки Dev. Правки компонентов/стилей обычно достаточно сохранить.
Окончательную плавность проверять отдельно в Release на устройстве: показатели
Debug не являются подтверждением release performance.

## Проверка работающего Metro и общих файлов

`pnpm --filter @pickchick/mobile dev:check` запрашивает iOS manifest у текущего
локального Metro и загружает именно его `launchAsset`. Нужен запущенный `dev`;
по умолчанию проверяется `http://127.0.0.1:8081`, другой loopback-адрес задаётся
через `MOBILE_DEV_URL`. Для Android: `MOBILE_DEV_PLATFORM=android` перед командой.
HTTP 200 и непустой bundle подтверждают загрузку JavaScript, но не заменяют
приёмку экранов на физическом устройстве.

8 сентября 2026 у владельца воспроизведён отказ `restaurant-locations.json`: файл
и относительный путь были корректны, но корневой `config/` не был workspace
package и не входил в стандартные `watchFolders` Expo. JSON появился после
старта Metro; долго работающий dev-процесс не замечал новый файл, хотя свежий
export проходил. `apps/mobile/metro.config.js` расширяет стандартную конфигурацию
только папкой публичного справочника `config/`. Пути импортов, Babel и TS
для обхода ошибки не меняются.

После изменения конфигурации Metro остановить только текущий процесс проекта
и запустить `pnpm --filter @pickchick/mobile dev --clear`, затем `dev:check`.
При ошибке на телефоне повторно открыть PickChick Dev или выполнить Reload.
Нативная переустановка, TestFlight и удаление данных приложения не нужны.
Не добавлять весь корень проекта в watchFolders только ради одного справочника:
`.local` содержит приватные служебные материалы.
