# Станции кухни KDS и выдача доставки: runbook точки

Полоса kds перехода 19.11.2026 (контракт `docs/architecture/cutover-2026-11-contracts.md`, §2.3, §5.2, §5.4, §6). Решение - [ADR-0016](../architecture/adr/0016-kds-layout.md).
Статус документа: код и тесты в ветке `codex/cutover-kds`; на сервере точки не установлено. Установку делает integration (`kds-upgrade-db.mjs`, окно С4) и оператор по этому документу.

## 1. Что меняется на кухне

Шесть станций вместо двух («Приготовление», «Сборка и выдача»):

| Функция             | Экран                        | Что делает                                                                                     |
| ------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------- |
| `breading`          | «Панировка (6)»              | своих задач нет; видит позиции столов, которые раскладка относит к панировке, и «Фингерсов: N» |
| `toasts`            | «Тосты и бургеры (5)»        | задачи тостов/бургеров; стол закрывает их сам («Собран»)                                       |
| `assembly_hall`     | «Сборка - зал (стол 1)»      | сборка зала и «с собой»                                                                        |
| `assembly_delivery` | «Сборка - доставка (стол 2)» | сборка заказов агрегаторов                                                                     |
| `issue`             | «Выдача (2)»                 | напитки и соусы всех заказов; заказ зала готов только здесь                                    |
| `delivery_handover` | «Выдача доставки (3)»        | заказ агрегатора готов здесь; передача курьеру с тремя отметками                               |

Что видит каждая станция на экране (kitchen 0.4.0, раздел 4):

| Экран               | Содержимое                                                                                                                                                                                                                                                  | Кнопки                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 6 «Панировка»       | «В очереди: N заказов», «Фингерсов: N» (если шеф задал количество), карточки ещё не собранных заказов: позиции и фингерсы                                                                                                                                   | нет; заказ уходит с экрана, когда стол нажал «Собран»                               |
| 5 «Тосты и бургеры» | полоса «Нужно сейчас: Тосты N · Бургеры M» и разбивка по позициям; в карточке - сколько сделать и на какой стол отдать                                                                                                                                      | «Готово»                                                                            |
| Стол 1, стол 2      | позиции стола без напитков и соусов, состояние тоста у позиции («Тост: готов ✓ / в работе / ждём»), «Фингерсов», красная метка «Нет в раскладке - сообщите менеджеру», подсказка «Напитки и соусы - на выдаче»; на столе 2 - метка «ДОСТАВКА · Glovo G-456» | «Собран» (сам закрывает тосты заказа)                                               |
| 2 «Выдача»          | колонки «Собирается» и «Готов к выдаче»; блоки «Подготовить на выдаче: напитки, соусы» и «Сборка: собран ✓ / собирается»; баннер «Менеджер вызван»                                                                                                          | «Готов - позвать гостя» (после стола), «Выдан»; для доставки - «Напитки переданы»   |
| 3 «Выдача доставки» | плитки по номеру агрегатора, поле «Номер из приложения курьера» (фильтр; точное совпадение ставит первую отметку), «Стол: собран ✓», «Напитки: переданы ✓», баннер                                                                                          | «Принять от сборки», «Передать курьеру» (диалог трёх отметок), «Отказ по протоколу» |

Правила раскладки (контракт §5.4): позиция без места в раскладке уходит на стол с меткой «Нет в раскладке - сообщите менеджеру»; заказ из-за раскладки никогда не отклоняется. Табло гостей заказы агрегаторов не показывает.

## 2. Выключатель

Всё новое работает только при `kds_settings.layout_enabled=true` и активной раскладке. Меняет только `infra/windows/kds-switch.mjs` в защищённой среде владельца базы точки (owner env), без интернета. Каждое изменение - новая версия с записью аудита (`kds_setting_changes`, причина 3-300 символов).

```
node --env-file=<owner.env> infra/windows/kds-switch.mjs status
node --env-file=<owner.env> infra/windows/kds-switch.mjs layout-build --tsv <шеф.tsv> [--terminals <экраны.tsv>] --out <layout.json>
node --env-file=<owner.env> infra/windows/kds-switch.mjs layout-apply --file <layout.json> --reason "<причина>"
node --env-file=<owner.env> infra/windows/kds-switch.mjs enable --reason "<причина>"
node --env-file=<owner.env> infra/windows/kds-switch.mjs disable --reason "<причина>"
```

- Файл шефа (TSV): `product_slug`, `function`, `unit`, `count` (`unit` и `count` оба пустые или оба заданы; `finger` - только у панировки, `toast`/`burger` - только у станции 5).
- Файл экранов (TSV): `function`, `terminal_id`. Без него берутся экраны действующей раскладки. Один экран (терминал) открывает не больше двух станций одного вида - они показываются вкладками (утро: стол 1 и выдача 2). Если в файле экранов нет строки `delivery_handover`, станция 3 становится второй вкладкой на каждом экране стола 2, где есть место (решение владельца §9 в.15); отчёт пишет «Выдача доставки (3): вкладка на экране стола 2 (по умолчанию)».
- `layout-build` печатает отчёт «Позиции меню без раскладки: N» - его подписывает шеф.
- `layout-apply` проверяет slug по активному меню, станции и экраны; версия раскладки неизменяема (повтор той же версии с другим содержимым - отказ).
- `enable` повторно строго проверяет раскладку: у каждой станции с работой должен быть экран, вход `kitchen` открывает все станции, и роль воркера fulfillment (`pickchick_fulfillment_sync`, а также `pickchick_fulfillment_worker`, если она есть) может читать `kds_settings` и `kds_layouts`. Без этих прав `enable` отказывает с `WORKER_GRANTS_MISSING` «У воркера fulfillment нет прав чтения раскладки KDS - заказы приложения и киоска уйдут на старые станции»: облачный допуск идёт под ролью воркера и без прав молча оставил бы заказы на старых станциях. Права ставит `kds-upgrade-db` (`WORKER_PRIVILEGES`, CR kds-3); после любой полной переустановки прав воркера (`fulfillmentWorkerGrants`) `status` покажет ту же строку.
- `enable` предупреждает `OPEN_ORDERS_ON_OLD_STATIONS` «Открытых заказов на старых станциях: N (из них агрегаторов: M) - их завершает начальник смены через переключатель станций». `status` показывает то же число в любой момент.

Пример файлов (slug и id - синтетические; настоящие slug - из активного меню, id экранов - из «Устройств»):

```
# шеф.tsv
product_slug	function	unit	count
pick-combo	breading	finger	3
pick-combo	toasts
pick-burger	toasts	burger	1
pick-combo	assembly_hall
pick-combo	assembly_delivery
pick-burger	assembly_hall
pick-burger	assembly_delivery
cola	issue

# экраны.tsv
function	terminal_id
breading	00000000-0000-4000-8000-000000000006
toasts	00000000-0000-4000-8000-000000000006
assembly_hall	00000000-0000-4000-8000-000000000001
issue	00000000-0000-4000-8000-000000000001
assembly_delivery	00000000-0000-4000-8000-000000000002
```

Позиция только на выдаче (есть в `issue` и нет ни на одном столе) - напиток или соус: её задача только на выдаче, и для доставки тоже. Тост или бургер (`toasts`) получает задачу на станции 5, стол закрывает её «Собран».

## 3. Порядок установки и включения (контракт §6.2)

1. Окно С4 (ночь 14→15.11): копия → 025 → новый рантайм (поведение прежнее) → 026 → копия → `kds-upgrade-db inspect/apply` (027, станции `provisionKdsStations`, права рантайма и воркера fulfillment, CR kds-1 и kds-3) → `/health/ready`. До этого рантайм должен уметь несколько prep-станций (`routing.ts`, коммит `6c0cd964`).
   Пока раскладка выключена, шесть новых станций не видны экранам: `GET /edge/v1/fulfillment/stations` отвечает байт-в-байт как до `provisionKdsStations` (вход `kitchen`, начальник смены, привязанные экраны приготовления и сборки), поэтому установленные 0.3.0 и 0.4.0 открывают прежнюю станцию «Приготовление» («Сборка» на экране сборки).
2. Шлюз LAN с профилем `kitchen`, где есть маршруты KDS (CR kds-5), установка PickChick Kitchen 0.4.0 (`apps/kitchen-desktop`, экраны KDS) на моноблоки, привязка экранов в «Устройствах». Без включённой раскладки 0.4.0 показывает прежний экран.
   Пакет 0.4.0 ещё не собирался и не запускался как приложение Electron (в контейнере разработки нет Electron и electron-builder). До RC-client (13.11) на чистой копии ветки на машине с Windows: `cd apps/kitchen-desktop && npm ci && npm run test:electron && npm run dist:win && npm run verify:win`. Результат каждой команды и SHA-256 установщика записать сюда и в отчёт полосы; без зелёного `verify:win` 0.4.0 на моноблоки не ставить (остаётся 0.3.0, раскладка выключена).

   | Проверка пакета 0.4.0   | Результат    | SHA-256 установщика |
   | ----------------------- | ------------ | ------------------- |
   | `npm run test:electron` | не запускали | -                   |
   | `npm run dist:win`      | не запускали | -                   |
   | `npm run verify:win`    | не запускали | -                   |

3. 16.11: `status` → `layout-build` → подпись шефа → `layout-apply` → `enable --reason "Т9"`.
   Перед `enable` - по `status` нет открытых заказов на старых станциях («Открытых заказов на старых станциях: 0»). Если включать приходится посреди смены: после `enable` вход `kitchen` на экране KDS видит только свои вкладки, поэтому заказы, принятые до включения на «Приготовление»/«Сборку», завершает начальник смены через переключатель станций. Заказ агрегатора с такой станции выдаётся кнопкой «Передать курьеру» с тем же диалогом трёх отметок.
4. После Т7/Т9 - **обязательно** `disable` до утра 19.11: пока работает iiko, экраны KDS не открыты, а заказы приложения и киоска иначе уйдут на неоткрытые станции. После `disable` станция KDS остаётся в списке станций, пока на ней есть незавершённый заказ (принятый при включённой раскладке), и пропадает из него, когда последний такой заказ выдан, отменён или освобождён.
5. 19.11 до открытия: `enable`, тестовый заказ каждого типа (зал, с собой, Яндекс Еда, Glovo, приложение).

Проверка после `enable`: `status` показывает «Раскладка KDS: включена», 6 из 6 станций и доступ входа `kitchen` 6 из 6, «Воркер fulfillment читает раскладку KDS»; `GET /edge/v1/fulfillment/layout` с экрана стола 1 отвечает `enabled:true` и `screens` с его станциями; тестовый заказ приложения появляется на столе 1, а не на старой станции.

## 4. Экраны кухни (PickChick Kitchen 0.4.0)

- Экран сам узнаёт свои станции: после входа он читает `GET /edge/v1/fulfillment/layout` и открывает станции, в которых раскладка указала этот терминал (`screens`, 1-2). Две станции - две вкладки, открыта первая; кнопки станций - не меньше 72 px по высоте (сенсорные моноблоки 1280x800 и 1920x1080).
- Вход `kitchen` на экране из раскладки видит только свои вкладки. Начальник смены видит прежний переключатель всех станций; экраны KDS показываются ему по функции выбранной станции. Экран, которого нет в раскладке, работает с прежним переключателем.
- Раскладка перечитывается раз в 30 секунд. После `disable` в течение 30 секунд экран возвращается к прежнему виду и показывает «Раскладка KDS на сервере точки выключена - работает прежний экран.». Ответ `{enabled:false}` или 404 (старый edge или шлюз без маршрутов KDS) - прежний экран; сбой связи не переключает экран, последняя раскладка сохраняется.
- При смене `enable`/`disable` экран заново читает список станций (edge показывает станции KDS только при включённой раскладке). После `enable` вход `kitchen` на экране из раскладки открывает свою первую вкладку без повторного входа. После `disable` экран остаётся на станции KDS, пока на ней есть незавершённые заказы, иначе переходит на первую станцию приготовления, как при входе. Если список станций не прочитан, экран ничего не меняет и пробует снова при следующем обновлении.
- Станция 6 читает `GET kds/breading` (своих задач нет), экраны 2 и 3 - баннер `GET incidents?scope=open` при каждом обновлении (раз в 5 секунд).
- «Передать курьеру» открывает диалог «Передача курьеру Glovo G-456» с тремя отметками; кнопка активна только при всех трёх. Команда идёт через журнал кухни: при потере ответа повтор отправляет то же тело с тем же ключом. Если edge отказал 400 (раскладку выключили или включили между обновлением экрана и нажатием), команда закрывается, экран перечитывает заказ, сотрудник передаёт заново по актуальному протоколу.
- «Отказ по протоколу» - форма: агрегатор, номер от курьера, причина, описание (подсказка «Не вводите телефоны и имена гостей и курьеров»; описание с номером телефона не отправляется). У записи свой журнал на экране: потерянный ответ повторяется тем же ключом, второй записи не будет.

## 5. Передача курьеру (Аг9)

- Заказ агрегатора (касса пробила его с каналом Яндекс Еда или Glovo и номером) при включённой раскладке собирается на столе 2 и готов на станции 3.
- «Передать курьеру» принимается edge только с тремя отметками: номер в приложении курьера совпал, курьер при сотруднике нажал «Принял заказ», курьер сфотографировал заказ. Без них edge отвечает 400 `HANDOVER_MARKS_REQUIRED` и ничего не меняет.
- С отметками в одной транзакции: заказ `handed_over`, событие в облако (прежней формы) и строка журнала `delivery_handovers` (агрегатор, номер, станция, сотрудник, экран, ключ команды). Повтор той же команды не создаёт второй записи.
- Отметки требуются ровно для заказов, у которых экран показывает «ДОСТАВКА»: заказ агрегатора при включённой раскладке. Заказы зала, приложения и киоска передаются как раньше; заказ агрегатора, принятый до включения, но ещё не выданный, после `enable` тоже требует отметок.
- При `disable` открытые заказы агрегаторов выдаются по-старому, без отметок (старый экран их не умеет); протокол на это время - бумажный.

## 6. Отказ по протоколу и баннер «Менеджер вызван»

- Экран 3 (или 2) записывает отказ: агрегатор (`yandex_eda`, `glovo`, `other`), номер, который назвал курьер (необязательно), вид (`number_mismatch`, `not_accepted_in_app`, `no_photo`, `courier_refused`, `other`), описание 3-500 символов. В описание не вводить телефоны и имена гостей.
- Ключ запроса (`Idempotency-Key`) - номер инцидента: повтор того же запроса тем же сотрудником с того же экрана возвращает ту же запись, другой запрос с тем же ключом - 409.
- Журнал только дополняется (`courier_incidents`), в облако в P0 не уходит (P1, вместе со статусами «на месте», «передано в поддержку», «решено»).
- Баннер (`GET /edge/v1/fulfillment/incidents?scope=open`): инцидент открыт 30 минут после записи, пока его заказ не выдан, не отменён и не освобождён. Журнал дня - `scope=today` (сутки по Алматы).
- При выключенной раскладке новая запись и список отвечают 404; повтор уже записанного инцидента тем же ключом (потерянный ответ) возвращает сохранённую запись.
- Телефон (+7 или 8 и десять цифр) не принимается ни в описании, ни в номере от курьера: edge отвечает 400, экран подсказывает убрать номер телефона.

## 7. Откат

| Ситуация                                                             | Действие                                                                                                                                                                                                                                |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Экраны KDS не работают, кухня встала                                 | `kds-switch disable --reason "..."`: новые заказы идут на старые станции, экраны в течение 30 секунд показывают прежний вид; начатые заказы KDS заканчиваются на своих станциях (станция видна в списке, пока на ней есть такие заказы) |
| Программа кухни 0.4.0 не запускается на моноблоке                    | вернуть установщик 0.3.0 только при выключенной раскладке (0.3.0 не умеет экранов KDS и отметок передачи); проверить `verify:win` пакета 0.4.0                                                                                          |
| «Передать курьеру» отвечает ошибкой сервера (500)                    | `disable`, выдать заказ по-старому; затем `kds-upgrade-db inspect` - проверить права рантайма на `delivery_handovers`/`courier_incidents` (`RUNTIME_PRIVILEGES`)                                                                        |
| Заказы приложения/киоска при включённой раскладке на старых станциях | `status`: строка про права воркера fulfillment. Нет прав (например, права воркера переустановлены целиком после 027) - `kds-upgrade-db inspect/apply`, права `WORKER_PRIVILEGES` (CR kds-3); до этого `enable` такую базу не включит    |
| Откат рантайма на версию без KDS                                     | только после выдачи всех заказов KDS: старый рантайм не закрывает тосты со стола автоматически - их закрывают на экране 5                                                                                                               |

Схемы и строки 027 никогда не удаляются.
