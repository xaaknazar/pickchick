# Вход в кабинет и открытая навигация

12 октября 2026. Задача `cabinet-entry`.

## Причина и изменение

`https://pickchick.kz/` отвечал HTTP 404 с JSON `NOT_FOUND`, тогда как
`/backoffice/` возвращал рабочую страницу входа. Для точного пути `/` только
на основном домене добавлен временный redirect 302 для GET/HEAD на
`/backoffice/`. API-поддомен, POST, остальные пути и платёжные маршруты
не попадают под этот matcher. `www` сохраняет существующий переход на
основной домен. Права и вход в кабинет остаются обязательными.

В боковом меню удалён раскрывающийся блок «Другие разделы». Все доступные
пользователю пункты идут одним списком с прежними названиями, порядком и
иконками. На узком экране остаётся общая кнопка «Разделы кабинета», внутри
неё нет второго раскрытия. Длинный список прокручивается; выделение текущего
раздела и проверки доступа сохранены.

## Проверки и выпуск

Локально прошли два браузерных сценария на реальной изолированной БД:
видимость 17 пунктов, клавиатурный доступ к последнему пункту, адаптивность
на 1440/768/393 px и переходы между разделами. Скриншоты desktop/mobile
проверены. Прошли 10 Python-тестов доменных операторов, 7 тестов пульта
и полный `pnpm check` (242 unit-теста, build/typecheck/lint/format/contracts/design). Оператор `infra/domains/release-root.py` проверяет точную зелёную Foundation
CI, манифест пакета, исходные указатели и хеш ingress, сохраняет резервную копию,
использует общий lock и Caddy validate/reload без перезапуска соседних контейнеров.
Изменяется только вставка в блок `pickchick.kz`; замена всего исторического
шаблона запрещена, поскольку рабочие платёжные маршруты развивались отдельно.

Известная ошибка после записи вызывает проверяемый откат. Неизвестный результат
или чужое изменение сохраняют блокировку для диагностики. Проверки оператора
покрывают точечность вставки, повторный запуск, успешное применение, откат,
потерянный ответ и защиту чужого изменения.

Портал обновляется существующим `infra/backoffice-login/update.py` отдельно
от маршрута. API и БД выпускать не требуется. Перед каждым шагом получать
фактические baseline pointers/hashes; после root reload передать новый front
hash оператору портала. Установка пока не выполнена: SSH-agent финансового
Mac пуст, владельцу отправлена инструкция разблокировки ключа.
