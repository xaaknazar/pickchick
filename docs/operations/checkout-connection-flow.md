# Проверка соединения после нажатия оплаты

Решение владельца 2 октября: кратковременные ошибки фоновой проверки меню не
блокируют «Оформить заказ» и «Оплатить через Kaspi» и не показывают сетевые
баннеры в корзине/оформлении. Стоп-лист не снимается: сервер проверяет состав
и сумму после явного действия клиента, на существующем экране подключения.

Оформление пассивно получает только конфигурацию комментария. Нажатие оплаты
сначала восстанавливает сохранённую попытку, затем проверяет незавершённые
заказы, получает текущую конфигурацию и котировку. Изменившаяся сумма требует
повторного подтверждения. Котировка повторяется с одним ключом; создание заказа
использует записанный до запроса ключ, платёж - прежний orderId. Повторное нажатие
не создаёт параллельную команду. Закрытие подготовки прерывает запросы; уже
сохранённый intent остаётся для восстановления, а не удаляется как неоплаченный.

Временные сетевые отказы повторяются внутри анимации. Через 60 секунд ожидание
становится доступным для ручного продолжения, без бесконечной автоматической
нагрузки. Можно вернуться к оформлению с сохранённой корзиной. Подтверждённые
бизнес-отказы (стоп-лист, закрытый ресторан, права) требуют понятного действия;
они не скрываются как успешное оформление. Постоянное интернет-соединение не
гарантируется кодом приложения.

Перед новым счётом worker проверяет банковскую сессию; существующие платежи
продолжают сверяться независимо от возможности новых отправок.
[Серверная проверка](kaspi-session-preflight.md).

на четырёх размерах (320/393/768/852), отмена, двойное нажатие, обрывы, прежние
ключи повторов и подтверждение новой цены. Adapter 23 и PostgreSQL 36 прошли.
