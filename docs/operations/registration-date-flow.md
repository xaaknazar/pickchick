# Регистрация: дата возвращает к выбору пола

30 сентября 2026. Владелец сообщил, что после ввода никнейма и даты рождения
анкета закрылась до выбора пола. Точный системный сбой на его iPhone не воспроизведён.

## Изменение

- На iOS календарь больше не создаёт отдельный React Native Modal поверх
  transparentModal регистрации. Его лист находится внутри AuthLayout и закрывает
  только выбор даты; системный колёсный DateTimePicker сохранён.
- Форма под календарём не принимает касания и скрыта от accessibility-дерева.
  Сохранение анкеты запрещено при открытом календаре и без выбранного пола.
- Web использует тот же вложенный лист с ограничением фокуса и Escape:
  Escape закрывает только календарь, а не родительское окно входа.
- Android сохраняет штатный DateTimePickerAndroid; подтверждение и отмена
  возвращают к анкете. Протокол дат и серверный профиль не менялись.
- Уже заполненный профиль пропускает анкету только при входе в шаг.
  После показа незаполненной анкеты фоновое обновление аккаунта больше
  не запускает автоматическое завершение. Сохранение завершается явной кнопкой.

## Проверки

Mobile typecheck, targeted ESLint/Prettier, 12 тестов даты/профиля прошли.
Browser customer account: 320×568, 390×844, 430×932. Никнейм -> дата ->
подтверждение -> анкета остаётся -> пол -> Готово -> профиль.
До явного сохранения PATCH профиля отсутствует. Отмена изменённой даты
через Escape сохраняет предыдущую дату. Повторное подтверждение календаря
с уже выбранным полом также не сохраняет анкету. Ошибок браузера нет.
Проверены восстановление сессии и выход; реальные OTP не отправлялись.

Снимок анкеты 390×844 проверен визуально. iOS Dev manifest/bundle HTTP200.
Нативная приёмка на iPhone/Android ещё требуется; браузерный тест не доказывает
исчезновение системного сбоя на устройстве. Переустановка Dev не нужна.
API/БД, оплата, версии native-зависимостей и подписи приложения не менялись.
Полная CI нового коммита отдельно от локальных проверок.
