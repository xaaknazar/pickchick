# Неоплаченный счёт Kaspi: 3 минуты

Решение владельца 1 октября 2026. Область: счёт по телефону мобильного приложения,
позже киоска. Кассовый POS-терминал этим адаптером не обслуживается.

## Поведение

- Новый счёт получает сохранённый deadline180 секунд от начала отправки.
  Повтор запроса, перезапуск или восстановление из истории не продлевает его.
  Уже выпущенные счета сохраняют записанный deadline.
- Worker сначала проверяет банк. Processed с проверенной суммой фиксирует оплату.
  По истечении срока отправляет отмену того же operationId, затем уточняет результат.
  Перед отправкой сохраняется намерение; потерянный ответ не порождает дубль отмены.
  Если запрос достоверно не отправлен или сессия недоступна, отмена повторяется после
  восстановления доступа. Неопределённость не считается подтверждением отмены.
- Опрос перед deadline ограничен оставшимся временем. Фактический ответ банка
  может прийти позднее трёх минут при сетевой задержке/недоступной сессии.
- Из списка клиента исключаются окончательно неуспешные неоплаченные попытки.
  Фильтр применяется до LIMIT30, чтобы старые действительные заказы не исчезли.
  Заказы с capture или attention сохраняются, включая частичную/позднюю оплату.
  PostgreSQL journal, invoices, attempts и capture не удаляются.
- На экране ожидания показан обратный отсчёт по серверному expiresAt. В нуле
  показывается ожидание подтверждения отмены, новая оплата не предлагается.
  После банковского подтверждения неуспеха доступен возврат к сохранённой корзине.
- Открытый список слушает изменения ожидающих оплаты заказов через существующий
  long poll; подтвердившаяся отмена убирает карточку без ручной перезагрузки.
  Фоновое приложение запросы останавливает; после возвращения сверяет статус.

## Проверки и выпуск

PostgreSQL проверяет180 секунд и границу срока, один cancel при потере ответа,
подтверждение отмены, paid/cancel race, неизменность истории и видимость capture.
Mobile проверяет таймер, отсутствие повторной оплаты до ответа банка и удаление
карточки из открытого списка. Визуальный мир и герой оплаты сохранены.
UI/UX Pro Max: loading feedback, native accessibility; Impeccable clarify:
различать ожидание ответа и подтверждённый результат.

API устанавливается через release-kaspi-expiry.py (baseline32b28db/publicfeb550c,
schema028), затем release-kaspi-expiry-worker.py меняет только worker и явно
задаёт TTL180 в compose. Секреты/сессия моста сохраняются. Обязательны полная CI
точного commit, backup/isolated restore, проверки данных и соседних контейнеров.
Перед заменой worker должны отсутствовать незавершённые счета. При их наличии
установка останавливается для сверки, а не удаляет/переиздаёт счета.

Установка ещё не выполнена. Новых реальных счетов для диагностики не создавали.
Приёмка фактической отмены в приложении Kaspi - следующий обычный неоплаченный счёт.
