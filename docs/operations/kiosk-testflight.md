# PickChick Kiosk — отдельный выпуск iPad

Приложение: `apps/kiosk`, Expo / React Native, только iPad, портретная ориентация,
полный экран. Название — **PickChick Kiosk**, Bundle ID — `kz.pickchick.kiosk`,
версия первого выпуска — **0.1.0 (1)**. Используется согласованная существующая
Apple Team `DAJTP6MC3Q`. Это отдельное приложение; его сборка не заменяет
пользовательский PickChick `kz.pickchick.app`.

## Что входит в проверяемую версию

Витрина без управления фоновым видео; RU/KZ интерфейс; в зале / с собой;
24 блюда каталога v0.3; варианты комбо, допы, напитки, КБЖУ и описание;
«Всегда кстати», корзина, проверка и имитация оплаты, серверный номер заказа,
восстановление операции и очистка между гостями. КБЖУ и составы остаются
данными предоставленного мокапа, без утверждения для реальных продаж.

Киоск обращается к существующему TEST API на VPS через HTTPS с каналом `kiosk`.
Корзина хранится отдельно от мобильного приложения. Сеанс устройства использует
SecureStore, незавершённая операция — отдельную запись AsyncStorage. Команда и
ключ повтора сохраняются перед отправкой. После потери ответа сначала проверяется
заказ на сервере; уже завершённую операцию не подменяют новым заказом.

Таймер 90 + 15 секунд очищает только безопасный гостевой черновик. Успешный
результат остаётся на экране 15 секунд, затем открывается витрина следующему
гостю. Неизвестная или ожидающая оплата блокирует автоматическую очистку.
Подтверждённый заказ остаётся на сервере и кухне после смены гостя.

Настоящие Kaspi/терминал, Чики, телефон/QR, имя на табло, чек и печать ещё
не подключены. Киоск сообщает об этом и не собирает номер ради фиктивного
начисления. TEST-платёж обозначен явно; списания денег и отправки SMS нет.
Без WAN эта версия не заменяет локальный edge.

## Подготовка и проверки

```sh
pnpm install --frozen-lockfile
pnpm --filter @pickchick/kiosk... build
pnpm test:kiosk
pnpm --filter @pickchick/kiosk export
PICKCHICK_PREVIEW_APP=kiosk KIOSK_PREVIEW_PORT=4184 node scripts/mobile/preview-server.mjs
```

Браузерный просмотр — `http://127.0.0.1:4184`; это тот же React Native UI через
web renderer, а не доказательство нативного поведения. Тест с изолированной HTTP
фикстурой — `tests/kiosk/browser_ui.py`, размеры 768×1024, 820×1180, 1024×1366.
Он не отправляет заказы на VPS.

После iOS prebuild и CocoaPods:

```sh
ruby scripts/mobile/ios_ui_smoke.rb --app kiosk --install
```

Создаётся отдельная Release-схема `PickChickKioskUITests`. Обычные XCTest проверяют
просмотр, модификаторы, закреплённые действия и сохранение корзины без создания
заказов. Только явно включённый `PICKCHICK_KIOSK_CONNECTED_TEST=1` запускает
сценарий одного синтетического заказа; его номер сохраняется в XCTest attachment
для дальнейшей проверки приготовления, сборки и табло. Номер не генерируется UI.

## Доставка в Apple

Общий проверяемый helper — `scripts/mobile/ios_release.py --app kiosk`.
Выбранные workspace, схема, Bundle ID, Team и семейство устройств проверяются
до экспорта. Профиль потребительского приложения отвергается. Для киоска export
и upload всегда содержат `testFlightInternalTestingOnly=true`.

1. В аккаунте Apple зарегистрировать отдельный App ID `kz.pickchick.kiosk` и
   App Store provisioning profile с существующим разрешённым distribution
   certificate. Затем создать отдельную запись **PickChick Kiosk** в App Store
   Connect и записать её числовой ID. ID мобильного PickChick использовать нельзя.
2. После проверок и чистого Git SHA выполнить `archive`, `export`, `upload`
   helper с `--app kiosk`, одним release label и отдельным профилем киоска.
   Приватные артефакты — `~/Library/Caches/PickChick/releases`; ключи и профили
   находятся только в исключённых из Git файлах с ограниченными правами.
3. Дождаться завершения обработки Apple; проверить приложение, версию, номер
   сборки и состав участников отдельной внутренней группы. Не создавать
   публичную ссылку или внешнюю группу.
4. Проверить установку на ресторанный iPad, затем применить и принять
   [закрытый режим устройства](ipad-kiosk-lockdown.md).

На начало этапа браузерные сессии App Store Connect и Apple Developer истекли.
Новый App ID / профиль и запись киоска ещё не подтверждены, установка из
TestFlight не заявляется. Состояние доставки обновляется по фактическому ответу
Apple в [протоколе проверок](../../tests/operations/verification-kiosk-native-2026-09-07.md).

TestFlight ограничен сроком сборки; постоянный ресторанный выпуск и MDM —
отдельная приёмка. Внутренняя группа ограничивает аккаунты, а разрешение только
конкретным iPad требует управления устройствами и отдельной серверной активации.
