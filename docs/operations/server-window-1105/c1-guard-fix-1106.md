# С1: исправление проверок после отката 06.11

## Статус

Подготовлен репозиторный оркестратор `infra/staging/c1-window.py` вместо
одноразовых `/private/tmp/C1-window-1106*.py`. Старые временные скрипты
не использовать. При импорте и тестах ничего не запускается. Сервер в этой
доработке не читался и не менялся. Причина прежнего AssertionError остаётся
недоказанной: исторический журнал не содержит имени упавшей проверки.

## Доказательство

- Все проверки именованные; журнал содержит phase/stage/check/status,
  expected/actual как SHA-256, тип, количество, имена ключей. Для команд
  сохраняется код возврата, для исключений только класс, без stderr/текста.
- API: проверяются image ID и org.opencontainers.image.revision. Метки
  com.docker.compose.* не сравниваются после разрешённого изменения.
- Соседи: полное равенство меток, имён, ID, образов, Running и StartedAt.
- Окружение: исходные ссылки строго старые, изменены ровно TERMS/PRIVACY,
  точный набор ключей и все ожидаемые значения. Дубликаты запрещены.
- auth/config: до и после ровно семь согласованных ключей; остальные поля
  и значения сохраняются, меняются только terms_url/privacy_url. Убрано
  предположение channels == [telegram]; наличие Telegram сохраняется как gate.
- Baseline, lock, состав 73/18, нулевая активная работа, ledger, указатели,
  readiness, health, snapshots и long-poll обоих адресов остаются проверками.
- 28 локальных Python tests PASS (26 оркестратор + 2 кандидат compose).
  Дополнительно 26 тестов оркестратора PASS с python3 -O: защитные проверки
  не используют отключаемый assert. Тесты блокируют subprocess и сеть.
- Тесты включены существующим unittest discover в Foundation CI / staging.
  Полная CI нового коммита проверяется отдельно; локальный PASS её не заменяет.

## Откат

При отказе после попытки установки возвращается защищённая копия compose,
пересоздаётся только API; повторно проверяются image/revision, точное
окружение, auth/config, соседи, ledger, указатели, состав активной работы.
При неуспешном откате lock сохраняется. Имя исходной и откатной ошибок
сохраняется отдельно. Отказ записи успешного журнала тоже запускает откат.
После успешного С1 lock остаётся для внешнего Domain gate 11/11 и перехода
к С3. Его снимает только владелец lock после всех внешних проверок/наблюдения.
