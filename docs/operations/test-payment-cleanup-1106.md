## Семантика

Физическое удаление запрещено защитой платёжной истории и не выполняется.
Административное закрытие использует терминальное состояние failed у попытки,
намерения и QR. Это локальное закрытие теста по сообщению владельца, а НЕ
подтверждённый отказ банка. Причина явно сохраняется в неизменяемой записи
OWNER_CONFIRMED_UNPAID_TEST_CLOSED:

- owner_confirmed_test=true, owner_reported_no_charge=true;
- bank_result_verified=false, bank_cancelled=false;
- provider_observation_created=false, history_retained=true;
- исходное состояние, сумма, идентификатор попытки и хеш зашифрованной копии.

QR помечается обработанным, чтобы worker не создал ложное банковское наблюдение.
Существующие запросы сверки отмечаются обработанными административно, их
содержимое не удаляется. Заказы, денежные суммы, банковские идентификаторы,
provider inbox, captures, возвраты, чеки и история инцидентов сохраняются.

## Защита и порядок

1. Свежие refs, собственный резерв @vps, отсутствие чужого lock.
2. Копия только затронутых строк потоком в age на VPS, права 0600; копия на Mac,
   совпадение SHA-256 и проверка чтения JSON в памяти без вывода содержимого.
   Отдельный закрытый targets.json содержит только три ID/суммы/времени.
3. Проверенный SQL infra/staging/close-test-qr-1106.sql: сначала apply=no
   (полный ROLLBACK), затем apply=yes. owner_confirmed=yes только по явному
   подтверждению владельца, полученному 06.11.
4. Одна транзакция, блокировки строк, точное совпадение ID, дат и сумм.
   Отказ при захваченном worker lease, capture, возврате, чеке, второй попытке,
   другой ожидающей команде или повторном выполнении. Никакие ограничения
   или триггеры не отключаются.
5. После: ровно три записи аудита; попытки/намерения/QR закрыты, история на месте,
   по ним нет активной сверки. Остальные деньги и процессы не изменены.
   Отдельно пересчитать другие блокеры - это не доказательство допуска к выпуску.

При любой ошибке SQL транзакция целиком откатывается. После успешного выполнения
обратное открытие возможно только адресно по зашифрованной копии с повторной
проверкой отсутствия оплаты и новым аудитом; не восстанавливать рабочую БД целиком
и не удалять запись о закрытии.
