# Восстановление связи после запуска и обрыва

Запрос владельца от 2 октября 2026: правильный PIN при запуске моноблока
не должен выглядеть ошибкой пароля из-за неготового локального сервера;
меню и статусы должны восстанавливаться без ручного вмешательства разработчика.
Рабочие часы подтверждены: 10:00-00:00, Asia/Almaty.

## Установленные причины

- Мобильная загрузка каталога прекращала повторы после трёх ошибок.
- Ручное обновление модели не перезапускало получение доступности блюд.
- Начальный запрос оформления не восстанавливался после транспортного сбоя;
  наблюдение истории исключало уже оплаченные, но ещё готовящиеся заказы.
- Кассовый PIN смешивал ответы 503/сетевую ошибку с неправильным PIN.
- Windows fulfillment worker мог ждать 60 секунд между попытками, хотя
  heartbeat стоп-листа действителен 30 секунд. Локальная блокировка одного
  заказа могла создавать чередование свежего/устаревшего меню при живом WAN.

## Изменения и ограничения

Worker сохраняет бесконечные последовательные повторы с jitter, но пауза
ограничена 15,25 секунды. Durable inbox/outbox, ревизии стоп-листа, lease,
идемпотентность и fail-closed при действительно устаревших данных сохраняются.
Это не гарантия доставки при отключённом интернете или выключенной кассе.

PIN предваряется ограниченными GET-пробами локального /health/ready.
POST с PIN остаётся однократным, серверный rate-limit не обходится.
503/транспортная ошибка объясняют неготовность локального сервера; 401/403 -
неверный PIN или отсутствие прав. Проверка не зависит от доступности VPS.

Мобильное восстановление и серверный график интегрируются отдельными
коммитами. Часы ограничивают только новые операции, не теряют начатую оплату
и не препятствуют чтению истории/завершению ранее оплаченных заказов.
Новый платёж не создаётся автоматически из-за повторного подключения.

## Проверки и фактическая установка

- Read-only проверка VPS: API и gateway здоровы, публичный availability
  возвращает enabled=true/fresh=true. Связь кассы с cloud в момент проверки есть.
- Worker: два Node-теста прошли; общий TypeScript build прошёл.
- PIN/readiness: 18 адресных Node-тестов и ESLint прошли в агентской ветке.
- `infra/windows/verify-native-connection-recovery.ps1` только читает SCM,
  delayed start, recovery, зависимости, listener, локальный readiness и boot time;
  не читает ключи/identity/env. PowerShell parser/runtime пока не проверены на Mac.
- Прежняя проверка tunnel подтвердила восстановление за 17,2 секунды,
  delayed auto-start и неизменность других служб. Перезагрузка Windows
  в той проверке не выполнялась; это не доказательство холодного старта.

Новый код ещё не установлен на VPS/моноблок/iPhone. Текущий адрес моноблока
запрошен у владельца: прежний LAN-адрес не отвечает из сети Mac. Не менять
SCM/службы вслепую до получения фактической конфигурации и проверки занятости.
Полная CI обязательна до выпуска. Apple upload предыдущей сборки7 отдельно
ожидает восстановления Xcode account; текущая TestFlight остаётся сборкой6.
Реальные счета, OTP и финансовые операции в этом этапе не создавались.
