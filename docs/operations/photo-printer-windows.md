# Постоянная фотопечать через Windows-кассу

16 октября 2026 владелец подтвердил восстановленную печать с iPad через Mac,
затем выбрал перенос USB-принтера и службы на постоянно включённую кассу.
Mac остаётся временным рабочим вариантом до приёмки Windows. Подготовленный
[Mac LaunchAgent](photo-printer-macos-recovery.md) не устанавливался.

## Устройство и границы

iPad -> HTTPS по Wi-Fi ресторана -> отдельная служба `PickChickPhotoPrinter`
-> выделенный USB-фотопринтер. USB между iPad и компьютером не требуется.
Касса и принтер должны быть включены, iPad должен видеть локальную сеть.
Отключённое питание, кончившуюся бумагу и обрыв USB программно устранить нельзя.

Касса найдена по имени `WIN-C583E2V3LH9.local`. На момент проверки её адрес
`192.168.2.61`, прежний `192.168.3.33` не отвечает. SSH fingerprint совпал с
[проверенным ключом](cashier-finance-ssh-2026-10-12.md).
Все семь существующих служб PickChick работали; их настройки не изменялись.
Для переноса зарезервирован `@windows/cashier` задачей `photo-printer-recovery`.

Служба получает адрес только выбранного физического адаптера по MAC. При смене
DHCP адреса завершает текущий запрос и перезапускается через Windows SCM.
Сертификат должен содержать DNS-имя кассы; доступность этого имени с iPad
проверяется отдельно. Не привязывать iPad к временному IP без SAN сертификата.
Не открывать порт в интернете и не выключать проверку TLS.

## USB и восстановление

`tools/photo-printer/windows/UsbPrinter.cs` использует системный `usbprint.sys`:
перечисляет присутствующие USB printer interfaces, проверяет IEEE1284 ID с
ESC/POS и открывает только точный выбранный путь. Не устанавливает драйверы,
не меняет принтер по умолчанию, не использует очередь/spool-файлы.
Фото остаётся в памяти. Пакет передаётся один раз порциями 1024 байта с паузой
40 мс, как на проверенном Mac. Частичный/неясный результат остаётся `unknown`.
Никаких автоматических повторов после сбоя, перезапуска или возврата USB.

Основание выбора системного канала:
[Microsoft USB printer driver](https://learn.microsoft.com/en-us/windows-hardware/drivers/print/usb-printing),
[USBPRINT programming](https://learn.microsoft.com/en-us/windows-hardware/drivers/print/programming-considerations-for-usbprint).
Это описание Windows API, а не гарантия совместимости конкретного принтера:
совместимость подтверждается коротким тестом на бумаге после подключения.

HTTPS остаётся доступен при отключённом принтере. `/v1/status` проверяет его
наличие, а перед каждой отправкой устройство проверяется заново. После USB
переподключения существующий токен остаётся действителен. Во время печати
проверка статуса не открывает уже занятый эксклюзивный USB handle.

## Подготовка и установка

1. Сверить свежие refs, резервы, все исходные службы/PID. Для изменений брать
   штатный exclusive handle `EdgeTools/unified-menu-maintenance.lock`.
2. Собрать отдельный Windows x64 runtime из точного исходного коммита:
   `tools/photo-printer`, `design/photo-alex`, логотип `apps/kiosk/assets/v3/logo.webp`,
   Node24.16+ и зависимости sharp из frozen lockfile. WinSW брать с проверенного
   существующего установочного артефакта, сверив его hash.
3. `manifest.json`: `sourceCommit` и `files` - объект относительный путь -> SHA256
   каждого файла пакета кроме manifest. Пакет не содержит сертификатов, ключей,
   токенов, реальных фото и БД. Проверить отсутствие внешних ссылок/других файлов.
4. Дождаться полной зелёной CI точного коммита. `ci.json` содержит `headRevision`
   и полный `checks` из проверки GitHub, включая итоговый Foundation gate.
5. Подготовить защищённый `PrivateInput`: `config.json`, `certificate.pem`,
   `private-key.pem`, `jobs.sqlite`. Сертификат кассы подписан уже доверенным
   Photo Local CA; приватный ключ CA на кассу не переносить.
6. До копирования БД остановить старый мост после завершения печати. Сделать
   согласованную SQLite backup и сверить строки jobs/devices. Не копировать
   только открытый основной sqlite без WAL. Не запускать оба хоста с одним
   принтером/разошедшимися копиями состояния. Существующие unknown не повторять.
7. Начальная конфигурация: `transport: windows-usb`, `windowsUsbPath` из реальной
   discovery, `windowsInterfaceMac`, `port: 13440`, `width: 576`, `cut: false`,
   **`protocolConfirmed: false`**. Пути helper/TLS/БД установщик задаёт сам.
8. Запустить `windows/install.ps1` с Package, PrivateInput, SourceCommit,
   CiProof, ManifestSha256 сначала без `-Apply`. После успешной проверки - Apply.
   Установщик не заменяет существующую установку. Создаёт отдельные каталоги
   Program Files/ProgramData, ограниченные ACL, службу LocalService с AutoStart,
   восстановлением после падения и отдельное правило HTTPS только LocalSubnet
   для Private/Domain профилей. Проверить профиль действующего адаптера, не
   открывать всю публичную сеть ради обхода диагностики.
9. Проверить права LocalService на выбранный USB, HTTPS и сертификат с iPad.
   Отправить только маленькую проверку логотипа. После подтверждения нормальной
   бумаги включить печать в защищённом config и штатно перезапустить только
   PhotoPrinter. Перенастроить iPad на DNS-имя кассы с одноразовым кодом.
10. Проверить фото, выбранный язык подписи, возврат на заставку, USB disconnect /
    reconnect и восстановление службы без повторной печати. Остановить старый
    Mac bridge. Проверку автозапуска после полной перезагрузки кассы проводить
    в согласованное время, чтобы не прерывать действующие заказы.

## Откат

Остановить только `PickChickPhotoPrinter`, отключить её отдельное firewall rule
и сохранить каталог состояния/логи. Не удалять задания и не переотправлять
unknown. При возврате на Mac использовать согласованную свежую копию метаданных
и прежний сертификат Mac; нельзя возвращать старую БД поверх новых заданий.
