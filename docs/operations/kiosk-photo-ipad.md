# Фотокабина на iPad: подготовка установки 15 октября 2026

Поручение владельца: установить фотокабину в действующий PickChick Kiosk.
Сохраняется согласованный сценарий: «Сделать фото» внизу стартовой заставки,
фронтальная камера, отсчёт, предпросмотр, «Переснять»/«Распечатать», автоматический
возврат на заставку. Оформление заказа работает отдельно. Фотография с логотипом
на термобумаге - сувенир, она не создаёт фискальный чек или платёж.

## Что мешает установке с финансового Mac

Проверено на этом Mac 15 октября:

- `xcode-select -p` указывает на CommandLineTools; `devicectl` недоступен.
  Полный Xcode в стандартных приложениях и индексе Spotlight не найден.
- `security find-identity -v -p codesigning`: **0 valid identities**.
- USB-инвентарь не содержит iPad и термопринтер. Это состояние подключения
  на момент проверки, а не утверждение о выключенных устройствах.

До подключения iPad и появления Xcode/разрешённой подписи native archive и
установка здесь невозможны. Альтернатива - Mac, с которого уже устанавливали
киоск. Приватный ключ подписи и пароли в чат/Git не передавать. Ничего на iPad,
кассе, VPS, в Apple или настройках сети этим этапом пока не изменено.

## Печать из iPad

Нативное приложение отправляет фото по HTTPS отдельной локальной службе.
Она хранит фото временно в памяти и отправляет один raster выбранному принтеру.
Есть два реализованных транспорта:

| Подключение                          | Служба          | Конфигурация                                                               |
| ------------------------------------ | --------------- | -------------------------------------------------------------------------- |
| Принтер по Ethernet в локальной сети | Windows или Mac | `transport: "tcp"` (по умолчанию), проверенные `printerHost`/`printerPort` |
| Принтер по USB к MacBook             | MacBook         | `transport: "mac-usb"`, точный обнаруженный `usbUri`                       |

Для второго варианта добавлен выбор проверенного Mac USB-адаптера в существующую
HTTPS-службу. Сохраняются полосы по 24 строки, порции USB 1024 байта/40 мс,
новый светлый профиль фото и защита от повторной печати. USB проверяется перед
стартом включённой службы и перед каждой отправкой. Нет автоматического перехода
на другой принтер при ошибке или неизвестном результате.

Windows USB этим изменением **не реализован**; нельзя выбирать `mac-usb` на Windows.
Он отклоняется при запуске. Смешанные настройки USB/TCP и неизвестные транспорты
также отклоняются. Внешний клиент не передаёт URI, порт, команды или число копий.

## Подключение iPad через USB-принтер Mac

1. Уточнить рабочую схему у владельца. iPad и Mac должны видеть друг друга в
   одной локальной сети без изоляции клиентов. Mac с USB-принтером должен быть
   включён и не спать всё время печати. Для постоянного ресторана выбрать
   постоянно работающий узел; ноутбук подходит для первой проверки.
2. Взять актуальные shared/claims и зарезервировать `@release/ios` перед сборкой.
   Сверить существующие pairing/Keychain, версию и Bundle ID установленного киоска.
   Не удалять приложение и не менять его идентичность.
3. Подготовить приватную копию `tools/photo-printer/config.mac-usb.example.json`.
   Подставить подтверждённый USB URI, абсолютные пути, текущий LAN IPv4 Mac и
   выделенный порт. Пример намеренно слушает loopback и выключает печать.
   `bind` допускает только loopback или один частный IPv4, не `0.0.0.0`/WAN.
4. Получить сертификат, доверенный iPad, с SAN, соответствующим точному HTTPS
   origin службы. Использовать штатный домен/LAN DNS либо управляемый локальный
   CA с явным доверием на iPad. Не отключать проверку сертификата и не добавлять
   общий ATS bypass. Не открывать принтер/службу в интернет.
5. Остановить Mac-only preview и любые другие отправители на этот принтер.
   Для одного физического аппарата должен работать только один процесс печати:
   локальный browser preview и iPad HTTPS-службу одновременно не запускать.
   Использовать прежнюю SQLite метаданных этого аппарата, чтобы сохранить
   неизвестные/отправленные задания; не удалять её ради повторной печати.
6. Сначала запустить HTTPS-службу с `protocolConfirmed=false`:

   ```sh
   node tools/photo-printer/server.mjs /absolute/private/photo-ipad.json --pair
   ```

   Код сопряжения одноразовый, 5 минут. Приватные ключи, токены и полные URI
   не сохранять в протоколах. Firewall разрешает только нужную локальную сеть.

7. На Mac с Xcode собрать **PickChick Kiosk**, сохраняя `kz.pickchick.kiosk`,
   Team ID и Keychain identity. Получить следующий свободный build number,
   не назначать его по старой документации. Использовать frozen lockfiles,
   `EXPO_NO_DOTENV=1`, прежние подтверждённые настройки commerce и точный
   `EXPO_PUBLIC_KIOSK_PHOTO_URL=https://<confirmed-host>:13440`.
   `EXPO_PUBLIC_KIOSK_PHOTO_MAC_PREVIEW` в native-выпуске не устанавливать.
   Значение в угловых скобках - шаблон, не адрес для сборки.
8. Prebuild/CocoaPods, Release archive, проверка подписи и разрешённого устройства.
   Установить поверх текущей версии через `devicectl`, прочитать фактическую
   версию после установки и запустить. Для общего выпуска требуется зелёная CI
   точного исходника, результат не переносить автоматически с базового коммита.
9. В фотокабине удержать логотип 5 секунд, ввести разрешённый HTTPS origin и
   одноразовый код. Разрешить камеру/локальную сеть. Убедиться, что без включения
   службы доступна съёмка/предпросмотр, но печать не объявляется успешной.
10. Подтвердить, что это тот же проверенный принтер, включить `protocolConfirmed`
    только в приватной конфигурации и перезапустить единственную службу.
    Сделать один новый снимок, проверить бумагу и возврат на заставку.

## Приёмка

Подробный список: [kiosk-photo.md](kiosk-photo.md#выпуск-на-ipad-и-приёмка).
Обязательны фронтальная камера/ориентация, люди по краям кадра, разрешения,
пересъёмка, читаемость фото/логотипа и возврат на заставку. Затем проверить
двойное нажатие, обрыв сети, отсутствие бумаги и восстановление неизвестного
результата без автоматической второй копии. Не создавать настоящую оплату
ради проверки фотокабины; заказ проверить отдельным существующим demo-сценарием.

На Mac полный отпечаток с логотипом уже подтверждён владельцем. После жалобы
на тёмное фото включён более светлый профиль; его бумажная приёмка остаётся
открытой. [Протокол Mac](kiosk-photo-mac.md). Новый HTTPS→USB путь проверен
программно с подставным транспортом, **не принят на физическом iPad**.

Локально: 31 Node-проверка фото/печати прошла, включая проверку реального
HTTPS entry с тестовым CA, pairing/auth, USB/TCP selection, отказ от неверного
устройства, отсутствие USB-эффекта при выключенной печати. Реальные фотографии
для тестов не использовались. Общие status/roadmap пока заняты
`mobile-combo-rewards`; после передачи перенести туда итог установки, SHA
и физическую приёмку. До этого запись установки не создавать.
