# Восстановление фотопринтера через Mac

## Причина обращения 16 октября 2026

Принтер на iPad показывался отключённым. Ручной HTTPS-процесс предыдущего дня
больше не работал, а Mac получил другой адрес Wi-Fi. Конфигурация была привязана
к прежнему IPv4. В момент диагностики USB backend не обнаружил принтер, iPad
тоже не был доступен. Физическое подключение нужно проверить отдельно.

## Постоянная служба

`tools/photo-printer/macos/supervisor.py` работает под владельцем Mac:

- запуск после входа пользователя через LaunchAgent и восстановление после сбоя;
- ожидание сети и точного ESC/POS USB-принтера с прежним серийным номером;
- привязка только к текущему частному IPv4 указанного физического интерфейса;
- после смены адреса или отключения USB прежний процесс штатно останавливается;
  при возвращении оборудования запускается снова;
- kernel lock исключает двух управляющих одним состоянием; после аварии
  освобождается ОС, без удаления чужих блокировок;
- аварийный USB-процесс не остаётся параллельно новому серверу;
- прежняя БД и pairing сохраняются. Нет автоматического повторения заданий,
  в том числе `unknown`, создания pairing-кодов или изменения доверия CA;
- `caffeinate -s` удерживает Mac от сна на питании от сети. Экран может гаснуть;
  системные настройки `pmset` не меняются.

Адрес в iPad остаётся HTTPS-именем Mac `.local`, а не меняющимся IP. iPad и Mac
должны быть в одной доступной локальной сети без изоляции Wi-Fi клиентов.
Кабель iPad-Mac не заменяет этот сетевой маршрут. Принтер подключается USB к Mac.

## Установка оператором

1. Зарезервировать `@mac/photo-printer`; проверить чистый опубликованный SHA и
   полную зелёную CI. Проверить отсутствие другого писателя и активной печати.
2. Подготовить неизменяемый каталог в `~/Library/Application Support/PickChickPhoto/releases/<sha>`.
   Сохранить структуру `tools/photo-printer`, `design/photo-alex`,
   `apps/kiosk/assets/v3/logo.webp`. Для пакета использовать его отдельный lockfile:
   `pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts --prod`.
   Node 24.16+ разместить вне Documents с проверкой хеша исходного исполняемого файла.
3. В приватный `state` перенести SQLite через backup API только после остановки
   старого писателя; сравнить строки jobs/devices. Перенести существующий серверный
   сертификат и ключ, без нового CA. Каталоги 0700, конфигурация/БД/ключ 0600.
4. Подготовить `state/config.json`: абсолютные `node`, `server`, `release`,
   физический `interface` (например `en0`), прежний объект `service` с USB URI,
   TLS, портом и путём БД. Поле bind вычисляется заново при запуске.
5. Запустить `launch_agent.py SUPERVISOR CONFIG LOG_DIRECTORY`. Он готовит
   `~/Library/LaunchAgents/kz.pickchick.photo-printer.plist`; существующий отличный
   plist автоматически не перезаписывается. Проверить `plutil -lint`, затем
   `launchctl bootstrap gui/<uid> <plist>`.
6. Проверить статус LaunchAgent, приватный `status.json`, фактический bind и
   HTTPS с прежним CA и токеном. `service-started` не доказывает печать бумаги.
   Проверить восстановление процесса без отправки задания и сохранность БД.
   Физические переподключение/печать и перезагрузку проверять отдельно.

При откате: `launchctl bootout gui/<uid>/kz.pickchick.photo-printer`, дождаться
освобождения kernel lock и порта; сохранить новую БД. Возвращать совместимый
проверенный runtime с этой БД, без повтора неопределённых заданий.

## Границы постоянной доступности

LaunchAgent работает после входа этого пользователя. Выключенный Mac, закрытая
крышка с переходом в сон, отсутствие питания/USB/Wi-Fi делают печать недоступной.
Для работы независимо от личного MacBook нужен постоянно включённый узел на
точке (например кассовый компьютер) и подключённый к нему либо к LAN принтер.
Перенос на кассу - отдельная установка с проверкой реального подключения.

## Проверки и состояние выпуска

Локальные регрессии охватывают позднее подключение USB, смену IP, падение сервера,
частный bind, точный серийный номер, исключение второго писателя, сохранение
путей БД и отсутствие команд повторной печати. Генерация LaunchAgent проверяется
с пробелами в путях, без shell и повышения прав.
Установка и реальная приёмка ещё не подтверждены; результат будет записан после
точной CI и проверки оборудования. Общие status/roadmap заняты другой задачей.
