# Windows: сохранение смешанных переводов строк при включении стопов

9 октября read-only проверка кассы выявила действующий `edge.env` с пятью CRLF
и тремя LF. Это исходные байты установленной конфигурации, а не повреждение файла.
Прежний оператор переключения флагов запрещал такую комбинацию до изменения файла.
Edge и его worker работают из `23fb39e1`, schema019 проверена, protocol4 и menu apply
уже включены. Флаг `EDGE_REMOTE_STOPS_ENABLED` на момент проверки отсутствовал
(значение по умолчанию `false`). Это исходное состояние, не запись об установке.

`infra/windows/reviewed-env-bytes.ps1` предоставляет чистую функцию
`Update-ReviewedEnvBytes`: она принимает проверенные UTF-8 bytes, имя ключа,
ожидаемое старое и новое значения. Функция сохраняет каждый перевод строки,
комментарии и прочие значения. При отсутствующем разрешённом ключе добавляет
только новую строку с последним существующим разделителем. Нормализации файла нет.
Дубликаты, неверный UTF-8, BOM, NUL, одиночный CR, незавершённая последняя строка,
неоднозначные присваивания и несовпадение старого значения остаются ошибками.
Значения окружения не включаются в сообщения об ошибках.

Это не самостоятельный скрипт изменения сервера. Проверенный частный оператор
импортирует функцию по точному SHA-256 из зелёного коммита; он сохраняет прежние
проверки CI/runtime/Switch/Verify, NTFS/ACL, maintenance lease, ожидаемого хеша,
резервной копии, atomic replacement и состояния служб. Перед apply повторяются
read-only план и проверка фактической публикации меню на кассе. После неопределённого
исхода сначала читается состояние, автоматический повтор не допускается.

Порядок остаётся [штатным](unified-menu-publication.md): сначала локальный флаг,
потом облачный `remote-stops`, затем `media-upload`. Для текущей кассы локальное
включение требует остановки только Edge и зависимой KitchenLink с обратным запуском;
фактический список оператор вычисляет и проверяет до изменения. PostgreSQL, tunnel,
банковские обработчики и данные заказов не переключаются. Backup env восстанавливают
только при совпадении текущего хеша с результатом этой операции, под той же блокировкой
и с проверкой ACL/служб; чужие последующие изменения перезаписывать нельзя.

Регрессии выполняют настоящий PowerShell-код на синтетических данных: все сочетания
LF/CRLF, положение изменяемого ключа, добавление в исходный смешанный шаблон,
UTF-8/Unicode, неизменность входного массива и отказ на неоднозначных данных.
В Foundation CI проверка запускается через Python discovery и требует PowerShell.
Native PowerShell 5.1 и применение на кассе подтверждаются отдельными доказательствами
после проверки точного коммита. Товар на стоп эти проверки не ставят и банковских
операций не создают.
