# Табель и ведомость сотрудников

Задача `payroll-september`, 13 октября 2026. Владелец передал месячный файл
с листами «График» и «Табель» и попросил перенести рабочий процесс в кабинет.
Уточнение владельца: листы служат отдельными образцами ввода; не подгонять
ведомость под часы другого листа. Текущий статус всех импортируемых сотрудников -
«Уточнить». Исторические часы не определяют факт увольнения.

## Рабочий процесс

- «График»: месячная сетка сотрудников и дней; день/неделя сохраняют список
  интервалов и действия. План не создаёт явку или начисление.
- «Табель»: фактические интервалы либо количество оплачиваемых часов за день.
  Десятичные часы сохраняются в целых миллисекундах, без выдуманного времени
  прихода. Пустой день не равен выходному. Цвет черновика сопровождается текстом.
- «Сотрудники»: должность отдельно от роли и текущий статус
  «Работает», «Не работает», «Статус нужно уточнить». Это кадровая карточка,
  она не предоставляет доступ к кабинету или кассе.
- «Начисления»: месячная ведомость с автоматической базой по подтверждённому
  табелю либо явно введённой исторической базой. Отдельные доплаты, авансы и
  удержания, статус проверки и исходные ячейки для сверки.
- «Сформировать по табелю» создаёт недостающие черновики по рассчитанным
  сотрудникам. Повтор не затирает ручные ведомости. KPI учитываются отдельно.
- Изменение и удаление требуют причины и актуальной ревизии. Удаление скрывает
  запись из рабочих списков, сохраняя аудит. Закрытый период защищён; для
  исправления требуется явное переоткрытие с причиной.

Ведомость не отправляет деньги и не подтверждает банковскую выплату. Налоговый
расчёт и автоматическое применение штрафов не добавлены. Часы без времени
прихода не классифицируются как ночные. BioCheck не имитируется.

## Импорт предоставленного файла

Файл и подготовленный JSON находятся вне Git. В репозиторий не включаются
имена сотрудников, индивидуальные ставки, начисления и удержания.

- SHA-256 источника:
  `c472abc9166effd8ed998a56d538e4e1bfe36d11276f757d1c8c791197620a55`.
- Источник содержит 68 уникальных имён, 631 дневную запись и 67 строк ведомости.
- Лист с заголовком «Факт часов» переносится в фактический табель; отдельные
  плановые интервалы из него не создаются.
- `scripts/payroll-workbook.py` читает формулы и сохранённые результаты через
  openpyxl. Оригинал не изменяется. Суммы и ячейки ведомости сохраняются отдельно
  от автоматического расчёта. Сотрудник, присутствующий только на одном листе,
  не получает выдуманную строку на другом.
- Исторические ставки ограничены последним днём исходного месяца. Для будущих
  месяцев управляющий задаёт действующую ставку с датой начала.
- `scripts/payroll-import.mjs` сначала строит план по текущим данным API.
  Применение требует точного хеша плана. Имена сопоставляются только однозначно;
  конфликт с существующей явкой/ставкой/ведомостью останавливает импорт.
- Каждая команда имеет стабильный идентификатор и серверную квитанцию.
  Импорт поэтапный: при обрыве повтор продолжает неподтверждённые записи,
  не удаляя уже сохранённые. Исправленная после импорта запись не затирается.
- Исходные суммы и формулы остаются неизменяемыми; бухгалтер исправляет рабочие
  поля, сохраняя историю и возможность сравнить с источником.

## Хранение и выпуск

Миграция `057_cloud_workforce_payroll.sql` добавляет вид `payroll` в существующий
журнал. Ранее применённые миграции не переписаны. Новых прав runtime не требуется.
Прежний API не умеет читать новые виды записей и длительности; откат после
начала ввода требует совместимого reader, удалять данные ради отката нельзя.

Локально пройдены 25 проверок расчётов, PostgreSQL, HTTP и модели; браузерные
сценарии графика, исправлений, истории, CSV и повторного формирования ведомости.
Проверены экраны на ширинах 1440 и 393 px, независимый UI-review: ship.
Сборка, типизация, адресные lint/format проверки пройдены. Установка на VPS и импорт
реальных данных ещё не выполнены. Серверный релиз должен учитывать точный
установленный API, последовательность миграций и независимый выпуск портала;
обновление всего VPS до общего HEAD не допускается.
