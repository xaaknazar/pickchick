## Восстановление общей сессии Kaspi

По поручению владельца выполнен повторный вход действующего кассира. До него
read-only проверка сессии и истории возвращала банковский отказ `-101001`;
мобильный обработчик откладывал существующий запрос счёта. Причина отказа
предыдущей сессии не установлена.

Две диагностические попытки с задержкой ввода SMS около семи минут получили
`OtpCodeIsWrong`. Последующий свежий код банк принял: подтверждён переход
`MobileDeviceRegistration / KPMobileCall / kpDeviceRegistration`.
На завершении обнаружена несовместимость моста с его read-only контейнером:
upstream `generateECDH()` пишет `/app/ecdh-keypair.json`, а этот путь недоступен
для записи. Это отдельный дефект после проверки SMS.

Для разрешённого восстановления использован изолированный оператор внутри
того же контейнера: временная P-256 пара хранится только в памяти процесса.
Двустороннее согласование 32-байтного секрета проверено локально до обращения
к банку. Подписи, постоянные ключи устройства и проверки завершения входа
сохранены. Исходники работающего моста и его образ этим оператором не изменены;
постоянный overlay для последующих входов ещё предстоит опубликовать и выпустить.

В **2026-10-09T08:51:27Z** новая сессия установлена после подтверждения банком
`active=true` и роли кассира. Проверены приватная резервная копия и неизменность
исходных файлов, сохранён inode bind-mounted session.env. Перезапущены только
