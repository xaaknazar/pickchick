# PICK FARM - план push «урожай созрел» (не реализовано)

Владелец 6 октября попросил push о созревании. В этой задаче сделан только план:
нужен нативный модуль и новая iOS-сборка, а `apps/mobile/ios` и `@apple/testflight`
сейчас зарезервированы активной задачей `tiptoppay-native13`. Общий push приложения -
задача roadmap `crm-push` (согласия, лимиты, opt-out); ферма должна идти через неё,
а не отдельным каналом.

## Этап 1 - локальные уведомления (без сервера)

- `expo-notifications` (нативный модуль, нужна новая сборка и согласование с владельцем
  `apps/mobile/ios`).
- Разрешение спрашивается в ферме после первой посадки, с объяснением; отказ ничего не
  ломает. Переключатель «Напоминания фермы» в «Как играть».
- После каждого подтверждённого сервером состояния клиент пересчитывает одно ближайшее
  событие: созревание грядок (`msUntilReady`), готовность животных (`animalStatus`),
  новый подарок дня. Отменяет прежние и ставит не более 2 уведомлений: «Урожай созрел»,
  «Яйца и молоко готовы». Тихие часы 22:00-09:00 по времени устройства.
- Только по подтверждённому состоянию: предсказание клиента не планирует уведомления.
- Нажатие открывает `/games/pick-farm`.
- Тесты: чистая функция расписания (что и когда) в `tests/mobile`, нативная проверка на
  iPhone (разрешение, фон, нажатие, переустановка).

## Этап 2 - серверные push (после `crm-push`)

- Токены APNs/FCM, согласие на маркетинговые/игровые уведомления отдельно от заказов.
- Планировщик на сервере по сохранению фермы (время созревания уже в state), частотный
  лимит, дедупликация, исключение opt-out, отправка не чаще раза в N часов.
- Наблюдаемость: отправлено/доставлено/открыто, без персональных данных в логах.

## Риски

- Push не должен будить ради мелочей: максимум 1-2 в день от фермы.
- iOS требует предупреждение о назначении уведомлений в описании проверки TestFlight.
- Без согласия на маркетинг игровые push считаются маркетинговыми - решение юриста.
