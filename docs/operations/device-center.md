# Центр устройств PickChick

## Назначение и факты

Раздел объединяет кассовый edge, зарегистрированные кухонные экраны/табло,
существующий iPad-киоск и карточки телевизоров с USB. Филиал берётся из прав
управляющего; аналитик читает, управляющий изменяет. Новая карточка телевизора
не выдаёт доступ к API или локальной сети. Доступы кассиров и PIN не меняются.

Реализованы поиск, фильтр проблем/архива, название, место установки, примечание,
причина изменения и история до/после с автором. Редактор встроен в страницу;
обновление не стирает ввод. Архивирование доступно только телевизорам USB.
Для рабочего экрана используется отдельный отзыв доступа с подтверждением.

Повторная отправка неизвестного результата сохраняет request_id. Сервер проверяет
revision и сохраняет историю в append-only журнале. Чужую карточку нельзя
переместить в другую точку. История не содержит ключи или пароли.

## Что означает связь

- Касса: последнее сообщение локального сервера о состоянии точки.
- Кухня/табло: успешная проверка терминальной сессии, переданная edge с поколением
  ключа. Старое поколение и отозванный доступ не освежают состояние.
- Киоск: отдельный подписанный запрос приложения раз в 15 секунд, только в активном
  состоянии. Платёжные запросы не используются для определения присутствия.
- USB-телевизор: только учёт оборудования. Состояние питания и изображение неизвестны.

Свежесть - 90 секунд, с проверкой серверного времени. Ошибка приложения, demo,
неподтверждённая привязка, устаревший ответ и потеря связи с родительской кассой
показываются отдельно. «На связи» не доказывает, что физический дисплей исправен.
Кнопка проверки обновляет данные сервера; она не включает выключенное устройство.

## Подключение и восстановление

Существующая процедура из [device-access.md](device-access.md) использует
одноразовый код на 10 минут, индивидуальный ключ и подтверждение кассы. Новый
код можно выпустить и для ранее отозванного экрана. После отзыва старый ключ
не возобновляет доступ. Для кухни остаётся отдельный вход сотрудника.
Восстановление пароля кухни не сбрасывает PIN кассира.

Текущий iPad сохраняет свою регистрацию и ключ. Перерегистрация и управление
платёжным терминалом не входят в этот выпуск. Для появления heartbeat нужна
новая нативная сборка с `apps/kiosk/src/device-presence.ts`; прежняя установленная
версия не объявляется онлайн по одному наличию регистрации.

## Порядок выпуска

На начало подготовки: API `ad7132fa5f4ae93bfa0693c8dd5e790c885d0201`, cloud057.
Схема051 уже присутствует, но новая процедура pairing выключена. Windows требует
свежей проверки фактической версии; последнее подтверждение - schema019.

1. Свежие refs/резервы, точная зелёная Foundation CI. API-кандидат от установленного
   ad7132, только изменения устройств; не устанавливать весь shared с ещё не
   выпущенными изменениями commerce/cloud-kitchen.
2. `infra/staging/release-device-center.py`: inspect, prepare, apply, verify с
   точными SHA/image/compose/gateway pins, общей блокировкой, шифрованной резервной
   копией и изолированным восстановлением. Применяет только cloud058 и ограниченные
   права карточек/телеметрии. `DEVICE_CENTER_ENABLED=true`; pairing остаётся выключен.
3. Отдельный `infra/backoffice-login/prepare.py` + `update.py` обновляет canonical
   кабинет, сохраняя учётные записи и остальные контейнеры.
4. `infra/public-staging/device-center-gateway.py` добавляет только POST
   `/v1/kiosk-checkout/device-presence`. Копирует и проверяет прежние публичные
   файлы; сохраняет остальные маршруты. Меняется только PickChick gateway.
5. Отдельная защищённая процедура Windows020/021, worker и kitchen portal,
   затем доказательство готовности и включение pairing. Старые операторы с
   жёсткой базой cloud050 нельзя запускать против cloud057/058.
6. Согласованная нативная сборка киоска и физическая приёмка экранов.

Rollback API допускается только на совместимый ad7132, понимающий импортированный
табель. Новые таблицы остаются; журналы и данные не удаляются. При неизвестном
результате миграции/переключения сохраняются доказательства и блокировка, повтор
не выполняется автоматически. Чужие сервисы idrink не затрагиваются.

## Проверки разработки

- 37 PostgreSQL/HTTP/client/edge проверок: роли, scope, CAS, идемпотентность,
  неизменность старых данных/ACL, отзыв, поколения, флаг выключения, proxy routes.
- 24 браузерных сценария на 1440/768/393 px; редактор сохраняет ввод при обновлении;
  диалоги имеют доступное имя, действия не выходят за ширину экрана.
- Адресный UI review: исправления inline editor, имени диалогов, ошибочной привязки
  и пустого блока ошибки приняты. Документер подтвердил сохранение текущего стиля.
  Impeccable launcher/detector недоступны (permission denied); проверка по исходникам
  и снимкам выполнена, автоматический detector не выдаётся за успешный.

Полная CI, установка и приёмка фиксируются отдельными фактами после выполнения.
