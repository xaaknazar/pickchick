## Отказ подготовки compose и локальное исправление

На защищённой локальной копии точного установленного compose вызван
`composeCandidate` из `infra/staging/cutover-cloud-owner.mjs`:

```json
{
  "status": "STOP",
  "check": "installed-compose-candidate",
  "reason": "Compose database anchors differ"
}
```

Helper ожидает YAML-якоря API и provision. Реальный JSON без provision уже
отмечен в [протоколе 06.11](server-window-1105/result-evening-2026-11-06.md).
Полный `provision.mjs` и добавление сервиса provision не использовались.

Подготовлен отдельный `infra/staging/cloud1-preflight.py`, не затрагивающий
helper, где Claude готовит шаг 076. Он:

- проверяет точный baseline SHA-256, набор сервисов и образ 6630eb0f;
- готовит только новый JSON-файл, меняя образ API и 14 новых флагов на `false`;
- сохраняет прежние env (включая работающий backoffice), соседние сервисы,
  сети, тома, порты и прочие значения;
- отказывается перезаписывать выходной файл или следовать выходному symlink;
- записывает результат с правами 0600, не печатает настройки/секреты;
- отдельно проверяет свежую голову GitHub, merge PR343 и все 11 jobs точного
  полного Foundation run; сохраняет запрет на skipped/cancelled и чужой SHA.

Это **подготовщик конфигурации и проверка кандидата, не полный оператор выпуска**.
Он не берёт серверную блокировку, не проверяет часы ресторана, не запускает
миграции, восстановление или переключение API. `PREPARED_ONLY` не означает
допуск к установке. После включения исправления нужен новый exact-SHA CI gate.

Локально для проверки преобразования использован SHA открытого PR343, только
как значение образа в выходном файле. Получен compose hash
`2786c800e847b94793ad580991ca3e80a3e84f90947e4ad78b49b043259f9b25`.
Файл остался на Mac и **не является release artifact**. Для принятой головы
cutover его необходимо построить заново.

Проверки: `python3 -m unittest discover -s tests/operations -p test_cloud1_preflight.py`

- **13 тестов PASS**, включая неверный baseline, сохранение соседей, частичный CI,
  смену головы, неправильный SHA, дубли ключей, права выходного файла и отказ перезаписи.

## Копия вне VPS и отказ восстановления

Скопированы на этот Mac три зашифрованных файла ночной копии:

- `cloud-20261110T021952Z.dump.age` (1 889 804 байта);
- соответствующий `.sha256`;
- `cloud-20261110T021952Z.manifest.json.age`.

SHA-256 дампа на Mac совпал с серверным файлом:
`6058818508193bbb13c859488eecdc479f660247a95f9aa80c9c0439b935b8a0`.
Это ручная независимая копия; автоматическое offsite-хранилище не настроено.
Файлы защищены локальными правами, в Git не добавлены.

Установленный `restore-drill.py` совпал с исходником, SHA-256
`08314b67059081cfaaec016a120769ea2d681315e6382ffcc82026bba13c393c`.
Запущен штатный `dump --require-manifest --identity -` с образом
`postgres:18.3-alpine@sha256:54451ecb8ab38c24c3ec123f2fd501303a3a1856a5c66e98cecf2460d5e1e9d7`.
Ключ передавался через stdin, на VPS не сохранялся. Ответ:

```json
{
  "event": "restore_drill",
  "ok": false,
  "error": "cannot decrypt cloud-20261110T021952Z.manifest.json.age"

```

Отдельное сравнение публичного получателя, вычисленного из локального ключа,
с настроенным backup-recipient: `localIdentityMatchesBackupRecipient=false`.
Приватные ключи и адреса подключений не выводились. Владелец подтвердил, что
нужный ключ хранится на другом Mac. Запрошен безопасный перенос файла, не текста
ключа в чат. Прежний локальный ключ не заменялся.

После отказа проверено: контейнеров с меткой `pickchick.restore-drill=1` нет,
current и compose hash прежние, `/health/ready` HTTP200. Репетиция 072-075
**не запускалась**, ответы миграционных шагов отсутствуют. Новый образ не собирался.
