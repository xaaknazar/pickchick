## Передача

Локальный комплект передаётся одним ZIP. На Windows распаковать его содержимое в
`C:\PickChickSetup\point-window-1114\`, не создавая лишнего вложенного уровня.
Далее распаковать operators-023.zip и operators-release-39f8ec85.zip рядом.
Получатся каталоги operators-023 и operators-release. Архив кандидата PENDING исключён
из окончательного комплекта. Старый prepared.zip не использовать вместе с новым.
Не распаковывать рантаймы в Program Files вручную: установку выполняют штатные операторы.
Распаковка RC-edge в отдельную папку для инструментов 026-028 описана в [COMMANDS.md](point-packages-1114/COMMANDS.md).

Фактическая доставка на Windows не выполнена. Проверка порта кассы остановлена
автоматической проверкой разрешений из-за запрета диагностики точки в этом окне.
SSH-доступ не объявляется отсутствующим или проверенным. Владелец передаёт ZIP Claude
через свой канал; новых разрешений для подготовки локальных файлов не требуется.

## Копия и восстановление без Mac

Да, `backup-native-service.mjs` умеет на том же PostgreSQL 18 создать временную БД
`pickchick_restore_<случайный UUID>`, восстановить custom dump и сверить счётчики,
отпечатки всех таблиц, branch и точный журнал миграций. В конце удаляет только эту БД
после проверки имени, OID, владельца и маркера. Рабочую pickchick_edge не восстанавливает
и не заменяет. Используется защищённая существующая bootstrap-учётная запись из toolsRoot.

Нужны свободное место, права администратора Windows, доступ к локальному кластеру и
pg_dump/pg_restore той же установки PostgreSQL. Команды схем 020,023,024 и шаблон следующих
ступеней приведены отдельно. Результат: backup-manifest.json и pickchick_edge.dump рядом.
При ошибке не писать completed/restoreVerified вручную и не удалять временную БД вслепую.

Этот инструмент оставляет незашифрованный дамп в защищённой папке для проверки оператора.
Он не заменяет обязательную зашифрованную копию штатной задачей EdgeBackup. Для неё нужна
установка нового инструмента копий с -AllowSameDisk на отдельный раздел, и проверка
успешного состояния задачи. Перед 028 задача должна подтвердить schema028 не старше 2 часов.
Копии перед 023/024/025 по проверке Assert-UnifiedBackup должны быть не старше 6 часов.
Снимок 05.11 для окна 14.11 не подходит.

каждой ступени и её копии, живой ключ и связь, достаточное место, питание и возможность
