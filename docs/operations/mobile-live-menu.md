# Опубликованное меню в мобильном приложении

## Состояние 9 октября 2026

Реализация от общего среза `cf25cb9e` готовится к выпуску. Установка нового API,
включение `CUSTOMER_CHECKOUT_HEAD_GUARD` и выпуск мобильного приложения ещё не выполнены.
Windows-касса требует сети точки; владелец подключит Mac позже. Работающий Kaspi QR
на iPad и банковские обработчики этим этапом не меняются.

## Поведение

- После публикации цены и состав обновляются в открытом приложении. PostgreSQL
  NOTIFY будит ограниченные long-poll запросы; резервное чтение - раз в 2 секунды.
  Новый каталог не ждёт загрузки фото. Неопубликованный черновик не используется.
- Открытая карточка сохраняет количество, выбранные доступные добавки и прокрутку.
  Недоступные позиции остаются в корзине с явной причиной, до удаления пользователем.
  Исчезнувшие обязательные добавки требуют нового выбора, без автоматической замены.
- При изменении цены видны прежняя и новая суммы и сообщение
  «Цены обновились. Проверьте итоговую сумму перед оплатой».
  Повторное нажатие оплаты подтверждает актуальную сумму; обновление меню само
  не создаёт заказ или счёт.
- Приложение сразу обновляет данные при возвращении на экран или восстановлении сети.
  Формат локальной корзины v2 сохраняет непринятые изменения и недоступные позиции;
  чтение прежнего формата v1 сохранено.

## Финансовая граница

`CUSTOMER_CHECKOUT_HEAD_GUARD=true` включает проверку опубликованного каталога
перед первой банковской попыткой мобильного заказа. Блокировка строки head
сохраняется до записи попытки; конкурирующая публикация сериализуется с ней.
Устаревший заказ без попыток получает durable cancellation и команду освобождения
резерва; только после commit возвращается MENU_CHANGED. Сумма заказа не переписывается.
Уже начатая попытка или capture остаются неизменными. Повторный запрос идемпотентен.
Путь киоска не изменён.

Новые коды ошибок отдаёт только профиль `pickchick.checkout-errors-v1` в Accept;
старые клиенты продолжают получать прежние CONFLICT/SERVICE_UNAVAILABLE.
Новая миграция БД для этой функции не нужна. Флаг по умолчанию выключен.

## Проверено локально

- API build, мобильный TypeScript, адресный ESLint/Prettier.
- 306 Node и 43 Python мобильных проверок.
- PostgreSQL 18: конкурентная публикация/первая попытка, durable отмена устаревшего
  заказа, неизменная сумма существующей попытки, LISTEN после commit и отсутствие
  уведомления после rollback; отдельный ограниченный пул 256 ожиданий публикации.
- Реальный web-клиент + изолированная PostgreSQL fixture: публикация видна в корзине
  не позже 3 секунд; количество/выборы сохраняются; удалённое блюдо сохраняется
  после перезапуска до явного удаления. Создано 0 заказов и 0 банковских попыток.
- Storybook для CatalogChangeNotice, CartLinePrice и ProductMenuNotice.

## Выпуск и откат

До установки: полная зелёная CI точного SHA, свежий project:check, резерв @vps,
штатная release-блокировка, проверенный backup/restore. Использовать отдельный
API-only guarded-профиль текущего cf25/schema050; прежний release-unified-menu.py
прибит к другому baseline и не должен запускаться вслепую.

Проверить runtime ACL для штатной unpaid cancellation и команды edge release.
Установить API с флагом выключенным, проверить readiness и доступность чтения меню,
затем включить один CUSTOMER_CHECKOUT_HEAD_GUARD и повторить read-only checks.
Банковский bridge, QR worker, mobile worker, опубликованные цены и текущие платежи
сохранить. Мобильное приложение требует новой native сборки: добавлен NetInfo.
Web-проверка не доказывает установку на iPhone/TestFlight.

Откат: выключить только новый флаг, восстановить прежний API image/compose через
проверенный профиль. Не удалять созданные durable cancellations и не переписывать
платежи. Возврат мобильной сборки не должен очищать локальные заказы или ключи.
