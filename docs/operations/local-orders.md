# Локальный POS: права, расчёт и неоплаченный заказ

Ниже — тестовый backend. Он не принимает реальные деньги, не пробивает чек и
не отправляет заказ готовиться. Нужны [локальный запуск](local-development.md)
и миграция `004_edge_local_orders.sql`.

## Подготовка

```sh
pnpm build
pnpm db:migrate
pnpm staff:setup examples/local-manager.json
pnpm staff:setup examples/local-cashier.json
pnpm start:edge
```

Сессии сохраняются в `.local/staff-UUID.json`, имеют срок 8 часов и связаны с
точкой/терминалом. Команды — trusted local setup с прямым доступом к edge-БД;
публичный вход кассира и центральная раздача прав будут отдельным этапом.
Для новой сессии того же сотрудника добавить `--renew`; прежняя сессия этой
пары сотрудник/терминал перестанет работать. Отзыв:

```sh
pnpm staff:revoke STAFF_UUID
```

Ключ не нужно читать и копировать вручную. Утилита `local:request` берёт его
из приватного файла, обращается только к localhost и не передаёт его в argv.

## Открытие приёма начальником смены

В другом терминале прочитать текущую версию настройки:

```sh
pnpm local:request 20000000-0000-4000-8000-000000000002 GET /edge/v1/ordering
```

На первом запуске `ordering_enabled=false`, `version=1`.
`examples/ordering-open.json` содержит `expected_version: 1`:

```sh
pnpm local:request 20000000-0000-4000-8000-000000000002 POST /edge/v1/ordering/open examples/ordering-open.json
```

Если версия уже другая, сохранить актуальную в собственном JSON в `.local/`.
Открытие здесь разрешает только тестовые неоплаченные заказы. Оно не открывает
кассовую смену ККМ, не включает мобильные продажи и не подтверждает часы работы.
Повторный запуск с новым Idempotency-Key и старой версией даст конфликт.

## Расчёт корзины кассиром

Сначала убедиться, что на edge активно меню примера v2 по
[инструкции синхронизации](menu-sync.md). Если меню другое, взять его
`release_id` и `variant_id`, сохранить свою корзину в `.local/cart.json`.
Пример v2 содержит порцию 3590 ₸; две порции дают 7180 ₸.

```sh
pnpm local:request 20000000-0000-4000-8000-000000000001 POST /edge/v1/checkout/quotes examples/local-cart.json
```

Ответ содержит `quote_id`, `expires_at`, строки и `total_minor: "718000"` для
этого примера. Суммы — минимальные единицы KZT. Расчёт действует пять минут.
Сохранить JSON `{"quote_id":"UUID_ИЗ_ОТВЕТА"}` в `.local/order-request.json`.
Указать только quote UUID, без цены, роли, телефона и branch ID.

## Создание и восстановление

```sh
pnpm local:request 20000000-0000-4000-8000-000000000001 POST /edge/v1/orders .local/order-request.json
```

Утилита выводит `idempotency_key`; сохранить его вместе с `order_id`.
При повторе после обрыва связи передать тот же ключ последним аргументом:

```sh
pnpm local:request 20000000-0000-4000-8000-000000000001 POST /edge/v1/orders .local/order-request.json UUID_ПРЕЖНЕГО_КЛЮЧА
pnpm local:request 20000000-0000-4000-8000-000000000001 GET /edge/v1/orders/ORDER_UUID
```

Ожидается `awaiting_payment / not_started / blocked` и
`next_action=payment_not_available`. POST возвращает 201 и тот же исходный
результат при повторе. GET возвращает текущее состояние. Остановить/запустить
edge — заказ остаётся в локальной PostgreSQL. Центральный API и Redis этому
пути не нужны. Это process restart, не испытание потери всего диска.

## Отмена и доступность

Для отмены сохранить `{"expected_version":1,"reason":"Тестовая отмена"}`
в `.local/cancel-request.json`, затем вызвать POST
`/edge/v1/orders/ORDER_UUID/cancel`. Кассир отменяет свой заказ на своём
терминале, начальник смены — любой локальный неоплаченный заказ точки.
Причина обязательна. Повтор требует прежнего ключа; неверная версия конфликтует.

Начальник смены закрывает приём POST `/edge/v1/ordering/close` с актуальной
`expected_version`. Существующие заказы сохраняются.
Ручной стоп: сначала GET `/edge/v1/availability/stops/VARIANT_UUID`, затем
POST `/edge/v1/availability/stops` с JSON
`{"variant_id":"VARIANT_UUID","stopped":true,"expected_version":0,"reason":"Тестовый стоп"}`.
Для ранее не настроенной позиции version=0; ответ изменения вернёт version=1.
Снять стоп — `stopped:false` и текущая версия. Кассир может прочитать состояние,
но изменять его не может. Новая публикация меню не удаляет ручной стоп.

## Ошибки и ограничения

| Код                | Действие                                                                               |
| ------------------ | -------------------------------------------------------------------------------------- |
| UNAUTHORIZED       | Проверить срок/отзыв сессии, сотрудника и терминала; получить разрешённую новую сессию |
| FORBIDDEN          | Операция недоступна роли; не менять role в body                                        |
| QUOTE_EXPIRED      | Повторно рассчитать корзину                                                            |
| MENU_CHANGED       | Получить новое меню и новый quote                                                      |
| ITEM_STOPPED       | Убрать недоступную позицию и пересчитать                                               |
| BRANCH_UNAVAILABLE | Проверить режим приёма и активное меню                                                 |
| CONFLICT           | Проверить expected version и неизменность запроса для Idempotency-Key                  |

Модификаторы, комбо, скидки, бонусы, часы работы, остатки/резервы, смены,
аппаратная касса, оплаты и кухня пока отсутствуют. События `order.created`
и `order.cancelled` сохраняются в outbox, но ещё не доставляются в центр.
Нельзя включать этот backend для реального ресторана или открывать его в WAN.

Проверки: `pnpm check`, `pnpm test:integration`. Сценарии нового этапа используют
свои временные схемы; основные синтетические данные локального стенда сохраняются.
