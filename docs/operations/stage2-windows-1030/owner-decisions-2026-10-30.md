# Уточнение владельца 30.10.2026: две ступени кассы

Источник: прямой ответ владельца в задаче подготовки окон. Это уточнение заменяет
прежний план в части выбора пакета 023 и восстановления базы при откате кассы.
Даты не назначены; разрешений на установку, миграции и включение флагов ещё нет.

1. Сохранить PR270, source `0fb95c9f09031d93e38e3af2a0c4a1bcc81f591c`.
   Новый переход 020->023 не разрабатывать. Использовать сохранённый проверенный
   архив; пересборка разрешена только при его отсутствии и строго из этого SHA.
2. До ночного окна на изолированном стенде, на восстановленной копии реальной
   базы 020, проверить цепочку: 020 -> PR270/023 -> копия 023 -> новый пакет 024
   -> готовность. Выполнить полный профиль ci. Отдельно подтвердить совместимость
   кассы 023 с новым API этапа 2 при выключенных флагах: это запасная версия.
3. Ночью каждую ступеньку начинать только после отдельного "да":
   - Не прошла проверка после 023: восстановить проверенную копию 020.
   - Не прошла проверка после 024: восстановить проверенную копию 023 и остаться
     на проверенном runtime 023.
4. Автопродление ключа установить в ту же ночь после успешной 024. Если окно
   не состоится до 10.11, продлить вручную по процедуре 21.10; крайний срок 13.11.
5. Серверное окно готовить независимо и проводить первым. Предложить по две даты.

## Условия воспроизводимого отката

До первой копии закрыть приём новых заказов на согласованное время и дождаться
завершения текущих операций. Любое изменение рабочего приёма - отдельный шаг с "да".
Сохранить все актуальные копии и остановить писателей перед восстановлением.
Проверки ступенек не должны создавать настоящие заказы или оплаты.
Если после копии появились новые операции, слепое восстановление запрещено:
сначала сохранить текущую базу, сверить изменения и согласовать их перенос, чтобы
откат не потерял принятые заказы. Штатные guards операторов не отключать.

Репетиция должна проверить оба восстановления вместе с возвратом соответствующих
служб/привязок, readiness, очередями, heartbeat и неизменностью данных.
Успех обычного ci на синтетической базе не является этим доказательством:
его Stand.create создаёт отдельную пустую схему и не использует восстановленный public.
Issue279 остаётся открытым: после восстановления возможен конфликт версий очереди.
До подтверждения указанных проверок ночное окно не готово.
