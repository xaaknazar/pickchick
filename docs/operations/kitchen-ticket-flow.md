# Кухня: подтверждение целого чека

23 сентября2026 владелец отклонил подтверждение каждой позиции и соуса:
для кухни нужен один шаг на чек, затем один шаг для сборщика. В текущем
этапе согласования это реализовано в `/kitchen-demo/`. Рабочий edge/API,
моноблок и защищённая кухня не обновлялись этим выпуском.

## Поведение демо

- Кухня видит блюда своей станции, комментарии клиента/заказа и одну кнопку
  «Готово - на сборку». Напитки/соусы показаны отдельно как добавляемые на сборке.
- Подтверждение сразу завершает позиции этой станции и убирает чек с кухни.
  Сборка получает чек только после готовности всех кухонных компонентов.
- Сборщик видит весь состав, отметки «Готово» и «Добавить при сборке».
  Одна кнопка «Собран - на выдачу» завершает сборку и показывает номер на табло.
  Фактическая выдача - отдельное действие «Заказ выдан».
- В шапке крупный номер чека, способ получения «С собой / В зале / Доставка»,
  отдельный источник «Касса / Приложение / Киоск / Яндекс Еда», время ожидания
  и время поступления. Строки нумеруются, количество видно отдельно.
- Общие комментарии выделены над составом на обоих экранах. Модификаторы
  остаются рядом с блюдом. Доставка/Яндекс здесь только вымышленные примеры,
  подключение Яндекса этим этапом не подтверждается.
- Повтор устаревшего нажатия и преждевременная сборка отклоняются. Состояние
  изолировано в памяти вкладки, после reload начинается заново.

## Обоснование интерфейса

Публичные первоисточники профессиональных KDS, изучены23 сентября2026:

1. [Toast: Item and Order Fulfillment](https://support.toasttab.com/en/article/Item-and-Order-Fulfillment-on-KDS)
   описывает выполнение всего заказа и отдельный опциональный режим по позициям.
   Для PickChick выбрано выполнение чека одной явной кнопкой, без скрытого double-tap.
2. [Toast KDS](https://pos.toasttab.com/hardware/kitchen-display-system)
   выделяет варианты обслуживания, инструкции и передачу между станциями.
   В макете источник отделён от способа получения, примечания не спрятаны в строках.
3. [Oracle Simphony: production workflow](https://docs.oracle.com/en/industries/food-beverage/simphony/19.7/kdscu/c_kds_production_lane_workflow.htm)
   описывает поступление в Expo после подтверждения станций приготовления.
   Поэтому сборка не может обойти готовность кухни.

Это перенос документированных принципов KDS, а не утверждение о точном
закрытом интерфейсе McDonald's, KFC или другой конкретной сети.

## Проверки и следующий этап

38 тестов кухни прошли: целый чек до выдачи, сохранность комментариев,
защита от повторного/чужого/преждевременного действия, HTML escaping,
изоляция и ограничение демо. TypeScript и lint прошли. Браузером заказ101
прошёл одним нажатием кухни и одним нажатием сборки до табло. Просмотрены
кухня и сборка1366×768; проверены1024×600 и390×844, без горизонтального
переполнения и сенсорных кнопок меньше44px. Обновление опубликовано на VPS,
публичная страница проверена в браузере без ошибок. Сохранены147 прежних
файлов вне демо и все соседние сервисы; рабочая кухня требует авторизацию.
Источник: `3c1223c47c2341f1503bcd0edf8eaebf07bfdf43`. SHA-256 пакета:
`ff26df992e6b66bb34d9464b56f7e63fbbc602914aee79560183441582049494`.
Приёмка владельцем ещё ожидается.

После согласования макета перенести подтверждение чека в атомарную команду
edge с версией заказа/станции, проверкой полномочий, идемпотентным receipt,
аудитом и outbox. Не заменять это цепочкой отдельных HTTP подтверждений блюд.
Общие комментарии и каналы должны поступать из проверенного snapshot заказа;
новые реальные источники/доставка требуют расширения согласованных contracts.
