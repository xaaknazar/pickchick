# Корзина и оплата по макету заказчика

Источник: архив «PickChick - корзина.zip», полученный 30 сентября 2026.
Точная копия целевого HTML: [cart-checkout-v1.html.txt](../../design/reference-source/cart-checkout-v1.html.txt).
Из всего архива использован документ «PickChick Корзина и оплата.dc.html»;
старые макеты кассы, входа и бэк-офиса не заменяют текущие требования.

## Перенос

- Корзина: высокий лист с радиусом 36, закрытие слева, очистка справа,
  название ресторана, компактные строки с белыми фото 84px, выбранными
  модификаторами, количеством и ценой. Редактирование доступно нажатием на
  фото/название. Минус, плюс, подтверждение очистки и возврат удаления сохранены.
- «Всегда кстати»: горизонтальные компактные дополнения из действующего меню,
  добавление одним нажатием. Используются реальные цены/состав. Белые фото,
  акции 7+1, промокод и переход обратно в меню сохранены по предыдущим решениям
  владельца; дополнительные разделы находятся ниже основного блока.
- Оформление: две карточки получения, ресторан и номер выдачи, Kaspi с номером
  аккаунта, неактивные Apple Pay/карта с пометкой «СКОРО», закреплённый итог.
  Смена способа получения пересчитывает серверное предложение.
- Ожидание Kaspi: герой, значок Kaspi, мягкое движение, точная сумма и понятное
  ожидание ответа банка. Reduce Motion отключает движение; в фоне оно остановлено.
- Успешная оплата: зелёная галочка, сумма, номер и способ получения, кнопка
  перехода к статусу. Через 2 секунды открывается существующий экран с поваром.
  Экран появляется только при переходе от неоплаченного состояния к серверному
  подтверждению, а не при каждом просмотре истории.
- Отказ: корзина сохранена, повторная попытка возвращает к проверке цены и
  отдельному явному подтверждению оплаты. При неизвестном результате такой
  кнопки нет. Удаление сохранённой попытки завершается до показа отказа.
- Готовка, сборка и выдача продолжают использовать OrderStatusView и существующие
  изображения. Макет прямо просит не заменять этот дизайн.

## Границы и отличия, обусловленные действующей системой

Это перенос интерфейса, а не включение эквайринга на VPS. API, фискальные
правила, банковские адаптеры и очередь кухни не менялись. Реальные счета при
проверках не создавались. Предложения/номер/сумма не берутся из примеров макета.

Поле комментария показано неактивным с подписью «Передача на кухню подключается»:
нынешний customer-checkout API не принимает комментарий. Нельзя молча терять
введённый текст; для активации нужен отдельный сквозной контракт до кухни.

Кнопка открывает публичный HTTPS-адрес Kaspi.kz. Подтверждённой ссылки на
конкретный счёт текущий API не возвращает; автоматический переход в приложение
банка не заявлен и без надёжного deep link не выполняется. Если приложение
банка не открылось, счёт можно найти в нём самостоятельно.

Не обещаем автоматический возврат при отказе: текст предлагает обратиться в
ресторан при фактическом списании. Фискальный чек не имитируется. Номер аккаунта
на экране частично скрыт. Цели нажатия 48px, размеры строк растут вместе с текстом;
клавиатура/контент не перекрывают закреплённые действия.

## Проверка

- Типизация mobile, адресный ESLint/Prettier, diff-check.
- 216 Node и 30 Python mobile-проверок.
- Изолированный браузерный Kaspi: 320×568, 393×852, 768×1024, 852×393;
  повтор после потерянного ответа использует прежний ключ, счёт отправляется
  один раз, неопределённый ответ не разрешает второй платёж, подтверждённый отказ
  разрешает новую попытку; успешная оплата переходит к прежним стадиям кухни.
- Отдельные сценарии корзины и отключённой оплаты: количество, модификаторы,
  удаление/возврат, постоянная нижняя кнопка, сохранённая корзина и закрытие листа.
- Исходный HTML отрисован с его runtime, шрифтами и изображениями; фактические
  web-экраны сверены с первичными макетами. Размеры адаптивны, а не абсолютны.
- Impeccable detector: нет замечаний на новых основных компонентах.
- PickChick Dev: iOS manifest и JavaScript bundle HTTP 200. Переустановка
  оболочки не требуется. Native-скриншоты новой версии и приёмка на физических
  iPhone/Android в этот этап не подтверждены; web-проверки не доказывают FPS,
  Dynamic Type и работу системных дикторов на устройстве.

Снимки фикстур не являются реальными оплатами. В них используются вымышленные
аккаунт и заказ. Актуальные примеры: [корзина](images/cart-checkout-design/cart-393.png),
