# Локальная разработка PickChick

Этот запуск содержит синтетическую организацию и тестовое меню. Реальная
точка, клиенты, оплаты, фискализация и интеграции поставщиков не подключены.

## Требования

- Node 24.16.0 (см. `.node-version`).
- pnpm 11.19.0 (см. `packageManager` в `package.json`).
- Запущенный Docker Desktop/Engine с Docker Compose.
- Свободные loopback-порты 55432, 55433, 56379, 3100 и 3101.

## Первый запуск

Из корня репозитория:

```sh
cp .env.example .env
pnpm install --frozen-lockfile
pnpm infra:up
pnpm build
pnpm db:migrate
pnpm db:seed
```

Если `.env` уже существует, сохранить свои настройки вместо повторного
копирования. `.env` исключён из Git; значения в `.env.example` предназначены
только для контейнеров на localhost. Не использовать их на удалённом сервере.

В двух терминалах:

```sh
pnpm start:api
```

```sh
pnpm start:edge
```

Проверка:

```sh
curl http://127.0.0.1:3100/health/ready
curl http://127.0.0.1:3100/v1/branches
curl http://127.0.0.1:3100/v1/branches/10000000-0000-4000-8000-000000000003/menu
curl http://127.0.0.1:3101/edge/v1/menu
```

Ожидаемая сумма тестового блюда — `price_minor: "349000"`, то есть 3490 ₸.
Это строка целых минимальных единиц, чтобы JSON не терял точность.
`ordering_enabled=false`: в этой версии нет endpoint приёма заказа.

Для локального edge остановить процесс центрального API и повторить чтение
его меню на порту 3101; затем перезапустить edge. Снимок сохраняется в своей БД.
Остановка центрального API не равна полному аппаратному WAN-испытанию.

## Проверки перед push

```sh
pnpm check
pnpm db:migrate
pnpm db:seed
pnpm test:integration
pnpm audit --audit-level=high
```

`pnpm check` включает build, types, lint, форматирование, unit tests и проверку
дрейфа генерируемых контрактов. После намеренного изменения Zod-схем выполнить
`pnpm build` и `pnpm contracts:generate`, закоммитить изменения JSON Schema/OpenAPI.

Интеграционные тесты требуют запущенных контейнеров, применённых миграций и
seed. Они создают временные тестовые схемы в выделенной локальной cloud-БД,
удаляют только свои схемы и откатывают проверочные транзакции. Тесты не
предназначены для production; проверка конфигурации это ограничивает.

Миграции и seed допускают повторный запуск. Изменение уже применённого SQL
отвергается по checksum: добавить следующую миграцию, не переписывать историю.
Не редактировать seed для смены действующего меню: это только начальные фикстуры.

## Остановка

Остановить процессы API/edge через Ctrl+C, затем:

```sh
pnpm infra:down
```

Тома PostgreSQL сохраняются. Команды уничтожения данных здесь намеренно не
входят в обычную последовательность запуска/остановки.

## Частые причины отказа

- Docker daemon не запущен: запустить Docker Desktop, повторить `pnpm infra:up`.
- `ready=false`, database down: проверить контейнер и правильный URL/порт.
- database up, schema down: применить миграции; edge дополнительно требует seed
  и корректный `EDGE_BRANCH_ID`.
- Redis down: центр показывает degraded; меню продолжает читаться из БД.
- Меню 404: нет активного снимка либо запрошена другая точка.
- Production/remote URL отклонён: текущая версия — только локальный стенд.
