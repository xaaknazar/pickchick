# Закрытые iPad PickChick Kiosk

Решение заказчика от 7 сентября 2026: отдельное приложение `kz.pickchick.kiosk`,
ограниченная выдача сборок и запрет выхода гостя в другие приложения.
Настройки ниже подготовлены для внедрения. **На физических iPad они ещё не применены**;
модели, ориентацию стойки и выбор MDM/Apple Business уточняет заказчик.

Связанные документы:

- [пошаговая подготовка iPad на месте](ipad-kiosk-onsite-runbook.md) (supervision, профиль,
  разрешения, код сотрудника, сборка, перезагрузка, попытки выхода, контрольный заказ);
- [постоянная выдача приложения вместо 90-дневного TestFlight](ipad-kiosk-distribution.md);
- [выпуск сборки киоска](kiosk-testflight.md).

## Факты Apple (проверено 24.10.2026)

Каждый факт ниже сверен с официальной документацией Apple в день подготовки. «Проверить на
iPad» означает: документация этого не обещает или формулирует неоднозначно, поэтому факт
считается подтверждённым только после проверки на конкретной модели и версии iPadOS.

| Факт                                                                                                                                                                                                                                                                                                        | Источник Apple                                                                                                                                                                             | Статус                                                                              |

Что код приложения сделать не может: React Native и Expo SDK 57 не дают JavaScript-доступа к
`UIAccessibilityIsGuidedAccessEnabled` или к статусу управляемой конфигурации, поэтому киоск не
проверяет сам, включён ли AppLock (аудит 19.10, замечание 3.6). Полноэкранный интерфейс и
скрытая навигация не отключают системные жесты; запрет выхода даёт только AppLock на supervised
iPad (или временно Гид-доступ).

## Профиль Single App Mode

[Шаблон](../../infra/ipad/pickchick-kiosk-applock.template.mobileconfig) содержит один payload
`com.apple.app.lock` для `kz.pickchick.kiosk`. Конкретны только Bundle ID и параметры:

| Ключ                                | Значение | Почему                                                                     |
| ----------------------------------- | -------- | -------------------------------------------------------------------------- |
| `DisableTouch`                      | `false`  | гость управляет киоском касанием                                           |
| `DisableDeviceRotation`             | `true`   | стойка портретная, приложение и так только портретное                      |
| `DisableSleepWakeButton`            | `true`   | гость не усыпляет и не выключает iPad верхней кнопкой                      |
| `DisableAutoLock`                   | `true`   | экран не гаснет (в приложении дополнительно `expo-keep-awake`)             |
| `UserEnabledOptions.VoiceOver/Zoom` | `true`   | доступность для гостей; что предлагает тройное нажатие - проверить на iPad |

Кнопки громкости, боковой переключатель и остальные функции оставлены по умолчанию Apple. Название
организации и два `PayloadUUID` - заполнители. `PayloadIdentifier`
`kz.pickchick.configuration.kiosk` постоянный, поэтому новая версия профиля заменяет прежнюю,
а не добавляется второй. В профиле нет паролей, Wi-Fi, сертификатов, адресов и ключей API.

Подготовка файла на Mac из корня репозитория:

```sh
node scripts/mobile/kiosk-applock-profile.mjs --organization "<название организации>"
plutil -lint .local/ipad/pickchick-kiosk-applock.mobileconfig
```

Скрипт подставляет новые UUID и экранированное название, отказывается работать без
названия или с изменённым шаблоном и пишет в `.local/ipad/` (не попадает в Git). Тест
`tests/kiosk/applock-profile.test.mjs` сверяет каждый ключ шаблона со схемой Apple и
разбирает готовый файл настоящим plist-парсером.

### Применение через Apple Configurator для Mac

Кратко (полный порядок с проверками - в [runbook](ipad-kiosk-onsite-runbook.md)):

1. iPad уже supervised этим Mac (Prepare с «Supervise devices», организация, supervision
   identity сохранена в резервной копии Mac).
2. Установлена согласованная сборка `kz.pickchick.kiosk`, выданы разрешения, пройдена
   настройка устройства и проверено «Состояние киоска».
3. Выбрать iPad в Configurator, перетащить на него `.mobileconfig` (или Add > Profiles).
   Альтернатива без файла: Actions > Advanced > Start Single App Mode, выбрать PickChick
   Kiosk и те же Options; тогда параметры профиля из Git не применяются, их нужно выставить
   вручную и записать.
4. Приложение открывается и не даёт выйти. Для обслуживания: Actions > Remove > Profiles
   (или остановить Single App Mode), обновить сборку, вернуть профиль.

При MDM (встроенном в Apple Business или внешнем) тот же файл загружается как собственная
конфигурация; поддержку AppLock конкретным сервисом проверяют на одном iPad до раздачи.

## Гид-доступ - только временно

Для проверки без supervision: «Настройки» > «Универсальный доступ» > «Гид-доступ», включить,
задать отдельный код; открыть киоск и трижды нажать верхнюю кнопку. Выход требует кода (или
Face ID/Touch ID, если их разрешили - для ресторанного iPad не разрешать). Гид-доступ не
заменяет приёмку AppLock.

## Защита на стороне приложения (без native-модулей)

Проверено кодом и тестами 24.10.2026 (полоса kln):

- **Простой**: 90 с без касаний - предупреждение, ещё 15 с - очистка корзины и возврат на
  заставку (как и раньше). Неизвестная или ожидающая оплата никогда не очищается.
- **Перезапуск** (питание, сбой, обновление, повторный запуск AppLock): если с последнего
  сохранённого изменения корзины прошло больше 90 + 15 с, черновик прошлого гостя очищается
  до показа любого экрана, его гостевая сессия завершается (без сети - позже, фоном). Если
  перезапуск случился сразу при госте, корзина сохраняется. Заказ или намерение оплаты
  перезапуск не трогает. Касания хранятся в памяти, поэтому после перезапуска считается
  время последнего сохранённого изменения (выбор режима, товары).
- **«Состояние киоска»** для персонала: удержание логотипа 5 с -> «Действия сотрудника» ->
  код сотрудника -> «Состояние киоска». Показывает сборку и release id, адрес API и профиль
  сборки, коммерческий режим, принят ли код сервером и когда последний сигнал присутствия
  дошёл до центра устройств (или код ответа). Строки, которых не должно быть на рабочем iPad,
  помечены «Проверить». Ключ устройства, данные гостей и код не показываются и не хранятся.
- **Присутствие в кабинете**: новые поля не нужны. Сборка и release id уже передаются в
  `appVersion`, время последнего сигнала - `observed_at` в `device_presence`; адрес API и
  коммерческий режим следуют из самого факта сигнала (его отправляет только коммерческая
  сборка на свой API), а настройка кода сотрудника - свойство сервера, а не устройства.
  Схема API и миграции не менялись, установленный API принимает сигнал как раньше.

## Камера фотокабины и разрешения (19.10.2026)

Аудит 19.10, замечание 3.6. В фотокабине нет кнопки «Открыть настройки»: если гость однажды
нажал «Не разрешать» в системном запросе камеры, следующий гость видит текст «Камера
выключена в настройках iPad. Пригласите сотрудника.» без выхода из приложения. Сотрудник
восстанавливает разрешение так:

1. Снять AppLock (MDM или Configurator) или выйти из Гид-доступа своим кодом.
2. «Настройки» -> PickChick Kiosk -> «Камера» -> включить. Там же проверить «Локальная сеть»
   (нужна фотопринтеру).
3. Вернуть режим одного приложения и проверить фотокабину.

Разрешения камеры и локальной сети выдаются при подготовке, до включения AppLock.
Фотопринтер владелец отложил; разрешения всё равно проверяются, чтобы не снимать AppLock
позже.

## Приёмка каждого iPad

Пошаговый порядок и протокол - в [runbook](ipad-kiosk-onsite-runbook.md). Конфигурация не
принята, если гость смог выйти из приложения любым способом, если после перезагрузки iPad не
вернулся в киоск или если «Состояние киоска» показывает строки «Проверить» на рабочей сборке.

Физический iPad к этой проверке не подключался; симулятор и браузер проверяют приложение, но
не доказывают блокировку реального устройства. Привязка production-доступа к устройствам,
enrollment в MDM и настоящие терминал/ККМ остаются отдельными частями внедрения.
