# Бэк-офис: редактор каталога

Проверяемый этап BO-01: `apps/backoffice` — отдельный браузерный интерфейс управляющего
к `catalog-admin`. Он читает реальные права доступа и серверный черновик, редактирует
позиции и выпускает отдельные версии каталога. Это ещё не весь бэк-офис ресторана.

## Запуск оператором

Нужны Node.js версии из корневого `package.json`, установленный workspace, PostgreSQL
с актуальными cloud-миграциями и API с включённым `CATALOG_ADMIN_ENABLED=true`.
Выпуск/отзыв доступа описан в [catalog-admin.md](catalog-admin.md).
Используйте личный JSON-файл управляющего из этого CLI, не customer/TEST/edge токен.

```sh
pnpm build
node --env-file=.env services/api/dist/main.js
```

В отдельном терминале:

```sh
node apps/backoffice/server.mjs
```

Откройте `http://127.0.0.1:4177` и выберите приватный JSON-файл. Название управляющего
и список его точек приходят от API. При необходимости оператор задаёт
`BACKOFFICE_PORT` и `BACKOFFICE_API_PORT` (по умолчанию `4177` и `3100`).
В Windows PowerShell, например, `$env:BACKOFFICE_API_PORT = '3100'`.
Пути/пароли/токены не передаются через URL и не включаются в web bundle.

Сервер интерфейса слушает только loopback. Он проксирует строго перечисленные
`/v1/admin/catalog/branches...` маршруты в API на `127.0.0.1`; произвольный upstream,
публичная выдача доступа, CORS и cookies отсутствуют. При работе с API на другом
сервере оператор может настроить защищённый SSH-туннель на этот локальный порт.
Это не готовая публичная панель на VPS: её HTTPS/сеть/развёртывание проверяются отдельно.

## Работа с каталогом

1. Выберите доступную точку. Если каталога нет, нажмите «Создать черновик из макета».
   Сервер создаст исходные 24 SKU. КБЖУ и аллергены сохраняют статус непроверенных;
   незаполненный KZ-перевод явно обозначается.
2. Найдите позицию по названию, ID или артикулу, отфильтруйте категорию и откройте
   «Изменить». Есть RU/KZ названия, описания и состав; порция, вес/объём, КБЖУ,
   аллергены, базовая цена, доступность, время приготовления, выбор существующего
   изображения, группы/варианты модификаторов и ссылки на компоненты комбо.
3. Цены вводятся в тенге с максимум двумя дробными знаками. В запросе они остаются
   строками целых минимальных единиц; вычислений денег через дробный `Number` нет.
   Невалидные суммы, циклы ссылок, неудовлетворимый обязательный выбор и удаление
   используемой позиции блокируются; сервер повторно проверяет весь снимок.
4. «Применить в черновик» сохраняет карточку **в этой вкладке**. «Сохранить черновик»
   записывает серверную ревизию. До явной публикации активная версия не изменяется.
5. Проверьте содержимое каталога, поставьте отметку проверки и сохраните черновик.
   «Опубликовать…» открывает отдельное подтверждение с точкой и ревизией.
   Публикация создаёт неизменяемую версию и обновляет основу черновика.
   Отметка управляющего не является сертификацией пищевой ценности.

Изображения выбираются из существующих ресурсов макета. Загрузка новых файлов,
редактор категорий, склад, себестоимость/маржа, техкарты, персонал, смены и аналитика
в этом этапе не реализованы. В боковом меню недоступные разделы отключены.

**Клиенты:** новая публикация доступна в нейтральном Catalog API. Переключение
мобильного приложения, киоска и кассы — следующий согласованный этап. Опубликованные
TEST-сборки сейчас используют прежний каталог, поэтому панель не обещает немедленного
обновления меню этих клиентов. Публикация не открывает приём заказов и не создаёт
платежей, чеков, kitchen tickets или событий списания запасов.

## Конфликты и потерянный ответ

Правки принадлежат личному управляющему и выбранной точке. Сохранение отправляет
ожидаемую ревизию, публикация — также ожидаемую активную версию. При конфликте локальные
правки сохраняются; автоматического перезаписывания серверной версии нет. Можно
перенести нужные значения из карточки и отдельно подтвердить загрузку серверного
черновика. Изменение точки с локальными правками также требует явного отказа от них.

Перед мутирующим HTTP-запросом в `sessionStorage` записываются точные тело, request ID,
точка и actor. При потере ответа или перезагрузке вкладки нажмите «Проверить результат»:
повторяется исходный запрос, затем загружается актуальное состояние. Новые сохранения
и публикации до разрешения неизвестного результата заблокированы. Отозванный доступ
не удаляет журнал; другой управляющий не получает его. Ошибка записи журнала
останавливает запрос до отправки.

Токен хранится только в `sessionStorage`; выход удаляет авторизацию и очищает экран.
Журнал этой вкладки остаётся для повторного входа того же управляющего. Закрытие вкладки
или очистка её хранилища может удалить и токен, и локальные правки/ожидающий request ID.
Браузер предупреждает перед уходом при незавершённой работе. Сначала завершите проверку
результата и сохранение; если вкладка уже закрыта, заново войдите и прочитайте серверное
состояние, не предполагая, что прежний запрос не выполнился. Автономная запись без связи
с API, общий offline-кэш и гарантированное восстановление после закрытия браузера не
заявляются.

## Проверки и визуальный источник

```sh
pnpm --filter @pickchick/backoffice build
node --env-file=.env --test --test-concurrency=1 tests/backoffice/*.test.mjs
```

Для browser-проверки нужен Python с Playwright и Chromium; при отдельной среде задайте
`BACKOFFICE_TEST_PYTHON`. Проверки создают временные PostgreSQL-схемы и настоящие scoped
manager grants, запускают настоящий HTTP-контроллер и loopback proxy. Единственное
вмешательство browser-теста — потеря одного уже выполненного ответа сохранения.
Схемы и временные файлы доступа удаляются после теста. VPS и ресторанные заказы не
используются.

Проверяются: 24 SKU, точная конверсия денег, формы и модификаторы, потерянный ответ и
reload без повторного эффекта, конфликт двух редакторов, публикация отдельно от
черновика, отзыв/разделение доступа, отказ локального хранилища до POST/PUT, CSRF/Host
и ограничение маршрутов proxy, безопасное отображение сохранённого HTML-подобного текста. Browser проверяет размеры 1680×1040, 1440×900 и
1024×768, длинное название и закреплённые действия карточки/сохранения. Это Chromium
на машине разработки; физическая приёмка Windows/iPad ещё предстоит.

Визуальный источник — предоставленный заказчиком `Pick Chick Бэк-офис (offline).html`
из Downloads bundle, раздел «Номенклатура», и его `Backoffice standalone-src.dc.html`.
Исходник рендерился напрямую, без замены CSS/данных. Сохранены тёмная палитра, Inter,
боковая навигация, верхняя панель, четыре карточки показателей, таблица и блок групп.
Макетные маржа/выручка/46 позиций заменены фактическими состояниями API; добавлены
фотографии, поиск, доступные элементы форм и действия от 48 px. Это адаптация рабочего
редактора по источнику, а не заявление о совпадении всех пикселей макета.

## Публикация статических файлов

`apps/backoffice/dist` можно обслуживать Caddy без Node-процесса UI. JS, CSS, шрифты
и изображения используют относительные пути; предусмотрено размещение в `/backoffice/`.
Для `/backoffice` нужен redirect на `/backoffice/`. Запросы API сохраняют корневой
префикс `/v1/admin/catalog/`, поэтому Caddy должен отдельно разрешать эти маршруты
и Bearer-заголовок к API. Локальный Node proxy в production не требуется.

Разрешайте только `index.html`, `app/api/model/domain/dom/editor.js`, `styles.css`,
`fonts.css`, подготовленные изображения `assets/*` и Inter `assets/fonts/*.woff2`.
Не публикуйте исходники, credential-файлы, директории `.local`/`node_modules` и `.env`.
CSP должен разрешать только self для script/style/font/img/connect и запрещать
object/base/frame-ancestors. API и ответы с личными данными — `Cache-Control: no-store`.
Browser-тест этого этапа проходит именно через `/backoffice/` со всеми локальными
ресурсами и настоящим API в корне origin; готовность конкретного VPS подтверждается
отдельным smoke-тестом после развёртывания.
