# К15: проверка инструментов кассы на PostgreSQL 18

`scripts/verify-cutover-postgres18.py` повторяет существующие проверки перехода
025 → 026 → 027 → 028, резервного копирования и восстановления, настройки продаж,
номера кассы и оплаченного дня в браузере. Это стенд с синтетическими данными,
не установка на кассе и не приёмка Windows или банковского оборудования.

Нужны Linux с локальным Docker (`/var/run/docker.sock`), Node и pnpm из выбранного
исходника, установленные зависимости проекта, Python Playwright с Chromium,
`pg_dump` и `pg_restore` версии 18.6. Проверяемая рабочая копия должна быть чистой,
содержать все шесть тестовых файлов из `TESTS` и не иметь незакоммиченных файлов.
Текущий общий срез без cutover-тестов для этого не подходит: используйте отдельную
копию интеграционной ветки. Инструмент не сливает ветки и не получает новые refs.

```sh
python3 scripts/verify-cutover-postgres18.py \
  --source /absolute/path/to/cutover-checkout \
  --expected-sha <полный-40-символьный-SHA> \
  --pg-bin /absolute/path/to/postgresql18/bin \
  --output /absolute/path/to/new-evidence-directory
```

Перед прогоном получить свежие refs штатным `project:check` и сверить нужный SHA.
Скрипт проверяет SHA, чистоту дерева и версии Node/pnpm, выполняет `pnpm build`,
поднимает два одноразовых PostgreSQL 18.6 с закреплённым digest и случайными
локальными портами. Данные находятся в tmpfs. Пароли генерируются для этого
прогона; `.env`, внешние URL баз, PG-переменные и серверные флаги не наследуются.
Docker всегда локальный; настройки выбора удалённого daemon не наследуются.
Проверки не используют Redis; обязательное поле конфигурации указывает на
неиспользуемый loopback-порт 1.

Результаты: `build.log`, `tests.tap` и `result.json`. Успех требует PostgreSQL 18.6
на обоих серверах, инструментов версии 18.6, успешной сборки, полного результата
TAP без ошибок/пропусков/todo и неизменённого исходного SHA. В JSON сохраняется
SHA-256 журнала тестов. Скрипт удаляет только созданные им контейнеры; ошибка
очистки даёт неуспешный итог и список `cleanupPending`. При принудительном
завершении процесса контейнеры могут остаться: их имена начинаются с
`pickchick-k15-`, label `pickchick.verification=k15`; перед удалением проверить
принадлежность своему прогону. Общие контейнеры и тома не удалять.

После изменения кода повторить на новом точном RC. Зелёный результат не заменяет
полную CI, репетицию на защищённой копии реальной базы, Windows PowerShell 5.1,
возврат служб, приёмку оборудования и отдельное согласованное окно установки.

Уточнение 08.11: первоначальный прогон на 18.3 проверял основную версию PostgreSQL,
но не совпадал с минимумом 18.6 закреплённого `native-foundation-db.mjs`.
Теперь образ и backup-инструменты явно закреплены на 18.6. Старые результаты
18.3 сохраняют исторический смысл; они не объявляются проверкой 18.6.
