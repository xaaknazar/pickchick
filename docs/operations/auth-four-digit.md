# Telegram: четыре цифры и обязательный пол

Решение владельца от 30 сентября 2026: новый код Telegram и форма ввода - 4 цифры;
значение даты рождения по центру строки; пол остаётся и обязателен для заполнения анкеты.
Это адресное изменение утверждённого auth-v3, исходный макет не переписан.

## Реализация

- Сервер генерирует четыре криптографически случайные цифры, включая ведущий ноль,
  передаёт тот же код в Telegram Gateway и хранит только HMAC. SMS остаётся шестизначным.
- Миграция 028 сохраняет длину challenge. Старые записи получают 6; повтор request_id
  возвращает исходную длину без новой отправки. Клиент сохраняет её вместе с challenge.
  Ответ старого сервера без поля продолжает означать 6.
- TTL 3 минуты, максимум 5 попыток и все бюджеты отправки сохранены.
  Код автоматически проверяется после нужного количества цифр.
- Анкета требует явного выбора пола. Повторное нажатие сохраняет выбор. Новую анкету
  нельзя завершить через «Заполню позже». Имя и дата по-прежнему необязательны.
  Сервер не принимает сброс пола в null и не отмечает неполную анкету завершённой.
  Уже сохранённые сессии и старые профили без пола остаются читаемыми.
- Дата и стрелка находятся в общем выровненном контейнере; совпадает высота строки текста
  имени и даты. На узком экране длинная дата переносится внутри правой части строки.

## Выпуск

Guard: `infra/staging/release-auth-four-digit.py`. База API 2661877, public 14e95c4,
schema027 -> 028. Обязательны exact-SHA Foundation CI, immutable image, backup с
изолированным восстановлением, сравнение всех прежних данных/ACL, проверка старого
образа и сохранение auth env/ключей. Gateway и платёжный режим не меняются.

На момент checkpoint сервер ещё не обновлён; установка и физическая приёмка
четырёхзначного входа отмечаются отдельно после проверки.

Telegram официально допускает явно переданный код длиной 4-8 цифр:
https://core.telegram.org/gateway/api#sendverificationmessage
