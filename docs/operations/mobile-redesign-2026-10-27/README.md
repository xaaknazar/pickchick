## Что изменилось для клиента

1. **Шапка как в Drinkit на Меню, Событиях и Заказах.** Слева логотип, название точки и часы
   работы (нажатие открывает выбор ресторана, как раньше). Справа, у правого поля, одна
   круглая кнопка профиля 48 pt (`header-profile`). Кнопка стоит в одной точке на всех трёх
   вкладках. Двойное нажатие открывает профиль один раз.
2. **Колокольчика больше нет.** Уведомления открываются из профиля: строка «Уведомления»
   сразу под карточкой с именем, число непрочитанных - только внутри этой строки. Снаружи
   профиля ничего о непрочитанных не показывается (ответ владельца).
3. **Три вкладки внизу:** Меню, События, Заказы. Вкладки профиля нет. Профиль - отдельный
   экран поверх вкладок по прежнему адресу `/profile`: назад, «Профиль», настройки; на iOS
   работает свайп назад. Гость, нажавший кнопку профиля, проходит прежний вход.
4. **Полоса корзины (только когда корзина не пуста).** Тёмная стеклянная капсула над нижней
   панелью: слева ручка с отметкой Kaspi, в центре только сумма (та же, что на кнопке
   «Оформить заказ» и в счёте, с учётом подарка комбо), справа фото последних добавленных
   товаров, до трёх, самое новое справа. Нажатие на сумму или фото открывает корзину.
5. **«Тяни для оплаты».** Удержать ручку - сумма и фото гаснут, в центре «тяни для оплаты»;
   дотянуть ручку до конца и отпустить - сразу начинается оплата: создаётся заказ и
   отправляется счёт Kaspi, как при нажатии «Оплатить через Kaspi». Отпустить раньше - ручка
   возвращается, ничего не происходит. Короткое касание только показывает подсказку.

## Экраны

- Меню (M06): шапка внутри прежней схлопывающейся подложки (теперь непрозрачной), полоса
  корзины над тремя вкладками.
- События (M26) и Заказы (M19, обе версии - симулятор и Kaspi): та же шапка сверху, прежние
  заголовки и содержимое ниже, та же полоса корзины. На низких экранах (меньше 700 pt)
  пустые Заказы компактнее, «Открыть меню» видна без прокрутки.
- Профиль (M30, `/profile`): экран поверх вкладок, без нижней панели и без полосы корзины;
  строка «Уведомления» со счётчиком.
- Уведомления (`/notifications`): назад - в профиль.
- Оформление (M12, `/checkout`): открывается свайпом с одноразовым намерением; «Вернуться в
  корзину» после свайпа открывает корзину.
- Вход (лист входа): защита от случайного второго нажатия.
- Демонстрация для Apple (DEMO-1, `/demo-order`): без полосы корзины и без запросов к API.

## Безопасность оплаты свайпом

- **Новой платёжной логики нет.** Свайп открывает существующее оформление и один раз вызывает
  его `submit()` - тот же путь, что нажатие «Оплатить через Kaspi»: согласие с условиями,
  расчёт цены, остановка при изменении цены, одна долговечная команда создания заказа и
  автоматический счёт этого нажатия. Охраны аудита 19.10 (0.2, 2.0, 2.1, 2.4, 2.5) в
  `KaspiCheckoutScreen`/`checkout-resume` не менялись.
- **Одноразовое намерение** (`slide-pay-intent.ts`): только в памяти процесса, ничего не
  сохраняется; берётся один раз, только свежим (до 30 с) и только выданным этим процессом.
  Перезагрузка, перезапуск, восстановление навигации, deep link, «назад» и повторный монтаж
  экрана его не повторяют. Любая остановка (согласие, цена, стоп-лист, сеть и т.д.) оставляет
  клиента в оформлении с прежним сообщением и обычной кнопкой - второй автоматической попытки
  нет.
- **Когда свайпа нет или он не платит:**
  - гость: свайп открывает вход, после входа - оформление без отправки (нужно новое явное
    действие);
  - корзина, которую не пустила бы кнопка «Оформить заказ»: открывается корзина с причиной;
  - сборка без Kaspi-оформления, симулятор заказов, образцы каталога (дизайн) или локальная
    учётная запись: ручки нет, слева значок пакета, вся капсула открывает корзину;
  - DEMO-1: полосы нет, запросов к API нет;
  - аккаунт проверки Apple: свайп делает ровно то же, что кнопка (сервер отклоняет заказ
    `FORBIDDEN`, счёта нет);
  - VoiceOver и клавиатура: действие ручки открывает оформление без автоматической отправки.

## Как собрать TestFlight

1. Сначала объединить PR #276 (сборка 23), затем эту ветку. Сборка 23 сейчас в App Review;
   новая сборка нужна для TestFlight, потому что JS встраивается в бинарник.
2. Следующий номер сборки - **24** (после 23). Версия `0.2.0` и `buildNumber` в этой ветке
   не менялись (`apps/mobile/app.json`: `buildNumber` "23"); поднять 23 -> 24 отдельным
   коммитом на выпускающем Mac.
3. Новых нативных зависимостей нет: `react-native-gesture-handler` и
   `react-native-reanimated` уже были в сборке 23, `package.json`/`pnpm-lock.yaml` не
   менялись.
4. Штатный выпуск профилем `storefront` (серверный вход, Kaspi, опубликованный каталог):

```sh
python3 scripts/mobile/ios_release.py doctor --app mobile --release "$MOBILE_RELEASE"
python3 scripts/mobile/ios_release.py archive --app mobile --feature-profile storefront --release "$MOBILE_RELEASE"
python3 scripts/mobile/ios_release.py export --app mobile --release "$MOBILE_RELEASE"
# Отдельное разрешение владельца на загрузку:
python3 scripts/mobile/ios_release.py upload --app mobile --release "$MOBILE_RELEASE" --asc-app-id 6809208492
```

5. Перед загрузкой: полный Foundation CI на опубликованной ветке, проверка флагов во
   встроенном JS. После: на iPhone - удержание и перетаскивание ручки, свайп назад из
   профиля, VoiceOver, крупный шрифт, `SmokeTests.swift` в симуляторе; реальная оплата только
   по отдельному «да» владельца.
