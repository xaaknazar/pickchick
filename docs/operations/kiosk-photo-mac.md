# Локальная фотокабина Mac и USB POS-80

Операторская проверка настоящей камеры Mac и отдельного USB-термопринтера.
Ветка `codex/photo-mac`. Используются действующие экран заставки, фотокабина,
шрифты и логотип киоска. Отдельный entry `tools/photo-printer/mac-app.tsx`
не создаёт контроллер заказа и не запускает API оформления или оплаты.
Нажатие основной кнопки заказа показывает пояснение о локальной проверке;
для фото используется «Сделать фото».

Это локальный режим на одном Mac. LAN/public rollout, установка на iPad,
настройка Windows, VPS и фискальной печати в этот этап не входят. Runbook
ресторанного iPad-сценария: [kiosk-photo.md](kiosk-photo.md).

## Принтер и пределы подтверждения

USB-обнаружение сообщает `MDL:POS-80;CMD:ESC/POS`. Ранее предоставленный selftest
указывает печатную ширину 72 мм и бумагу 80 мм. Локально выбран тестовый raster
576 точек; `cut=false`. Это рабочий профиль для проверки, а не подтверждение
фактического DPI, качества изображения или совместимости всех команд аппарата.
Серийный номер и полный USB URI хранятся только в приватной конфигурации.

**Полный снимок с логотипом физически напечатан 14 октября.** Владелец
подтвердил нормальную печать после исправления транспорта, затем уточнил:
фото слишком тёмное и нечёткое. Поэтому прохождение камеры/отправки подтверждено,
а качество нового профиля обработки ещё требует бумажной приёмки.

По уточнению владельца первый короткий
диагностический логотип напечатался красиво. Непонятные символы и около метра
бумаги появились позже, после нажатия «Распечатать» для фотографии. В SQLite
сохранено одно задание `unknown`; подробные данные завершения транспорта тогда
не собирались. Точная причина сбоя не установлена. Удачный короткий логотип,
обнаружение `CMD:ESC/POS` и ответ backend `sent` не подтверждают корректную печать
полной фотографии.

После сбоя локальная служба `13441` была остановлена; активных USB-процессов
не осталось, `protocolConfirmed` переключили в `false`. Владелец уточнил,
что печать уже закончилась; перезапуск питания не подтверждён.
После исправления отправлен один маленький логотип: 384×72 точки, три полосы,
3488 байт. Транспорт завершился с code=0, timedOut=false, written=true,
pipeError=false. Владелец подтвердил: «Да, маленький логотип нормальный».
Затем профиль включён для контролируемой проверки одного нового снимка
в Safari. Один новый полный снимок напечатан с логотипом, без посторонних
символов и длинной ленты; это подтвердил владелец. В SQLite один `sent` и один
прежний `unknown`. Старое задание не повторяли и не удаляли.
При новом сбое остановить службу и вернуть
`protocolConfirmed=false`. Этот режим разрешает камеру/предпросмотр, но не USB.
`cut=false` сохраняется.

Отдельно review обнаружил дефект обработки grayscale/composite в `raster.mjs`.
В коде композиция фото/логотипа теперь материализуется перед отдельным проходом
grayscale; программная проверка исправления прошла. Этот дефект не объявлен
доказанной причиной символов или протяжки бумаги.

## Подготовленная локальная конфигурация

Команды ниже выполняются из корня репозитория. Нужны macOS, Node **24.16.0**
из `.node-version`, pnpm **11.19.0**, установленные зависимости киоска и отдельного
`tools/photo-printer`. При подготовке чистой рабочей копии использовать lockfiles:

```sh
pnpm install --frozen-lockfile
pnpm --dir tools/photo-printer install --ignore-workspace --frozen-lockfile --ignore-scripts
```

Приватный файл `.local/photo-mac/config.json` уже подготовлен для этого Mac.
При переносе на другой Mac создать его заново по фактически обнаруженному
устройству; не копировать USB URI вслепую.

| Поле                | Назначение текущего профиля                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------- |
| `usbUri`            | Точный URI выбранного ESC/POS-устройства из системного USB-backend; приватное значение с серийным номером |
| `width`             | `576`, тестовая ширина raster                                                                             |
| `cut`               | `false`                                                                                                   |
| `protocolConfirmed` | `true` на этом Mac после успешного полного отпечатка; `false` для нового устройства или при сбое          |
| `port`              | `13441`, при запуске служба слушает только `127.0.0.1`                                                    |
| `webRoot`           | Абсолютный путь к `.local/photo-mac-web` этой рабочей копии                                               |
| `database`          | Абсолютный путь к `.local/photo-mac/jobs.sqlite` этой рабочей копии                                       |

Конфигурация, SQLite, `jobs.sqlite.token` и `jobs.sqlite.url` имеют права `0600`.
Служба устанавливает `umask 0077`; новый каталог БД создаётся с `0700`.
Эти файлы, полный URL с ключом, серийный номер и реальные снимки не включать
в Git, общий журнал, CI-логи или скриншоты отчёта.

## Повторяемая проверка без бумаги

После установки зависимостей можно собрать UI и выполнить изолированные тесты:

```sh
node tools/photo-printer/build-mac-preview.mjs
node --test tests/photo-printer/*.test.mjs
python3 tests/photo-printer/browser_mac.py
```

Для последней команды нужны Python Playwright и его Chromium. Browser fixture
слушает случайный порт `127.0.0.1`, использует синтетическую камеру и заглушку
отправки, не вызывает системный USB-backend. Основную службу `13441` для этих
тестов запускать не требуется. Реальный принтер тесты не используют.

## Повторяемый запуск камеры с отключённой печатью

Этот режим позволяет проверить настоящую камеру Mac и raster-предпросмотр,
сохраняя физическую печать отключённой. USB-принтер для него не требуется.

1. Сохранить `protocolConfirmed=false` и `cut=false` в приватной конфигурации.
   Служба проверяет формат URI, но при отключённой печати не вызывает USB discovery
   и не отправляет данные аппарату.
2. Собрать изолированный web-entry:

   ```sh
   node tools/photo-printer/build-mac-preview.mjs
   ```

   Сборка создаёт временный Expo-проект в `apps/kiosk/.local/photo-mac-app`,
   экспорт в `.local/photo-mac-web` и маркер `photo-mac-build.json`.
   Скрипт отключает загрузку `.env` и commerce, явно включает Mac photo adapter
   и очищает ресторанный photo origin. Обычный kiosk export для этого запуска
   не использовать: служба требует маркер локальной сборки.

3. Запустить службу в отдельном терминале:

   ```sh
   node tools/photo-printer/mac-preview.mjs .local/photo-mac/config.json
   ```

   Она обслуживает UI и photo API на `http://127.0.0.1:13441` и создаёт приватный
   `jobs.sqlite.url`. Токен не выводится в stdout. Если порт занят, сначала
   определить уже запущенный экземпляр; не запускать параллельную отправку.

4. Во втором терминале открыть приватную ссылку без вывода ключа в консоль:

   ```sh
   python3 - <<'PY'
   import json
   import subprocess
   from pathlib import Path
   config = json.loads(Path('.local/photo-mac/config.json').read_text())
   link = Path(config['database'] + '.url').read_text().strip()
   subprocess.run(['open', link], check=True)
   PY
   ```

   Разрешить браузеру доступ к камере Mac. Использовать адрес с буквальным
   `127.0.0.1`, не `localhost` и не LAN-адрес. Открытие голого origin без ключа
   в новой вкладке не авторизует печать.

5. «Сделать фото» открывает камеру. Снять после отсчёта, проверить чёрно-белый
   предпросмотр с логотипом, при необходимости нажать «Переснять». «Распечатать»
   остаётся недоступной; API также отклоняет отправку с `NOT_CONFIGURED`.
   Выйти на заставку штатной кнопкой. Не менять конфигурацию ради теста бумаги.
6. Завершать службу `Ctrl+C`: она закрывает HTTP listener, очищает предпросмотры
   и закрывает SQLite. Сохранять БД метаданных и приватный токен между запусками,
   чтобы не терять связь с предыдущими заданиями.

## USB-транспорт и восстановление

На этом Mac пользовательская отправка включена после успешного полного
отпечатка. На новом аппарате начинать с `protocolConfirmed=false` и отдельной
проверки совместимости. При включённой печати запуск проверяет наличие точного
USB URI; перед самой отправкой это проверяется повторно.

`mac-usb.mjs` вызывает системный `/usr/libexec/cups/backend/usb` напрямую.
Перед каждой передачей повторно проверяет точный URI, задаёт `DEVICE_URI`,
передаёт один экземпляр raw raster через stdin. CUPS scheduler, очередь,
spool-файлы, принтер по умолчанию и автоматические повторы не используются.
Пакет содержит фото и логотип; отрезка выключена. Текущий адаптер передаёт
данные порциями до **1024 байт** с паузой **40 мс** между ними, сохраняя один
процесс backend и одну копию. Raster кодируется отдельными командами `GS v 0`
по **24 строки** (последняя полоса может быть короче), без дополнительных
переводов строки между полосами. Эти изменения ограничивают размер порций;
один полный отпечаток этим способом подтверждён владельцем. Точная причина
прежнего сбоя и устойчивость серии заданий ещё не установлены.

`sent` означает завершение записи stdin и нулевой код выхода USB-backend без
ошибки канала. Это транспортный результат; датчики бумаги и крышки не проверены.
Ошибка до попытки передачи даёт `failed`; после начала передачи ошибка или
таймаут 15 секунд даёт `unknown`. Автоматического повтора нет.

SQLite хранит только метаданные заданий и хеш токена. `sending` фиксируется
до внешней отправки; после перезапуска такое задание становится `unknown`.
Повтор того же ID/предпросмотра не создаёт вторую копию. Не удалять БД и не
начинать новую операторскую сессию ради обхода неизвестного результата.
Сначала проверить статус и фактическую бумагу, затем принять решение вручную.

## Изоляция и временные данные

- HTTP привязан только к `127.0.0.1`. Проверяются точный `Host` и браузерный
  `Origin`; чужой origin и `/v1/pair` отклоняются. Photo API требует Bearer,
  POST принимает JSON. Cookies для авторизации не используются.
- CSP ограничивает сетевые обращения собственным origin; локальные inline
  стили/скрипты и необходимые `data:`/`blob:` изображения допускаются.
  Встраивание страницы запрещено, ответы не кэшируются; microphone запрещён.
- Ключ передаётся в fragment приватной ссылки, сохраняется в `sessionStorage`
  вкладки и удаляется из адресной строки. Там же хранится ID ожидающего задания,
  но не фото. Обычный reload сохраняет эту идентичность; закрытие вкладки её
  завершает. Адаптер допускает только фиксированные photo API-пути своего origin.
- Снимок и raster существуют временно в памяти. Предпросмотр службы живёт
  до 90 секунд, удаляется при отмене или отправке; выход из фотокабины и её
  таймаут очищают UI. Фото не записываются в SQLite, Photos, облако или spool.
- Встроенная настройка ресторанного HTTPS-принтера здесь не используется:
  Mac-адаптер берёт конфигурацию из локального запуска и запрещает её замену
  через `writeConfig`.

## Коррекция тёмного отпечатка

После замечания владельца фотография обрабатывается отдельно от логотипа:

- После уменьшения до размера печати применяется мягкая резкость только для
  границ (`sigma=0.7`, `m1=0`, `m2=1.5`, предел осветления/затемнения 8).
- Кривая `255 × (яркость / 255)^0.65` поднимает тени и полутона, сохраняя
  чёрную и белую опорные точки. Гистограмма фотографии не растягивается
  автоматически: тёмный фон не задаёт произвольную экспозицию всей сцены.
- Floyd-Steinberg проходит строки поочерёдно в двух направлениях. Логотип
  обрабатывается с отдельным буфером ошибки, поэтому его рисунок не зависит
  от яркости снимка. Поля остаются белыми.
- Предпросмотр PNG и отправляемый raster используют одни и те же бинарные
  пиксели; на бумаге результат может отличаться из-за плотности нагрева,
  свойств бумаги и механики. Настройки нагрева принтера не менялись.

Реализация резкости сверена с [документацией Sharp](https://sharp.pixelplumbing.com/api-operation/#sharpen).
Чёрно-белый термоотпечаток остаётся стилизованным сувениром; настройка не
восстанавливает детали, которых камера не сняла. Для следующей проверки нужен
новый снимок при свете перед лицами, без яркого окна за спиной. Новый профиль
проверен программно и установлен в локальную службу; его качество на бумаге
ещё не подтверждено. Автоматической повторной печати прежней фотографии нет.

## Программные результаты и следующий шаг

Актуальный программный прогон в `.local/photo-mac-unit.log`: **27 тестов,
27 passed, 0 failed**. Покрыты
USB discovery/однократная передача stdin, неизвестный результат при таймауте,
Host/Origin/auth, запрет pairing и traversal, ограничения browser-адаптера,
сохранение pending при reload, raster, идемпотентность и восстановление заданий.
Добавлены проверки передачи большого изображения порциями без потери или
дублирования байтов, полос raster без промежуточной протяжки и сохранения
яркости цветного фото с видимым логотипом после composite/grayscale.
Дополнительно проверены осветление тёмных полутонов, различимость светлых
градаций, неизменность логотипа и сохранение обоих краёв кадра на трёх ширинах.
Изолированная web-сборка завершилась успешно (`.local/photo-mac-build.log`).

После исправления grayscale `tests/photo-printer/browser_mac.py` прошёл
(`.local/photo-mac-browser.log`):
камера, термопредпросмотр, пересъёмка, ровно одна отправка, автоматический возврат
на заставку, отсутствие внешних HTTP-запросов и записей в `localStorage`.
Этот browser-тест использовал синтетическую камеру Chromium и заглушку USB;
он не подтверждает настоящую камеру Mac, совместимость реального USB-принтера
или бумажный результат.

Следующий шаг - сравнить один новый отпечаток с более светлой обработкой.
Для установки в ресторан отдельно проверить iPad, ориентацию, серию заданий,
отсутствие бумаги и обрыв кабеля. Общая GitHub CI проверяется отдельно;
локальная приёмка не означает готовый выпуск iPad.
В отчётах фиксировать
качество, ориентацию и читаемость логотипа без реальных фото и приватных
идентификаторов. Новый `unknown` автоматически не повторять.

`docs/project-status.md` и `docs/roadmap/project.json` заняты задачей
`mobile-combo-rewards` и здесь не изменяются. После передачи области выполнить
reconciliation: перенести подтверждённые факты, точный коммит и результаты
физической приёмки в общий статус/roadmap и журнал координации. До этого данный
runbook фиксирует локальный программный этап, первый неудачный полный снимок,
успешный полный отпечаток после исправления транспорта и последующую коррекцию
яркости. Приёмка качества нового профиля остаётся открытой.
