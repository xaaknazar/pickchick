# Понятное сообщение продавца Kaspi

Решение владельца от 1 октября: вместо технической метки показывать номер заказа,
наименования, количество и выбранные модификаторы.

Пример: `Заказ №12: Pick Combo - 1 шт. (Coca-Cola 0,5 л, Сырный соус)`.
Источник - неизменяемый серверный снимок заказа. Телефон, имя клиента и свободный
комментарий в текст не добавляются. Бюджет приложения - 255 UTF-16 единиц (не подтверждённый лимит банка): длинный состав
сокращается с `ещё N поз.`, без разрыва Unicode. История старых счетов сохраняется.

## Номер и оплата

Edge schema015 резервирует display_number при допуске заказа до платежа и
сохраняет его при принятии кухней. Номер не разрешает готовить: held не содержит
задач кухни и authorized_event_id. Повтор команды возвращает тот же номер.
Миграция не перенумеровывает существующие заказы и не меняет правила смен.
Отменённые неоплаченные резервы могут оставлять пропуски в последовательности.
Старый held без номера получает номер при авторизации, как раньше.

Cloud/transport сначала должны принимать номер в held/released, затем обновляется
касса. Во время смешанной версии новый счёт без зарезервированного номера содержит
только состав: произвольный номер не подставляется.

## Восстановление после обрыва

Cloud schema029 сохраняет точный invoice_comment до запроса в банк, поле неизменно.
Случайная reference остаётся внутренней. Старые строки с NULL продолжают искать
старую банковскую метку. Для новых счетов нужны одновременно:

- единственная попытка с таким текстом в данном аккаунте и единственная точная
  запись Comment в истории (дубли, частичные совпадения и номер без состава не подходят);
- совпадающие сумма и идентификатор банковской операции;
- OrderRegDate с явным часовым поясом в интервале отправки: -5 секунд до начала,
  до requestTimeout +5 секунд после начала;
- ClientMobile из деталей банка совпадает с телефоном подтверждённого клиента.

Недостаточные/маскированные данные оставляют unknown; повторный счёт и зачисление
не выполняются. Телефон не записывается в сообщение или новый столбец. Формат полей
истории/деталей проверен read-only на существующих счетах, без создания нового.
