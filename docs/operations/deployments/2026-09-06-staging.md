## Найденная и исправленная проблема

Первый вариант подключал API только к internal Docker network. Внутренний smoke
проходил, но Docker не публиковал host-порт. Добавлен отдельный ingress bridge
только для API; проверка host-loopback включена в CI до/после restart. Прежний
образ `df213bc` не использовать как рабочий rollback target для удалённого доступа.
Первый рабочий стенд можно остановить `dc stop api` с сохранением БД.

## Оставшиеся задачи

Стенд инженерный, исключительно синтетический. Нет клиентских UI, публичного
HTTPS, входа пользователей, настоящего устройства ресторана и оплат/чеков.
Ежедневные копии лежат на том же VPS: отдельное backup-хранилище в РК, внешние
алерты, production PITR/HA и RPO/RTO не реализованы.

Root password policy, общий firewall и idrink не менялись. Пароль root из чата
владельцу следует заменить после проверки ключа и консоли восстановления.
ОС имела 188 ожидавших обновлений и reboot-required; обслуживание общего хоста
нужно проводить в согласованное с idrink окно. Дополнительно установлен только
пакет age, существующие контейнеры не перезапускались.

Следующий инфраструктурный этап: выделить публичный staging-домен и его защиту,
подключить независимое хранилище в РК, мониторинг и безопасный remote enrollment.
Работы каталога/quote по плану продолжаются независимо от готовности VPS.
