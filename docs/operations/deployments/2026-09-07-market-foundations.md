## Сохранность и эксплуатация

- Свежий PostgreSQL dump зашифрован age и проверен по SHA-256. Он восстановлен
  в отдельную временную БД на VPS; хеши строк всех 23 прежних таблиц и состояние
  последовательностей совпали. Временная БД удалена; live-БД не восстанавливалась
  поверх существующих данных.
- Миграции `007`–`013` применены новым provision; повторный provision прошёл.
  Старые migration checksum, строки и последовательности сохранились.
  Проверен точный набор ограниченных runtime grants для редактора каталога;
  identity/commerce/loyalty не получили runtime-доступ при выключенных доменах.
- Обновлены только PickChick API и собственный gateway. БД, Redis, соседние
  контейнеры и iDrink Caddyfile сохранили проверенные параметры; старые TEST
  capabilities и оба каталога v0.2/v0.3 совпали с исходными.
- Зашифрованная копия дополнительно скачана в приватное локальное хранилище
  оператора, SHA-256 совпал. Это отдельная копия, **не** настроенная автоматическая
  репликация резервных копий или PITR.
- Установлено задание `pickchick-ops` каждые 15 минут с привязкой к release SHA.
  Прежние записи crontab сохранены. Ручной первый запуск identity cleanup прошёл
  в **18:46:18 UTC**; SMS не отправлялись. Первый запуск именно по расписанию и
  внешнее оповещение о просроченном/неуспешном выполнении проверяются отдельно.

Дополнительная локальная [репетиция отката](../../../tests/operations/verification-rollback-api-compatibility-2026-09-07.md)
реально запустила прежний API на схеме 001–013 с восстановленными 48 прежними
ACL. Readiness, capabilities и оба TEST-каталога совпали. Старый provision
поверх новой схемы не запускался.

## Рабочий бэк-офис

Адрес: [редактор каталога](https://pickchick.185.129.51.103.nip.io/backoffice/).
Создан один отдельный управляющий с доступом только к существующей тестовой
точке. Его JSON credential сохранён вне Git в
`.local/catalog-owner/pickchick-catalog-manager.json`, права `0600`; токен не
выводился в терминал и не включался в URL. На странице входа выбирается этот файл.

24 блюда оригинального макета загружены как серверный черновик **r1**.
Сохранены описания, исходные цены, КБЖУ и модификаторы. `content_reviewed=false`,
опубликованной версии нет. Фактические составы, аллергены, переводы и налоговые
настройки требуют заполнения/проверки управляющим. Публикация нового каталога
не меняет автоматически старый TEST-каталог мобильного приложения и киоска.

После выпуска проверены:

- все **145 публичных runtime-файлов** по manifest/hash, пять SPA-маршрутов,
  шесть запретов приватных статических путей;
- **38 проверок HTTPS ingress**, сохранённые TEST capabilities, запреты
  внутренних и неподключённых маршрутов, обязательная авторизация;
- реальный вход управляющего в браузере, загрузка 24 блюд и редактор КБЖУ
  при ширинах **1680, 1280 и 1024 px**; фиксированное действие редактора видно,
  горизонтального переполнения страницы нет, JavaScript ошибок — ноль;
- браузерная проверка не отправляла команды записи; после заполнения исходного
  черновика реальные заказы, платежи, чеки и SMS не создавались.

Приватные доказательства, копия, журнал развёртывания и снимки экрана находятся
в `.local/market-release/7cd53b6300ad9147ddafb51cf84ed77027fb30d0/`.
В Git публикуется этот протокол, без credential, env, дампов и сырых ошибок.

## Граница выпуска

Это действующий **staging**. Новый редактор включён; customer auth/SMS,
реальный checkout, банк и фискализация выключены. HTTP аккаунтов и новые
внутренние commerce/loyalty модули присутствуют в коде, но не объявлены
production-интеграциями. Новая локальная кухня ещё не развёрнута на оборудовании
точки. TestFlight этим серверным выпуском не обновлялся; повторная проверка
мобильной сборки требует восстановления браузерной сессии Apple.

Физический пилот, постоянная установка iPad, cloud–edge transport, склад,
внешние интеграции и production gate остаются в
[реестре зависимостей](../launch-inputs.md) и [состоянии проекта](../../project-status.md).
