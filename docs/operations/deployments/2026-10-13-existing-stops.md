## Первая попытка и исправление

Попытка `afb48570` 12 октября в 12:02 UTC была остановлена проверкой NTFS. При атомарной
замене Windows сохраняет наследуемую DACL назначения; прежняя проверка ошибочно
требовала protected DACL. Исходные байты env восстановлены, но та же ошибка
оставила `rollback_verified=false`. Запись сохранена без изменения.
Независимая проверка подтвердила исходный env, ready, runtime/schema/menu ACK,
шесть работающих служб и четыре неизменённых соседних PID.

В новом операторе сравниваются исходные owner/group/protection/ACE, ACL включена
в CAS плана. Проверки прав не ослаблены; лишний writable principal отклоняется.
Регрессия воспроизведена и исправление проверено на настоящих временных NTFS-файлах.
Выпуск выполнен новой попыткой после полной CI, старый attempt сохранён.
Промежуточный CI `38247793231` выявил вызов Windows ACL в Linux-тесте; portable
byte/SCM suite отделена от настоящих Windows ACL, новый CI выше прошёл полностью.

При первом серверном backup общий recipient принадлежал второму Mac, поэтому
restore с ключом финансового Mac не прошёл. API и права БД не менялись;
исходный baseline независимо совпал с планом, временная restore-БД удалена,
собственная блокировка освобождена после проверки. Исправленный backup использует
public recipient локальной identity, как уже установленный кадровый оператор.
Общий recipient и чужие ключи не менялись. Включение на Windows выполнено
оператором `22f167d1` (Foundation CI 38247970211), затем новым оператором
повторена read-only проверка без дополнительного перезапуска.
