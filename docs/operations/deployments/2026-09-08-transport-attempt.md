# Остановленная попытка обновления транспорта

8 сентября 2026, staging VPS PickChick. Source попытки:
`dccc516f0d75f5bdbfb183b097ded4c11a228a09`.
[Все шесть CI jobs](https://github.com/xaaknazar/pickchick/actions/runs/34158903648)
прошли. `prepare` создал отдельные API/web artifacts без изменения действующих
сервисов. Эта запись **не подтверждает успешное применение выпуска**.

## Отказ до изменения схемы

`apply` взял собственный deployment lock и существующий cleanup flock, затем
переключил только PickChick gateway на временную заглушку. Контейнер не смог
прочитать `/etc/caddy/maintenance.json`: `permission denied`.

Файл был создан оператором UID 1000 с правами `0600`. Caddy работал от root,
но с `cap_drop: ALL` и без `DAC_OVERRIDE`; root внутри такого контейнера не
может обойти права чужого файла. В прежней Docker-репетиции владелец файла
совпадал с пользователем контейнера, поэтому это отличие VPS не было проверено.

Compose завершился с определённой ошибкой unhealthy. Helper остановился на
`stopped_before_proven_baseline`, сохранив locks. Прежний API `7cd53b6` продолжал
работать; в ledger оставалось ровно 13 миграций. API ещё не останавливался,
baseline и backup не создавались, provision/миграция 014 не запускались.
Доступ через gateway временно был нарушен.

## Проверенное восстановление

Тот же оператор после завершившейся команды проверил exact owner UUID,
неизменные rollback artifacts/image, оба прежних pointers, работающий API,
точные 13 ledger checksums, cleanup owner/flock и фактическую maintenance command.
Автоматический retry или присвоение чужого lock не выполнялись.

Затем запущен прежний штатный gateway из `7cd` без изменения API/БД. Проверены
его manifest/config, readiness API, старые capabilities и TEST-каталоги,
авторизация CMS и закрытые публичные маршруты. После успешных проверок
освобождены cleanup flock и только принадлежащий этой попытке deployment lock.
Восстановление завершилось **7 сентября 2026 в 20:40:29 UTC**
(8 сентября 01:40:29 по Алматы).

Дамп поверх БД не восстанавливался; migration 014 не применена этой попыткой.
Существующие данные не объявляются неизменными за всё окно: API до остановки
gateway мог законно принять запросы. Доказано отсутствие запуска миграции и
восстановление прежних сервисов.

## Исправление и повторный выпуск

Исправление даёт `0644` только несекретному `maintenance.json`.
`owner.json`, Compose metadata и приватный каталог сохраняют `0600`/`0700`;
полномочия контейнера не расширяются. Предварительный `caddy validate` теперь
также запускается с ограничениями контейнера, до изменения gateway.
[Linux-регрессия](../../../tests/operations/evidence/maintenance-permissions-2026-09-08.json)
воспроизвела старый отказ на файле UID 1000 при фактических ограничениях
production Compose и подтвердила 503 с отдельным container health после
исправления. Все собственные контейнер, сеть и volume удалены; 26 offline-проверок
прошли. На VPS после восстановления также прошёл штатный cleanup в 20:45 UTC.

Следующая попытка требует нового immutable source, всех шести CI jobs и нового
`prepare`. Artifacts неудавшегося `dccc516` не перезаписываются и не выдаются за
проверенный выпуск. Приватные журналы и recovery evidence находятся в
`.local/transport-release/dccc516f0d75f5bdbfb183b097ded4c11a228a09/` и не публикуются.
