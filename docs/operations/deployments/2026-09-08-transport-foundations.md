# Проверенный VPS-выпуск транспортного фундамента

8 сентября 2026 API и публичные web artifacts PickChick staging обновлены до
`93b14e7f8491645dcf8ed2aabdd501afc6481a90`. Cloud schema — `001`–`014`.
[Все шесть CI jobs](https://github.com/xaaknazar/pickchick/actions/runs/34160995354)
прошли именно для этого source. [Изменения и review](https://github.com/xaaknazar/pickchick/pull/22).

## Фактическое применение

Использован [отдельный профиль обновления](../transport-release.md) с прежнего
API/web `7cd53b6300ad9147ddafb51cf84ed77027fb30d0`, schema 013. Предыдущая
[неудавшаяся попытка и восстановление](2026-09-08-transport-attempt.md) сохранены
отдельно; её artifacts не перезаписывались.

После успешной проверки ограниченным Caddy временно закрывался только наш
gateway. Существующий cleanup удерживался тем же Linux flock, API был остановлен
до снимка данных. По журналу closing начался 7 сентября в `21:09:35 UTC`,
доступ снова открыт в `21:12:03 UTC`; итоговые проверки закончились в
`21:12:08 UTC` — 8 сентября `02:12:08` по Алматы.

Проверено на действующем VPS:

- Свежий зашифрованный `pg_dump` восстановлен в отдельную временную БД;
  совпали все строки и sequences **69 прежних таблиц**, временная БД удалена.
- Provision выполнен дважды; добавлены только migration 014 и **шесть пустых
  транспортных таблиц**, новых sequences нет. Старые ledger rows, включая
  время применения, сохранены.
- Все прежние row hashes и runtime table/column/sequence ACL совпали до
  повторного открытия доступа. Каталог, TEST-заказы и аккаунтные таблицы
  не перезаписывались.
- За закрытым gateway реально запускался старый точный image `7cd` на новой
  схеме 014, затем возвращён новый image. Старый provision/migrate не запускался.
- Проверены фактические API image, web manifest/config и переключение двух
  наших pointers. Соседние контейнеры и конфигурация iDrink не изменились.
- Cleanup pin `7cd` и crontab сохранены; собственные cleanup/deployment locks
  освобождены после успешных проверок. Новый таймер не устанавливался.

После открытия разрешены обычные пользовательские записи; совпадение live-БД
со старым снимком после этого не утверждается. Дамп поверх действующей БД не
восстанавливался ни на одном этапе.

## Проверки после открытия

- **38 HTTPS/ingress checks** прошли; внутренние/реальные финансовые маршруты
  остаются закрыты.
- Хеши **145 web-файлов**, пять SPA-путей и шесть запретов на приватные static
  paths совпали с подготовленным manifest.
- Настоящий scoped вход управляющего прочитал бэк-офис: **24 блюда**, черновик
  **r1**, не опубликован. Проверка не отправила ни одного HTTP-запроса записи.
- Зашифрованная копия размером **320 447 bytes** сохранена также приватно на
  компьютере владельца и проверена по SHA-256. Это разовая копия; автоматическое
  внешнее резервирование/PITR этим действием не настроены.
- Первый штатный cron после выпуска стартовал **7 сентября в 21:15:01 UTC**
  и завершился успешно: прежний cleanup image `7cd` работает на schema 014.
  Дополнительно подтверждено отсутствие deployment lock.

[Открыть бэк-офис](https://pickchick.185.129.51.103.nip.io/backoffice/).
Существующий приватный JSON-доступ управляющего не заменялся.

## Граница выпуска

`TEST_ORDER_FLOW_ENABLED` и `CATALOG_ADMIN_ENABLED` включены.
`CUSTOMER_AUTH_ENABLED`, `EDGE_FULFILLMENT_ENABLED`,
`CLOUD_FULFILLMENT_TRANSPORT_ENABLED`, `EDGE_FULFILLMENT_TRANSPORT_ENABLED`
остаются `false`. Реальные SMS, Kaspi, ККМ и финансовый checkout не активированы;
credential устройства или ресторана не выдавался автоматически.

Cloud transport code установлен, но связь с физическим edge ещё не включена.
Edge schema 006, новый LAN-клиент и worker не установлены на ресторанное
оборудование этим VPS-выпуском. Подэтап отмены 015/007 находится отдельно в
[PR #23](https://github.com/xaaknazar/pickchick/pull/23); все шесть
[CI jobs его source `ad660387`](https://github.com/xaaknazar/pickchick/actions/runs/34161193112)
прошли, но он ещё не развёрнут. Новые TestFlight builds этим серверным выпуском
не загружались.

Приватные backup, before/after evidence, CI proof и журналы находятся в
`.local/transport-release/93b14e7f8491645dcf8ed2aabdd501afc6481a90/`; в Git
сохранён только этот обезличенный протокол. Рыночная приёмка, физический WAN
тест, production SLO и интеграции остаются отдельными воротами roadmap.
