## Процедура

`infra/staging/release-finance-dashboard.py` использует существующие owned
deployment/cleanup locks, maintenance, immutable artifacts, CAS указателей
и явное продолжение rollback. Исторический finance-ledger helper не изменяется.
Новый профиль фиксирует установленный baseline41d; gateway и compose сохраняются
побайтно, миграции/права не меняются. Из public заменяется только backoffice.
Все окружение API, политики доступа/оплаты, ACL и соседние контейнеры проверяются.

Полный snapshot для backup/restore не исключает поля. В runtime-сравнении
нормализуется только availability heartbeat; привязки и стоп-листы сравниваются
полностью, монотонность revision/observed_at проверяется отдельно.

Проверки anonymous finance используют валидные даты и JSON, чтобы проверять
именно отказ авторизации. Дополнительно проверяются доступность новых JS,
сохранение маршрутов меню/сессий и закрытие платёжных маршрутов киоска/TipTop.
Проверки не создают реальных финансовых записей, заказов или банковских запросов.

## Резервная копия и откат

Финансовый Mac создал отдельную локальную age identity в приватном файле
`~/.ssh/pickchick-finance-backup/identity.agekey` с правами 0600. В Git и журналы
содержимое не выводится. Для локальной работы используется официальный
[age v1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2), архив
darwin-arm64 проверен по опубликованному GitHub asset SHA256
`e2020b073c44f692685a24d6abc378817eb81ffaaf49fd0531ef8565f767f2f5`.

Копия шифруется одновременно на прежний recipient сервера и recipient
финансового Mac. Файл прежнего recipient и расписание резервирования не меняются.
Дамп не скачивается на Mac и не публикуется. Ключ подаётся через SSH stdin,
восстановление выполняется только в отдельную временную БД. Полные таблицы
и sequences сравниваются; после успешной проверки временная БД удаляется.
Неизвестный результат restore сохраняет временную БД и блокировки до диагностики.

Старый API несовместим с новыми операциями без счёта. Поэтому полный rollback
допустим только при неизменных финансовых/предметных данных; при новых записях
он останавливается, ничего не удаляя. После начала ввода новых операций нужен
совместимый API, даже если откатывается интерфейс. Production dump не восстанавливается.
