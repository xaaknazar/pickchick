## Проверки

Перед выпуском прошли TypeScript, Vite build, ESLint/формат, пять browser-групп
staff/display, восемь сценариев восстановления киоска, проверка его геометрии
и пять тестов упаковки. В браузере проверены роли, состояния API, stale,
независимые страницы очередей, отсутствие удалённых элементов и размеры
1920×1080/1280×720. Использовались локальные HTTP fixtures.
[Просмотренные изображения и воспроизведение](../../../tests/operations/screenshots/operations-display/README.md).

После переключения прошли:

- SHA-256 всех 147 опубликованных runtime-файлов, пять SPA-маршрутов
  и шесть запретов публикации приватных файлов.
- Все 38 существующих ingress smoke-проверок; служебные API остаются закрытыми.
- Read-only вход в приготовление, сборку, табло и управляющего, открытие киоска:
  57 HTTP-чтений, ноль команд изменения данных, ноль ошибок JavaScript.
- Визуальный просмотр опубликованного табло 1920×1080 после загрузки шрифтов/фона.
- Фактический read-only mount gateway, manifest и атомарный public pointer
  соответствуют новой версии. Собственный deployment lock освобождён.

Обновлён только `pickchick-public-gateway`. Идентификаторы, образы и время старта
API/PostgreSQL/Redis и трёх соседних контейнеров совпали до и после выпуска.
API readiness подтвердил database/schema/redis up. Конфигурации gateway,
общего входного Caddy и файлы остальных web-приложений сохранены.
Миграций, изменений feature flags, заказов, SMS или финансовых команд не было.

GitHub Actions ранее сообщил об ограничении оплаты аккаунта либо spending limit;
[CI опубликованного source](https://github.com/xaaknazar/pickchick/actions/runs/34218391326)
также завершён с failure до выполнения шагов во всех шести jobs.
Локальные результаты не означают зелёный удалённый CI. Применено только явно
описанное исключение для этого staging UI. Приёмка на физическом LED-экране
ресторана ещё не выполнена. Реальные продажи и TestFlight этим выпуском не включены.

## Возврат

Предыдущий immutable release `93b14e7f8491645dcf8ed2aabdd501afc6481a90`
и его исходные Compose/Caddyfile сохранены. При необходимости под deployment lock
повторно проверить актуальный pointer, запустить только gateway через прежний
`infra/public-staging/compose.yaml`, проверить
mounts, static/ingress smoke и атомарно вернуть public pointer. Не перезаписывать
чужой более поздний выпуск. API pointer и БД для возврата этого UI не меняются.

Конфигурации и приватные ключи доступа в Git не включены. Проверки не создавали
заказы на VPS; локальные фикстуры не являются заказами ресторана.
