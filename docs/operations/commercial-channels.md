# Общий каталог и коммерческий киоск - 4 октября 2026

## Реализованный этап

Каталог директора может одной транзакцией опубликовать коммерческий снимок,
локальное меню и событие durable outbox. Отдельное соответствие версий сохраняет
историю: версия коммерческого каталога не заменяет версию edge-меню.
Статус `applied` требует ACK точного снимка от активного устройства, которое
сейчас привязано к исполнению заказов этой точки. Потерянный ACK вызывает
повтор доставки, без повторной публикации. Старые оплаченные заказы и выданные
котировки сохраняют свой состав и цену.

В этом этапе поддержаны общие цены. Различающиеся цены по каналам явно
отклоняются при публикации на edge: действующая касса не умеет выбирать такой
прайс. Право директора менять разные цены остаётся следующим этапом.

Коммерческий киоск использует отдельные устройство и гостевой сеанс. Телефон
нужен для счёта Kaspi, не создаёт аккаунт клиента и не даёт доступ к его истории
или бонусам. Устройство и сеанс проверяются сервером; секреты хранятся как хеши,
телефон - AES-256-GCM с привязкой к сеансу и точке. Телефон неизменяем после
первого запроса оплаты. После суток он удаляется, если нет незавершённой
банковской попытки. Завершение гостевого сеанса не останавливает банковскую
сверку. На сеанс допускается один заказ.

Проверяются версия каталога, стопы, часы ресторана, доставка меню и сумма.
Сервер сам считает модификаторы. Киоск сравнивает котировку с показанной гостю
суммой и при изменении возвращает к корзине до создания заказа. Однозначный
отказ котировки также позволяет исправить корзину. Потеря ответа после создания
заказа сохраняет намерение в SecureStore и восстанавливает тот же заказ.
Повтор оплаты использует один серверный ключ. Только подтверждение банка
зачисляет деньги и разрешает последующее исполнение. Канал `kiosk` проходит
облачную авторизацию кухни; права неоплаченного кассового заказа не расширены.

Клиентское состояние и особенности native-настройки: [киоск](../../apps/kiosk/COMMERCIAL.md).

## Переключатели и договорённости

Все новые переключатели по умолчанию выключены:

- `CATALOG_EDGE_PUBLICATION_ENABLED=true` и `CATALOG_EDGE_PUBLICATION_BRANCH_ID`
  включают публикацию меню на единственную выбранную точку.
- `KIOSK_CHECKOUT_ENABLED=true`, `KIOSK_CHECKOUT_ORGANIZATION_ID`,
  `KIOSK_CHECKOUT_BRANCH_ID`, `KASPI_REMOTE_ACCOUNT_ID` задают серверную область.
- `KIOSK_CHECKOUT_PII_KEY` - отдельный приватный ключ из 64 hex-символов.
  Он нужен API и платёжному worker; его сохраняют для восстановления старых
  платежей, даже когда оформление новых заказов выключено.
- `KIOSK_CHECKOUT_FISCAL_POLICY` по умолчанию `required`, тогда обязателен
  `KIOSK_CHECKOUT_FISCAL_ACCOUNT_ID`. Режим `deferred_pilot` включается отдельно
  оператором только для согласованного пилота; пользователь киоска его не выбирает.
- `KIOSK_CHECKOUT_APPROVAL_REFERENCE`, `KIOSK_CHECKOUT_TAX_CODE` и
  `KIOSK_CHECKOUT_MAX_MINOR` задаются оператором. Максимум по умолчанию 10000
  минимальных единиц (100 тенге). Налоговый код нельзя придумывать.
- Часы берутся из существующих `CUSTOMER_KASPI_OPENING_TIME`,
  `CUSTOMER_KASPI_CLOSING_TIME`, `CUSTOMER_KASPI_TIMEZONE`; для киоска они обязательны.
- `EXPO_PUBLIC_KIOSK_COMMERCIAL=1` выбирает коммерческий native-клиент.
  Device key запрещено помещать в Expo public env. TEST-путь остаётся отдельным.

## Контракт API

Маршруты `/v1/kiosk-checkout` требуют `X-Kiosk-Device` и `X-Kiosk-Key`.
Кроме создания сеанса нужен `Authorization: Bearer <guest token>`.
Все ответы помечены `Cache-Control: no-store`.

| Метод и путь                               | Назначение                                                          |
| ------------------------------------------ | ------------------------------------------------------------------- |
| POST `/sessions`                           | Идемпотентно зарегистрировать заранее сохранённые sessionId/token   |
| POST `/sessions/end`                       | Завершить гостевой доступ; повтор после потерянного ответа допустим |
| GET `/config`, `/catalog`, `/availability` | Настройка, опубликованный снимок, свежие стопы                      |
| POST `/quotes`                             | Рассчитать SKU/модификаторы в целых минимальных единицах            |
| POST `/orders`                             | Создать один заказ из принадлежащей этому гостю котировки           |
| POST `/orders/:id/payment`                 | Закрепить номер и поставить одну попытку Kaspi в outbox             |
| GET `/orders/:id`                          | Прочитать только собственный kiosk-заказ                            |

Коллизия предложенного guest UUID с UUID клиента не даёт доступа между
каналами: quote/order/payment/history/feedback проверяют канал и customer_id
в дополнение к principal и точке. Kiosk worker читает только гостевые kiosk-заказы.

## Установка отдельно от реализации

Этот этап не обновляет VPS, кассу или iPad и не выставляет реальные счета.
Сейчас нельзя включать только клиентский флаг поверх прежнего API.

Перед установкой нужны точный зелёный CI-коммит, резервная копия и штатные
блокировки выпуска. Установить cloud034-036, edge017 и согласованные версии
API, Kaspi worker, edge/transport и кухни. Edge017 допускает предоплаченный
kiosk-канал, сохраняя ограничения неоплаченного POS. Старые скрипты выпуска с
фиксированным списком миграций нельзя использовать как готовый выпуск этой версии.

После обычных прав применяются явные дополнения из
`infra/staging/commercial-channel-grants.mjs`: каталог, киоск и worker имеют
разные права; наблюдение банковских денег киоску не выдаётся. На gateway добавить
только перечисленные методы/пути и сохранить фильтрацию внутренних маршрутов.
Секретные заголовки и тела не должны попадать в access/debug логи.

`node scripts/provision-kiosk.mjs` создаёт запись устройства и приватный файл
0600 согласно параметрам CLI. Затем доверенный native enrollment должен записать
ключ в SecureStore. Операторский экран enrollment и установка на физический iPad
ещё не реализованы/не приняты. Коммерческий web намеренно выключен: хранить
credential устройства в localStorage нельзя.

Публикация рабочего каталога включается после сверки с ценами PickChick Dev,
подтверждения ACK кассой и проверки стопов. Для киоска дальше необходимы
нативная проверка восстановления/клавиатуры/очистки гостя, один согласованный
реальный счёт, передача именно этого заказа кухне и проверка отмены/истечения.
Webkassa, Smart POS кассы, публичный запуск и автономная смена этим этапом
не подтверждены.

## Проверки

Включены PostgreSQL-проверки публикации/ACK, изоляции сеансов и каналов,
серверного расчёта, одного заказа/счёта, шифрования и восстановления платежа.
Банк в тестах подставной: реальные списания и чеки не выполняются.
Клиентские проверки покрывают стопы, изменение суммы, потерянные ответы,
повтор запроса и очистку данных. Проверены ограничения runtime-ролей.
Точные результаты этапа записаны в `docs/project-status.md`; аппаратная
и визуальная native-приёмка остаются отдельными отметками.
