# Два моноблока: касса с сервером и переключаемая кухня

14 сентября 2026 владелец подтвердил Windows 10 Pro на обоих устройствах,
общую локальную сеть и размещение серверной части на кассовом моноблоке.
[Решение и последствия](../architecture/adr/0009-two-windows-workstations.md).
Это порядок монтажа; успешная установка на Windows пока не подтверждена.

## Что устанавливаем

| Устройство | Компоненты                                                         | Назначение                                                           |
| ---------- | ------------------------------------------------------------------ | -------------------------------------------------------------------- |
| Касса      | PickChick POS + отдельная установка PostgreSQL/edge и нужных служб | Кассовый интерфейс и постоянное локальное хранение заказов           |
| Кухня      | PickChick Kitchen + защищённое соединение с кассой                 | Крупные кнопки приготовления, сборки и выдачи; отдельный режим табло |

IP-адреса переданы владельцем и сохраняются в приватной карточке монтажа,
а не в общих установщиках. Нужно проверить маску сети на обоих устройствах:
разные третьи октеты адресов сами по себе не доказывают ни разрыв, ни общую LAN.
На Mac проверена маска /23. Сетевые настройки Windows пока не прочитаны.

Доступные POS-артефакты: [поставка 0.1.0](releases/2026-09-08-windows-pos-preview.md).
Кухня: [Windows-поставка 0.1.0](releases/2026-09-14-kitchen-windows-preview.md).
Кассовый installer не содержит backend. После его установки без edge можно
увидеть вход, но нельзя объявлять сервер установленным или принимать продажи.

Кухня использует реальные назначения станций. Одному сотруднику с ролью `kitchen`
выдаются prep и assembly; кнопки видны по данным API. Сборка включает подтверждение
выдачи готового заказа. Неизвестный результат команды блокирует переключение
до восстановления. Доступ управляющего ради смены экрана не требуется.

## Последовательность на точке

1. Получить разрешённый удалённый доступ или выполнить установку с сотрудником
   на месте. TCP-проверка SSH/RDP/WinRM на переданных адресах ответа не получила;
   это не доказывает, что устройства выключены. Публичный VPS не заменяет доступ
   к этим Windows. 15 сентября сеанс кассы принят, рабочий стол виден. Обрывы
   `anynet_unknown` удалось остановить параметром `/np` из
   [инструкции AnyDesk](https://support.anydesk.com/session-has-ended-unexpectedly).
   Затем AnyDesk/инструмент управления на Mac перестал отвечать; требуется
   восстановить управление. Установка на Windows ещё не подтверждена.
2. Прочитать Windows build/x64, RAM, свободный диск, сетевые маски/шлюз, подключённые
   устройства и существующие службы. Зафиксировать размещение iiko, если оно есть,
   и сохранить её данные/настройки. Не накатывать dev compose или общую seed-команду
   поверх действующих баз.
3. На кассе подготовить отдельные пути и роли PostgreSQL/edge, контролируемый запуск
   и остановку. Мигрировать только новую целевую edge-БД; не выполнять общий
   `scripts/migrate.mjs`, который также обращается к cloud, без явного выбора базы.
   Данные тестового fixture не становятся реальным меню/платежами ресторана.
4. Закрепить адрес кассы/имя в сети, настроить защищённый канал кухни. PostgreSQL
   остаётся loopback. Для SSH-туннеля нужны проверка host key, отдельный ключ
   кухонного устройства, ограничение порта и сопровождение переподключения.
   OpenSSH является доступным компонентом Windows 10 при выполнении требований
   версии; наличие компонента проверяем на устройстве.
   [Инструкция Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse).
5. Установить клиент кассы на первый моноблок и клиент кухни на второй. Проверить
   x64 и SHA-256 артефакта. Установщики preview пока без Authenticode-подписи;
   системную защиту ради установки не отключать, блокировку разбирать по её сообщению.
6. Выдать отдельные сессии сотрудников/терминалов, два kitchen-назначения и реальную
   конфигурацию станций/меню. Права и токены не помещаются в URL, EXE или общий ярлык.
7. Настроить автозапуск, обновления и питание. Сервер кассы должен переживать закрытие
   POS и повторный вход Windows; произвольный сон кассы прерывает обслуживание кухни.
8. На тестовых помеченных данных проверить очередь, touch/масштаб, смену станций,
   табло, потерю ответа и reboot. Затем отдельно принимать реальные банк/ККМ/выдачу.

## Передача установщиков по локальной сети

`scripts/workstation-downloads.py` предназначен только для временной передачи
проверенных EXE с Mac на указанные рабочие места. Он проверяет SHA-256 manifest,
держит проверенные байты, отдаёт только точные имена EXE и страницу установки,
проверяет Host и allowlist IP. Нет листинга папок, загрузки файлов на Mac,
служебных токенов, произвольных URL и публикации репозитория.

Manifest хранится рядом с EXE вне Git:

```json
[
  {
    "file": "PickChick-POS-Setup-0.1.0-x64.exe",
    "label": "Кассовый моноблок",
    "sha256": "37e37d87fb18c20ffa56683e7b0b3737c01736cf2617e7d59134b219b29cf6d3"
  }
]
```

В параметры `--bind`, `--allow` и `--manifest` передаются реальные локальные значения.
Бинд - конкретный IP Mac, не `0.0.0.0`; `--allow` повторяется для каждого устройства.
Страница требует включённого Mac и доступности LAN. После передачи процесс
останавливается; постоянная работа кассы/кухни от Mac зависеть не должна.
HTTP здесь передаёт только несекретные установщики. Сессии и рабочие API через
этот сервер не обслуживаются. Если сеть изменится, адреса/доступ проверяются заново.

## Что остаётся до коммерческой смены

Отдельные edge-only миграция, ограниченные runtime grants БД и проверка NTFS ACL
для staff-файлов реализованы: [команды и проверки](../../infra/windows/README.md).
В интеграционной ветке прошли 13 тестов с PostgreSQL и kitchen HTTP, Unix-файлами
и ACL fixtures; выполнение PowerShell на физическом Windows ещё не принято.
Перед фактическим монтажом нужны узкий setup меню/станций, проверка защиты
device credentials и установка служб.
Обычная команда `sc create` для `node.exe` также не заменяет Windows service wrapper.
Edge сейчас допускает `APP_ENV=local`/`test`, а не production-конфигурацию;
режим стенда не переименовывается в production ради установки.

Закреплённые зависимости backend нужно упаковать отдельно от Expo и clients,
включая `dist`, edge migrations и setup, без внешних symlink, dev-данных и секретов.
Выбор конкретного supervisor, версии Windows PostgreSQL и прав подтверждается
инвентаризацией устройства и запуском реальной команды под runtime-ролью.
Staff-сессии текущего ядра истекают через 8 часов; штатный повторный вход/выдача
доступа и поведение после перезагрузки входят в приёмку, бессрочный вход не обещан.

Оплаты/ККМ/периферия, рабочие денежные смены, допуск POS-заказов на кухню,
обмен с центром, backup/restore, физические WAN/LAN/питание и нагрузка.
Два установленных окна не закрывают эти требования. Полный список:
[Windows POS](windows-pos.md), [локальная кухня](lan-kitchen-client.md),
[автономность и переход с iiko](../03-offline-and-reliability.md).
