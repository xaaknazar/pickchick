# Панель статуса заказа - 27 сентября 2026

## Решение владельца

Новый визуальный источник для статуса - два присланных скриншота приготовления
и готовности: открывающаяся снизу неполноэкранная панель, ресторан, действия,
закрытие, номер/имя, персонаж, время/этап, карточки блюд и игровое предложение.
Остальные экраны и брендбук не заменяются. Применены UI/UX Pro Max (React Native:
доступные действия, анимация на UI thread) и Impeccable (motion/craft/native).

## Реализация

- `/order-status` - transparent modal с существующим OrderSheet: подъём 340 ms,
  закрытие 210 ms, жест за ручку, Back/Escape и Reduce Motion. Исторические
  `/screen/M17`, M18 и M20 перенаправляются в эту же панель.
- После оформления убираются предыдущие корзина/checkout из стека. Закрытие
  возвращает к основному экрану, а не к повторной отправке заказа.
- Ресторан определяется по branch_id, имя - из текущего профиля; неизвестную
  точку не подменяем первой. Номер не форматируется заново на клиенте.
- `OrderChef` использует две новые прозрачные фирменные 3D-иллюстрации:
  фритюрница и поднос. Это анимированные растровые сцены, не интерактивная
  3D-модель с ригом. Pause/reduced motion/focus/background учтены.
- Статус следует существующим событиям заказа: кухня, сборка, готовность, выдача,
  отмена. Дополнительного опроса API нет. 15-секундный локальный таймер обновляет
  только подпись прошедшего времени; он не отправляет запросов и не меняет статус.
- Показывается прошедшее время с создания или время серверного обновления
  готовности/выдачи в Алматы. Обещаний «осталось три минуты» и выдуманной скорости нет.
- При приготовлении - горизонтальные карточки с фото из каталога, сохранёнными
  названием, модификаторами, количеством и ценой. После готовности состав скрыт
  за отдельным действием, но остаётся доступен.
- Pick Blocks открывается отдельным игровым экраном с возвратом к статусу.
  На готовности приглашение меняется на «Ещё один раунд?».
- Меню действий: поддержка, обновление, отмена во время приготовления.
  Внизу: чек, поддержка, адрес/способ получения. После выдачи - существующая
  форма оценки. Обращения/отзывы используют прежние API и idempotency.
- Настоящий чек по-прежнему не выпускается: раздел сообщает, что подключение
  оплаты/чеков в процессе. Нет фиктивного fiscal URL или успешной оплаты.
- Галерея M17/M18/M20 использует тот же компонент с явно обозначенным примером,
  без записи заказа и вызовов кухонных операций.

## Проверки

- Mobile typecheck и адресный ESLint/Prettier прошли.
- 178 Node + 30 Python mobile-тестов прошли; добавлены проверки этапов и времени
  (включая пустые задачи, смещение часов и остановку времени готовности).
- Expo export iOS/Android/web прошёл. Живые Dev manifest и JS bundles обоих
  native-платформ вернули HTTP 200; Metro запущен на этом Mac.
- CUA, изолированный настоящий API/PostgreSQL, Telegram заменён локальной
  заглушкой: вход вымышленного клиента, комбо, оформление без оплаты,
  панель приготовления, действие кухни и автоматическая готовность пройдены.
  Поддержка и честное состояние чека открываются для того же заказа. Pick Blocks
  открывается из панели и возвращает в тот же заказ; готовность восстанавливается
  после перезагрузки.
- Веб-снимки 393×852, 320×568 и 768×1024 сверены с композицией владельца:
  шапка, номер, центральная сцена, время, статус, горизонтальный состав.
  Сохранены фирменные тёмно-синий/синий/оранжевый и Jost/Manrope.
- Impeccable detector не выдал замечаний. Он не заменяет визуальную проверку.
- Сценарий `tests/mobile/browser_orders.py` обновлён: панель, закрытие/повторное
  открытие, события сборки/готовности/выдачи, скрытие состава и старые отзывы/
  поддержка/чек. Локально Python browser-automation не запускалась; CUA описана выше.

## Границы выпуска

Нового TestFlight, VPS API/БД, кухни и платежей этот этап не выпускает.
Физические iPhone/Android, VoiceOver/TalkBack, Dynamic Type и FPS ещё не приняты;
web-снимки и JS export не являются доказательством нативной приёмки.
Базовая Foundation CI 3ef80c9 завершилась failure (36248802188); новая CI должна
быть проверена отдельно. До полной зелёной CI онлайн-roadmap не обновляется.
Продолжение серверного пилота и вопрос хранения остаются в `server-pilot.md`.
