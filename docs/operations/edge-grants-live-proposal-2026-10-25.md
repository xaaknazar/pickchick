# Предложение: запрет сброса прав на живой кассе

Отдельная задача `edge-grants-proposal-1024`, вне PR277. Это проект исправления,
не изменение действующего инструмента и не разрешение на выпуск.

## Причина

`scripts/edge-runtime-grants.mjs <role> --cloud-link` вызывает
`applyEdgeRuntimeGrants` из `infra/windows/edge-runtime-grants.mjs`.
Операция пересоздаёт набор прав роли и отзывает ранее выданные права, включая
права терминалов и присутствия. Добавление двух колонок для состояния интернета
не должно менять остальные привилегии. Проблема касается повторного вызова
общего инструмента и без `--cloud-link`.

## Предлагаемое изменение

1. До первого `REVOKE` в транзакции проверить точный ledger и наличие действующего
   набора прав роли. Для schema020+ запретить reset существующей runtime-роли,
   независимо от наличия `--cloud-link`. Не добавлять обход `--force`.
2. В CLI отклонять `--cloud-link` с ясной ссылкой на охраняемый
   `infra/windows/cloud-link-grant.mjs inspect|apply|revoke` из этапа 2.
   Чистое первоначальное развёртывание и изолированные тестовые схемы отделить от
   обслуживания установленной кассы. Разрешение первоначальной установки проверять
   по состоянию БД, а не по одному флагу пользователя.
3. Не менять исторические установщики, закреплённые хешами. Их схемы до020 и
   воспроизводимость архивов сохранить. В тестовом офлайн-стенде получать cloud-link
   через отдельную аддитивную функцию с теми же ограничениями, не через reset.
4. На живой кассе до этого исправления применять только охраняемый инструмент
   `cloud-link-grant.mjs`: он сравнивает весь набор прав до/после и допускает только
   две заданные колонки. Никаких общих reset-команд.

## Обязательные проверки будущего исправления

- Реальная изолированная PostgreSQL schema023/024, runtime с правами терминалов,
  присутствия и restore-fence: старый CLI с флагом и без него отказывает до изменения.
- Снимок прав таблиц, колонок, последовательностей, функций и схемы совпадает после отказа.
- Аддитивное apply меняет только две колонки; повтор идемпотентен; revoke сохраняет
  все остальные права. Ошибка в середине транзакции не оставляет частичного состояния.
- Старые первоначальные установки и контрольные хеши исторических файлов проходят.
- Полная Foundation CI и отдельный PR. Выпуск и применение прав - по отдельному решению.
