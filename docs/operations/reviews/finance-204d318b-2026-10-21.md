## Вердикт

**204d318b не принят для включения в следующий выпуск API по полному перечню
критериев владельца.** Серверные финансовые инварианты подтверждены; блокирующее
несоответствие - интерфейс на актуальном shared называет ранний месяц открытым,
хотя закрытый поздний месяц запрещает операции в нём. Это нарушает явный критерий
приёмки о понятном объяснении неявно заблокированных периодов.

Исправление интерфейса и дополнительные проверки подготовлены в отдельной ветке
`codex/finance-acceptance-1021`. Исходный финансовый коммит повторно не переносился,
серверный финансовый код не менялся. PR не сливается этой задачей. Для снятия
блокировки необходимо принять исправление интерфейса, проверить CI точного
совместного SHA и зафиксировать повторную приёмку перед отдельным выпуском.
Положительные локальные проверки исправления не являются разрешением на выпуск.

## Найденный дефект интерфейса

При `2026-09: closed=true` и `2026-08: closed=false` старый интерфейс выводил
`Статус 2026-08: открыт`, таблица - `Открыт`, а кнопка открытия была доступна.
Для июля без строки периода получался тот же вводящий в заблуждение результат.
Общий `CONFLICT` не объяснял влияние более позднего закрытия. Пункт 4.4 ops.md
честно отмечал это ограничение, но требование владельца теперь делает его
критерием приёмки, а не необязательной рекомендацией.

Браузерный регрессионный тест сначала завершился ошибкой:

```text
Expected: Статус 2026-08: заблокирован закрытием 2026-09
Actual:   Статус 2026-08: открыт
```

Предлагаемая правка вычисляет последний закрытый месяц из серверного списка,
показывает неявную блокировку в выбранном периоде и таблице, объясняет обе даты
и порядок открытия. Кнопка открытия недоступна для раннего месяца, пока закрыт
поздний, и для уже открытого месяца. Общая ошибка конфликта сохраняет вариант
конкурентного изменения записи и добавляет путь проверки через «Настройки».
Сервер остаётся источником проверки версии, прав и окончательного решения.

[`finance-period-ui.test.mjs`](../../../tests/backoffice/finance-period-ui.test.mjs)

## Ограничения и передача

- Это локальная финансовая приёмка, не полная CI всей платформы и не релиз.
- Новый PR должен быть рассмотрен и слит отдельно; самостоятельно не сливать.
- До этого явный отрицательный вердикт для полного набора критериев сохраняется.
- Контракт API и схема не менялись; нового миграционного шага не требуется.
- Закрывать месяцы строго последовательно по-прежнему не обязательно; открывать
  их нужно от последнего закрытого назад. Открытие позднего месяца не отменяет
  защиту другого, более раннего закрытого месяца.
- Прямые административные SQL-записи вне приложения не являются проверенным
  способом корректировки. Приёмка относится к штатным финансовым командам.
- Общие документы и онлайн-roadmap не публиковались из-за чужих резервов и
  прямого ограничения задачи на выпуск. Принимающий агент переносит итог
  протокола в общий статус в рамках собственного резерва.
