# PICK FARM - первый игровой срез

Решение владельца 4 октября 2026: собственная ферма с овощами, фруктами,
цветами и деревьями, на телефоне на весь экран горизонтально. Это новая игра
по мотивам жанра, без исходников и нелицензированных материалов Lovely Farm.

## Что реализовано

- 12 грядок с расширением до 24. Морковь, томаты, клубника, подсолнухи,
  тюльпаны, яблоня. Яблоня даёт три урожая с интервалами роста.
- Магазин семян, склад, продажа урожая и три повторяемых заказа.
  Монеты и XP только игровые: не деньги, не Чики, не скидки.
- Прототипная экономика: 100 монет при старте; рост 30-180 секунд.
  Это ускоренный баланс для проверки, не финальная сезонная экономика.
- Изометрическое поле, панорамирование, pinch/кнопки масштаба,
  посадка/созревание с анимацией, общий цикл покачивания растений,
  подтверждённый сбор со вспышками. Reduce Motion и пауза в фоне.
- Собственные сгенерированные обложка/растения, лицензированное окружение
  Kenney CC0. Источники и промпты: `apps/mobile/assets/games/pick-farm/PROVENANCE.md`.
- Игра открывается вне tab bar. Root Stack портретный, farm route горизонтальный
  с скрытым status/navigation bar и auto-hide home indicator. Возврат восстанавливает
  ориентацию соседнего экрана. Настройки ОС и safe area соблюдаются.

## Архитектура

Для первого поля из 24 грядок выбран React Native с Animated и статическими
спрайтами, без дополнительного WebView/Phaser. Это сохраняет текущую навигацию,
авторизацию, доступность и уменьшает вес прототипа. При переходе к большой карте
и множеству персонажей движок можно пересмотреть отдельно.

`@pickchick/farm-game` - общие строгие схемы и чистые правила, не зависящие от React.
`@pickchick/farm-persistence` - транзакционное состояние PostgreSQL с блокировкой
по клиенту. Миграция `037_cloud_farm.sql` добавляет две отдельные таблицы.
GET `/v1/customer-farm` возвращает `{state,serverNow}`.
POST `/v1/customer-farm/commands` принимает `{commandId,expectedRevision,command}`.
Customer ID берётся из подтверждённой серверной сессии, не из тела запроса.
Время роста определяет сервер. Пока приложение закрыто, никакой таймер/worker
не требуется: готовность вычисляется из plantedAt и времени БД.

Повтор одного commandId не создаёт второй эффект. Потерянный ответ восстанавливается
по неизменному локальному intent; сервер возвращает актуальную ферму, даже если
после исходного действия играли с другого устройства. Stale revision требует
нового осознанного действия, не автоматического пересчёта списания.
Результат с неизвестным статусом сохраняет pending-команду до восстановления.
Сохраняются максимум 100000 квитанций на клиента, лимит 120 новых действий/минуту.
При удалении аккаунта связанные игровые данные удаляются каскадно.

## Включение и выпуск

По умолчанию выключено. Нужны оба флага:

- API: `FARM_ENABLED=1`, миграция 037, права из `infra/staging/farm-grants.mjs`;
- mobile: `EXPO_PUBLIC_PICK_FARM=1` и штатный `EXPO_PUBLIC_CUSTOMER_AUTH=server`.

Перед включением установить API и миграцию по общему release-runbook с зелёной CI,
проверенными предшествующими миграциями и резервированием VPS. Не применять
только последнюю миграцию поверх неизвестного baseline. Нужен маршрут
`/v1/customer-farm*` в фактическом gateway/CORS по тому же правилу, что customer API.
Grant helper выдаёт только необходимые table/column права; не давать runtime superuser.

Для горизонтального режима нужна новая нативная сборка: Expo `orientation: default`
разрешает ориентации на уровне бинарника, Stack фиксирует их по экранам.
OTA обновление старого portrait-only TestFlight не меняет Info.plist/AndroidManifest.
Приёмка на физическом телефоне, Android и публикация TestFlight пока не выполнены.
На production флаги не включались, реальные аккаунты не изменялись.

## Проверки

- Чистые игровые правила: `pnpm --filter @pickchick/farm-game test`.
- Durable client: `node --test tests/mobile/pick-farm-client.test.mjs`.
- PG и HTTP: FARM_TEST_DATABASE_URL должен указывать на изолированную тестовую БД;
  `pnpm --filter @pickchick/farm-persistence test:integration`. Тесты создают
  отдельные schemas, используют synthetic identity, проверяют runtime grants,
  параллельные действия, replay, rollback, конфликты, auth и лимиты.
- `tests/mobile/browser_pick_farm.py` использует web export с двумя флагами выше
  и только подставные перехваченные HTTP-ответы; это проверка UI, не live API.
- Typecheck mobile/API, ESLint, формат и generated OpenAPI.

Подтверждено локально 04.10: 6 engine, 6 durable client + 3 account-access,
2 PostgreSQL/HTTP, 7 release guards и 7 roadmap тестов. Сборка API,
mobile typecheck и экспорт iOS/Android/web прошли. Browser на 852x393,
667x375 и 1024x768: загрузка, сбор, посадка, склад и заказы; изображения
проверены по снимкам. Native rotation/FPS на устройстве этим не подтверждены.
