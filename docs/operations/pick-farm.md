## Что реализовано

- Свободное поле 64x64, один постоянный дом. Игрок начинает без готовых грядок,
  покупает и размещает их по клеткам; грядки и деревья можно переносить.
  Дом резервирует одну клетку, максимум 4095 купленных объектов.
- Все шесть культур сохранены: морковь, томат, клубника, подсолнух, тюльпан, яблоня.
  Магазин, склад, продажа и три повторяемых заказа. Монеты/XP только игровые.
- Начальный баланс: 500 монет, первая грядка 150, первая яблоня 250; дальнейшие

## Архитектура

Сохранён React Native со статическими спрайтами и короткими Animated-переходами.
Пустые клетки не создают 4096 элементов: рисуются купленные объекты и локальная
сетка выбора места. Производительность полностью застроенной карты на физическом
телефоне ещё не принята; перед массовым наполнением нужна проверка FPS/видимой области.
Заборы, декорации и смена дома оставлены на следующие этапы по решению владельца.

`@pickchick/farm-game` - общие строгие схемы и чистые правила, не зависящие от React.
`@pickchick/farm-persistence` - транзакционное состояние PostgreSQL с блокировкой
по клиенту. Миграция `037_cloud_farm.sql` добавляет две отдельные таблицы;
`038_cloud_farm_field_capacity.sql` увеличивает JSON-лимит до 1 MiB для большого поля.
Состояние v2 содержит координаты и тип объекта. V1 переносится под той же блокировкой,
с сохранением revision, монет, склада и времени посадки. Старые квитанции `expand`
повторяются без эффекта; новая команда `expand` отклоняется как LEGACY_COMMAND.
GET `/v1/customer-farm` возвращает `{state,serverNow}`.
POST `/v1/customer-farm/commands` принимает `{commandId,expectedRevision,command}`.
Customer ID берётся из подтверждённой серверной сессии, не из тела запроса.
Время роста определяет сервер. Пока приложение закрыто, никакой таймер/worker
не требуется: готовность вычисляется из plantedAt и времени БД.

Повтор одного commandId не создаёт второй эффект. Потерянный ответ восстанавливается
по неизменному локальному intent; сервер возвращает актуальную ферму, даже если
после исходного действия играли с другого устройства. Stale revision требует
нового осознанного действия, не автоматического пересчёта списания.
Результат с неизвестным статусом сохраняет pending-команду до восстановления.
Сохраняются максимум 100000 квитанций на клиента, лимит 120 новых действий/минуту.
При удалении аккаунта связанные игровые данные удаляются каскадно.

- mobile: `EXPO_PUBLIC_PICK_FARM=1` и штатный `EXPO_PUBLIC_CUSTOMER_AUTH=server`.
