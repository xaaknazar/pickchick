# Касса и веб-кухня одной точки

Статус: канал установлен на VPS/Windows, контрольный заказ №4 прошёл внешние
экраны до выдачи. [Протокол](deployments/2026-09-22-kitchen-live-link.md).
Физическая кухня по LAN и LED пока не подключены.

Маршруты `/kitchen/prep`, `/kitchen/assembly`, `/display` обслуживаются
`apps/kitchen`, обращаются к той же очереди edge, что и касса. Три терминала
и раздельное хранилище сессий позволяют открывать экраны одновременно.
Вход - кухонный логин и личный пароль; кассовые PIN не передаются в портал.
Пароль задаётся локальным операторским сценарием на кассе, не в переписке.

`PickChickKitchenLink` работает от LocalService, автоматически запускается и
делает исходящие HTTPS запросы. Входящие порты и firewall для внешнего портала
не открываются. Код и конфигурация имеют отдельные ACL. VPS sidecar не имеет
доступа к Docker socket, бизнес-БД или операторским SSH-ключам.

Физическая кухня: установить native `PickChickKitchen`, настроить существующий
`infra/windows/install-kitchen-lan.ps1`, передать публичную конфигурацию с
закреплённым TLS сертификатом. Проверить реальный IPv4 кухни, доступ по Wi-Fi,
резервирование адресов, отключение WAN при работающем LAN, восстановление и reboot.
Внешние HTTPS страницы при отсутствии интернета офлайн-кухню не заменяют.

## Проверки и эксплуатация

- `pnpm --filter @pickchick/kitchen build` и `test`.
- `node --test tests/kitchen-portal/link.test.mjs`.
- Изолированная PostgreSQL: `tests/kitchen-portal/browser.test.mjs`;
  проверяет три вкладки, приготовление/сборку/табло/выдачу и потерю ответа с
  точным повтором сохранённой команды после reload.
- `python3 -m unittest discover -s tests/kitchen-portal -p 'test_*.py'`.
- Пакет: `node infra/kitchen-portal/package.mjs` после проверенного коммита;
  `kitchen-package.json` содержит SHA источника и файлов. Ключ не входит в пакет.
- Windows установка: `install-agent.ps1`, проверяемые manifest/Foundation hashes,
  отдельный защищённый config. Существующая установка никогда не перезаписывается.
- VPS первая установка: `remote-deploy.py --package … --expected-source-sha …
--expected-public-release … --expected-api-release … --expected-gateway-sha256 …`.
  Сначала inspect, затем `--apply`; отдельная защищённая конфигурация уже должна
  существовать в `/opt/pickchick-staging/kitchen-portal/private/config.json`.
  Секреты не вводить аргументами команд.
- Публикация проверяет все прежние файлы сайта и неизменность соседних контейнеров;
  ошибочный запуск возвращает прежний gateway. При неопределённом результате
  lock сохраняется для проверки оператором, слепой повтор запрещён.

При обрыве результат команды неизвестен. Не повторять действие с другого
терминала: сначала восстановить журнал или сверить состояние через интерфейс.
Отключение службы связи влияет только на веб-экраны, не останавливает edge/POS.
Смена/заказ/оплата не живут в памяти портала. Оплата и чек пока не создаются.
Cloud replication в бэк-офис остаётся отдельной приёмкой по
[ADR-0011](../architecture/adr/0011-kitchen-live-link.md).
