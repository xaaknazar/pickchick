# Восстановление оплаты Kaspi в мобильном приложении

14 октября 2026. Исходная база `b81a3498`, ветка `codex/mobile-payment-recovery`.

## Проблема и поведение

Владелец свернул окно «Отправляем счёт», затем оплатил в Kaspi. Заказ остался
на сервере, но закрытый экран уже не следил за оплатой и приготовлением.

- Во время подготовки, отправки и неопределённого результата оплаты шторка
  не показывает ручку, не закрывается фоном, Escape или Android Back.
  Для маршрута отключён нативный жест закрытия, пока действует блокировка.
  Обычная корзина и оформление до отправки сохраняют прежнее закрытие.
- Подтверждённый сервером ID записывается рядом с прежним ключом команды.
  Перезапуск и возврат в приложение открывают сохранённое оформление по
  customer ID. Известный заказ восстанавливается чтением; потерянный ответ
  создания восстанавливается прежним идемпотентным ключом.
- Если человек оплатил, пока приложение было закрыто, восстановленный ответ
  показывает «Оплачено», затем настоящий статус кухни. Уход в фон прерывает
  восстановление; возвращение возобновляет его. Новая попытка оплаты из-за
  восстановления не создаётся.
- Результат банка отображается до асинхронной очистки локальной записи:
  сбой хранилища не прячет уже подтверждённую оплату.

## Отмена без выдуманного банковского результата

Действующий customer-checkout API не предоставляет отмену отправленного счёта.
В этой правке он, банковский worker, VPS и касса не меняются.
Кнопка «Отменить в Kaspi» открывает компактную инструкцию по штатному отказу
покупателя: в Kaspi.kz найти счёт PickChick и выбрать «Отклонить счёт».
После подтверждённого сервером результата `failed` можно вернуться к корзине
или начать новую попытку. Открытие инструкции само ничего не отменяет.
Неизвестный результат и истёкший локальный таймер не дают новую оплату.
Если банк подтвердил оплату, продолжается оплаченный заказ.

Источник: [Kaspi Гид для клиента](https://guide.kaspi.kz/client/ru/gold/shopping/Pay/q15143),
проверен 14 октября. Прямая кнопка банковской отмены внутри PickChick требует
отдельной серверной команды и проверки гонки оплаты/отмены; она не реализована
этим изменением.

## Проверки и ограничения

- Установлены зависимости frozen/offline из закреплённого lockfile.
- Собраны workspace packages; mobile typecheck и адресный ESLint прошли.
- 361 Node mobile tests прошли, включая 3 проверки сохранённой команды.
- Python mobile suite: 49/50 успешны; тест NativeManualProjectTests не запущен
  успешно из-за отсутствия CocoaPods `xcodeproj` gem. Это ограничение окружения,
  весь `pnpm test:mobile` не зелёный.
- Browser checkout на 320×568, 393×852, 768×1024 и 852×393: 4/4 успешны.
  Проверены закрытие, восстановление из меню, оплата во время закрытого приложения,
  единственный счёт, неизвестный исход, подтверждённый отказ и новая попытка,
  статусы кухни, история, сохранение и повторная загрузка отзывов.
  Первый прогон получил ошибку fixture `sessionStorage` на `about:blank`;
  тест перезапуска исправлен на переход к меню того же приложения.
- Expo web и нативные Hermes bundles iOS/Android собраны. Они не являются
  подписанным IPA/APK и не подтверждают физический жест на устройстве.
- UI/UX Pro Max: две адресные native-проверки поиска не дали совпадений;
  применены общие native-правила и существующая дизайн-система. Impeccable
  harden/craft-floor/polish прочитаны напрямую после ошибки прав launcher.
  После первого визуального прохода инструкция отмены вынесена в отдельное
  компактное состояние, проверена на малом экране. Новые SDK не добавлялись.
- На этом Mac установлен только Xcode Command Line Tools, полный Xcode отсутствует.
  Выпуск iOS на момент подготовки занят `kiosk-owner-polish-1013`; передача
  запрошена. На телефоне исправление пока не установлено.

## Следующий шаг

Пройти полную CI точного SHA, передать проверенный коммит в общую ветку, затем
собрать/установить мобильное приложение на Mac с Xcode после передачи iOS-резерва.
Физическая приёмка: отправка → попытка свайпа/тапа вне окна → переход в Kaspi →
оплата → возврат и приготовление; отдельно закрытие PickChick до оплаты,
отказ в Kaspi, потеря сети и Android Back. Не создавать реальные счета из CI.

Общие `docs/project-status.md` и roadmap закреплены за другим Mac; актуальный
результат сохраняется здесь и в журнале координации до согласованного обновления.
