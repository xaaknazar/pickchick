# Реальное меню к переходу 19.11.2026: импорт, проверка, публикация (М1, М4)

Контракт: `docs/architecture/cutover-2026-11-contracts.md`, задачи CC-1 и CC-2, порядок - §6.2 шаг 1.
Дизайн: `docs/architecture/cutover-2026-11/design-catalog.md`, раздел 3.3.

Что делает этот этап: одна публикация каталога из 54 позиций с ценами зала AILILLU для кассы,
киоска и приложения. Публикуется штатным API установленного облака (c3a0fbee) на установленную
кассу (edge 020) **без деплоя и без нового кода на сервере**: используются только существующие поля
каталога. Цены в приложении и киоске меняются в момент публикации (решение Р4: 09.11 вечером после
подписи управляющего).

Что сюда не входит:

- цены Яндекс Еды и Glovo (CC-3, отдельная публикация после деплоя и флага
  `CATALOG_AGGREGATOR_PRICES_ENABLED`, раздел «Цены Яндекс Еды и Glovo» ниже); колонки цен
  агрегаторов в листах уже есть, в каталог этой публикации они не попадают;
- раскладка станций кухни (полоса kds, `kds-switch.mjs`), фиксированный состав комбо (М2, P1),
  фото и KK-переводы (М5, P1), сверка трёх каналов после публикации (`catalog-channel-parity`, P1).

## Инструменты

| Команда                                                 | Что делает                                                                                                                                     | Сеть         |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `node scripts/catalog-menu-import.mjs build`            | листы TSV → `payload.json`, `review.md` (отчёт управляющему), `expected-edge-changes.json` (список изменений кассы), `manifest.json` (SHA-256) | нет          |
| `node scripts/catalog-edge-parity.mjs --allow <список>` | проходит, только если отличия «касса ↔ новый каталог» ровно те, что в проверенном списке                                                       | нет          |
| `node scripts/catalog-menu-import.mjs save`             | сохраняет проверенный каталог черновиком; единственное место, где ставится `content_reviewed:true`                                             | API каталога |
| `node scripts/catalog-menu-import.mjs publish`          | публикует ровно сохранённый черновик, только с чистым отчётом `--allow` для того же каталога и того же меню кассы                              | API каталога |

Все файлы этапа хранятся в `.local/menu-import/2026-11/` (вне Git, права 0700/0600): исходные листы
управляющего, снимки, результаты сборки, квитанции. В Git - только инструменты, синтетические тесты и
стартовая фикстура листов.

## Листы импорта

Стартовая фикстура: `packages/catalog-admin/fixtures/real-menu-2026-11/` (собрана из
`docs/operations/iiko-menu-details-2026-09-28.md` и `docs/operations/real-menu.md` по таблице slug
design-catalog 3.3). Её загружают в таблицу (Google/Excel) по листу на файл, управляющий правит,
каждый лист выгружается обратно как **UTF-8 TSV** с тем же заголовком. UTF-16 («Юникод-текст» Excel)
инструмент отклоняет.

| Файл             | Лист          | Строка                                                                   |
| ---------------- | ------------- | ------------------------------------------------------------------------ |
| `positions.tsv`  | Позиции       | одна позиция меню (54)                                                   |
| `groups.tsv`     | Группы выбора | одна опция группы (напитки, бесплатный дип, 3 платные группы, вкус Piko) |
| `rules.tsv`      | Правила комбо | правило группы у позиции: min, max, опция и количество по умолчанию      |
| `components.tsv` | Состав комбо  | пусто для P0 (М2); если заполнить, меняются задачи кухни                 |
| `catalog.tsv`    | Каталог       | время готовности и список допродажи, как в v11                           |

Правила, которые проверяет `build` (ошибка - каталог не собирается):

- цены - **целые тенге** (`3690`, `3 690`, `3690,00`); дробные тенге, ведущие нули, 0 и значения больше
  100 000 ₸ (похоже на цену в тиынах) отклоняются; доплата опции - от 0 до 10 000 ₸;
- все 24 slug опубликованного меню остаются (фото, хиты, подарок 7+1 на `pick-combo`, идентичности
  кассы); при `--current` - и все slug текущей публикации;
- у `kind=combo` slug оканчивается на `-combo` или `-duo`; категории - только «Комбо», «На двоих»,
  «На компанию», «Допы», «Соусы», «Напитки»;
- опция по умолчанию покрывает min группы (в iiko умолчаний нет, схема каталога их требует);
- до 100 позиций, до 10 групп у позиции, до 20 опций в группе, каталог не больше 230 KiB
  (жёсткий предел 256 KiB зашит и в установленных клиентах);
- строка со статусом `исправить` блокирует сборку; пустой статус и `ок` допустимы;
- каталог проходит ту же проверку, что сервер при публикации (`CatalogPayloadSchema`,
  `assertCatalogPublishable`, проекция на кассу).

## Решения в стартовых листах (проверяет управляющий)

- Названия позиций - как в карточках AILILLU (`Finger Combo`, `Кока-кола жб`); в отчёте рядом
  название v11. KK заполнен только у латинских названий (38 позиций без KK, касса покажет `-`).
- Вес: дробный вес iiko и сомнительные значения (фингерс 342 г, Кока-кола zero жб 790 г) не
  публикуются; фирменные соусы названы в мл при единице «Грамм» - порция по названию, вес и объём
  пусты. Напитки без объёма в карточке - порция «1 шт».
- КБЖУ - нули со статусом «не проверено», аллергены - «не указаны» (в iiko их нет).
- Описания: у 24 позиций v11 оставлены тексты макета (для комбо отмечено «состав не подтверждён»),
  у новых - пусто.
- Фото: у новых позиций временное фото похожего блюда или `generic-drink` (в отчёте «временное»/«нет»).
- Группы комбо: `drink` (20 опций, id = slug напитков, по умолчанию `cola-bottle`), `sauce`
  (бесплатный дип, 5 опций, по умолчанию `sauce`), три платные группы `sauce-paid-signature|cheese|hot`
  с опциями `…-plus-790|1090|1390` (объём не указан в iiko). Группы `extras` и `size` v11 сняты,
  12 соусов - отдельные товары. У сетов фингерсов групп нет (как в iiko).
- min бесплатного дипа: у Pick Meal 1, у остальных 0 (iiko показывает только max) - UNCONFIRMED.
- Piko: вкусы яблоко/апельсин сохранены из v11; «-чай фирменный» = Ice Tea - UNCONFIRMED.

Все такие места помечены в отчёте `UNCONFIRMED` и собраны в разделе «Все отметки UNCONFIRMED».

## Порядок (М1, без деплоя)

0. Доступ: файл управляющего каталогом, выданный владельцем
   (`node packages/catalog-admin/dist/cli.js provision --input … --output .local/…/catalog-manager.json`),
   права 0600. Токен инструменты не печатают и никуда не пишут.
1. Снимки (только чтение), в одну папку `.local/menu-import/2026-11/snapshots/`:
   - `state.json` - `GET /v1/admin/catalog/branches/<branch>` (опубликованная v11, черновик, `edge_delivery`);
   - `edge-menu.json` - активное меню кассы `GET http://127.0.0.1:<порт edge>/edge/v1/menu` на сервере точки;
   - `routing.json` - активная маршрутизация кухни со станциями `{routing, stations}`
     (как для фазы `verify-edge`, `docs/operations/unified-menu-publication.md`).
2. Сборка:
   ```sh
   node scripts/catalog-menu-import.mjs build --dir .local/menu-import/2026-11/sheets \
     --out .local/menu-import/2026-11/build-1 \
     --current .local/menu-import/2026-11/snapshots/state.json \
     --edge .local/menu-import/2026-11/snapshots/edge-menu.json
   ```
   Выход 0 - собрано; 1 - ошибки (они в `review.md` и `manifest.json`, `payload.json` не пишется);
   2 - неверные аргументы. Папка `--out` должна быть новой. Повтор с теми же входами даёт те же байты.
3. Управляющий читает `review.md` (каждая цена, «было → стало», опции, правила, что уходит, изменения
   кассы), отмечает «Проверено» и подписывает. Правки - в листах, затем новая сборка в новую папку.
   После подписи файлы сборки не меняются: `save`/`publish` проверяют их SHA-256 по манифесту.
4. Паритет кассы (М4):
   ```sh
   node scripts/catalog-edge-parity.mjs --catalog .local/menu-import/2026-11/build-1/payload.json \
     --edge .local/menu-import/2026-11/snapshots/edge-menu.json \
     --routing .local/menu-import/2026-11/snapshots/routing.json \
     --allow .local/menu-import/2026-11/build-1/expected-edge-changes.json \
     > .local/menu-import/2026-11/build-1/parity.json
   ```
   Выход 0 только если отличия ровно проверенный список, для того же меню кассы и того же каталога.
   В `allow`: `unexpected` - отличие, которого нет в списке; `missing` - отличие из списка, которого
   больше нет; `stale` - другое меню кассы (`EDGE_MENU_CHANGED`), другой каталог (`PAYLOAD_CHANGED`)
   или точка; `blocking` - касса отклонит публикацию (`PROJECTION_FAILED`, `ROUTING_UNRESOLVED`).
   Любое из этого - снова шаги 1-3. Без `--allow` отчёт прежний (выход 1 на любом изменении цены).
5. Сохранение:
   ```sh
   node scripts/catalog-menu-import.mjs save --manifest .local/menu-import/2026-11/build-1/manifest.json \
     --reviewed-by "<ФИО управляющего>" --branch <branch> \
     --token-file .local/<…>/catalog-manager.json --api https://<адрес API>
   ```
   `request_id` выводится из SHA-256 манифеста. Повтор после успеха ничего не меняет
   (`already_saved`). Отказ `PUBLISHED_CHANGED` - опубликована другая версия, чем в отчёте: заново с шага 1.
   Квитанция: `save-receipt.json` рядом с манифестом.
6. Публикация:
   ```sh
   node scripts/catalog-menu-import.mjs publish --manifest .local/menu-import/2026-11/build-1/manifest.json \
     --parity .local/menu-import/2026-11/build-1/parity.json --branch <branch> \
     --token-file .local/<…>/catalog-manager.json --api https://<адрес API>
   ```
   Публикуется только черновик, совпадающий с проверенным каталогом (`DRAFT_DIFFERS` иначе), и
   только с чистым отчётом шага 4 для этого каталога и этого списка; если касса успела сообщить другое
   меню - `PARITY_STALE`. Повтор после успеха - `already_published`, новая версия не создаётся.
   Квитанция: `publish-receipt.json` (версия, `edge_delivery`).
7. Касса применяет меню (служба меню на сервере точки): в бэк-офисе `edge_delivery.status = applied`;
   `GET /edge/v1/menu` - 54 позиции; новые позиции получили маршрут `prep|assembly_item`.
8. М6: стоп реального блюда в бэк-офисе виден в приложении и киоске; стоп компонента комбо на кассе -
   только после деплоя stage 2 (`combo_stops`).

Адрес API по умолчанию - `http://127.0.0.1:3100` (локальная проверка). Обычный HTTP разрешён только
на этот компьютер; удалённый API - только HTTPS.

## Ошибки и что делать

| Код                                                           | Причина                                                      | Действие                                         |
| ------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------ |
| `PRICE_NOT_WHOLE_TENGE`, `PRICE_INVALID`, `PRICE_IMPLAUSIBLE` | цена не целые тенге, пусто, 0 или похоже на тиыны            | исправить ячейку, новая сборка                   |
| `EXISTING_SLUG_MISSING`                                       | пропал slug опубликованного меню                             | вернуть строку (slug менять нельзя)              |
| `TSV_HEADER`, `TSV_ROW`, `TSV_ENCODING`                       | лист выгружен не тем форматом                                | выгрузить UTF-8 TSV с исходным заголовком        |
| `PAYLOAD_BUDGET`                                              | каталог больше 230 KiB                                       | сократить описания                               |
| `OUTPUT_CHANGED`                                              | файл сборки изменён после подписи                            | новая сборка и подпись                           |
| `PUBLISHED_CHANGED`, `PARITY_STALE`                           | после сборки опубликовано другое меню или касса сменила меню | шаги 1-4 заново                                  |
| `PARITY_FAILED`, `PARITY_REQUIRED`                            | нет чистого отчёта `--allow` для этой сборки                 | шаг 4                                            |
| `DRAFT_DIFFERS`                                               | черновик изменён после `save`                                | выяснить, кто правил; `save` заново              |
| `API_REFUSED`                                                 | ответ API (код и причина, без данных)                        | по коду: `401` - доступ, `409` - конфликт версий |

## Откат

Публикации неизменяемы, откат - новая версия с прежним каталогом; касса получает её штатно. Снимок
`state.json` шага 1 содержит опубликованную v11 целиком и хранится до 19.11.

**Пока не сделано:** команды восстановления каталога из такого снимка в инструменте нет (следующий
шаг полосы cloud). До неё откат 54 позиций к v11 возможен только правкой в редакторе бэк-офиса, это
долго. Поэтому `publish` - только после подписи управляющего и чистого паритета, в согласованное окно
(Р4). Цены агрегаторов этим этапом не публикуются, откатывать их не нужно.

## Цены Яндекс Еды и Glovo (CC-3, контракт R4 и 5.3, §6.2 шаг 5)

Модель: у товара в `channel_prices_minor` появляются ключи `yandex_eda` и `glovo`. Ключ есть -
позиция продаётся в этом канале по этой цене; ключа нет - касса не продаёт её в канале («Нет в
меню Яндекс Еды» / «Нет в меню Glovo»). Доплаты опций у агрегаторов - как в зале (§9 в.10). Цена
зала, киоска и приложения - по-прежнему `price_minor`. Касса получает цены отдельным полем
`aggregator_prices_minor`; приложение и киоск их не получают никогда.

Флаг `CATALOG_AGGREGATOR_PRICES_ENABLED` (env API, по умолчанию `false`; любое значение, кроме
`true`/`false`, - ошибка запуска `CATALOG_AGGREGATOR_PRICES_CONFIGURATION_INVALID`). Действует только
вместе с `CATALOG_EDGE_PUBLICATION_ENABLED=true` и только для точки публикации на кассу.

| Состояние    | Что происходит                                                                                                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| флаг `false` | цены агрегаторов можно сохранить в черновик, публикация - `409 CHANNEL_PRICES_NOT_SUPPORTED`; релизы меню, ответы `pull`/`ack`, состояние каталога и витрины - байт-в-байт прежние                                         |
| флаг `true`  | публикация с `yandex_eda`/`glovo` разрешена (собственные цены `mobile/pos/kiosk` по-прежнему отклоняются), релиз кассы несёт `aggregator_prices_minor`, в состоянии каталога `publication_support.aggregator_prices: true` |

Доставка на кассу: касса новой сборки заявляет `menu_features=combo_stops,aggregator_prices` и
получает полную форму. Установленная касса (без фич) и касса этапа 2 (только `combo_stops`)
получают ту форму, которую разбирают, со своей контрольной суммой; облако принимает подтверждение
любой из четырёх форм. Публичное меню точки `GET /v1/branches/<id>/menu` и каталоги приложения и
киоска цен агрегаторов не содержат. Публичный `GET /v1/catalog/branches/<id>` отдаёт опубликованный
каталог целиком (как уже отдаёт `image` и `kitchen_route`): установленные клиенты его не читают,
цены агрегаторов и так публичны у самих агрегаторов.

Откуда берутся цены:

- листы импорта, колонки `yandex_price_tenge` и `glovo_price_tenge`, сборка с
  `--aggregator-prices sheet` (пустая ячейка или `-` - не продаётся) или
  `--aggregator-prices hall-fallback` (§9 в.11: пустая ячейка = цена зала с пометкой
  `UNCONFIRMED` в отчёте, `-` - не продаётся). Без ключа сборка прежняя, колонки только проверяются;
- редактор бэк-офиса: раздел «Цены агрегаторов» в карточке (виден при включённом флаге или если
  у позиции цена агрегатора уже есть), в списке позиций - строка «Яндекс Еда: … · Glovo: …».
  Редактор меняет только поле, которое правили; остальные поля позиции сохраняются как есть.

Порядок:

1. Предусловия: облако (Cloud-1) и касса (окно С4) обновлены, М1 опубликован и применён,
   `pos_sale` ещё выключен. Бэк-офис обновляется вместе с API: прежняя сборка бэк-офиса не
   открывает черновик с ценами агрегаторов.
2. Управляющий заполняет колонки агрегаторов (прайсы Яндекса 47 и Glovo 52, вопрос §9 в.12). Если
   полных прайсов нет к 12.11 - режим `hall-fallback`, управляющий ставит `-` у позиций, которых нет
   у агрегатора.
3. Снимки и сборка как в М1 (шаги 1-3 выше), с ключом:
   ```sh
   node scripts/catalog-menu-import.mjs build --dir .local/menu-import/2026-11/sheets \
     --out .local/menu-import/2026-11/build-agg-1 --aggregator-prices hall-fallback \
     --current .local/menu-import/2026-11/snapshots/state.json \
     --edge .local/menu-import/2026-11/snapshots/edge-menu.json
   ```
   В `review.md` - колонки «Яндекс Еда» и «Glovo», каждая цена зала вместо цены агрегатора помечена
   `= зал (UNCONFIRMED, контракт 9 в.11)`, раздел «Цены агрегаторов на кассе». Подпись управляющего.
4. Владелец включает `CATALOG_AGGREGATOR_PRICES_ENABLED=true` и перезапускает API. В бэк-офисе в
   окне публикации появляется строка про цены Яндекс Еды и Glovo.
5. Паритет с ценами агрегаторов (каждая новая цена - `AGGREGATOR_PRICE_CHANGED` из списка):
   ```sh
   node scripts/catalog-edge-parity.mjs --aggregator-prices \
     --catalog .local/menu-import/2026-11/build-agg-1/payload.json \
     --edge .local/menu-import/2026-11/snapshots/edge-menu.json \
     --allow .local/menu-import/2026-11/build-agg-1/expected-edge-changes.json \
     > .local/menu-import/2026-11/build-agg-1/parity.json
   ```
6. `save` и `publish` как в М1. `publish` сборки с ценами агрегаторов требует отчёт, сделанный с
   `--aggregator-prices` (иначе `PARITY_FAILED`), и включённый флаг (иначе `AGGREGATOR_PRICES_DISABLED`
   до запроса к API).
7. Касса применила: в бэк-офисе `edge_delivery.status = applied`; `GET /edge/v1/menu` - у позиций
   `aggregator_prices_minor`. Паритет после применения:
   `node scripts/catalog-edge-parity.mjs --aggregator-prices --catalog <снимок state.json> --edge <меню кассы>` -
   выход 0, `summary.aggregator_price_changes = 0`.
8. Витрины: в `GET /v1/branches/<id>/menu`, каталогах приложения и киоска нет `yandex_eda`,
   `glovo`, `aggregator_prices_minor`.

Откат:

- цены: новая версия без цен агрегаторов (сборка без `--aggregator-prices` или очистка полей в
  редакторе) - касса получает меню без них, режим агрегатора на кассе показывает «Нет в меню …»;
- флаг: `false` - только после публикации без цен агрегаторов (с выключенным флагом публикация с
  ними отклоняется, а уже применённая на кассе версия остаётся до следующей публикации);
- рантайм API до CC-3: только когда ни опубликованный каталог, ни черновик не содержат
  `yandex_eda`/`glovo` (прежняя схема каталога их не разбирает: витрины и бэк-офис не откроют
  каталог). Порядок: очистить, опубликовать, затем откатывать.

Ошибки:

| Код                                  | Причина                                                                          | Действие                                    |
| ------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------- |
| `CHANNEL_PRICES_NOT_SUPPORTED` (409) | публикация с ценами агрегаторов при выключенном флаге или с ценами `pos`/`kiosk` | включить флаг или очистить поля             |
| `AGGREGATOR_PRICES_DISABLED`         | `publish` сборки с ценами агрегаторов, флаг в облаке выключен                    | шаг 4                                       |
| `AGGREGATOR_PRICE_CHANGED` (паритет) | цена агрегатора на кассе и в каталоге различаются                                | в списке `--allow` - ожидаемо; иначе разбор |
| `PARITY_FAILED`                      | отчёт паритета сделан не с тем ключом `--aggregator-prices`                      | шаг 5 тем же ключом, что сборка             |
