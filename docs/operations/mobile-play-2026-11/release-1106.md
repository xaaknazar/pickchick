### Data safety - окончательное сохранение 07.11

По повторному поручению владельца форма полностью проверена и сохранена
кнопкой «Сохранить». Console показала «Изменение сохранено», а в обзоре
публикации появилась строка «Безопасность данных - Прохождение опроса».
Это сохранённая декларация для будущей проверки, не отправка Google и не выпуск.

Исправлен пропуск в исходном `data-safety.md`: идентификатор устройства
используется при входе независимо от FCM. Актуальные ответы:

| Тип                                                   | Обязательность        | Цели                                                                   |
| ----------------------------------------------------- | --------------------- | ---------------------------------------------------------------------- |
| Имя (ник)                                             | По желанию            | Функции приложения, управление аккаунтом                               |
| Номер телефона                                        | Для входа и заказа    | Функции приложения, управление аккаунтом, предотвращение мошенничества |
| Другие сведения (дата рождения, пол)                  | По желанию            | Функции приложения, управление аккаунтом                               |
| История покупок                                       | Для оформления заказа | Функции приложения                                                     |
| Другой пользовательский контент (комментарии, отзывы) | По желанию            | Функции приложения                                                     |
| Идентификаторы устройства или другие идентификаторы   | Для входа             | Функции приложения, управление аккаунтом, предотвращение мошенничества |

Все шесть типов: «Собирает», обработка не временная, «Передаёт» не отмечено.
Для Kaspi/Telegram применяются описанные в пакете исключения Google:
обработчик по поручению или действие, явно инициированное пользователем.
Основная функция заказа требует входа; необязательные поля профиля и
комментарии отмечены отдельно. Идентификатор не является рекламным ID.

Общие ответы: сбор есть, передача шифруется, вход по телефону и коду
(«Имя пользователя и другие данные для подтверждения личности»).
Удаление аккаунта - `https://pickchick.kz/support/#delete-account`.
Удаление данных без удаления аккаунта - «Нет»: отдельный процесс не заявлен.
Независимая сертификация безопасности и UPI не заявлены.
Геолокация, карта/банковские реквизиты, email, адрес, контакты, фото/видео,
аудио, файлы, календарь, здоровье, история браузера, аналитика и crash SDK
не отмечены. FCM не настроен; ответ публичного config - HTTP 404.

Доказательство идентификатора: `customer-session.ts:327` создаёт случайный
`device_id`; строки 448/504/548 отправляют его при OTP/refresh. Сервер
`packages/customer-identity/src/index.ts` сохраняет `device_hash` в challenges
и sessions и использует его вместе с телефоном/IP для лимитов и защиты входа.
Значения идентификаторов и токенов не читались и не записывались в журнал.

Исходный `data-safety.md` занят `mobile-android-1105`: claim отказал по пересечению.
Его строку об идентификаторах нужно исправить при согласованной интеграции;
настоящий раздел содержит фактически сохранённые ответы Console.
Срок хранения из PR315 сохраняется; сервер, политика и механизм удаления
не менялись. П6 всё ещё должен подтвердить HTTP 200 и якорь трёх языков
