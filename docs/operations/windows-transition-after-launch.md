# Б9: план перехода рабочих устройств с Windows 10

План подготовлен 08.11.2026. Это подготовка обновления ОС **после запуска**,
не разрешение обновлять или перезагружать кассу сейчас. Новый Windows 11 Pro
компьютер разработчика не является ресторанной кассой и не входит в эту замену.
Фактическая опись оборудования (КД6) пока не получена; совместимость конкретных
моноблоков, драйверов и лицензий не подтверждена.

## Порядок и ответственные

| Шаг                     | Кто                                       | Условие перехода дальше                                                                        |
| ----------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1. Опись КД6            | Управляющий на точке + Codex              | Для каждого устройства заполнена строка шаблона, подтверждены ОС, периферия и роль             |
| 2. Выбор пути           | Codex готовит варианты, владелец выбирает | Проверены требования производителя, драйверы и законная лицензия; расходы отдельно согласованы |
| 3. Копии и откат        | Codex + сотрудник на точке                | Есть проверяемый образ системного диска, копия БД и независимое хранение ключа восстановления  |
| 4. Репетиция            | Codex на запасном устройстве/диске        | Пройдены проверки ниже; тестовая копия не связана с рабочими банком и cloud                    |
| 5. Один пилот           | Codex + управляющий                       | После двух полных стабильных смен PickChick, в отдельное согласованное окно                    |
| 6. Наблюдение           | Управляющий                               | Полная рабочая смена без проблем и зафиксированные результаты                                  |
| 7. Остальные устройства | Codex + сотрудник                         | По одному, с собственной копией и теми же критериями приёмки                                   |

Не совмещать обновление ОС с переходом с iiko, миграцией схемы БД, сменой
сертификатов, адресов или кассового оборудования. Не назначать обновление
рабочих устройств на окно запуска 18–19 ноября. Календарные окна после запуска
подтверждаются по результатам стабильной работы, а не только по дате.

## Что собрать

Заполнить [шаблон описи](windows-device-inventory-template.csv), одна строка
на физическое устройство. Указать:

- Метку устройства, роль и станцию; производителя, точную модель и CPU,
  объём памяти, свободное место на системном диске и наличие запасного диска.
- Редакцию Windows, версию и build. Отдельно проверить официальный срок
  поддержки именно этой редакции и наличие действующего ESU, если применимо.
  Не переносить вывод об обычной Windows 10 на LTSC/IoT без проверки редакции.
- Результат официальной проверки совместимости Windows 11: CPU, TPM,
  Secure Boot и остальные требования. Не обходить проверки установщика.
- Принтер и драйвер, ширину чека, подключение USB/LAN, способ открытия ящика;
  модель Kaspi-терминала и его способ подключения. Наличие драйвера проверять
  для целевой ОС, а не только по совпадению названия устройства.
- Локальный адрес и DHCP-резервацию, экран/сенсор, автозапуск приложения,
  установленные службы PickChick, версию PostgreSQL и активный runtime.

В шаблоне не должно быть PIN сотрудников, паролей, product key Windows,
закрытых SSH-ключей, банковских реквизитов или recovery key. Полную опись с
локальными адресами хранить в защищённом рабочем хранилище, не в публичном Git.

## Как выбрать путь

| Состояние устройства                                                                                  | Действие                                                                                           |
| ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Windows 11 официально поддерживается, драйверы и лицензия подтверждены                                | Репетиция обновления на копии, затем один пилот в согласованное окно                               |
| Windows 11 не поддерживается, но для текущей редакции подтверждены действующие официальные обновления | Временное сохранение поддерживаемой ОС с датой следующей проверки; планировать замену оборудования |
| Нет поддерживаемого пути и подтверждённых обновлений                                                  | Подготовить замену устройства; бюджет и покупка требуют решения владельца                          |
| Не работает обязательная периферия или неизвестна лицензия                                            | Стоп обновления этого устройства до подтверждения совместимости/лицензии                           |

Отключение защиты, обход TPM/CPU, неофициальные сборки Windows и установка
«универсального» драйвера неизвестного происхождения не являются путём миграции.

## Копия и репетиция

1. Закрыть смену штатно и убедиться, что нет незавершённых операций. Сохранить
   версии ОС, runtime, схемы, конфигурации и состояние синхронизации. Сверить
   остаток POS-sync: не сбрасывать подтверждения и не отправлять старые события
   повторно ради обновления ОС.
2. Снять образ системного диска и зашифрованную копию БД штатными инструментами.
   Проверить контрольные суммы и восстановление. Копия только на том же
   системном диске не считается резервом. Ключ восстановления хранить отдельно
   от копии и не передавать в чат/Git.
3. Сохранить сведения о службах, правах, автозапуске, firewall и DHCP, а также
   установщики официальных драйверов. Секреты и приватные ключи сохранять только
   через защищённую процедуру восстановления. Не копировать `.git` или личные
   SSH-ключи рабочего компьютера разработчика на кассу.
4. Восстановить копию на запасной диск/устройство в изолированной сети. Клон с
   действующей identity не должен соединяться с рабочим cloud, банком или
   ресторанной сетью одновременно с оригиналом. Для функциональных сценариев
   использовать синтетические данные и тестовую конфигурацию.
5. Обновить ОС штатным официальным способом, проверить драйверы, права служб,
   запуск и сценарии приёмки. Само обновление ОС не должно применять миграции БД
   или менять runtime. Результаты записать для конкретной модели устройства.

## Приёмка пилота

- После холодного старта работает сеть и сенсор, разрешение/масштаб экрана
  подходят интерфейсу, нет неожиданного запроса прав администратора.
- Запущены именно службы из сохранённой описи; PostgreSQL, касса, кухня и
  шлюз проходят штатные health-проверки. Сверены версии runtime и схемы.
- Действующий fulfillment-туннель сохраняет 43100; установленный отдельный
  POS-sync использует 43110. Не удалять или перепривязывать первый туннель.
- Каталог, номер кассы и назначение кухонного экрана совпадают с описью.
  Проверены вход сотрудника, открытие/закрытие смены, печать тестового документа,
  ящик и локальная доставка заказа на нужный экран.
- Проверены потеря WAN, восстановление соединения и отсутствие дублей после
  синхронизации. Существующий восьмичасовой ресторанный тест К12 не заменяется
  короткой проверкой после обновления ОС.
- Резервное копирование выполняется, свежая копия читается и восстанавливается
  на изолированном стенде; watchdog видит устройство без новых ошибок.
- Банковские и фискальные проверки проводятся отдельно уполномоченным
  сотрудником по согласованному сценарию. Не создавать реальные платежи или
  чеки автоматически для проверки драйвера.
- Если изменился SSH host key, сотрудник сверяет новый отпечаток на самом
  устройстве. Не отключать проверку ключа и не принимать неизвестный отпечаток
  как обычное последствие обновления.

## Откат

При отсутствии обязательного драйвера, сбое БД/служб, потере печати, ошибке
денежного учёта или неконтролируемой повторной отправке событий пилот не принят.
Не обновлять следующие устройства. Остановить новые операции и зафиксировать
состояние; не пытаться исправить расхождения удалением данных.

Для отката вернуть проверенный образ/предыдущий диск и согласованные версии.
Если после обновления уже появились новые продажи, сначала сохранить их и
сверить с cloud; нельзя восстанавливать старую БД поверх новых денег или
запускать две копии с одной identity. Восстановление БД выполняется отдельно
по [edge-restore.md](edge-restore.md), с fence/review там, где они требуются.
Управляющий подтверждает возврат в работу по той же приёмке. Предыдущий диск и
проверенную копию хранить до принятия всей партии устройств.

## Как отмечать Б9

План и шаблон описи подготовлены. Это не утверждение, что устройства совместимы
с Windows 11 или обновлены. Исполнение плана начинается после КД6, выбора пути
для каждого устройства и согласования окна после запуска. Б9 в части подготовки
плана выполнена; установку ОС фиксировать отдельными протоколами по каждому
устройству.
