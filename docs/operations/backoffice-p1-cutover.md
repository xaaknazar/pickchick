# Бэк-офис P1 (полоса bo-ui): включение, проверка, откат

Экраны P1 бэк-офиса за флагами, которые по умолчанию выключены (решение владельца 05.11). Дизайн:
`docs/architecture/cutover-2026-11/design-bo-ui.md`, перенос в облако: CR `bo-ui-1` (075, права, флаги)
и `bo-ui-2` («Касса»). Облачная часть перехода (продажи кассы, роли, склад v2, отчёт продаж) - в
`backoffice-cutover.md`; этот файл продолжает его и дополняется на шагах 3-8 полосы.

Общие правила для каждого флага P1:

- флаг - переменная окружения API, по умолчанию `false`; включается только при `BACKOFFICE_ENABLED=true`;
- пока флаг выключен, ответы API и кабинет те же, что у облачной полосы (тест
  `tests/integration/backoffice-p1-flags.test.mjs`, браузерный тест «флаг выключен»);
- кабинет показывает раздел, только когда `GET .../branches/<точка>` сообщает
  `capabilities.<ключ>=true`, поэтому порядок «сначала права, потом флаг» безопасен;
- откат - флаг `false` и перезапуск API; данные не меняются.

## Касса в бэк-офисе (`BACKOFFICE_POS_DAY_ENABLED`)

Один кассовый день точки в кабинете: смены с Z-отчётом, чеки с оплатами, отменами и возвратами,
номера Webkassa, имена кассиров. Только чтение: кабинет ничего не пишет ни в облако, ни на кассу.
Данные - проекции продаж кассы 073 (`cloud_pos_*`, поток `posSales`, CC-4) и отчёты кассы 033 для
смен, у которых ещё нет Z.

### Что видит управляющий

- **«Касса»** (в меню после «Заказы»). Вверху выбор дня (календарь Алматы) и кассы, кнопка
  «Обновить» и строка свежести «Данные кассы получены в 23:41». Вкладки:
  - «Смены и Z» - выручка кассы, чеки и средний чек, «Без выручки» (питание сотрудников и
    маркетинг), «Webkassa не оформлено»; способы оплаты за день (восемь способов кассы); карточка
    каждой смены: открыта или закрыта, кто открыл, наличные (разменный фонд, внесения, изъятия,
    наличные продажи и возвраты, ожидается, пересчитано, расхождение), Kaspi терминал (по кассе,
    введено при закрытии, разница), способы оплаты по Z-отчёту. Для открытой смены - суммы по
    полученным чекам с пометкой «Это не X-отчёт кассы».
  - «Чеки» - время, номер и касса, кассир, канал и режим (зал, с собой, Яндекс Еда, Glovo), номер
    заказа агрегатора или ChocoFood, оплата, сумма, состояние, номер Webkassa или «не оформлен».
    Поиск по номеру заказа, номеру агрегатора и номеру Webkassa; фильтры: касса, способ оплаты,
    канал, состояние. Карточка чека: позиции, оплаты со сдачей, отмены и возвраты с причиной, кто
    оформил и кто подтвердил, чеки Webkassa.
  - «Webkassa» - сначала не оформленные чеки (касса, номер, вид, сумма, время, сколько ждёт), потом
    оформленные и «Чек не нужен»; «Итого по Webkassa» для сверки с кабинетом Webkassa за день.
  - Три выгрузки CSV в тенге: Z-отчёты, чеки, чеки Webkassa (UTF-8 с BOM, «;», десятичная запятая).
  - «Как считается» - правила дня ниже, тем же текстом.
- **«Главная»** - блок «Сегодня, ДД.ММ.ГГГГ»: выручка, чеки, средний чек, каналы, «Без выручки»,
  открытые смены, не оформленные чеки Webkassa, кнопка «Открыть «Кассу»». Каналы приложения и киоска
  блок берёт из отчёта продаж, если включён `BACKOFFICE_SALES_REPORT_ENABLED`; без него - «Только
  касса». Ниже, как раньше, показатели за выбранный период.
- **«Заказы»** - колонка «Касса» («Касса 1», «Касса 2»): у каждой кассы свои номера заказов, поэтому
  два «№1» разных касс различимы. Дата в одну строку, фильтр по кассе, порядок (новые, старые, по
  номеру, по сумме), «Итого по списку» с разбивкой по кассам, CSV с датой, временем, номером,
  кассой и суммой в тенге. Оплаченный на кассе заказ - «Оплачено», а не «Не начата»; карточка такого
  заказа показывает чек кассы.
- **Отчёт по кассовой смене** («Главная», выбранная смена продаж): «Оплачено на кассе», наличные
  продажи и возвраты в расчёте остатка, касса по имени, кассир по имени (CR pos-4 §2).

Пустые состояния без «нулей»: без таблиц 073 или без прав на них - «Облако ещё не получает продажи
кассы. Смены видны по отчётам кассы, чеков и сумм пока нет.»

### Как считается (тот же текст в кабинете)

- День - календарный день Алматы. Смена относится к дню открытия: смена, закрытая после полуночи,
  и её чеки остаются в дне открытия (в «Продажах» CC-7 чек считается по времени продажи, поэтому суммы
  могут отличаться). Чек без известной смены - по своей дате продажи.
- Продажи - все чеки дня, отменённые тоже, как в Z-отчёте. Выручка = продажи - отмены - возвраты,
  сделанные в сменах дня. Возврат сегодня по вчерашнему чеку уменьшает сегодняшнюю выручку, а чек
  показан в списке с пометкой даты.
- Питание сотрудников и маркетинг не входят в выручку и средний чек («Без выручки»).
- Чек Webkassa продажи - в дне продажи, чек возврата - в дне возврата.
- Список чеков - не больше 2000 за день (и до 200 более ранних чеков с возвратом в этот день). Если
  чеков больше, кабинет пишет, что список неполный; итоги дня всё равно по всем чекам.

### Имена кассиров: `scripts/edge-staff-id.mjs`

Касса и облако знают кассира только по uuid. Чтобы «Касса» показывала имя, учётная запись кассы
создаётся с номером, который выводит этот скрипт из карточки сотрудника бэк-офиса («Сотрудники»).
Скрипт ничего не пишет; номер - чистое вычисление (`edgeStaffId`, тот же код в
`packages/backoffice-core/src/edge-staff.ts`, закреплён вектором).

```sh
# карточки сотрудников точки и их три номера для кассы (только чтение, один SELECT)
CLOUD_DATABASE_URL=... node scripts/edge-staff-id.mjs --list --branch <точка>

# номер одного сотрудника для роли кассы: cashier | shift_manager | kitchen
node scripts/edge-staff-id.mjs --employee <карточка> --role cashier

# готовый файл для scripts/staff-setup.mjs (staff_id, terminal_id, name, role)
node scripts/edge-staff-id.mjs --employee <карточка> --role cashier \
  --terminal <касса> --name "<имя как на кассе>" > /secure/staff-<карточка>.json
```

Файл для `staff-setup.mjs` передаётся на сервер точки так же, как другие файлы учётных записей
(без копий в чатах и тикетах), и удаляется после настройки. Одна роль - один номер: если человек
работает и кассиром, и начальником смены, у него две учётные записи кассы с разными номерами, и
обе показывают одно имя. Учётные записи, созданные раньше со случайным номером, не меняются:
кабинет показывает их как «Сотрудник 1a2b3c4d (нет карточки)». Чтобы появилось имя, нужна новая
учётная запись кассы с номером из скрипта (решение владельца кассы, вне смены).

### Названия касс

«Касса 1», «Касса 2» - по порядку первой смены каждой кассы (Z-отчёты и отчёты кассы точки), кассы
только с продажами - после них. Новая касса получает следующий номер; номер кассы не меняется, пока
не удалены её смены (в облаке смены не удаляются).

### Включение (после Cloud-2: 075 и права уже стоят)

1. Права на чтение 073. Helper `infra/staging/backoffice-p1-grants.mjs` с `posDay: true` добавляет
   SELECT на шесть таблиц `cloud_pos_sales`, `cloud_pos_tenders`, `cloud_pos_refunds`,
   `cloud_pos_refund_tenders`, `cloud_pos_fiscal_receipts`, `cloud_pos_shift_reports` (тот же набор,
   что `cloudPosSalesGrants(role, {backoffice: true})` полосы pos). Вызов в `provision.mjs` - CR
   `bo-ui-1` §1: `BACKOFFICE_POS_DAY_ENABLED=true` в env `provision`, затем провижининг. Проверка -
   `assertBackofficeP1Privileges(client, 'pickchick_app', {..., posDay: true})` в том же шаге.
2. Имена: для каждого кассира и начальника смены точки - учётная запись кассы с номером из
   `edge-staff-id.mjs` (раздел выше). Можно позже: без этого видны короткие коды.
3. `BACKOFFICE_POS_DAY_ENABLED=true` в env API, перезапуск API.
4. Проверка (управляющий, затем бухгалтер и начальник смены):
   - в меню есть «Касса»; день Т7 или первый день продаж; строка «Данные кассы получены в ...»
     со временем последней продажи;
   - выручка и способы оплаты закрытой смены совпадают с её Z-отчётом на кассе;
   - «Webkassa»: «Итого по Webkassa» совпадает с кабинетом Webkassa за день, не оформленные
     совпадают с вкладкой Webkassa на кассе;
   - «Заказы»: у двух касс «№1» с разными «Касса 1» и «Касса 2»; CSV открывается в Excel;
   - телефон: «Касса» на 390 px, суммы и кнопки видны.

Права ролей (контракт §5.10, `reports.read`): управляющий, начальник смены, бухгалтер, аналитик
читают день; прочие роли и чужая точка - 403.

### Откат

- `BACKOFFICE_POS_DAY_ENABLED=false` и перезапуск API: `GET .../ops/pos-day` отвечает 404 как
  неизвестный вид, раздела «Касса» и блока «Сегодня» нет, реестр заказов и отчёт смены - как до
  полосы, ответ `GET .../branches/<точка>` без `pos_terminals`, `pos_staff`,
  `cashier_metrics.paid_total_minor`. Данные не меняются: раздел ничего не пишет.
- Права на чтение 073 остаются: тот же набор выдаёт `cloudPosSalesGrants(role, {backoffice: true})`
  полосы pos, и сбрасывает их только он.
- Учётные записи кассы с номерами из скрипта не откатываются: это обычные учётные записи кассы.

### Чего «Касса» пока не знает

- Объяснение расхождения при закрытии смены и причина закрытия в облако не передаются (CR
  `bo-ui-2` §2 полосе pos). Кабинет показывает сумму расхождения без объяснения.

## Исправления аудита кабинета (шаг 3 полосы)

Аудит 05.11 (находки F01-F20) закрыт в коде. Новых флагов нет: каждое исправление идёт за флагом
своего раздела, а общие - за флагом кабинета перехода. Пока все флаги выключены, кабинет тот же, что
у облачной полосы (браузерный тест «every flag off»).

| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BACKOFFICE_STOCK_V2_ENABLED` (или флаг «Кассы»)      | окна «Поставка», «Списание», «Инвентаризация»: вопрос перед закрытием по Esc, «Закрыть» и обновлению страницы, черновик в этой вкладке и «Продолжить ввод» на странице «Остатки»; при одновременном документе - «Остаток изменился, пока вы вводили документ», колонка «По учёту» обновляется, строки остаются, тот же документ проводится ещё раз; вкладка «Ингредиенты», окно «Поставка»                                                                                                                    |

| `BACKOFFICE_POS_DAY_ENABLED` (флаг кабинета перехода) | всё остальное: «Обновляем…» вместо пустой страницы, «Нет связи с сервером. Показаны данные на ЧЧ:ММ» и «Повторить» (про доступ - только при 403); вкладки не пропадают при наведении; период только на «Главной», «Заказах», «Отчётах», «Оплатах и чеках» и в кассовых сменах; журнал аудита с именами, русскими названиями операций и фильтрами; таблицы карточками на телефоне; CSV в тенге; даты ДД.ММ.ГГГГ; деньги «11 670 ₸»; срочные и просроченные обращения сверху; стоп-лист сразу «Только на стопе» |

Почему общие исправления за флагом «Кассы»: дополнение контракта требует, чтобы при выключенных флагах
кабинет был байт-в-байт прежним, а отдельного флага для исправлений в списке полосы нет. Флаг «Кассы»
включает кабинет перехода 19.11, поэтому исправления приходят вместе с ним. Решение - одна функция
`auditFixes` (`apps/backoffice/src/operations-model.ts`); если интеграция решит иначе (без флага или
свой флаг), меняется только она (CR `bo-ui-3`).

### Проверка после включения (5 минут, управляющий)

1. «Остатки» → «Поставка», ввести номер и одну строку, нажать Esc: кабинет спрашивает «Отменить ввод
   документа?». Ответ «Отмена» - окно и ввод остаются. Обновить страницу: браузер спрашивает; после
   обновления на «Остатках» есть «Есть незавершённый документ «Поставка»» → «Продолжить ввод» - строки
   на месте. Закрыть окно с ответом «ОК» - черновик удалён.
2. «Журнал аудита»: в колонке «Автор» имена, в «Операции» - «Поставка», «Изменение: ингредиент» и т. п.,
   фильтр «Раздел» сужает список; переключателя периода нет.
3. Телефон (390 px): «Остатки» и «Финансы» → «Журнал операций» - строки карточками, сумма видна без
   прокрутки вбок; в шапке «Вы: ...».
4. Бухгалтер (назначение `accountant`): «Финансы» → «Добавить операцию» доступна; на «Остатках» есть
   «Поставка» и текст «Списание проводят управляющий и начальник смены.».

### Откат

Флаг раздела `false` и перезапуск API - кабинет снова прежний для этого раздела. Черновики окон
живут только в `sessionStorage` вкладки (ключи `pickchick.backoffice.stock-draft.v1:*`,
`record-draft.v1:*`, `audit-fixes.v1:*`) и пропадают при закрытии вкладки; на сервере ничего не
хранится. Имена в журнале аудита - чтение, без записи.

### Что не исправлено и почему

- F18 (текст на экране входа при неверном файле доступа): до входа кабинет не знает флагов сервера,
  поэтому без флага его не изменить; ждёт ответа на вопрос `design-bo-ui.md` §8 в.1.
- Выбор дат в окнах браузера (`мм/дд/гггг` в браузере с английским языком) рисует сам браузер; в
  русском Chrome формат ДД.ММ.ГГГГ.
- Сортировка по клику на заголовок таблицы (часть F19) не сделана: в реестре заказов есть «Порядок».
