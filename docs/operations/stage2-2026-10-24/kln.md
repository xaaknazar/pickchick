## Подробно

### Перезапуск и простой (`apps/kiosk/src/commercial-controller.ts`)

Что было: после перезапуска (питание, сбой, обновление, повторный запуск AppLock) киоск
восстанавливал режим и корзину прошлого гостя на экране меню и до первого такта простоя
(до 1 с) показывал их; если гостевая сессия истекла, сначала продлевал её ради уже брошенного
черновика.

Сейчас: если с последнего сохранённого изменения черновика (режим или корзина, без заказа и
намерения оплаты) прошло не меньше 90 + 15 с, `restore` ставит штатную метку сброса и
завершает гостя тем же путём, что и сброс по простою. Без сети метка остаётся, заставка уже
чистая, завершение повторяет опрос. Черновик моложе 105 с восстанавливается как раньше (сбой
перед гостем). Заказ, намерение оплаты и неизвестная оплата перезапуском не затрагиваются.
Касания в хранилище не пишутся (как и раньше), поэтому считается время последнего сохранённого
изменения. Формат сохранённого состояния не менялся.

Пять существующих тестов продления истёкшей сессии моделировали черновик, брошенный на сутки;
теперь сессия в них истекает, пока черновик свежий (реальный случай: сессия выдаётся ещё на
заставке). Цель тестов - продление без потери черновика - сохранена.

Сборка-симулятор (`controller.ts`, только разработка) не менялась.

### «Состояние киоска» (`kiosk-health.ts`, `KioskHealthList`, `GuestScreen.tsx`)

- Удержание логотипа 5 с (или «Сотруднику» на экране восстановления) -> «Действия сотрудника»
  -> новая кнопка «Состояние киоска». В коммерческой сборке нужна проверка кода сервером
  (`/staff/verify`, как для демо и сервисного сброса); при отказе ничего не показывается и факты
  не читаются. В сборке-симуляторе кода нет - строка открывается сразу и вся помечена
  «Проверить».
- Строки: сборка (`версия (номер), выпуск pk-...`), сервер (`origin (production|staging)`),
  коммерческий режим, код сотрудника, сигнал в центр устройств («N с назад, принят», «сервер
  ответил 404», «нет связи», «ещё не отправлялся»). Пометка «Проверить» (текст и цвет ошибки):
  нет release id, профиль не production, не коммерческая сборка, нет кода, сигнал не 2xx,
  старше 60 с или ещё не было.
- Ключ устройства, данные гостей и код сотрудника не показываются и не хранятся; код
  очищается после ответа. При закрытии диалога строка забывается.
- `device-presence.ts`: необязательный наблюдатель исхода каждого отправленного запроса (HTTP
  статус или «нет ответа»). Запрос, тело, расписание и обработка ошибок не изменились;
  ошибка наблюдателя не влияет на присутствие.
- Тексты KZ/RU/EN (`i18n.ts`), казахские формулировки нужно проверить носителю языка.

### Профиль и генератор

- Шаблон: `com.apple.app.lock` для `kz.pickchick.kiosk`, `DisableTouch=false`,
  `DisableDeviceRotation`, `DisableSleepWakeButton`, `DisableAutoLock` = `true`, VoiceOver/Zoom
  для гостя. Заполнители: название организации и два `PayloadUUID`. `PayloadIdentifier`
  прежний (`kz.pickchick.configuration.kiosk`): новая версия заменит установленную.
  Название профиля с обычным дефисом.
- `node scripts/mobile/kiosk-applock-profile.mjs --organization "<название>" [--out ...]`:
  новые UUID, экранирование XML, отказ без названия или с изменённым шаблоном, вывод в
  `.local/ipad/` (вне Git).
- Тест сверяет ключи шаблона со схемой Apple (`com.apple.app.lock.yaml`, `TopLevel.yaml`) и
  разбирает результат Python `plistlib`.

## Флаги и переменные

Новых флагов нет. Изменения работают только в новой сборке киоска и не требуют настройки
владельца: очистка при перезапуске - защитное поведение (ослабить его нечем), строка
состояния видна только персоналу. Используются существующие:

| Имя                            | Где           | По умолчанию  | Значение для полосы                                                     |
| ------------------------------ | ------------- | ------------- | ----------------------------------------------------------------------- |
| `EXPO_PUBLIC_KIOSK_COMMERCIAL` | сборка киоска | выкл.         | `1` - код сотрудника обязателен, присутствие отправляется               |
| `KIOSK_STAFF_PIN_VERIFIER`     | env API       | пусто = выкл. | без него «Состояние киоска» в рабочей сборке не открыть                 |
| `DEVICE_CENTER_ENABLED`        | env API       | выкл.         | без него и маршрута gateway строка сигнала покажет «сервер ответил 404» |

## Риски

- Черновик гостя, который долго выбирал без изменений корзины и попал на сбой, после
  перезапуска очищается (считается последнее сохранённое изменение) - осознанный выбор в
  пользу приватности.
- Без связи с API или без верификатора кода «Состояние киоска» в рабочей сборке не открыть
  (так задумано: только за кодом); runbook это учитывает.
- Факты Apple могут измениться; дата проверки указана в документах.
- TestFlight остаётся единственным каналом до решения владельца: сборка перестаёт запускаться
  через 90 дней, нужен календарь замены.
