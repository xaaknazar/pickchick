# Этап 2, полоса cfg: доставка плана станций на кассу (24.10.2026)

Ветка `codex/station-plans-edge-1024` от `4cc11e05`. Задача roadmap `backoffice-config-delivery`:
«Cloud сохраняет версии/намерение публикации, но worker/lease/receipt плана станций ещё не
реализованы». Критерий приёмки: **кабинет показывает версию, подтверждённую кассой, а не только
публикацию в облаке.** Всё новое выключено по умолчанию. Ничего не установлено на VPS, кассу,
iPad; приёмка владельцем не проводилась.

## Что сделано

Поток повторяет надёжную схему доставки меню (menu-sync), но отдельным каналом:

```
публикация станции в кабинете -> версия плана (cloud070) -> касса забирает план (pull)
-> применяет в одной транзакции ИЛИ отклоняет с причиной (edge024) -> квитанция (receipt)
-> кабинет: опубликовано / получено кассой / применено / отклонено с причиной / заменено
```

- **План** - полный состав опубликованных станций точки на момент публикации (последняя
  опубликованная ревизия каждой станции). Версии растут только вверх и выдаются под блокировкой
  точки; новая версия всегда выше версии, которую касса сообщила как действующую.
  Схема плана `schema_version: 1`, контрольная сумма - SHA-256 канонического JSON (тот же
  формат, что у меню).
- **Облако (cloud070):** `bo_station_plans` (неизменяемые версии), `bo_station_plan_deliveries`
  (когда и сколько раз касса получила план, только вперёд), `bo_station_plan_receipts`
  (неизменяемый ответ кассы, один на версию), `bo_station_plan_edge_state` (какой план касса
  применяет сейчас и её станции кухни; наблюдение, не команда).
- **Транспорт:** `POST /internal/v1/edge/station-plans/pull` и `.../receipt`, аутентификация
  ключом устройства кассы, резервный бюджет edge (`@EdgeDeviceRoute`), тот же приватный туннель,
  что у меню; публичный gateway эти пути не маршрутизирует. Без флага оба пути отвечают 404.
  Pull всегда отдаёт только новейшую версию без ответа: каждая версия - полный план, поэтому
  более старые версии без ответа показываются как «заменено». Отдельного lease-токена нет: на
  точке одна активная касса (unique index), а ответ идемпотентен по `plan_id` + checksum.
- **Касса (edge024):** `station_plan_snapshots` (применённые планы, неизменяемые),
  `station_plan_active` (действующий план; триггер разрешает только более новую версию и запрещает
  удаление), `station_plan_receipts` (inbox и durable outbox в одном: один ответ на план,
  `reported_at` ставится один раз). Проверки по порядку: целостность (иначе ошибка и повтор, без
  ответа), версия схемы (`SCHEMA_UNSUPPORTED`), содержимое (`INVALID_PLAN`), версия
  (`VERSION_NOT_NEWER`), привязка каждой активной станции к станции кухни кассы
  (`UNKNOWN_STATION`, `STATION_KIND_MISMATCH`, с id станции плана), две активные станции на одной
  станции кухни (`INVALID_PLAN`). При отклонении применение откатывается, коммитится только
  ответ: **предыдущий план остаётся действующим**. Повтор того же плана возвращает сохранённый
  ответ; тот же `plan_id` с другим содержимым - конфликт.
- **Worker кассы:** шаг плана станций в существующей службе `PickChickMenuSyncWorker` и под её
  ролью `pickchick_menu_sync`, изолированный от меню: его ошибки не меняют ожидание, счётчик
  ошибок и код выхода цикла меню. Сначала отправляется сохранённый неотправленный ответ, затем
  pull с отчётом (действующий план + станции кухни), применение и сразу ответ. Без работы шаг
  повторяется раз в 10 с, при 404 облака или без схемы/прав - раз в минуту (без запроса в облако,
  если нет схемы 024 или прав). Ответ, который облако отказалось записать (404/409), не блокирует
  получение новых планов до перезапуска службы.
- **Кабинет («Станции и маршруты»):** под таблицей станций панель «Доставка плана на кассу»:
  последняя версия в облаке, версия, подтверждённая кассой (ответ «применено» или отчёт кассы,
  что новее), время последней связи, состояние текстом (причина отклонения по-русски, с названием
  станции), таблица последних 10 версий, кнопка «Отправить план на кассу» (только управляющий,
  при включённом флаге; если план не изменился и не был отклонён, новая версия не создаётся).
  В карточке станции - выбор «Станция кухни на кассе» из станций, о которых сообщила касса (только
  приготовление и сборка). Серверу без доставки кабинет не отправляет новое поле и не показывает
  новую панель: со старым API кабинет работает как раньше.
  `capabilities.edge_configuration_delivery` теперь правдив.

План **не меняет маршрутизацию заказов и допуск заказов**: маршруты по-прежнему выводятся из
публикации меню и локальной настройки кухни, а уже принятые заказы не трогаются. Касса хранит
подтверждённую конфигурацию (`readActiveStationPlan`) для следующего шага - экранов кухни и
норм времени; использовать её на кухне - отдельное решение.

## Флаги

| Флаг                                       | Где                  | По умолчанию                         | Значение                                                                                                                                                                         |
| ------------------------------------------ | -------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BACKOFFICE_STATION_PLAN_DELIVERY_ENABLED` | API (VPS)            | `false`                              | Публикация станции создаёт версию плана, работают pull/receipt и команда «Отправить план на кассу». Нужны cloud070 и права `stationPlanGrants`; readiness API проверяет оба.     |
| `EDGE_STATION_PLAN_SYNC_MODE`              | worker меню на кассе | `auto` (Windows), `off` (dev-скрипт) | `auto`: переключатель - сама база: шаг работает только после охраняемого обновления 024, выдавшего роли права. `off` - не трогать; `report` - только отчёт; `apply` - применять. |

`menu-sync.env` на кассе закреплён проверенным установщиком (`install-native-menu-sync.ps1`,
его хеш закреплён в трёх скриптах), поэтому новую строку в этот файл не добавлять: на Windows
работает значение `auto`. Без флага облака касса получает 404 и ничего не применяет.

## Миграции

- **cloud070** `070_cloud_station_plans.sql` (SHA-256 `794f90d8...ef0c`): четыре новые таблицы,
  триггеры неизменяемости/только вперёд. Добавочная, существующие таблицы не меняются.
  Права: `stationPlanGrants(role, {backoffice, delivery})` в
  `infra/staging/station-plan-grants.mjs`. Это отдельный helper, потому что
  `backoffice-grants.mjs` закреплён по SHA-256; он подключён в `provision.mjs` после
  `backofficeStopGrants`. Без флага - только SELECT (кабинет видит историю), без бэк-офиса -
  ничего; планы и ответы нельзя изменить или удалить.
- **edge024** `024_edge_station_plans.sql` (SHA-256 `cd3cbf65...064a`): три новые таблицы.
  Охраняемое обновление `infra/windows/station-plan-upgrade-db.mjs` (по образцу
  `display-numbers-upgrade-db.mjs`/`restore-fence-upgrade-db.mjs`): `inspect`/`apply`, база ровно
  schema023 из проверенного релиза, одна точка, одна транзакция под блокировками; выдаёт права
  только роли `pickchick_menu_sync` (если она установлена), доказывает её точный набор прав, что
  никакая другая роль не видит новые таблицы и что строки/последовательности/ACL прежних таблиц
  не изменились; повтор отказывает. `menu-sync-upgrade-db.mjs` при повторном запуске после 024
  сохраняет эти права (`menuSyncWorkerGrants(..., {stationPlans})`).

## Контракты

`openapi.json` перегенерирован: пути `/internal/v1/edge/station-plans/pull|receipt`, схемы
`StationPlanPullRequest`, `StationPlanPullResponse`, `StationPlanReceipt`,
`StationPlanReceiptResult`; в `BackofficeRecord_station` необязательное `edge_station_id`; в
`BackofficeRequest` команда `{type:'deliver_station_plan'}`. Новые причины ошибок бэк-офиса:
`STATION_PLAN_DELIVERY_DISABLED`, `STATION_PLAN_EMPTY` (409 `NOT_READY`). Схемы - в
`packages/contracts/src/station-plans.ts`.

## Выпуск и откат

Порядок (каждый шаг отдельно включается и отдельно откатывается):

1. **Облако, схема.** Образ API с этой веткой; миграция 070 охраняемым owner-шагом (как
   064/066/068), права `stationPlanGrants('pickchick_app', {backoffice: true, delivery: false})`.
   Флаг выключен: публикации как раньше, кабинет показывает «Доставка выключена». Прежний API
   работает на схеме 070 (новые таблицы ему не нужны).
2. **Касса, runtime.** После отложенного выпуска runtime 020->023: runtime с этим кодом.
   На schema023 шаг плана пишет `station_plan_sync` `schema_missing` один раз и в облако не ходит.
3. **Касса, 024.** Службы кассы остановлены, свежая проверенная копия базы. Из проверенного
   checkout, сначала `inspect`, затем `apply`:

   ```sh
   node --env-file=<owner env> infra/windows/station-plan-upgrade-db.mjs inspect <toolsRoot> <appRoot> <branchId>
   ```

   Запустить службы, проверить `/health/ready`. Касса начинает сообщать станции кухни; без флага
   облака - `unavailable` раз в минуту.

4. **Облако, флаг.** `BACKOFFICE_STATION_PLAN_DELIVERY_ENABLED=true` в окружении API и
   `stationPlanGrants(..., {backoffice: true, delivery: true})`, перезапуск API, `/health/ready`
   (проверяет 070 и права). В кабинете привязать станции к станциям кухни кассы, опубликовать
   станцию или нажать «Отправить план на кассу», дождаться «Применено на кассе».

Откат: выключить флаг облака (и права обратно на `delivery: false`) - пути отвечают 404, новые
версии не создаются, касса продолжает с последним применённым планом (его ничто не использует
для заказов). Схемы 070/024 и строки не откатывать и не удалять. Прежний runtime кассы работает
на 024 (не читает эти таблицы). Чтобы касса перестала ходить за планами без флага облака -
отозвать права роли на три таблицы 024 (отдельное ревью оператора).

## Что нужно от владельца

- Решение, что делает кухня с подтверждённым планом: экраны станций, нормы времени, маршруты.
  Сейчас план только доставляется и подтверждается.
- Состав станций точки и их привязка к станциям кухни кассы. У кассы есть только станции
  «приготовление» и «сборка»; «Напитки» и «Выдача» привязать нельзя (кабинет и касса это
  проверяют).
- Когда включать флаг на VPS (после выпусков runtime и 024 на кассе).
