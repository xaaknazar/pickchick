## Серверное окно: T0 назначает владелец, резерв 120 минут

Это бюджет времени, не обещание длительности. Если копирование или восстановление
не укладывается, применение отменяется или окно продлевается только владельцем.
Работающий API до переключения сохраняется; короткий перезапуск API возможен на шаге4.
Кабинет и watchdog в это окно не включены: для них отдельный план и отдельное «да».

| Время от T0 | Действие                                                                                                                                        | Условие перехода                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 0-10мин     | Получить «да» на окно/шаг миграций, занять release lock, повторить read-only сверку и зафиксировать baseline                                    | Все закреплённые значения совпали, чужих блокировок нет                                |
| 10-35мин    | Свежая зашифрованная копия cloud068, manifest и SHA-256, копия шифрованных файлов на Mac; восстановление в отдельный контейнер без внешней сети | Копия именно этого окна, хеш совпал, ledger и количества таблиц/строк проверены        |
| 35-50мин    | На восстановленной копии репетиция069/070/071 и запуска кандидата, затем live inspect и один deploy --with-069                                  | Новые таблицы и ledger ожидаемы, прежние данные/права сохранены, все новые флаги false |
| 50-75мин    | Остановиться для отдельного «да» на API. Prepare/apply защищённым оператором, включая новую копию071, изолированное восстановление и запуск     | Старые артефакты сохранены; кандидат готов; только API, без provision/миграций/worker  |
| 75-90мин    | Наблюдение и read-only проверки API, каталога, доступности, App Store поведения и соседних служб                                                | Нет новых ошибок; три флага false; данные и настройки сохранены                        |
| 90-120мин   | Резерв на диагностику/откат API и итоговый протокол                                                                                             | Время фактических операций и итог фиксируются; без автоматического следующего шага     |

Если в 50 мин разрешение на API не получено, окно заканчивается после успешных миграций:
старый API продолжает работу, новые таблицы остаются неиспользуемыми. Не занимать
рабочую release-блокировку бессрочно в ожидании ответа; завершить протокол и штатно
освободить свою блокировку, перед следующим шагом повторить сверку и claims.

## Команды и доказательства

Ниже шаблоны из существующих инструментов, не команда к немедленному запуску.
Переменные подставляются из проверенного закрытого протокола окна; пока нет совместного
кандидата и свежего baseline, заполненного безопасного launch-пакета нет.

Копия до миграций: проверенная установленная `infra/staging/backup.sh` от `pickchick-ops`
с существующими настройками. Проверить именно новые файлы и `lastSuccessAt`: при занятом
backup lock скрипт может вернуть0 без новой копии, это не допуск к миграциям.
Не менять retention/offsite/PITR ради этого выпуска. На Mac проверить шифрованный дамп:

```sh
python3 infra/staging/restore-drill.py dump \
  --dump "$ENCRYPTED_DUMP" --manifest "$ENCRYPTED_MANIFEST" \
  --identity "$AGE_IDENTITY_PATH" --require-manifest
```

Репетиция owner-шагов выполняется в изолированной БД с именем `pickchick_cloud`,
ролью `pickchick_owner` и закрытым окружением кандидата, без исходящих банковских сетей.
Те же entrypoints на VPS запускаются внутри закреплённого образа кандидата с
существующим owner-доступом только после «да», копии и репетиции:

```sh
node infra/staging/stage2-cloud-owner.mjs inspect --with-069
node infra/staging/stage2-cloud-owner.mjs deploy --with-069
```

Ожидаются исходный schema068, затем ровно069/070/071 и проверенные checksums.
Если069 уже есть, не переключаться молча на другую команду: обновить план владельцу.
После успеха inspect/deploy повторно не запускать: оператор намеренно требует068/069.
Результат071 проверить отдельным read-only ledger/ACL, без повторного применения.

Для API использовать один набор аргументов из закрытого протокола:

```sh
python3 infra/staging/release-stage2-1024.py prepare \
  --sha "$SOURCE_SHA" --branch "$BRANCH" \
  --expected-api-sha "$API_BASELINE_SHA" --expected-public-sha "$PUBLIC_SHA" \
  --expected-api-image "$API_IMAGE" --expected-compose-sha256 "$COMPOSE_HASH" \
  --expected-gateway-sha256 "$GATEWAY_HASH" --ssh-key "$SSH_KEY_PATH" \
  --backup-identity "$AGE_IDENTITY_PATH" --ci-proof "$CI_PROOF_PATH"
```

После отдельного «да»: те же аргументы для `prepare --apply`, затем `apply --apply`.
Шаг API требует уже установленную071, поэтому его backup не заменяет копию068
до миграций. В api/provision добавляются только три буквальных `false`, остальные
настройки сохраняются; provision не запускать. Самостоятельно запускать старый
оператор1021 на069/070/071 нельзя: у него другие закрепления и границы.

Проверки после: `/health/ready`, точный SHA/image и pointer, ledger071/checksums,
права ролей, неизменность соседей и прежнего окружения, публичные catalog/availability,
три флага этапа 2=false и push=false. Без новых заказов, QR, счетов или платежей.
Протокол включает время, CI, хеши, результат копий/репетиций/переключения; без строк БД
и секретов. Функциональная приёмка владельцем отмечается отдельно.

## Откат и остановка

- До COMMIT миграций любая ошибка откатывает всю owner-транзакцию. При потере ответа
  сначала read-only ledger, а не повтор deploy. Новые таблицы071 после успеха не удалять:
  при выключенных флагах прежний API совместим с ними. Рабочую БД не восстанавливать
  поверх актуальных заказов ради отката API.
- До переключения API отказ копии/репетиции оставляет старый API. Сохранить receipt и
  блокировку для разбирательства; чужую блокировку не удалять.
- После переключения при неготовности, несовпадении SHA, изменении соседей/прав или
  регрессии App Store выполнить `rollback --apply` с теми же закреплёнными параметрами
  и владельцем блокировки в рамках согласованного плана отката API. Вернуть прежний
  image/compose/pointer, оставить071, проверить readiness и наблюдать минимум 10 мин.
- При неожиданно включённом флаге оператор отката откажет. Не обходить проверку:
  остановиться и согласовать выключение/совместимое меню. Restore рабочей БД - отдельный
  аварийный план и отдельное разрешение, не автоматическая часть этого окна.
- Касса020, каталог, цены, платёжные обработчики, iPad и Apple этим окном не меняются.
