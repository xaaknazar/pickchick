# Игры из заказа: неподвижный экран

14 октября 2026. База `885afaa58846088c77d175d3b60f32c7a1bbab6f`,
ветка `codex/order-game-gestures`. Статус: исправление приложения;
установка и приёмка на физическом iPhone ещё не подтверждены.

## Причина и изменение

PICK MAN, открытый поверх экрана заказа, наследовал нативное модальное
представление iOS. Вертикальный жест двигал окно вместо управления игрой.
Локальное `gestureEnabled: false` на уже открывающемся экране не выбирает
полноэкранный контейнер заранее. В текущем Expo Router экран без явного
`presentation` после модального маршрута становится `modal`; это подтверждено
исходником установленной версии и регрессионным тестом с её `getModalRouteKeys`.

В корневом Stack все четыре игровых маршрута теперь используют существующие
`ARCADE_SCREEN_OPTIONS`: `fullScreenModal`, `gestureEnabled: false`.
Ранее это было объявлено только для PICK BLOCKS. React Native Screens отображает
этот режим через `UIModalPresentationFullScreen`, без перемещаемой page sheet.
Дизайн, игровые жесты, ориентация и ограничения доступности сохранены;
отключённая PICK FARM не включалась.

Кнопки выхода из PICK MAN ставят игру на паузу и возвращают назад. При запуске
из заказа подпись - «К заказу»; прямой вход без истории возвращает в «События».
Из маршрутного экрана заказа возвращается тот же экран. Из истории оплаченных
заказов возвращается список, из которого можно снова открыть тот же заказ:
прежнее закрытие React Native Modal перед запуском игры сохранено.

## Проверки и границы доказательства

- Все 363 теста `tests/mobile/*.test.mjs` прошли, включая проверку всех игровых
  маршрутов после Events, order-status и checkout через установленный Expo Router.
- TypeScript, адресный ESLint и форматирование проверены.
- Изолированный браузерный сценарий трекера: 5 стадий TEST и 3 стадии Kaspi;
  запуск PICK BLOCKS, PICK MAN, Magic Sort, возврат и повторное открытие заказа.
  В PICK MAN четыре направления сенсорного ввода, неизменные координаты экрана
  и сохранённое направление движения. Реальные счета и оплаты не создавались.
- Отдельный браузерный сценарий PICK MAN: запуск из Events, вход в аккаунт,
  свайпы, пауза, сохранение, перезапуск, победа/поражение и пять размеров экрана.
- Web, iOS и Android Hermes exports проверяют сборку JavaScript. Они не являются
  подписанным приложением и не доказывают поведение UIKit на телефоне.

Применены Impeccable harden/polish и адресная проверка React-компонентов.
UI/UX Pro Max не нашёл точного соответствия запросу про native modal;
решение опирается на существующий шаблон PICK BLOCKS и установленный native stack.
Новых элементов, стилей и библиотек нет. При визуальной проверке исправлена
также устаревшая подпись выхода в меню паузы PICK MAN.

## Выпуск и физическая приёмка

На этом Mac доступен только Command Line Tools, полного Xcode нет.
Резерв `@release/ios` остаётся у `mobile-payment-recovery`; следующий мобильный
выпуск должен включить исправление оплаты `885afaa` и эту ветку.
Сервер, касса, платежи и установленные приложения этой правкой не обновлялись.

На Mac с настроенной подписью получить общую версию, принять резерв выпуска и
следовать [mobile-testflight.md](mobile-testflight.md). На iPhone проверить:

1. Открыть существующий заказ из истории и из экрана после оплаты.
2. Запустить каждую доступную игру. Окно занимает экран целиком, нет ручки
   сворачивания и видимой шапки заказа над игрой.
3. В PICK MAN многократно провести вверх, вниз и в стороны, включая длинные
   свайпы. Двигается персонаж; окно не сдвигается и не закрывается.
4. Поставить игру на паузу, выйти стрелкой и кнопкой «К заказу»; проверить
   сохранность заказа и актуальный статус. Повторить запуск из «Событий».
5. Переключиться в фон и вернуться; проверить паузу и возобновление игры.

Общие `docs/project-status.md` и `docs/roadmap/project.json` во время работы
зарезервированы `kiosk-owner-polish-1013`. Результат и следующий шаг передаются
этим документом и журналом координации; общую сводку обновить при согласованном
выпуске, отдельно указав установленную версию и факт физической приёмки.
