# Номера заказов по сменам

Решение владельца 25 сентября 2026 заменяет прежний сброс в 00:00 Алматы.
Один счётчик действует до закрытия операционной смены точки. Открытие следующей
смены начинает выдачу с 1. Перезапуск, полночь, смена сотрудника и повтор запроса
не сбрасывают счётчик. Отмена/выдача не переиспользует номер. Незавершённые
заказы остаются в своей смене и сохраняют номер после её закрытия.

## Реализованная область и границы

Этот этап меняет текущую облачную очередь мобильного приложения/web-киоска,
`/test/kitchen/*`, `/test/display` и `/manager`. Открывает/закрывает смену
роль manager на странице управляющего; закрытие требует подтверждения.
Закрытая смена запрещает новые заказы (409 SHIFT_CLOSED), но позволяет
завершать старые. Корзина остаётся у клиента. До первой смены в новом synthetic
namespace допускается однократный bootstrap для совместимости; после явного
закрытия автоматического открытия нет.

Локальная касса и её local_cash_shifts пока отдельны. Кнопки Windows-кассы НЕ
управляют облачной сменой этим изменением. Общая операционная смена всех каналов
с владельцем edge и надёжной синхронизацией cloud/edge остаётся отдельной
интеграцией; смены сотрудников и ККМ не должны случайно сбрасывать общий номер.
Это не подключение оплат, чеков или коммерческого checkout.

## Хранение и совместимость

Миграция021 создаёт test_service_shifts, связывает номера со сменой и меняет
назначающий trigger. Выдача номера транзакционная, уникальная по shift_id;
закрытие/открытие идемпотентны и проверяют предыдущую смену/версию под общим
command lock. База сама запрещает выдачу в закрытой смене даже старому API.

Миграция не переписывает номера, заказы, платежи, outbox или результаты команд.
Исторические даты становятся закрытыми периодами, текущая активная очередь
получает bootstrap-смену с прежним последним номером за текущую дату. Номер
продолжится, а не начнётся заново при установке. Далее календарь не участвует
в выборе счётчика. Счётчики переживают удаление старых заказов.

`number_format=daily` остаётся совместимым именем параметра короткого номера;
после021 его счётчик относится к смене. Без параметра сохраняется T-номер для
старых клиентов. UUID остаётся идентификатором команд, доставки и UI-ключей.
Табло запрашивает `shift_context=1`: только такой ответ дополняется shift_number.
При двух одинаковых номерах из разных смен выводится «Смена №…». Старый API
игнорирует дополнительный query, старые клиенты не получают новых полей.

Runtime получает SELECT/INSERT(branch_id,state)/UPDATE(state,version,closed_at)
на смены и USAGE новой sequence. Счётчик last_number и привязки номеров изменяет
только owner-trigger. Readiness требует021 и SELECT таблицы смен.
Новые gateway маршруты строго ограничены GET shift и POST shift/open|close,
включая соответствующие CORS preflight. Auth/роль проверяются API.
