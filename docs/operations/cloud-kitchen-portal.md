# Облачные заказы на страницах кухни (портал, ADR-0014 S6)

Решения владельца 2026-10-10: заказы iPad-киоска и мобильного приложения, которые выполняет
облако (`fulfillmentOwner: "cloud"`), показываются на **существующих** страницах
`pickchick.kz/kitchen/prep`, `/kitchen/assembly` и `/display` (портал `infra/kitchen-portal`,
[ADR-0011](../architecture/adr/0011-kitchen-live-link.md)). По решению 5
[ADR-0014](../architecture/adr/0014-cloud-kitchen-channel.md) кухонный экран аутентифицируется в
облаке **как экран**, без пароля повара и без кассы; действия записываются на экран и станцию.
Контракт API: [cloud-kitchen-s4.md](../architecture/cloud-kitchen-s4.md).

Статус: код и тесты в ветке `codex/cloud-kitchen-portal`; **в production не включено**, флаг
портала по умолчанию выключен, релиз на VPS не выполнялся.

## Как это работает

- **Привязка экрана.** При включённом флаге страница сначала просит «Код экрана» -
  одноразовый код cloud 056 (`XXXX-XXXXXX`, 10 минут), выпущенный в бэк-офисе или
  `infra/staging/cloud-kitchen-screen-owner.mjs` для экрана этой роли. Браузер отправляет код
  порталу (`POST /kitchen-live/<роль>/cloud/pair`), портал на сервере обменивает его в API
  (`POST /v1/kitchen/pairing`) и получает ключ экрана `pcks_...`.
- **Cookie вместо ключа.** Ключ браузеру не выдаётся. Портал кладёт его в зашифрованную cookie
  `pickchick_cloud_screen_<роль>` (AES-256-GCM, ключ выводится из секрета портала и привязан к
  роли и пути): `HttpOnly; Secure; SameSite=Strict; Path=/kitchen-live/<роль>/`, срок 1 год.
  Cookie prep не открывает assembly; подделанная или выпущенная другим порталом не читается.
- **Каждый запрос проверяет облако.** Портал ничего не хранит в памяти: на каждый запрос
  ленты/команды он расшифровывает cookie и идёт в API с ключом этого экрана. Отзыв или ротация
  экрана (новый `generation`) - API отвечает `401`, портал отвечает `401` и стирает cookie,
  страница возвращается к вводу кода («Экран отключён от сервера. Введите новый код экрана.»).
  Перезапуск портала привязку не теряет. Недоступность API - `503`, cookie не трогается,
  индикатор «Сервер: нет связи».
- **Код другой роли или точки** портал не принимает (`409`, cookie не ставится). Код при этом
  уже израсходован облаком - нужен новый код для этого экрана. Неверный код - `401`; попытки
  ограничены 12 в минуту на клиента порталом и 5 неверными на код облаком.
- **Лента и команды.** Браузер читает облако через `/kitchen-live/<роль>/cloud/v1/fulfillment/*`
  (тот же контракт и проверки, что лента кассы). Опрос идёт только с открытой страницы
  (раз в 5 секунд) - это heartbeat станций для `KITCHEN_OFFLINE`; станцию вне экрана портал в
  облаке не опрашивает. Команды - `POST /v1/kitchen/commands` с ключом экрана,
  `Idempotency-Key` и `expectedVersion`; журнал облака пишет их на этот экран и станцию.
- **Касса - отдельно и по-прежнему.** Заказы кассы видны и выполняются только после входа
  повара (кнопка «Вход повара», прежний логин и, для ADR-0013, прежняя привязка терминала к
  кассе). Cookie экрана не является сессией повара: кассовые маршруты без повара отвечают
  `401`. Действие через кассу для заказа облака портал отклоняет. Выход повара не отвязывает
  экран.
- **Одна очередь.** Дубли по `orderId` отбрасываются (копия облака главнее), метка источника
  «Касса»/«Сервер», индикаторы «Касса: на связи / нет связи / нужен вход повара» и «Сервер: на
  связи / нет связи / экран не подключён». Недоступная лента оставляет последние заказы на экране
  с выключенными кнопками. Журнал незавершённых команд свой для каждого владельца
  (`pickchick.kitchen.pending.v1.cloud.screen.<точка>.<экран>` и прежний ключ повара).
- **Табло** привязывается своим кодом роли `display` и показывает номера облака (киоск 300-599,
  приложение 600-899) и, если вошёл повар или табло привязано к кассе по ADR-0013, номера кассы
  (1-299).
- Сохранённая сессия повара при выключенной кассе не мешает экрану: облачная очередь работает,
  вход повара повторяется при каждом обновлении, пока касса не ответит.
- `/kitchen-live/health` отдаёт `cloudConnected` только при включённом флаге; без флага портал и
  renderer ведут себя как раньше.

## Конфигурация (флаг по умолчанию выключен)

В защищённый `config.json` портала (`KITCHEN_STATE/private/config.json`, `0600`, не в Git):

```json
"cloudKitchen": {
  "enabled": true,
  "apiOrigin": "http://pickchick-api:3100",
  "branchId": "<uuid точки>"
}
```

Ключей в конфигурации нет: они живут только в cookie привязанных экранов. `apiOrigin` - только
внутренний адрес (имя docker-сервиса или частный IP, без пути). Неверная конфигурация - портал не
стартует (`INVALID_PORTAL_CONFIG`). Cookie шифруются существующим секретом портала `key`: его
смена отвязывает все экраны.

Сеть: оверлей `infra/kitchen-portal/compose.cloud.yaml` подключает портал к внутренней сети
`pickchick-kitchen_cloud`. API подключается к ней с алиасом из `apiOrigin`; сеть базы данных API
порталу не открывается. На API: `CLOUD_KITCHEN_API_ENABLED=1`, `CLOUD_KITCHEN_PUBLIC` не задан
(портал не шлёт заголовков пересылки, `/v1/kitchen/*` наружу не публикуется).

Станции облака должны быть заведены с теми же id, что станции кассы
(`provisionCloudKitchenInTransaction`), чтобы заказы обоих владельцев попадали на одну станцию.

## Шаги владельца для выпуска (не выполнялись)

Выпуск - отдельная guarded-операция по runbook с резервацией `@vps`; бэкап, проверка CI и откат
обязательны. Предварительно: на VPS применены cloud 053-056 и гранты
`cloud-kitchen-grants.mjs`, `channel-number-grants.mjs`, `cloud-kitchen-screen-grants.mjs`;
станции и маршрутизация облака заведены.

1. Сеть и API: `docker network create --internal pickchick-kitchen_cloud`,
   `docker network connect --alias pickchick-api pickchick-kitchen_cloud <контейнер API>`,
   `CLOUD_KITCHEN_API_ENABLED=1` на API.
2. Портал: добавить блок `cloudKitchen` в `config.json`, обновить портал с
   `-f compose.yaml -f compose.cloud.yaml` (`update-deploy.py` сверяет SHA-256 конфигурации -
   передать новый `expected-config-sha256`; сам оверлей скрипт пока не подключает).
3. Экраны - по одному на каждый физический экран/браузер:

   ```sh
   node infra/staging/cloud-kitchen-screen-owner.mjs create --branch <id> --role prep \
     --station <id цеха> --name "Горячий цех" --operator <имя> --reason "кухня без кассы"
   node infra/staging/cloud-kitchen-screen-owner.mjs create --branch <id> --role assembly \
     --station <id сборки> --name "Сборка" --operator <имя> --reason "кухня без кассы"
   node infra/staging/cloud-kitchen-screen-owner.mjs create --branch <id> --role display \
     --name "Табло" --operator <имя> --reason "кухня без кассы"
   ```

   Команда печатает код один раз (10 минут). Код вводится на самом экране:
   `pickchick.kz/kitchen/prep` (`/kitchen/assembly`, `/display`) -> «Код экрана». Ключ
   никуда вручную не переносится.

4. Проверить: `/kitchen-live/health` -> `cloudConnected: true`; индикаторы на странице; тестовый
   заказ киоска в режиме `cloud` виден на prep/assembly/табло и доводится до выдачи при
   выключенной кассе без входа повара.
5. Новый код для живого экрана (`pairing-code --screen <id>`) - ротация: старая привязка
   перестаёт работать в момент обмена. Отзыв (`revoke --screen <id>` или BO) - страница сразу
   возвращается к вводу кода.

## Ограничения

- Заказы кассы и номера кассы на табло без привязки ADR-0013 по-прежнему требуют входа повара
  и самой кассы.
- `confirm_cancel` облачных заказов - только управляющий через BO, не экран.
- Отчётное зеркало (protocol 5, edge 022) и X/Z с облачными заказами - этап S7.

- `tests/kitchen-portal/cloud.test.mjs`: конфигурация без ключей; флаг выключен; касса
  выключена и свежий браузер - код -> cookie (`HttpOnly`, `Secure`, `SameSite=Strict`, путь роли)
  -> лента и команда с ключом экрана, без повара, повтор идемпотентен, `409`, ключ не
  появляется ни в одном ответе; перезапуск портала - cookie действует; отзыв -> `401` и
  стирание cookie; подделанная, чужая и cookie другой роли - `401`; выход облака - `503` без
  стирания; код другой роли/точки - `409`, неверный - `401`, неполный - `400` без запроса в
  облако, cross-site - `403`, лимит попыток - `429`; табло; кассовые маршруты требуют повара.

  повара добавляет кассу, «Сервер: нет связи», «Касса: нет связи», отзыв -> экран кода, табло,
