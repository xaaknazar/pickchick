# Вход PickChick через WhatsApp

Решение владельца от 23 сентября 2026: добавить доставку кода входа в WhatsApp.
Владелец подтвердил, что бизнес-аккаунта WhatsApp пока нет. Реальная отправка,
аккаунт Meta, номер, шаблон и доставка клиентам этим этапом не включены.

## Актуальное решение от 1 октября 2026

Владелец заменил ручной выбор автоматическим: Telegram первым, WhatsApp при
подтверждённой невозможности отправки. Четыре цифры, один challenge, без выбора
канала пользователем. Актуальные контракт, ограничения, конфигурация и порядок
включения: [автоматические каналы](automatic-auth-channels.md). Ниже сохранён
исторический этап подготовки от 23 сентября; его ручной выбор и SMS-резерв
больше не являются текущим планом мобильного входа.

## Пользовательский сценарий

Предлагаемый основной путь: номер телефона → «Получить код в WhatsApp» →
сообщение PickChick → копирование/ручной ввод шести цифр → существующий аккаунт.
Перед отправкой явно показываем канал и номер. Просмотр меню остаётся гостевым.
SMS предлагается как запасной способ; окончательная доступность зависит от
проверки обоих каналов. Не нужно заставлять гостя первым писать боту в чат.

Канал меняет только доставку кода. PostgreSQL остаётся источником аккаунтов,
попыток, одноразовых кодов и сессий. Используем один customer ID по номеру,
существующие ограничения и сохранение входа. Код живёт 3 минуты; смена способа
доставки не обнуляет лимиты и не создаёт второй действующий challenge.

Для первого подключения выбран официальный Meta WhatsApp Cloud API напрямую.
BSP-посредник остаётся вариантом при сложностях с регистрацией/оплатой; отдельного
провайдера и платного договора этим решением не оформляли. QR-автоматизация
обычного WhatsApp Web не используется как инфраструктура входа.

## Что подготовить владельцу

1. Корпоративный номер, которым компания управляет и на который может принять
   SMS/звонок при регистрации. Предпочтительно выделенный номер входа PickChick.
   Если выбран действующий номер поддержки, сначала проверить поддерживаемый
   сценарий coexistence/переноса; не отключать работающий WhatsApp без плана.
2. Meta Business Portfolio на владельца бизнеса, доступ администратора для
   настройки, корректные название/сайт/контакты компании. Начало:
   [Meta Business](https://business.facebook.com/) и
   [Meta for Developers](https://developers.facebook.com/apps/).
3. Создать Meta app с WhatsApp, связать WhatsApp Business Account (WABA),
   зарегистрировать номер и выполнить требования, которые показывает кабинет
   для бизнес-проверки, display name и доступа к Authentication templates.
   Наличие обычного приложения WhatsApp Business на телефоне не заменяет API.
4. Настроить оплату сообщений и согласовать дневной бюджет. Не обещаем цену
   ниже SMS: актуальный тариф зависит от рынка получателя, категории и объёма;
   посредник может добавлять свои сборы.
5. Утвердить privacy/условия и явный выбор WhatsApp при запросе кода; маркетинг
   не входит в согласие на вход. Утвердить RU/KZ-тексты и проверить поддержку
   выбранных языков шаблона в кабинете.

Разработчику нужны WABA ID, Phone Number ID, версия API, имя/язык одобренного
Authentication-шаблона и доступ к настройкам. Секреты (system-user token,
app secret, webhook verify token) передаются только в защищённое хранилище
сервера, не в чат, Git, мобильное приложение или URL. Минимальные права
отправителя: `whatsapp_business_messaging`; управление шаблонами и настройками
выделяется отдельно по требованиям Meta. Временный тестовый токен не подходит
для рабочего сервиса.

## Шаблон и доставка

Используем категорию Authentication и Copy Code. Основной текст задаёт Meta;
это не произвольное рекламное сообщение. Код передаётся в body и параметре
кнопки `url` с индексом `0`. Для шаблона согласовать предупреждение о секрете,
срок 3 минуты и TTL доставки не больше срока нашего challenge. Фактическое
истечение проверяет сервер, подпись под кодом его не продлевает.

Copy Code позволяет вернуться в приложение и вставить код. Автозаполнение
зависит от ОС/версии WhatsApp и проверяется на устройствах; ручной ввод остаётся.
Ответ `/messages` с `wamid` подтверждает только принятие отправки. Доставка,
прочтение и владение номером - разные события; вход подтверждается только
правильным кодом в нашем challenge.

## Реализованный технический этап

- `WhatsAppCodeDelivery` в `@pickchick/phone-verification` формирует официальный
  HTTPS-запрос с Authentication template. Версия API явно задана конфигурацией,
  адрес ограничен `graph.facebook.com`, токен передаётся в Authorization.
- Проверяет номер/шесть цифр, конфигурацию, структуру ответа и получателя.
  Ограничивает ответ 16 KiB и ожидание 5 сек, включая зависшее чтение тела.
- При неопределённом результате возвращает `unknown`; не повторяет запрос,
  не переключает канал, не выдаёт сессию, не логирует номер/код/токен.
- Адаптер экспортирован отдельно, **фабрика публичного входа его пока не выбирает**.
  `PHONE_DELIVERY_PROVIDER=whatsapp_cloud` отклоняется до следующего этапа.
  Работа SMS и публичный API остались прежними. VPS/TestFlight не обновлялись.

Это подготовка транспорта, а не завершённый вход через WhatsApp. Отправка
реальному человеку в данном этапе не выполнялась.

## Что завершить после регистрации

1. В кабинете проверить пригодность номера/аккаунта, платёжный метод, права
   отправителя, статус `APPROVED`, язык/кнопку/TTL шаблона и поддерживаемую API-версию.
2. Добавить channel в config/request/response, хранимый выбор и идемпотентность
   challenge, обновить mobile UX. Существующим клиентам сохранить совместимость;
   нельзя отправлять WhatsApp, когда интерфейс обещает SMS.
3. Реализовать подписанные webhook доставки: проверка подписи по сырому телу,
   WABA/номера, долговечная корреляция `wamid` с попыткой, дедупликация и
   обработка переставленных событий. Callback никогда не авторизует гостя.
4. Реализовать явный переход на SMS после интервала/ошибки без двух действующих
   кодов, сброса бюджета или слепой повторной отправки после timeout. Проверить
   позднюю доставку, повтор запроса и одновременные попытки с двух устройств.
5. Ограниченный тест на согласованных номерах: iPhone/Android, новый/существующий
   аккаунт, нет WhatsApp, неверный/просроченный код, отказ провайдера, потеря сети,
   повторный запуск, SMS-резерв и сохранение сессии. После этого включать канал.

## Проверки этого этапа

24 unit-теста транспорта SMS/WhatsApp и identity прошли на синтетических данных,
без внешних сообщений. В том числе проверены зависшие fetch/body, ограничение
ответа, ошибки провайдера, неверный получатель, запрет повторной отправки и
закрытая фабрика. Build phone-verification, typecheck customer-identity и ESLint
прошли. Это не свидетельство одобрения шаблона или реальной доставки Meta.
