# Решения владельца для работ по переходу с iiko (05.11.2026)

Эти решения обязательны для всех полос. Они важнее предположений в design-*.md и contracts.md.

1. 19.11.2026 ресторан полностью уходит с iiko на PickChick. Посредники iikoTransport, Kwaaka и AILILLU убираются.
2. Виды оплаты на кассе - как в iiko, без AILILLU. Ровно восемь:
   - наличные (со сдачей);
   - терминал Kaspi Smart POS (пока кассир отмечает оплату вручную, адаптер позже);
   - Kaspi вручную;
   - Яндекс (оплачено агрегатором);
   - Glovo (оплачено агрегатором);
   - ChocoFood;
   - питание сотрудников;
   - маркетинг.

   Нужна смешанная оплата. Оплата «kaspi ailillu» не переносится, канал AILILLU закрывается.

3. Скидки создаются и редактируются в бэк-офисе, касса применяет их с подтверждением менеджера. На запуске скидок нет: механизм не входит в P0, данные и интерфейсы не должны ему мешать.
4. Сервер точки (edge, PostgreSQL, службы) остаётся на отдельном моноблоке PickChick 192.168.2.69. На кассы и кухню ставятся только программы, они ходят к серверу по локальной сети.
5. В зале две кассы: два кассовых моноблока с POS PickChick, оба работают с сервером точки по локальной сети.
6. Моноблоки на всех станциях кухни и ZKTeco уже стоят на точке (сейчас под iiko). Покупать экраны не нужно, нужно поставить на них PickChick.
7. Агрегаторы до прямых API работают через свои планшеты: заказ вводится в кассу PickChick.
8. Фискальные чеки. API Webkassa пока нет, поэтому временно чек пробивается вручную в кабинете Webkassa. Касса фиксирует номер чека; для будущего адаптера оставляем шов.
