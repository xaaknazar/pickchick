# ADR-0010: касса, кухня и бэк-офис в режиме без оплаты

Статус: решение владельца принято15 сентября 2026; код проверяется, физический запуск отдельно.

## Причина

Владелец поручил временно проводить кассовые заказы до кухни и бэк-офиса без
оплаты и чека, сохранив будущие банковские и фискальные интеграции. Также нужны
личный пароль сотрудника, фотографии меню, удобный выбор состава, полноэкранный
кассовый интерфейс, часы, количество заказов и открытие/закрытие смен.

## Решение

Оператор явно назначает точке `pos_service_mode=unpaid_service`, план станций и
права сотрудников. Подготовка не открывает приём. Отдельное включение проверяет
тот же каталог, конфигурацию и полное покрытие товаров станциями. Обычный кассир
не меняет этот режим. Исходный `payment_required` остаётся значением по умолчанию.

В одном PostgreSQL transaction сохраняются кассовый заказ, связь со сменой,
неизменяемый снимок состава/цены, допуск на кухню, задания, номер, оба outbox и
аудит. У операции один durable idempotency key. Неизвестный ответ сохраняется в
нативном журнале до проверки тем же запросом. Перезапуск не повторяет POST сам.

В сервисном заказе неизменяем `execution_mode=unpaid_service`; отсутствуют оплата,
чек и бонусное начисление. Состояния остаются `payment_state=not_started` и
`fiscal_state=not_requested`. Стоимость заказа не становится выручкой. Интерфейс
показывает номер/готовность кухни отдельно от оплаты. Для отмены кассиром все
кухонные задания должны ещё быть queued. Начавшееся приготовление возвращает
`ORDER_IN_PRODUCTION`; дальнейшая отмена/списание остаётся отдельным процессом.

Кухня использует уже существующий автомат состояний prep, assembly и handoff.
Cloud-команды оплаты/выдачи не могут перехватить `commercial_owner=edge_pos`.
Коммерческая и кухонная версии передаются отдельно; бэк-офис получает наблюдаемые
проекции с inbox/подтверждениями, без права переписать деньги или локальные задания.
Потеря WAN оставляет фактическую работу на кассовом узле; синхронизация догоняет
после восстановления канала. Это требует физической проверки сети и worker.

Пароль проверяется локальным edge, роль берётся из существующей записи сотрудника.
Первое задание/смена пароля выполняется оператором с двойным скрытым вводом;
готового общего пароля нет. В native config закреплён terminal UUID, которого
сотрудник не вводит. Выход отзывает сессию на сервере; при отсутствии сети
приложение выходит локально и сохраняет незавершённый журнал.

## Сеть

Для запрошенного 22 сентября автономного аппаратного теста разрешён отдельный
локальный пилот с постоянными UUID из защищённой записи монтажа. Если регистрации
в cloud ещё нет, эти UUID прямо помечаются `local_test_only`; исходящие workers
и приём cloud-команд выключены. Это позволяет проверить кассу/кухню до привязки
ресторана в облаке. Наличие локального `fulfillment_config` не объявляется cloud
регистрацией или синхронизацией с бэк-офисом. Перед их включением нужны отдельные
проверенные привязки и решение о сохранении/переносе тестовых данных.

Для кухни вместо предварительно предложенного SSH-туннеля из ADR-0009 выбран
отдельный HTTPS gateway на частном IP кассы. Он не требует устанавливать SSH
сервер на кассу. Сертификат с IP SAN создаётся на Windows и закрепляется в
кухонном клиенте. Firewall/маршруты ограничены кухонным моноблоком и KDS API;
PostgreSQL и edge продолжают слушать loopback. Проверка сертификата обязательна.

Для связи с облаком внутренний API остаётся закрытым от публичного ingress.
План монтажа - отдельный ограниченный исходящий SSH-туннель и worker-служба;
его фактическая установка не выводится из наличия кода синхронизации.

## Приёмка

1. Личный вход кассира/кухни, неверный пароль, повторный вход и отзыв сессии.
2. Смена, фото, состав и серверная сумма; один заказ после потери ответа/перезапуска.
3. Тот же заказ и модификаторы на кухне, сборка, готовность и выдача.
4. Обновление бэк-офиса и история версий; отсутствие платежа, чека и бонусов.
5. Разрыв WAN и LAN, восстановление обоих клиентов и отложенной синхронизации.
6. Обновление Windows с сохранением базы/профилей, запуск служб после reboot.

Этап не является приёмкой банка, ККМ, кассовых операций с наличными, возвратов,
лояльности, норм расхода каждого компонента комбо или полной production-готовности.
Все эти требования общего плана сохраняются.
