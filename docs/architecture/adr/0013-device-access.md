# ADR 0013: Доступ рабочих экранов и восстановление пароля кухни

Статус: реализовано в исходниках; развёртывание и приёмка на точке выполняются отдельно.
Дата: 2026-10-09.

## Причина

Владелец поручил продолжить план Claude для раздела «Устройства» и исправить доступ к
кухне, сборке и табло. Прежний отзыв `devices.status` позволял управляющему отключить
основную кассу без переноса её состояния. Привязка экрана и пароль сотрудника были
смешаны в процедуре ручной выдачи файлов. Подключённый iPad уже принял реальную
оплату, его ключи и платёжные процессы необходимо сохранить.

## Решение

Cloud владеет выдачей разрешений управляющим, их областью точки и аудитом. Edge
владеет фактом подключения, проверкой ключа и работой кухни при потере WAN. Для
новых разрешений нужен WAN; после подключения локальное приложение работает с edge
через существующий закреплённый TLS LAN-канал. Облачный kitchen-live портал зависит
от WAN и не выдаётся за автономный локальный клиент.

Выделен отдельный `POST /internal/v1/edge/devices/exchange`, а не новая версия
fulfillment protocol 4. Он использует существующие device identity и активную
привязку edge к точке. На обеих сторонах PostgreSQL хранит inbox, команды и ACK.
Повтор команды допустим только с тем же содержимым. Отзыв доставляется и после
истечения поля expiresAt: отключение нельзя потерять за период отсутствия WAN.
Заказы, платежи, фискализация и их обработчики в этот transport не входят.

Управляющий выпускает 128-битный код на 10 минут, видимый только в ответе выдачи и
оперативной памяти UI. В базах хранится SHA-256 кода. Plaintext не попадает в URL,
аудит, storage или повтор ответа. Код привязан к точке, конкретному edge, устройству,
назначению prep/assembly/display и поколению. Проверка назначения предшествует
потреблению. Старое поколение не может восстановить доступ после перевыпуска или
отзыва. Публичный ввод ограничен размером, временем и устойчивым счётчиком попыток.
Неопределённый результат UI не повторяет автоматически.

При подключении генерируется самостоятельный terminal key. Браузер получает только
HttpOnly/SameSite cookie с AES-GCM шифрованием; ключ доступен gateway, который
удаляет пользовательский X-Terminal-Key и сам подставляет проверенную идентичность.
Cookie криптографически связана с режимом и путём. На Windows ключ шифрования cookie
сохраняется через Electron safeStorage, отдельно от renderer. В edge хранится только
hash terminal key. Регистрация не даёт роли сотрудника: prep/assembly дополнительно
требуют staff-сессию, station grants и проверку режима при действии. Display получает
только номера для табло, без входа сотрудника и без команд изменения заказов.

`local_terminals.device_access_managed` сохраняет обязательность ключа независимо от
feature flag. Отключение новых маршрутов не превращает уже зарегистрированное
устройство в legacy. Старые терминалы совместимы, автоматического изменения их
ключей/паролей/сессий нет. Для нового runtime необходима схема edge020 до смены
бинарных файлов; выключенный флаг не является совместимостью со схемой019.

Восстановление пароля - отдельная команда в том же ограниченном mailbox. Она
разрешает только существующий активный `local_staff` с ролью `kitchen` и существующим
парольным логином `kitchen` в этой точке. Cloud не знает staff UUID и не подменяет его
UUID управляющего: edge разрешает точное соответствие при получении и повторно при
потреблении. Никакая учётная запись или роль не создаётся. На подключённом prep или
assembly вводятся код и новый пароль. В одной транзакции проверяются актуальный
terminal key, TTL и ticket, записывается scrypt verifier, потребляется ticket,
отзываются прежние staff sessions и создаётся локальный аудит. PIN кассы не меняется.
Пароль не передаётся cloud; транспортный worker не имеет прав читать/менять verifier.

## Границы и последствия

- Аналитик читает устройства/аудит, но не выдаёт коды и не отзывает доступ.
- Edge нельзя отозвать обычной командой BO; требуется отдельная процедура переноса.
- Новое registry-устройство нельзя отозвать legacy-командой без edge ACK.
- BO различает команду, переданную кассе, подтверждённое подключение и состояние
  heartbeat самой кассы. Heartbeat кассы не называется присутствием браузера.
- Существующий iPad показан для инвентаризации. Его alias/ключ не перевыпускается.
  Новый kiosk enrollment остаётся штатным отдельным процессом; произвольная
  регистрация iPad здесь не реализована.
- Возврат к старому binary до schema020 требует отдельного доказанного отключения
  только новых managed терминалов/их сессий. Иначе старый binary не знает этой границы.
- Миграции cloud051/edge020 и новые ACL требуют guarded release с резервной копией,
  проверкой восстановления и полной CI. Включение флага не заменяет эти доказательства.

## Проверка

Реальные PostgreSQL тесты проверяют branch/role scope, отсутствие plaintext кода,
идемпотентность, конкуренцию, поколение, отзыв, невозможность обойти registry через
legacy-команду, restricted roles и парольный reset без изменений PIN/ролей. HTTP
проверки охватывают настоящий контроллер и BO proxy, cookie gateway, ограничения
табло, старые staff login и pinned LAN TLS. Storybook имеет состояния каждого нового
компонента; browser проверки включают 393/768/1280 px и очищение чувствительных полей.
Конкретные результаты и ограничения выпуска приведены в `docs/operations/device-access.md`.
