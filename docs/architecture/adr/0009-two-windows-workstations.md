# ADR-0009: касса и локальный узел на одном Windows-моноблоке

Статус: размещение выбрано владельцем; установка и аппаратная приёмка открыты.
Дата: 14 сентября 2026.

## Решение владельца

Получены два моноблока с Windows 10 Pro. Первый предназначен для кассира,
второй - для кухни с переключением приготовления, сборки и выдачи. Владелец
подтвердил общую сеть с Mac, разрешил настройку и отдельно выбрал размещение
серверной части на кассовом моноблоке. Прежнее ожидание настройки отдельного
локального сервера больше не определяет размещение этой точки.

## Размещение

- Кассовый моноблок: PickChick POS, локальные PostgreSQL и edge, необходимые
  worker и управляемый запуск служб. POS обращается к loopback API.
- Кухонный моноблок: PickChick Kitchen с локальными ресурсами интерфейса,
  одной обычной kitchen-сессией и назначениями prep + assembly. Выдача - действие
  станции assembly; отдельная более привилегированная роль для переключения не нужна.
- Кухня обращается к edge кассы по защищённому LAN-каналу. Текущие клиенты
  рассчитаны на loopback: целевой вариант для первого монтажа - управляемый
  туннель с отдельным ключом устройства, проверенным host key и разрешением
  только нужного локального порта. Настройка туннеля ещё не выполнена.
- PostgreSQL и внутренний edge не открываются в LAN простым изменением bind.
  Удалённое администрирование и постоянное соединение кухни - разные доступы.

Для server-компонентов рассматривается native Windows установка PostgreSQL
и Node.js с отдельными путями данных, служебными учётными записями и supervisor.
Версии, драйверы, свободные ресурсы и способ службы проверяются на устройстве
до установки. Docker Desktop/WSL и переустановка ОС не требуются этим решением.
Официальный [источник Windows-пакетов PostgreSQL](https://www.postgresql.org/download/windows/)
предоставляет установщик/бинарные архивы EDB; его таблица испытанных платформ
для PostgreSQL 18 перечисляет Windows Server, поэтому совместимость именно
этих моноблоков подтверждается собственным аппаратным прогоном.

## Последствия и границы

Касса становится единственным локальным владельцем данных точки. Её сон,
выключение, обновление или поломка останавливают общую очередь кухни. Требуются
управляемое питание/обновления, резервная копия вне её диска, автозапуск после
перезагрузки и измерение нагрузки одновременно с POS. Питание/UPS, режим сна
и восстановление проверяются на точке. Один моноблок не заявляется отказоустойчивым
кластером или доказательством сетевой мощности 1 000 заказов.

Установщики клиентов не содержат БД, общих паролей или автоматически выданных
прав. Отдельные POS и kitchen-профили сохраняют свои незавершённые команды.
Переключение станции не отменяет команду с неизвестным результатом.
Подключение локального сервера не включает само по себе банк, ККМ и допуск
неоплаченных кассовых заказов на кухню. Эти приёмки из ТЗ сохраняются.

Предыдущие предложения отдельного Linux edge в ТЗ/ADR-0008 остаются вариантом
для других точек; для этой установки приоритет имеет настоящее решение владельца.
Архитектура денег, outbox/inbox и владение заказом не меняются.

## Приёмка

1. Инвентаризация обоих Windows: x64, build, RAM/диск, touch/масштаб, существующие службы.
2. Изолированная БД/службы на кассе, проверка сохранённых данных и запуска после reboot.
3. Защищённое подключение кухни только к назначенному edge, отдельные staff/terminal grants.
4. Один kitchen-вход: приготовление → сборка → выдача; режим табло; отсутствие обхода прав.
5. Установка/обновление клиента сохраняет журнал; после неизвестного POST точный повтор безопасен.
6. Разрыв WAN, разрыв LAN, закрытие POS, reboot кассы, восстановление вне её диска.
7. Отдельная подтверждённая приёмка оплаты/чека и всей коммерческой смены.
