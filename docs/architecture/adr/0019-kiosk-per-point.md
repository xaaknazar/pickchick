# ADR 0019: киоск на любой точке сети

Статус: принято 16.11.2026 (запрос владельца: сеть открывает новые точки, управляющий подключает
iPad-киоск к любой точке из бэк-офиса без шага оператора или Codex на каждую точку).
Реализация: миграция cloud081, commerce-core, API, бэк-офис «Устройства», приложение киоска.

## Контекст

- API киоска обслуживал одну точку: `KIOSK_CHECKOUT_BRANCH_ID`. Гость другой точки получал
  `FORBIDDEN`, «Подключить киоск» (миграция 079) работал только на этой точке.
- Kaspi QR на экране киоска идёт через мост, привязанный к одной учётной записи
  (`KIOSK_KASPI_QR_ACCOUNT_ID`); счёт на телефон - один воркер на `KASPI_REMOTE_ACCOUNT_ID`.
- Оплата на своём терминале Kaspi Smart POS (ADR-0018) идёт с iPad без моста: по своей природе
  годится для любой точки, если у точки есть своя учётная запись провайдера `kaspi-pos`.
- `kiosk_devices` уже хранит точку устройства (миграция 035), кухня уже выбирается по точке
  (`fulfillment_transport_bindings`: точка - сервер точки).

## Решение

1. **Точка из env остаётся как есть.** Её QR, счёт на телефон, учётные записи и все общие для
   организации значения (организация, налоговый код, фискальная политика, ссылка на одобрение,
   предел суммы, ключ ПДн, часы работы) по-прежнему берутся из env.
2. **Флаг `KIOSK_MULTI_BRANCH_ENABLED`** (по умолчанию выключен; любое значение кроме `true` и
   `false` останавливает запуск API). Выключен - ответы API и бэк-офиса точно прежние, таблица 081
   не читается.
3. **Таблица `kiosk_branch_settings`** (миграция 081): точка, `enabled`, учётная запись оплаты на
   терминале (`kaspi-pos` юрлица точки), кто и когда менял, `version` для оптимистичной
   блокировки. Строки не удаляются, `version` растёт ровно на 1 (триггер).
4. **API киоска**: с флагом гость допускается, если его точка - точка из env или точка той же
   организации с `enabled=true`. Выключенная точка - `NOT_READY` (iPad ждёт, а не теряет гостя),
   без флага - прежний `FORBIDDEN`. Для другой точки: только `kaspi_terminal` на её учётной
   записи (`terminal_payment_account_id`, иначе `KIOSK_KASPI_TERMINAL_ACCOUNT_ID`), без QR и без
   счёта на телефон. `GET config` отдаёт имя и id этой точки, `paymentMethods: []` и
   `kaspi_terminal: { enabled, terminal, only: true }`; `enabled` не требует привязанного
   терминала (привязка - дело iPad).
5. **Бэк-офис, «Устройства»**: блок «Киоски на этой точке» - состояние, учётная запись оплаты и
   переключатель для управляющего (роль `manager`; аналитик только видит). При первом включении
   точка получает свою учётную запись `kaspi-pos` через функцию `kiosk_branch_terminal_account`
   (SECURITY DEFINER: роль API не получает INSERT на `commerce_provider_accounts`). Выключенную
   оператором учётную запись функция не включает. Запись идемпотентна по `request_id`
   (`bo_commands`), аудит - `bo_audit`, действие `kiosk_branch_settings`. «Подключить киоск» и
   обмен ID/ключа на iPad работают на точке из env и на включённых точках.
6. **Деньги и кухня**: попытка, приём итога терминала и запись оплаты те же, что в ADR-0018
   (`observePayment`), только с учётной записью точки. Заказ точки идёт на сервер своей точки.
7. **Приложение киоска**: при `kaspi_terminal.only` кнопка «Kaspi» означает терминал. Если
   терминал на этом iPad не привязан, оплата не начинается и гость видит «Здесь оплата только на
   терминале Kaspi, а он не подключён к киоску. Пригласите сотрудника.» QR не показывается.
   Установленные сборки без этой поддержки на другой точке оплату не начинают (молча, как при
   выключенной оплате) - нужна сборка с ADR-0018 и этим изменением.

## Ограничения

- Фискальная политика `required` на другой точке не поддерживается: фискальная учётная запись в
  env принадлежит точке из env, поэтому другая точка остаётся `enabled: false`. Сейчас действует
  `deferred_pilot`.
- Kaspi QR и счёт на телефон остаются только на точке из env (один мост, один воркер).
- Смена учётной записи оплаты точки - только оператором в базе; бэк-офис её не меняет.
