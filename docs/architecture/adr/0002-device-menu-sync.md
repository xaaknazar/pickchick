# ADR 0002 — идентичность edge и доставка меню

Статус: принято для локального этапа 1Б. Дата: 06.09.2026.
Решение реализации: Codex в пределах порученной поэтапной разработки.

## Контекст

Этап 1А создавал две копии меню прямым seed. Нужен первый реальный обмен
через HTTP с повтором после сбоя. Срок проекта — четыре месяца; внешние
Kaspi/ККМ/Яндекс-доступы и инфраструктура production ещё не подтверждены.
Требования: принадлежность устройства точке, атомарное применение меню,
непрерывная последовательность, ACK после commit, сохранение версии без WAN.

## Решение

Отдельный пакет `@pickchick/menu-sync`. Центр — владелец меню; edge сам
опрашивает центр. Входящие подключения к точке для этого протокола не нужны.
Первый транспорт работает только на числовом loopback HTTP, без redirect.
Публичный staging/production-транспорт появится отдельным изменением с TLS.

Локальный оператор выдаёт ключ заранее созданному pending edge через CLI.
Ключ содержит 256 случайных бит; центр хранит SHA-256, срок 30 дней и журнал
provision/rotate/revoke. На edge ключ находится в `.local/edge-identity.json`
с правами 600, каталог — 700. Ключ не печатается и не попадает в Git.
Ротация требует `--rotate`, сразу инвалидирует старый ключ; revoked устройство
не активируется повторно. Один active edge на точку ограничен unique index.
Операции pull/ACK проверяют active/kind/expiry/hash в PostgreSQL; shared locks
защищают транзакцию от одновременного изменения ключа/статуса.

Это trusted local provisioning, а не публичный enrollment с одноразовым кодом.
RBAC сотрудников, OTP клиентов, mTLS, удалённая выдача ключей и аппаратная
защита секретов остаются отдельными задачами.

Публикация принимает неизменяемый release UUID и следующую версию точки.
Повтор того же UUID с тем же содержимым возвращает то же событие; изменённое
содержимое конфликтует. Release + outbox + увеличение sequence фиксируются
одной транзакцией под блокировкой точки. До ACK активная версия центра прежняя.
Исключение — историческое синтетическое меню seed этапа 1А; оно не является
доказательством доставки.

У каждой точки свой cloud producer для меню. Sequence выделяется изменением
строки в транзакции; rollback не оставляет пробел. Pull возвращает только
старейшее неподтверждённое событие; клиент не может перескочить через cursor.
Envelope проверяется Zod, checksum — SHA-256 UTF-8 JSON с рекурсивной сортировкой
ключей и сохранением порядка массивов. Это наш формат protocol v1, не заявление
о реализации общего стандарта канонизации. Денежные значения остаются строками
целых минимальных единиц, version ограничена PostgreSQL integer.

Edge проверяет точку, тип/схему события, идентичность release, hash и следующий
sequence. В одной транзакции: immutable snapshot, active menu, inbox, cursor
и ACK в outbox. Повтор сообщения с прежним hash возвращает сохранённый результат;
с другим hash — ошибка. Старое меню не заменяет новое. У ACK отдельный producer.
При gap/change producer поток останавливается с ошибкой; версия не пропускается.

Worker сначала отправляет сохранённый ACK, затем получает следующее меню.
Cloud сохраняет ACK inbox, activation и outbox acknowledgment одним commit.
Потеря HTTP-ответа оставляет ACK на edge для безопасного повтора. Старый ACK
после новой версии не откатывает activation. Отправка по сети никогда не держит
открытую DB-транзакцию. Timeout — 5 секунд, ответ ограничен 3 MB, menu — 2 MB.
Watch использует паузу 2 секунды, при ошибках exponential backoff до 60 секунд
с jitter; backoff после рестарта начинается заново. Состояния/attempts сохраняются
в PostgreSQL; неподтверждённые сообщения не удаляются по TTL.

## Рассмотренные варианты

| Вариант                                 | Сложность                     | Следствие                                                       |
| --------------------------------------- | ----------------------------- | --------------------------------------------------------------- |
| HTTP pull + PostgreSQL outbox/inbox     | Низкая для одного потока      | Выбран; явный ACK и простые испытания отказов                   |
| WebSocket + тот же долговечный протокол | Средняя                       | Полезен для кухни позднее; не устраняет необходимость inbox/ACK |
| Прямая репликация cloud/edge таблиц     | Высокая при разных владельцах | Не даёт доменного подтверждения; не выбрана                     |

Цена простоты — один пакет меню за цикл, отсутствие подписанных snapshot/replay
после потери всей edge-БД, автоматической смены устройства и fencing epochs.
Обычный restart сохраняющейся БД поддерживается; восстановление старого backup
или замена edge требует будущего recovery-протокола. Ошибки не дают ложного ACK;
полноценные DLQ, метрики и оповещения ещё нужны до production.
