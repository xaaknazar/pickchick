# ADR-0008: Устанавливаемая Windows-касса и локальное владение заказом

**Статус:** принято для подготовки настольного дистрибутива; аппаратная приёмка открыта.
**Дата:** 8 сентября 2026.
**Основание:** владелец потребовал программу для установки на Windows BX S6 Dual,
без работы через браузер, с автономным приёмом и последующей синхронизацией.

## Контекст

ТЗ уже предусматривает Electron для кассы и отдельный локальный узел
Node.js/PostgreSQL. До этого этапа `apps/pos` запускался только в браузере
через loopback HTTP server. Установщиков Windows в репозитории не было.

Существующий POS создаёт **неоплаченные** edge-owned заказы. Это закреплено
ограничениями `004_edge_local_orders.sql`: оплата `not_started`, чек
`not_requested`, кухня `blocked`. Отдельная локальная кухня принимает
cloud-owned коммерческие команды; наличие её тестов не соединяет её с POS.
Существующий fulfillment transport переносит события другой очереди,
а не `outbox_events/order.created` локальной кассы.

## Решение

1. Доставлять собственный Windows x64 installer и отдельное настольное окно.
   Интерфейс компилируется из существующего `apps/pos` и входит в пакет.
   Он не скачивается с VPS при запуске. Браузер, Node.js и npm пользователю
   для запуска самого клиента не нужны.
2. Сохранить единый расчёт/состояния/права на локальном edge PostgreSQL.
   Установщик клиента не заменяет установку и настройку этого узла.
   Не устанавливать новую БД поверх действующего iiko без обследования.
3. Использовать постоянный собственный origin и профиль приложения, один
   экземпляр, изолированный renderer и только разрешённый доступ к edge API.
   Не давать renderer доступ к shell, произвольным файлам, URL или базе.
4. Доставку созданий/отмен локального POS выделить в отдельный поток с
   подтверждением центра после commit. Обрыв WAN не меняет владельца заказа.
   Не подтверждённые события остаются в PostgreSQL. Повтор и потерянный receipt
   не создают вторую центральную запись.
5. Поставлять первую программу с точным указанием фактических функций.
   Отсутствующие оплата/ККМ/кухонный допуск не заменяются кнопкой «Оплачено».
   Локальные fixtures и предпусковая сборка не объявляются рабочей кассой ресторана.

## Рассмотренные варианты

| Вариант                                                 | Соответствие запросу                                               | Последствия                                                                                           |
| ------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Установочное Electron-приложение с локальными ресурсами | Соответствует предусмотренному ТЗ и требованию отдельной программы | Повторно использует проверенные UI/контроллер; требует обновления runtime и испытания Windows         |
| PWA или ярлык на страницу VPS                           | Не соответствует прямому запросу                                   | Не принимается как Windows-поставка и не решает автономность edge                                     |
| Новый WinUI/.NET клиент                                 | Возможный отдельный проект                                         | Потребует повторной реализации UI/контроллера и тестов; не ускорит подключение оплаты и синхронизации |

## Последствия

Рабочие данные остаются у локального узла после закрытия программы. Клиент
восстанавливает неизвестную команду с прежним ключом; он не рассчитывает
финансовое состояние из локальной копии интерфейса. Отключение WAN и отказ
локальной сети/edge - разные случаи: во втором нельзя подтвердить новый заказ.

Наличие EXE не означает готовность оплаты, фискализации, локальной кухни,
защищённого LAN или автономного режима конкретной ККМ. Эти пункты имеют
отдельные критерии приёмки POS-01/03/05 и AC-03/22/30/32.
Полная замена действующей кассы остаётся закрыта до их проверки.

## Действия

- Подготовить и проверить Windows-дистрибутив, его состав и сохранение профиля.
- Проверить реальный локальный edge/PostgreSQL: заказ, обрыв после commit,
  повтор и перезапуск клиента без дубликата.
- Проверить отдельный POS sync через настоящий HTTP и две временные БД.
- Зафиксировать расположение локального сервера, Windows/драйверы и сеть BX.
- Соединить edge-owned оплату/чек с кухней и испытать весь ресторанный цикл.
- Пройти установку/обновление и аппаратный WAN/restart тест на Windows.

Защитные настройки сверяются с официальными
[рекомендациями Electron](https://www.electronjs.org/docs/latest/tutorial/security).
Подпись и ограничения cross-build отражаются в протоколе конкретного артефакта,
а не считаются автоматически пройденными при успешной упаковке.
