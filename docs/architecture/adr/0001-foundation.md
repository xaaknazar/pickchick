# ADR 0001 — исполняемый фундамент cloud/edge

Дата: 06.09.2026. Статус: принято для локального этапа 1.

## Решение

Один pnpm workspace; TypeScript; NestJS API и edge как отдельные процессы;
общие runtime-схемы Zod и генерируемые OpenAPI/JSON Schema. SQL-миграции
через node-postgres. Контроллеры используют параметризованные запросы.
Транзакционные операции используют один выделенный client, включая rollback.

Зафиксированы Node 24.16.0, pnpm 11.19.0, TypeScript 5.9.3, NestJS 12.0.1.
Версии проверены по текущему окружению/официальному npm registry; lockfile
фиксирует полное дерево зависимостей. TypeScript 5.9 выбран как совместимая
база, обновление компилятора — отдельное проверяемое изменение.

В локальном Docker Compose два независимых PostgreSQL-контейнера и Redis cache.
Данные центра и edge имеют разные схемы и владельцев. Redis не нужен edge
для чтения сохранённого меню. Redis queue/BullMQ появятся вместе с worker;
сейчас очереди доставки ещё не реализованы.

Миграции блокируются advisory transaction lock, сохраняют checksum и scope,
проверяют существующий ledger и применяют DDL/ledger одной транзакцией.
Смешивание cloud/edge, изменение уже применённого файла и нарушение порядка
отвергаются. Никакого автоматического schema push при старте API нет.

Публичное меню центра читается только из активированной версии; edge читает
свою immutable snapshot. Начальная тестовая provisioning-команда загружает
одинаковые синтетические данные напрямую в обе БД. Это не реализация доставки,
подтверждения публикации или синхронизации и не прохождение Gate B целиком.

## Границы первого этапа

Сервисы доступны только на loopback, конфигурация допускает local/test и
специально названные локальные БД. Production-запуск запрещён до реализации
аутентификации устройств/сотрудников, TLS и согласованного deployment.
Пока реализованы только чтение меню/точек и health endpoints.
Заказ, расчёт, платёж, ККМ, OTP и кухня отсутствуют, тестовая точка не принимает заказы.

`/health/live` сообщает только о работе процесса. `/health/ready` проверяет
PostgreSQL, migration ledger и serving tables; edge также проверяет свою
привязку к точке. Недоступная БД/схема даёт 503; недоступный cache Redis
даёт `ready=true, degraded=true`, поскольку чтение меню идёт из PostgreSQL.
Сбой Redis не маскируется, не запускает бесконечные reconnect и не задерживает
probe более ограниченного таймаута.

## Последствия

Сейчас нет ORM: явный SQL позволяет проверять составные FK, immutable снимки,
типы денег и границы транзакций. При добавлении ORM миграции и инварианты
остаются каноническими; изменение инструмента требует отдельного ADR.
Схема `branch_prices` — исходные цены точки; versioned цены по каналам,
модификаторы и комбо расширяются перед реализацией quote.

Health и меню имеют runtime validation; общий конверт события подготовлен
для следующего этапа. Обработчики, последовательности, retry/ACK и replay
не объявляются реализованными наличием таблиц outbox/inbox.

## Официальные основания

- [NestJS: создание приложения](https://docs.nestjs.com/first-steps).
- [node-postgres: один client на транзакцию](https://node-postgres.com/features/transactions).
- [Docker Desktop CLI](https://docs.docker.com/desktop/features/desktop-cli/).

Нагрузочные SLO, аппаратные испытания и 8-часовой WAN-тест остаются будущими
приёмочными этапами. Короткий тест доступности меню после остановки API
и перезапуска edge подтверждает только этот ограниченный сценарий.
