# ADR 0012: Kaspi-счёт на номер через локальный мост кассира

Статус: техническая подготовка по присланному владельцем коду, 29 сентября 2026.
Адаптер выключен. Подтверждённого подключения к Kaspi и допуска к LIVE нет.

## Контекст

В mobile обязателен Kaspi.kz. Официальный remote API Kaspi для PickChick не
подтверждён: обращение к менеджеру Kaspi Pay от 24 сентября без ответа.
Владелец передал для проверки реализацию на базе проекта
[tapter-dev/kaspi-pos-automation](https://github.com/tapter-dev/kaspi-pos-automation)
(MIT, исходники `28c9167f9c72cd6758a25e254bc92bc610daa485`, 24.07.2026). Он повторяет приложение Kaspi Pay:
вход кассира по SMS, выставление счёта на номер, статус, отмена.

## Решение

- Мост работает отдельным процессом на том же сервере, слушает только
  127.0.0.1, запускается из закреплённого коммита с патчем PickChick
  (`infra/payments/kaspi-bridge/pickchick-hardening.patch`): без демо-UI, без
  возвратов, без логов заголовков/тел/телефонов, без сохранения сессии на диск.
- В `commerce-core` добавлен провайдер `kaspi-remote`: попытка оплаты из
  финансового ядра → счёт на подтверждённый телефон клиента → статус из Kaspi →
  `observePayment`. Отдельный worker `services/api/dist/kaspi-remote-worker.js`.
- Деньги засчитываются только по статусу `Processed` и валидной сумме из Kaspi.
  Подстановка цены заказа вместо отсутствующей суммы запрещена. Доставка
  результата в ledger повторяется после сбоя с тем же ключом inbox.
  Отказ - только явные `RemotePaymentCanceled/RemotePaymentRejected/Expired`.
  Незнакомые статусы и потерянные ответы не считаются отказом.
- После `KASPI_INVOICE_TTL_SECONDS` (10 минут от начала выставления) выполняется
  попытка отмены. Отсутствие ответа не доказывает отмену; продолжаем читать статус.
  Сбой между сохранением намерения и отправкой отмены требует ручной сверки.
- Включение нового checkout, как и для TipTopPay, после фискализации Webkassa.

## Последствия и риски

- Это **не официальный API Kaspi**. Мост подделывает параметры iPhone-приложения
  Kaspi Pay; Kaspi может в любой момент изменить протокол, отклонять запросы,
  потребовать обновить мост или ограничить кассира/merchant. Нужен отдельный
  номер кассира только для сервера: вход с этим номером на телефоне вытесняет
  серверную сессию.
- Сессия кассира - полный доступ кассира к Kaspi Pay. Она хранится только в
  приватном env-файле сервера (0600), не в Git, не в чатах.
- При официальном ответе Kaspi заменяется только адаптер провайдера; ядро,
  заказы и mobile-контракт не меняются.
- Требования и возможности Kaspi, описанные в мосте, не проверены на реальном
  merchant PickChick до пробного счёта владельца.
