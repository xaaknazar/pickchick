# ADR-0011: веб-кухня обращается к единственному локальному владельцу заказа

Дата: 22 сентября 2026. Статус: веб-канал установлен и проверен;
физическая LAN-приёмка открыта.

Владелец поручил связать установленную кассу с `/kitchen/prep`,
`/kitchen/assembly` и `/display`. Ранее эти страницы показывали отдельный
TEST backend; Windows обслуживает собственную локальную очередь unpaid_service.
Подмена TEST данными кассы или фиктивной банковской оплатой недопустима.

## Решение

Локальный PostgreSQL/edge остаётся владельцем заказа и кухонных переходов.
Физическая кухня использует существующий LAN HTTPS gateway с закреплённым
сертификатом. Отдельный Windows worker устанавливает только исходящие HTTPS
соединения к узкому порталу VPS. Портал передаёт разрешённые staff/fulfillment
запросы к кассе; ответы проходят проверку размера и JSON. Три веб-экрана имеют
отдельные терминалы, сессии и журналы незавершённых команд. Табло через публичный
маршрут не принимает команды изменения заказа. Пароль проверяется на edge;
публичный портал не выдаёт роль и не хранит пароль или копию очереди.

Ключ служебного канала хранится в защищённых файлах Windows/VPS, отдельно от
сотрудников. PostgreSQL и edge не открываются в интернет или LAN. Общий доступ
SSH оператора не используется для постоянного канала кухни.

## Альтернативы и последствия

- Облачная репликация POS/fulfillment остаётся отдельным этапом: зарегистрировать
  организацию/точку/device, обновить совместимые cloud API и миграции, проверить
  durable outbox/inbox и backoffice projections. Канал веб-кухни её не заменяет.
- Обратный SSH требует отдельной ограниченной учётной записи/политики сервера.
  Использовать существующий широкий операторский доступ для этого не следует.
- Только LAN не даёт заказчику просмотр по указанным внешним HTTPS ссылкам.

Операционная очередь портала ограничена и существует только в памяти. Она
не является outbox заказа или журналом бизнес-команд. После таймаута, перезапуска
или потери ответа результат считается неизвестным. Команды не переотправляются
автоматически; браузер сохраняет исходные тело/версии/ключ в durable журнале,
сверяет состояние и использует прежний ключ при явном повторе. Идемпотентный
результат хранится в PostgreSQL edge. При потере WAN внешние страницы недоступны;
локальная кухня продолжает работать при доступном LAN и включённой кассе.

Это подключение одной тестовой точки, не многоточечный routing и не облачный
backup. Оплата, чек, cloud sync и реальное подключение LED подтверждаются отдельно.

## Приёмка

Заказ POS -> обе станции -> готовность на табло -> выдача. Дополнительно:
чужой terminal/origin/ключ, запрещённые маршруты, переполнение, разрыв до/после
commit, повтор прежнего ключа, рестарт worker/портала, сохранение локальных
заказов/смен/PIN, неизменность соседних приложений VPS и прежних публичных файлов.
