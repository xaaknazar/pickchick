# ADR 0003 — локальные права, quote и неоплаченный заказ

Статус: принято для локального этапа 1Б.2. Дата: 06.09.2026.
Решение реализации: Codex в рамках порученной разработки по этапам.

## Контекст и границы

После доставки меню нужен проверяемый путь POS: сотрудник → расчёт → заказ.
Банковские и фискальные адаптеры ещё не подтверждены. Первый заказ поэтому
сохраняется в `awaiting_payment`, с `payment_state=not_started`,
`fiscal_state=not_requested`, `fulfillment_state=blocked`.
Ответ `next_action=payment_not_available` явно запрещает трактовать его как
оплаченный/принятый кухней. Даже сумма 0 не даёт автоматической оплаты.

Этот этап покрывает обычные SKU и количество. Комбо/модификаторы, промо,
Чики, складские резервы, часы работы, кассовые смены, реальные оплаты,
кухонные задания и синхронизация заказов с центром ещё не реализованы.
Неизвестные поля корзины отвергаются; неподдержанные опции не игнорируются.
Вместо полного Gate B закрывается базовый сценарий неоплаченного POS-заказа.

## Решение по правам

У edge свои таблицы staff, terminals, sessions. Это локальная проекция будущих
центральных прав; сейчас её создаёт доверенный оператор через CLI на localhost.
Публичного логина, PIN/паролей, OTP, provisioning по одноразовому коду и выдачи
центральных подписанных offline grants пока нет.

Сессия — случайный секрет 256 бит, в БД только SHA-256; выдача и доступ
сотрудника ограничены 8 часами. Срок — временная политика стенда, подлежит
согласованию перед пилотом. Клиент не может продлить его сам. Повторный trusted
setup с `--renew` выдаёт новый секрет и отзывает прежние сессии пары
сотрудник/терминал. Другие терминалы имеют отдельные сессии; их собственный
TTL не продлевается. Revoked staff/terminal не активируется setup-командой.
Роль существующего сотрудника setup-команда не изменяет.

Каждая операция проверяет сессию, active сотрудника и терминала, сроки, branch
и текущую роль. Shared locks удерживаются до commit, поэтому изменение прав
не происходит посреди подтверждаемой операции. При долгом WAN-сбое доступ
заканчивается по сроку: постоянные автономные полномочия не выдаются.
Блокировки auth/renewal берутся в одинаковом порядке staff → terminal → session,
после блокировки срок и ключ проверяются повторно.

| Роль          | Разрешено в этом этапе                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------- |
| cashier       | Quote, создание, чтение/отмена своих неоплаченных заказов на своём терминале; чтение режима/стопа |
| shift_manager | То же; чтение/отмена всех локальных заказов точки, открытие/закрытие приёма, стоп-лист            |
| kitchen       | Только проверка собственной сессии; финансовый POS API запрещён                                   |

Сотрудник, терминал и branch берутся из проверенной сессии/конфигурации, а не
из body. FK запрещают смешение принадлежности. Сессии персонала независимы
от device key для обмена меню с центром. `.local/staff-UUID.json` имеет mode 600,
каталог 700; ключи не выводятся в stdout, argv, OpenAPI или Git.

## Расчёт и создание

Quote принимает release UUID, «в зале»/«с собой», до 50 уникальных SKU и 1–99
порций на строку. Цены и имена берутся только из активного snapshot edge.
Вся арифметика — BigInt с верхней границей PostgreSQL bigint; JSON суммы —
строки минимальных единиц. Скидка на этом этапе равна нулю, валюта KZT.

Quote сохраняет снимок, автора, терминал, release и TTL 5 минут по часам БД.
Он неизменяем. Повторный quote-запрос может создать новый предварительный
расчёт; идемпотентность требуется для последующих команд заказа/настроек.

Создание заказа принимает только quote UUID и `Idempotency-Key` UUID в header.
В транзакции после auth: lock branch → поиск прежнего результата команды →
проверки владельца/TTL/активного меню/режима точки/ручных стопов → order →
commercial outbox event → audit → command result → commit.
Один quote может породить только один заказ (unique FK). Повтор той же
команды возвращает исходный ответ и после смены меню/закрытия приёма;
тот же ключ с другим содержимым конфликтует. Новая команда с уже использованным
quote тоже конфликтует. Отозванная сессия не может получить даже replay.

Отмена — отдельная команда с expected version и причиной, только из
`awaiting_payment`. Это отмена неоплаченного заказа, не refund. Сохраняются
новая версия, событие, audit и результат команды в одной транзакции.
Replay создания возвращает исходный ответ создания; текущее состояние читается
через GET. Возврат cancelled к awaiting_payment и подмена успешной оплаты
запрещены текущими SQL-ограничениями и trigger.

Immutable quote является снимком заказа через FK: он не удаляется и не
пересчитывается после новой публикации меню. Строки заказа доступны через
snapshot; сумма заказа дополнительно связана composite FK с суммой quote.
Будущий экспорт/фискализация используют этот снимок.

## Доставка, конкуренция и варианты

Коммерческие события локального заказа имеют собственный producer/sequence,
отдельный от menu ACK. Событие и sequence коммитятся вместе с заказом; сеть
не вызывается в транзакции. Worker доставки заказов и центральный consumer
пока отсутствуют, события остаются неподтверждёнными в edge outbox.
Payload уже содержит полный quote snapshot для будущей центральной проекции,
без необходимости брать текущие цены или обращаться обратно к edge за составом.
`order.created` не является разрешением готовить.

Для локальной точки выбран общий row lock branch для checkout, stop, режима
и применения меню: операции имеют понятный последовательный результат.
Альтернатива — несколько более мелких блокировок и optimistic retry; это
выгоднее при высокой конкуренции, но сложнее для первого стенда. Перед пилотом
измерить задержки; нельзя объявлять плановые SLO достигнутыми этими тестами.

Вариант «клиент передаёт готовый итог» исключён: клиентские суммы не являются
источником цены. Вариант «сразу отправить созданный заказ на кухню» не выбран:
пока нет доверенного платёжного/фискального результата и допуска исполнения.
