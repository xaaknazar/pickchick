# ADR-0013: реестр устройств точки и подключение по одноразовому коду

Дата: 9 октября 2026. Статус: предложено, реализация MVP в работе.
Выпуск на VPS - только охраняемым профилем после согласия владельца.

## Контекст

Владелец попросил вкладку «Устройства» в бэк-офисе: видеть кассу, киоски,
экраны кухни и табло точки, подключать новое устройство и сбрасывать доступ.
Состояние на установленном API `cf25cb9e` (схема 050):

- вкладка `devices` показывает таблицу `devices` и кнопку «Отозвать доступ»;
  команда `revoke_device` ставит `status='revoked'` без журнала устройства;
- кнопка доступна и для `kind='edge'`. `authenticateDevice` пускает только
  `active` edge, а повторной выдачи для `revoked` нет. Одно нажатие необратимо
  останавливает menu-sync, fulfillment, pos-sync и медиа точки;
- iPad-киоск подключается логином и паролем enrollment-alias
  (`kiosk_enrollment_aliases`, миграция 044, срок до 24 часов). Alias сейчас
  выпускается только офлайн-скриптом `scripts/provision-kiosk-enrollment.mjs`;
- экраны кухни, табло и POS используют фиксированные terminal UUID на edge,
  пароли и PIN сотрудников меняются только CLI на кассе
  (инвариант «edge runtime cannot create/reset verifiers», edge 011 и 014);
- ключ связи кассы с облаком (`device_credentials`) живёт 30 дней и
  поворачивается только локальным `device:setup --rotate`.

## Решение

1. **Единый реестр - таблица `devices`.** Миграция
   `051_cloud_device_registry.sql` только добавляет: nullable-колонки `devices`
   (`role`, `kiosk_device_id`, `edge_terminal_id`, `last_seen_at`, `app_version`,
   `revoked_at`, `revoked_by`, `created_by`), таблицы `device_pairing_codes` и
   `device_events`. `kiosk_devices` и `device_credentials` не переписываются:
   на них держатся оплата и синхронизация. `role` старых строк заполняется из
   `kind`; прежние колонки и строки не меняются (это доказывает шаг владельца).
2. **Журнал.** `device_events` - только добавление, `UPDATE/DELETE` запрещены
   триггером, как у `bo_audit`. CHECK `device_audit` (actor `local_setup`) не
   расширяется.
3. **Код подключения.** Открытый код не хранится: `code_hash` =
   HMAC-SHA256(pepper, нормализованный код). Pepper - секрет
   `DEVICE_PAIRING_PEPPER` (32 случайных байта, 64 hex), только в приватном
   `release.env` API, не в БД и не в backup БД. Код одноразовый, срок не больше
   15 минут (CHECK), 5 ошибок сжигают код, одна открытая запись на устройство.
   Повтор с тем же `requestId` не показывает код второй раз.
4. **Киоск в MVP - существующий alias.** Бэк-офис выпускает alias (логин и
   12-символьный пароль) сроком 30 минут вместо 24 часов. Сборка iPad не
   меняется. Только для точки `KIOSK_CHECKOUT_BRANCH_ID`; для других точек UI
   честно пишет, что киоск не настроен. «Сброс» киоска = отключение
   `kiosk_devices` + новая строка и новый alias (триггер 035 запрещает перенос
   устройства между точками).
5. **Edge отключать из бэк-офиса нельзя.** `revoke` для `edge` отвечает 409
   `EDGE_REVOKE_REQUIRES_REPLACEMENT_PROTOCOL`, кнопки нет. Замена моноблока
   требует отдельного протокола (неизменяемый `fulfillment_transport_bindings`).
6. **Права.** Чтение - `analyst` и `manager`, запись - только `manager` этой
   точки. Причина 3-500 символов обязательна, для отключения нужно ввести имя
   устройства. Роль API получает ровно перечисленные в
   `infra/staging/device-registry-owner.mjs` (`REGISTRY_PRIVILEGES`) права;
   `DELETE` и чтение `device_credentials.token_hash` не выдаются.
7. **Кухня, табло, POS в MVP - только чтение** с инструкцией: пароль сотрудника
   меняется на кассе `scripts/staff-password-setup.mjs --replace`.
   Коды для этих экранов (обмен на edge по команде протокола transport 5,
   edge-миграция 020) - этап 2. Сброс пароля сотрудника «билетом» из облака
   меняет инвариант edge 011 и требует отдельного решения владельца (этап 3).

## Выпуск

`infra/staging/release-device-registry.py` от установленного `cf25cb9e`:
точная зелёная CI, ledger 001-040, 042-050, общая блокировка, зашифрованный
backup с проверкой восстановления, шаг владельца (051 и гранты в одной
транзакции REPEATABLE READ), compose переносится байт в байт плюс две строки:
`BACKOFFICE_DEVICE_REGISTRY_ENABLED: "true"` и `DEVICE_PAIRING_PEPPER`, откат на прежний образ. Порядок -
[docs/operations/backoffice-devices.md](../../operations/backoffice-devices.md).
Маршруты в прокси бэк-офиса и gateway выпускаются отдельно.

## Альтернативы

- **Отдельная таблица реестра вместо `devices`.** Отклонено: две правды о
  статусе устройства, `authenticateDevice` и бэк-офис читают `devices`.
- **Хранить код или pepper в БД.** Отклонено: дамп или чтение БД дали бы
  перебор 40-битного кода офлайн.
- **Обмен кода кухни и табло в облаке.** Отклонено: экраны работают через
  edge и должны жить без WAN; ключ терминала принадлежит edge-БД.
- **Оставить отзыв edge с подтверждением.** Отклонено: ошибка необратима до
  протокола замены.

## Последствия

- Подключённый киоск может создавать заказы и Kaspi QR. Кража сессии `ceo`
  (MFA нет, сессия 8 часов) позволяет подключить чужой iPad. Смягчение: срок,
  одноразовость, причина, журнал; позже повторный ввод пароля и MFA.
- Потеря pepper делает недействительными только открытые коды (не больше
  15 минут). Смена pepper - отдельная операция, текущий профиль её не делает.
- Лимиты частоты держатся в БД; лимит в памяти контроллера не переживает
  рестарт и несколько реплик.

## Нужно решение владельца

- модель «билет сброса» для паролей сотрудников;
- перенос «Устройства» в основное меню;
- модель LED-табло.
