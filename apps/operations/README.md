# PickChick — связанные рабочие экраны тестового контура

React web-клиент серверного `/v1/test`, с исходными изображениями, видео,
шрифтами и визуальной компоновкой предоставленного PickChick mockup.
Каждая страница помечена «Тестовый контур — не ресторан».

| Путь                | Работающий сценарий                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `/kiosk`            | Гостевая сессия → стандартные SKU → серверный quote → сохранённый заказ → явный симулятор оплаты → серверный статус |
| `/kitchen/prep`     | Авторизованная очередь приготовления, подтверждение обязательных компонентов                                        |
| `/kitchen/assembly` | Зависимости приготовления, сборка после всех компонентов, подтверждение выдачи                                      |
| `/display`          | Только номера готовящихся/готовых заказов; исчезают после серверной выдачи                                          |
| `/manager`          | Реальный список тестовых заказов, состояния, состав, разрешение неизвестной симуляции, отмена с причиной, выдача    |

Киоск получает новую двухчасовую сессию только при нажатии «Начать». Ключ и
черновик хранятся в `sessionStorage` этой вкладки. Создание/оплата/отмена сохраняют
точное тело и UUID команды **до** HTTP-запроса; при потере ответа доступно повторение
той же команды, включая после перезагрузки. Новый сеанс блокируется, пока сохранённая
операция не разрешена. После подтверждённой тестовой оплаты и показа номера кнопка
«Следующий гость» очищает только локальные данные: серверный заказ остаётся на кухне.
Предупреждение бездействия 90 + 15 секунд очищает неоформленную корзину либо уже
подтверждённый экран. Неизвестная/незавершённая операция не сбрасывается таймером.

Служебный вход принимает временный непрозрачный ключ конкретной роли, выданный
trusted CLI backend. Публичной выдачи staff-ключей нет; ключи не записываются
в исходники, URL или сборку. Права и версия каждой команды проверяются сервером.
Сотрудник должен подтвердить выдачу; киоск не отмечает собственный заказ выданным.

Очереди обновляются раз в 2,5 секунды, только на видимой странице, и сразу после
возвращения к ней. Ошибка транспорта сохраняет последний полученный список,
показывает время наблюдения и блокирует действия до обновления. Оптимистической
готовности нет. Табло показывает по шесть номеров каждого столбца, перелистывая
длинную очередь раз в 8 секунд без анимации; телефон, имя и состав туда не попадают.

## Сборка

```sh
pnpm --filter @pickchick/test-order-flow build
pnpm --filter @pickchick/operations typecheck
pnpm --filter @pickchick/operations build
pnpm --filter @pickchick/operations dev
```

Локальный просмотр: `http://127.0.0.1:4180/kiosk`. Артефакт — `dist/`, с локальными
хешированными изображениями/видео/шрифтами. Развёртывание должно направлять пять
рабочих путей в `index.html` и обслуживать `/assets/*`. Ссылки управляющего на
будущие редакторы ведут к явно обозначенным макетам `/design/prototype/index.html`;
это отдельный разрешённый статический subtree, не CRUD этого клиента.

API зафиксирован в `src/client.ts`: `https://pickchick.185.129.51.103.nip.io/v1/test`.
Контракты импортируются из чистого browser-safe entry point
`@pickchick/test-order-flow/contracts`; ответы проверяются Zod-схемами.
Деньги отображаются из целых минимальных единиц через BigInt; расчёт quote выполняет
сервер. Cookies не отправляются. Для локального HTTP preview сервер должен разрешать
CORS заголовки Authorization, Content-Type и Idempotency-Key.

Версии зафиксированы: React/ReactDOM 19.2.3, TypeScript 5.9.3, Vite 8.2.2.
[React 19.2](https://react.dev/blog/2025/10/01/react-19-2),
[требования Vite к Node](https://vite.dev/guide/) и фактические npm metadata
проверены 6 сентября 2026; используется Node 24.16.0.

## Границы

Работающие серверные состояния не делают это production-приложением ресторана.
Киоск пока web, без MDM/нативной оболочки и LAN edge. В нём нет регистрации,
реального телефона/OTP, QR-расходования Чиков, Kaspi, ККМ, фискального чека,
модификаторов и конструктора комбо, промокодов или готовой программы лояльности.
Комбо продаются в этом тесте как стандартные SKU из каталога. Недоступные функции
объяснены явно и не меняют цену/баланс локально. Кнопки симулятора доступны только
для специально помеченного `/v1/test`; сервер запрещает production-режим.

Список управляющего отражает только тестовые заказы, не продажи/остатки/банковский
баланс. Автономность при потере WAN, физический iPad, сканер/терминал и полноценный
RU/KZ выпуск ещё требуют отдельных реализаций и аппаратной приёмки.

Локально проверены TypeScript, production build и ESLint. Welcome просмотрен
в Chromium 1024×1366 без JS-ошибок и переполнения. Полный реальный сценарий на VPS
проверяется после развёртывания API и получения служебных ролей; эта документация
не объявляет его пройденным заранее.
