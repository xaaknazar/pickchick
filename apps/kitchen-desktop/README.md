# PickChick Kitchen для Windows

Отдельное приложение для моноблока кухни: приготовление, назначенные станции,
сборка и табло выдачи. Интерфейс и gateway берутся непосредственно из
`apps/kitchen`; отдельной копии renderer и бизнес-логики нет. Обновления
переключателя станций входят в EXE после сборки той же версии репозитория.

Это предпусковой клиент. Установщик не содержит PostgreSQL/edge, меню, заказов,
паролей или прав сотрудника и не даёт кассе допускать неоплаченный заказ на кухню.
Существующие серверные проверки ролей, станций, версии заказа и идемпотентности
сохраняются. Реальный ресторанный цикл и оборудование принимаются отдельно.

## Установка на второй моноблок

1. Установить `PickChick-Kitchen-Setup-0.1.0-x64.exe` для текущего пользователя
   Windows или запустить `PickChick-Kitchen-Portable-0.1.0-x64.exe`.
2. Оператор настраивает `%APPDATA%\PickChickKitchen\config.json`. При размещении
   edge на кассе задаются `edgePort` (порт LAN TLS gateway), `edgeHost` (частный
   IPv4 кассы), `edgeCertificatePem` (публичный PEM сертификата этого gateway),
   `terminalId` (UUID кухонного терминала) и `branchLabel` (подпись точки).
   IP и сертификат указываются только вместе. Сертификат должен быть действующим
   и содержать этот IP в SAN. Приватный ключ, пароль сотрудника и bearer token
   в конфигурацию не включаются. Передачу файла и его ACL выполняет оператор.
3. Перезапустить приложение после изменения конфигурации. При отсутствии обоих
   TLS-полей сохраняется прежний локальный upstream `http://127.0.0.1:3101`
   (другой порт задаётся `edgePort`). Этот режим подходит для локального edge или
   заранее настроенного защищённого туннеля. Прямой удалённый HTTP не поддерживается.
4. Войти по своему логину и паролю. Первый пароль выдаёт управляющий через
   защищённый CLI локального узла. Пароль очищается после отправки и не попадает
   в сессию или журнал. Неверные данные дают общее сообщение; при ограничении
   попыток виден обратный отсчёт. Без `terminalId` обычный вход отключён.
   Импорт прежнего файла сессии остаётся в «Обслуживание терминала».
   UI показывает все назначенные сервером станции приготовления и сборки.
   Полный перезапуск требует нового входа.

Клиент проверяет единственный настроенный сертификат как явный TLS trust anchor
и использует штатную проверку имени/IP, срока действия и цепочки Node.js.
Минимальная версия TLS - 1.2; чужая CA, неправильный SAN и redirect отклоняются.
Системные публичные CA не добавляются к заданному сертификату, отката на HTTP нет.
Публичный `/config.json` renderer содержит только подпись точки и `terminalId`;
адрес upstream и сертификат в renderer не передаются. Замена IP или сертификата
требует операторского обновления конфигурации до истечения сертификата.

Приложение открывается развёрнутым. Системное закрытие окна доступно; это не
блокировка Windows и не замена настройке рабочего места. Автозапуск при входе
Windows, служба защищённого туннеля, питание, обновления ОС и права Windows
настраиваются отдельным этапом. Касса и кухня имеют разные appId и профили.

Порт UI фиксирован: `http://127.0.0.1:4178/`. Если он занят, приложение сообщает
ошибку и прекращает запуск. Оно не открывает страницу чужого процесса и не
выбирает случайный порт. Для одновременного запуска отдельного web-preview
кухни нужно освободить 4178; менять origin установленного клиента нельзя.

## Сессия и незавершённые команды

Профиль: `%APPDATA%\PickChickKitchen`, partition: `persist:kitchen-v1`.
Сессия находится в `sessionStorage`; журнал неизвестного результата - в
`localStorage` существующего клиента, с областью точки, сотрудника и терминала.
Установка и portable используют один профиль и single-instance lock.
Обновление и удаление программы не удаляют данные профиля.

Если ответ на «Начать», «Готово» или другое действие потерян, журнал остаётся.
Новые действия и переключение станции блокируются до восстановления. После
повторного входа тем же сотрудником повтор использует исходные тело и ключ
команды; другой сотрудник не получает этот журнал в своём интерфейсе. Кнопка
повтора не создаёт новый ключ. Подтверждённый заказ остаётся в PostgreSQL edge,
а клиентский журнал сохраняет контекст неизвестного результата.

Не очищать профиль при неизвестной команде. Оболочка вызывает
`flushStorageData` при штатном закрытии; сохранность `localStorage` проверяется
перезапуском Electron. Это браузерное хранилище, а не отдельный fsync-журнал POS.
Аппаратное отключение питания, повреждение диска, замена рабочего места и
восстановление из резервной копии требуют отдельного испытания. Профиль не
является Windows Credential Vault; его приватность зависит от ACL пользователя.

## Защитные границы

- Electron renderer: `sandbox`, `contextIsolation`, `webSecurity`; Node,
  preload, IPC-API, webview и небезопасный контент отсутствуют.
- Gateway слушает только `127.0.0.1`. Код byte-for-byte совпадает с
  `apps/kitchen/server.mjs`: проверка Host/Origin, CSP, allowlist существующего
  fulfillment API, заголовков и query-параметров, таймаут 10 секунд, запрос
  до 16 KB (вход по паролю - 2 KB), ответ до 3 MB, запрет redirect и передачи
  произвольных headers. Разрешены только staff login/logout/session и прежний
  fulfillment API; вход использует UUID терминала из конфигурации. Logout204 и
  Retry-After429 передаются без cookies и сторонних заголовков.
- Electron дополнительно разрешает только локальные assets и этот API.
  Внешние адреса, прямой доступ renderer к edge, навигация, новые окна,
  downloads, разрешения устройств и screen capture запрещены.
- UI и шрифты локальные; ни CDN, ни VPS для открытия страницы не нужны.
  Нет auto-updater или загрузки удалённого кода.
- В binary отключены RunAsNode, NodeOptions, Node CLI inspect и дополнительные
  привилегии `file:`; включены OnlyLoadAppFromAsar и ASAR integrity.
- Неизвестный ответ не становится успешным. Gateway не повторяет POST,
  не меняет ключи и не подтверждает оплату. Сессию выпускает только edge после
  проверки пароля; выход отзывает её на сервере по возможности и всегда убирает
  локальный доступ, сохраняя незавершённую команду.

## Сборка и проверка

Пакет изолирован от pnpm workspace, как `apps/pos-desktop`. Node.js ветки 24,
начиная с 24.16.0; npm 11.13.0. Electron 44.2.0, builder 26.16.1 и build toolsets
закреплены собственным lockfile/конфигурацией. Первое скачивание требует сети
или заранее подготовленного cache. Dev-зависимости не входят в ASAR.

```sh
cd apps/kitchen-desktop
npm ci
npm run build
npm run typecheck
npm test
npm run runtime:install
KITCHEN_TEST_PYTHON=/path/to/python-with-playwright npm run test:electron
```

`test:electron` запускает настоящий Electron с исходным renderer, временным
профилем и синтетическим локальным HTTP edge. Он проверяет sandbox и Web Locks,
вход, станции, табло, запрет внешних запросов/навигации, журнал до отправки,
потерю ответа, полный штатный перезапуск, изоляцию сотрудников и точный повтор
без второго эффекта в fixture. Это проверка оболочки; PostgreSQL/полная кухня
проверяются существующими integration/browser tests в `apps/kitchen` и `tests`.
Тест не обращается к VPS и не использует реальные сессии. Для запуска binary
напрямую необходим `runtime:install`; также доступны `KITCHEN_TEST_PLAYWRIGHT`
(абсолютный путь модуля Playwright) и `KITCHEN_ELECTRON_PATH`.

В unpackaged Electron абсолютный `PICKCHICK_KITCHEN_TEST_USER_DATA` позволяет
использовать временный тестовый профиль. Установленная программа игнорирует
эту переменную. Параллельно не запускать другую кухню на фиксированном 4178.

После проверки и коммита исходников:

```sh
npm run dist:win
npm run verify:win
```

Release-сборка требует чистый HEAD. Manifest содержит SHA коммита и SHA256
входных исходников, конфигурации, lockfile и всех 13 renderer assets.
`verify:win` сверяет точный HEAD, хеши исходников и ASAR, byte-for-byte gateway,
явный список файлов (включая локальные шрифты), PE32+ AMD64 payload и fuses.
Результат и SHA256 EXE сохраняются в `release/verification.json`.

Результаты: `release/PickChick-Kitchen-Setup-0.1.0-x64.exe` и
`release/PickChick-Kitchen-Portable-0.1.0-x64.exe`. NSIS распаковщик может быть
PE32; вложенное приложение проверяется как PE32+ AMD64. Build-результаты не
включаются в Git. `pack:mac-test` предназначен только для проверки Mac-пакета.

Authenticode-подпись не настроена. Сборка на macOS и структурная проверка PE
не доказывают запуск на Windows 10 Pro: установка, Defender/SmartScreen,
сенсорное управление, обновление, LAN TLS, перезагрузка и смена на физических
моноблоках остаются в приёмке. Побитовая воспроизводимость NSIS не заявляется.

Порядок локального узла и доступа: [LAN-кухня](../../docs/operations/lan-kitchen-client.md).
Общая оболочка кассы: [POS desktop](../pos-desktop/README.md).

Дополнительно проверяются настоящий TLS-сервер с временными сертификатами
(чужой сертификат не получает пароль), проверка SAN, пределы body/response,
редиректы и приватность config. Browser-проверка PostgreSQL выполняет вход по
паролю, приготовление, переключение сборки, табло и выдачу при двух разрешениях.
Канал `pos` показывается как «Касса»; состав допускает все 100 модификаторов
канонического контракта. Это не подтверждение реальной установки на Windows.
