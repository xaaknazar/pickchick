# Коммерческое оформление гостя

`EXPO_PUBLIC_KIOSK_COMMERCIAL=1` выбирает отдельный коммерческий контроллер.
Флаг по умолчанию выключен. TEST-контроллер и его хранилище сохранены;
коммерческий контроллер никогда не обращается к TEST API и не имитирует оплату.

Клиент использует `/v1/kiosk-checkout`, опубликованный каталог канала kiosk,
серверную котировку и заказ. Для новых оплат config обязан подтвердить
`paymentMethod: kaspi_qr`. Телефон, аккаунт, OTP и бонусы не нужны.
В котировку уходят SKU из опубликованного меню, версия, модификаторы и режим
получения. Сумма сервера сравнивается с показанной гостю до обновления меню;
изменение возвращает к проверке корзины. Свежая availability накладывает stop
позиции и опции; устаревшая доступность закрывает оформление.

Первый запуск native показывает операторскую настройку. Сотрудник вводит
ID и секрет устройства, выданные администратором. Настройка
вызывает `provisionCommercialKiosk`, проверяет credential на сервере через
`POST /enrollment/check` до локальной записи и сохраняет его в SecureStore с
`WHEN_UNLOCKED_THIS_DEVICE_ONLY` и отвергает замену существующего устройства,
сессии или flow. Доступ к настройке сам по себе не регистрирует устройство на
сервере. Отказ preflight или отсутствие связи оставляют устройство без локальной
регистрации. Ключ не помещается в Expo public env, URL, логи или репозиторий.
Commercial web запрещён адаптером хранения; браузерное превью не доказывает
работу SecureStore или физическую активацию iPad.

Native секрет гостя и незавершённое намерение хранятся отдельно от TEST в
SecureStore. Session ID/token, ключи котировки, заказа и оплаты сохраняются
до HTTP. Новый платёж отправляет `{method: kaspi_qr}` с прежним payment key
при восстановлении потерянного ответа. Старое намерение телефонного счёта
может только прочитать уже сохранённый заказ; новый счёт не создаётся.
Старое намерение без заказа требует разбора сотрудником.

Серверный payment projection содержит kind, state, qrPayload и expiresAt.
Настоящий QR кодируется локально qrcode-generator и отображается native через
SVG expo-image, без внешнего сервиса изображений. QR показывается только для
pending с payload и будущим сроком; checking, неизвестный результат и истечение
срока скрывают код, сохраняя проверку прежнего заказа. Только авторитетная фаза
заказа подтверждает оплату; `payment.state=paid` отдельно гостя не освобождает.
Отсутствующий QR не заменяется фиктивным изображением.

End session сохраняет marker до ответа, удаляет гостевой секрет, затем flow.
Потеря ответа не означает выполненное удаление. Новый гость разрешён только
после авторитетной успешной оплаты или окончательного неуспеха. Серверный
кухонный/банковский процесс продолжается после очистки экрана. Отмена активной
оплаты клиентом не реализована.

Проверки: `node --test tests/kiosk/commercial-core.test.mjs tests/kiosk/guest-core.test.mjs tests/kiosk/qr.test.mjs`,
`corepack pnpm --filter @pickchick/kiosk typecheck`.
Изолированные фикстуры проверяют восстановление, stop/SKU/цену, QR expiry,
отсутствие TEST fallback и отсутствие повторного телефонного счёта.
Это не банковская операция и не приёмка iPad. Перед включением нужны
подтверждённый QR-адаптер, server provisioning, контрактная E2E-проверка,
native сканирование QR, restore/privacy/keyboard и физическая установка.
