# Коммерческое оформление гостя

`EXPO_PUBLIC_KIOSK_COMMERCIAL=1` выбирает отдельный коммерческий контроллер.
Флаг по умолчанию выключен. TEST-контроллер и его хранилище сохранены;
коммерческий контроллер никогда не обращается к TEST API и не имитирует оплату.

Клиент использует `/v1/kiosk-checkout`, опубликованный каталог канала kiosk,
серверную котировку и CustomerCommerceOrder. В запрос котировки уходят SKU из
опубликованного меню, номер версии, состав модификаторов и режим получения.
Авторитетная сумма - серверная. Кассовый стоп оставляет позицию недоступной,
не уменьшает уже выбранную корзину молча.

Устройство должно быть заранее зарегистрировано на сервере и локально
настроено оператором через `provisionCommercialKiosk(deviceId, key)` из
`src/storage.ts`. Этот доверенный native enrollment сохраняет credential в
SecureStore с `WHEN_UNLOCKED_THIS_DEVICE_ONLY` и отвергает замену действующей
настройки. Гостевой экран не выдаёт такие права. Нельзя подставлять device key
в Expo public env, приложение, URL, логи или общий репозиторий. Операторский
экран enrollment и физическая настройка iPad остаются отдельным внедрением.

Commercial web запрещён адаптером хранения: ключи и гостевая сессия не
переносятся в localStorage. Native гостевой секрет, flow с активным намерением,
телефоном счёта и ссылкой на заказ хранятся отдельно от TEST в SecureStore.
Клиент генерирует session ID/token до POST sessions и сохраняет их до запроса.
Потерянный ответ повторяется с той же идентичностью. Ключи котировки и заказа
и телефон оплаты сохраняются до HTTP; восстановление не меняет их.
Телефон нужен только для счёта Kaspi, аккаунт/OTP/бонусы не создаются. Поле
телефона очищается при отправке; после подтверждённого ответа телефон удаляется
и из намерения. Активная оплата, неизвестный ответ или ошибка защищённого
хранилища удерживают киоск для проверки прежнего заказа.

Новый гость разрешён после авторитетной успешной оплаты либо окончательного
неуспеха. End session сохраняет marker до ответа, удаляет гостевой секрет,
затем очищает flow; потеря ответа не означает выполненное удаление.
POST sessions/end должен принимать идемпотентный повтор для уже завершённой
сессии с тем же устройством и секретом. Кухонный/банковский процесс продолжается
на сервере после очистки экрана. Отмена активной оплаты клиентом в этом этапе
не реализована; её результат приходит от серверной проверки/TTL Kaspi.

Проверки: `node --test tests/kiosk/commercial-core.test.mjs tests/kiosk/guest-core.test.mjs`,
`pnpm --filter @pickchick/kiosk typecheck`. Изолированные фикстуры подтверждают
восстановление намерения, работу stop/SKU/цены и отсутствие TEST fallback;
это не банковская операция и не физическая приёмка iPad/SecureStore.
Перед включением требуются server provisioning, контрактная E2E-проверка,
установка и native restore/privacy/keyboard проверка на устройстве.
